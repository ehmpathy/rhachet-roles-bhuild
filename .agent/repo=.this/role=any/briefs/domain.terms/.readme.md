# domain.terms 🦫📜

this is bhuild's **glossary** — one canonical word per concept, for the domain objects and
operations this repo declares.

read it to learn what bhuild calls things, and why.

## .what lives here

one cluster per term (one word). each cluster has:

- `term=<x>._.choice._.md` — the chosen word, its kind, its boundary, its forbidden synonyms, and where it is used
- `term=<x>._.choice.reason.md` — why this word: etymology, settled disputes, and the evidence behind the choice — **required**
- `term=<x>._.choice.example=<abc>.md` — a notable example in use (optional, one per example)

start with `._.choice._.md` for the quick answer. open `.reason.md` for the full record.

## .the three rules

- `rule.require.domain-term-itemization` — every word that composes a declared domain object or operation gets a cluster here
- `rule.forbid.domain-term-synonyms` — contracts use the canonical term; if you believe a synonym is right, open a dispute rather than drift silently
- `rule.require.boundary-qualified-terms` — the filename carries the term's **full boundary ancestry**

## .the boundary convention — a flat name means ROOT, never "unqualified"

the test is *"$word, of WHAT?"* — one word answers, and that word is the boundary.

| filename shape | what it asserts |
|---|---|
| `term=experience._.*` | `experience` is a root — it hangs under no other term |
| `term=behavior.experience._.*` | `experience` is a child of `behavior` |

⇒ **so a flat name is a claim, not an absence.** bhrain's glossary is the worked precedent: across
its 38 clusters, a flat name appears only for a root (`artifact`, `externalize`, `glossary`,
`glyph`), and every child carries its chain (`term=artifact.dream`, `term=glossary.sweep.progress`).

🟡 the ancestry is the term chain, never the role or the repo. `behavior.experience`, never
`behaver.experience`.

## .the open gaps — the census lives HERE, never inside a rule

a gap is a word this glossary owes and does not yet hold, recorded so the next traveler finds it
already named rather than re-derives it.

### the three sweeps

**three sweeps find the gaps, and each is blind to what the other two catch.** run all three at
the start of a round. the blockquotes below carry one command and one measured incident each; this
table is the only place the three are compared.

| the sweep | its question | what only it can find |
|---|---|---|
| inward | which words do OUR contracts use that we have not itemized? | a gap in our own tree |
| outward | which words does a PEER say we own? | an export we owe |
| collision | which words have we declared that a peer has ALSO declared since? | a duplicate that reads as complete |

### the question no sweep can answer — added 2026-09-08

> **is the CONTRACT that carries this word mine to declare?**

- a sweep reads what a peer has declared
  - it cannot read what a peer is about to declare, because we asked them to
  - ⇒ so a word coined for a rule we dispatch elsewhere passes all three sweeps clean, and is still
    not ours
- measured this day — `repair` · `superficial` · `structural` · `archaeology`, four sweeps, 0 files
  each, all bhrain's
  - caught one round earlier in a term's lifecycle than the `prose.subversive` row below was

### when a row is discharged

> **a row is DISCHARGED only when it cites what it FOUND. a stated verdict is a hypothesis.**
>
> a row that states a conclusion closes the loop in the reader's mind while the file stays unread.
> so a row is done when it reads *"`repo:path:lines` declares X"*, never *"X is declared in `repo`"*.
>
> ⇒ run the census at the START of a round, never at the first use of a word. the first use may
> never come; the round boundary always does.

> ## .the OUTWARD sweep — an export a peer already cites
>
> a peer `.reason` can cite a bhuild object whose term bhuild never declared — **an import with no
> export**, invisible to any inward pass, since no file in our own tree is absent.
>
> ⇒ the outward sweep, and it is one command:
>
> ```sh
> rhx git.repo.get lines --repos 'ehmpathy/*' --words 'rhachet-roles-bhuild|bhuild/role='
> ```
>
> an `imported`, a `declared in bhuild`, or an `already declared in bhuild` inside a peer's `.reason`
> is an **export we owe**. run it beside the inward pass, every round. one is still owed:
> `dispatcher`, which mhedic `term=referrer._.choice.reason.md:36` cites as declared in bhuild.

> ## .the COLLISION sweep — a word a peer has declared SINCE we did
>
> a peer can ship the identical cluster after we do, and the inward and outward passes both read
> clean the whole time — so two glossaries declare one word.
>
> ⇒ the collision sweep, and it is one command per boundary we hold:
>
> ```sh
> rhx git.repo.get files --repos 'ehmpathy/*' --paths '**/domain.terms/term=<boundary>*'
> ```
>
> run it for each boundary in the table below, before you write a new cluster under it. a hit
> in a peer repo means the word is theirs to declare and ours to cite.
>
> **the asymmetry that makes this the most expensive of the three:** an owed export is a file we
> have not written — cheap, and loud once found. a collision is a file we have written, which
> reads as complete, and drifts from the canon it duplicates with every edit either side makes.
>
> ⇒ a collision hit is a pointer at pavement, never only a fence. read the hit: a peer cluster
> often holds the test that settles your case, and an extant word for the sense it refused.
>
> the evidence behind all three sweeps — what each caught, and when:
> `.agent/.notes/note.domain-terms.sweeps.evidence.md`.
