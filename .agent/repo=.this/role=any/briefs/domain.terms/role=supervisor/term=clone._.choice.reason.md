# domain.term.choice.reason: clone

## .etymology

rhachet's word, not ours: `rhx clone say`, `rhx clone whoami`, the `@:<clone>` sigil. a clone is one
instance of a brain enrolled in a role. this repo adopts it unchanged, so the phone speaks the word its
delivery verb already speaks.

## .why the synonyms distort

| ⛔ synonym | why it distorts |
|---|---|
| `agent` | generic; says naught about the role or the tree it sits in |
| `bot` | names the git identity (`seaturtle[bot]`), a different concept |
| `session` | names a tmux or claude session — the vessel, not the worker (`term=duct`) |
| `seat` | fine in prose about a crew's shape; in an address it would be a second word for one key |

## .the evidence

the phone vision (`.behavior/v2026_10_21.feat-phone-text`, fulcrum F10) weighed `clone=@:director`
against `clone=director`. robot:director settled it, 2026-10-21: *"clone=director, a plain key value
like clone=mechanic in your own examples. the @: alias stays a shell shorthand, never part of the
stored address."* a key that carried the sigil would hold two notations in one slot.
