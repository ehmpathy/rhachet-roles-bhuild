# 🌙 dream: enroll review lanes must emit the numeric count lines

- kind: reseed (owner: ehmpathy/rhachet-roles-bhrain, the review guard + tallier)
- caught 2026-11-20, in rhachet-roles-bhuild route `v2026_11_08.feat-vision-root-purpose`, stone 5.3

## .the cue that fired

the i003 `enroll-verif-snapshot-blemishes` lane wrote its verdict as prose
(`Tally: 0 blockers, 7 nitpicks`), with no `N blockers` / `N nitpicks` lines. a sub-brain then
tallied it, read the prose mentions of "blocker" as real ones, and held the stone on 2 blockers the
reviewer never raised (fulcrum F25).

## .the gap, precisely

- `contract.reviewer-output` requires a numeric count for both dimensions on stdout. an enroll
  lane, which runs a clone, does not enforce it, so its prose falls to a sub-brain tally
- that tally is unsound on prose that names a severity it does not raise: "the rule calls this a
  blocker; I graded it a nitpick" reads as one blocker

## .the shape of the fix

- the enroll review wrapper appends the contract's two numeric lines to its prompt, as a demand,
  and refuses a given that lacks them as a `💥 malfunction` (re-run), never a sub-brain guess
- or: the tallier reads only `[blocker]` / `[nitpick]` labels at the head of an enumerated concern,
  never the bare word in prose

## .why it is not done in this round

the tallier and the enroll wrapper live in rhachet-roles-bhrain. this repo only consumes them.
