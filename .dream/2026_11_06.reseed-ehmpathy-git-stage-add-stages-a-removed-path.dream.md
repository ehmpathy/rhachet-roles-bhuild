# 🌙 dream: git.stage.add stages a path tracked in HEAD but removed from disk

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (role=mechanic)
- caught: 2026-11-06

## .the cue that fired

peer review i005 (r010, r011) on 5.1 of `v2026_10_24.feat-init-behavior-preship-reflect`: the
6.preship ledger lists removed paths (`[-]`), and `git.stage.add` cannot stage one.

## .the gap, precisely

`git.stage.add.sh` (1.41.0, lines 163–169) exits 2 with `file not found` for any path absent from
disk, before it stages aught. a removed file is absent by definition. the only paved route to
stage a removal is `git add <parent-dir>`, which sweeps every other change under that dir.

## .the shape of the fix

in the existence guard, accept a path absent from disk when `git ls-files --error-unmatch -- <path>`
finds it in the index (a tracked removal); then `git add -- <path>` stages the deletion. a path
neither on disk nor tracked still refuses.

## .why it is not done in this round

it is another repo's skill. 6.preship carries a stone-text arm meanwhile: stage the nearest extant
parent dir only when `git status --porcelain <dir>` shows no off-ledger dirty path, else hold.
