- **kind** = seed
- **owner** = `ehmpathy/rhachet-roles-ehmpathy`, `role=mechanic`
- **caught** = 2026-09-26

## .the cue that fired

`arch-hazards-maintenance` cited `rule.require.immutable-vars` against **bash** twice, two rounds
apart, and the second time it did so **eleven times**:

| round | target | why it missed |
|---|---|---|
| i010 | `set -euo pipefail` | a shell **option**, not a variable at all |
| i012 | `create=false` · `BLOCKERS=()` · `UNREADABLE=0` · 8 more | real variables — but the rule's instrument is `const`, which bash lacks |

both were disputed (`F15`). **and the dispute is the wrong long-term answer**, because the reviewer
reaches for a real concern and finds no brief that holds it.

## 🔴 .the gap, precisely — the rule prescribes an instrument, not a principle

```
rule.require.immutable-vars   (ehmpathy/role=mechanic, code.prod/pitofsuccess.procedures/)
  .how      = "use const for all bindings; forbid let or var"
              "use object spreads or .clone()"  ·  "use withImmute() and .clone()"
  .examples = const updated = { ...original, status: 'complete' };
  .links    = domain-objects.withImmute
```

⇒ every mechanism it names is TypeScript. so a reviewer that grades **shell** has two choices, and
both are bad: skip immutability entirely, or **translate the rule itself** — which is what happened
(*"In bash, this translates to … `readonly`"*). that translation is the reviewer's invention, and an
invented bridge is not auditable.

⚠️ **the deeper point: the corpus this repo now ships is 46 shell entrypoints and ~78k lines of
bash.** the mechanic role has a full `lang.prose` and `code.prod` practice set and **not one brief
whose examples are shell.** so every shell rubric is a TypeScript rubric aimed sideways, and `F15` is
the second measured instance of the consequence.

## .the shape of the fix

author `rule.require.immutable-vars.bash.md` (or extend the extant brief with a `.bash` section) that
names bash's own instruments:

| the move | bash |
|---|---|
| freeze a value that never varies | `readonly NAME=value` · `declare -r` |
| bound a variable to its function | `local name` — and **`local` before every assignment in a function**, or it leaks to global |
| the parse-then-freeze pattern | accumulate through the `while`/`case` parse, then `readonly` each result once the loop exits |
| an accumulator that must mutate | declare the mutation deliberate, with a one-line `# .note` on why |

### 🔴 the exemption the brief most needs to state

> **an argument-parse accumulator is mutable by construction and is NOT a violation.**

`create=false` → `create=true` on `--create` is the whole mechanism of a flag. a rule that reads it as
a defect generates exactly the 11 nitpicks of i012, and a reviewer cannot tell the difference with no
brief to tell it. ⇒ **the exemption is the load-central half of the brief, not an afterthought.**

🟡 the honest counter to the *"then just add readonly after the parse"* answer: it costs one extra
declaration per variable — ~30 lines across 3 files in this corpus alone — to forbid a mutation that
has already stopped. so the brief should say whether that ceremony is **required**, **preferred**, or
**a nitpick only where the variable is later read far from its parse**. `F15` guessed the last; the
brief should settle it.
