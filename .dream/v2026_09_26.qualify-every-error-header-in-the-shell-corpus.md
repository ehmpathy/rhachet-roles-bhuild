## .the cue that fired

peer review i011, `mech-failhides` **nitpick.2** — 42 sites across 14 lifted supervisor skills emit
a bare `error:` prefix where `rule.require.qualified-error-headers` demands the exact form:

```
✋ ConstraintError: <what went wrong>
💥 MalfunctionError: <what went wrong>
```

## 🔴 .the gap, precisely — and it is WIDER than the review could see

the reviewer's bind is `--diffs since-main`, so it counted only what this lift moved. the corpus
count is larger, and the difference decides who owns the defect:

```
rhx grepsafe --pattern 'echo .error: ' --glob 'src/domain.roles/**/*.sh'
  → 71 lines
```

| where | count | in the lift's diff? |
|---|---|---|
| the 14 lifted `supervisor/skills/*.sh` | **42** | ✅ yes |
| `behaver/skills/review.behavior.sh` · `review.deliverable.sh` | 16 | 🔴 **no — already on `main`** |
| `dispatcher/skills/radio.uses.{global,org,local,operations}.sh` | 13 | 🔴 **no — already on `main`** |

⇒ **the `error:` convention is the repo's, not the lift's.** it predates the lift in files the lift
never touched. ⚠️ a sweep scoped to the reviewer's 42 would leave the package with **two** conventions
for one concept — the `rule.forbid.ambiguous-labels` failure the rule exists to close.

## 🔴 .the shape of the fix

### 1. classify before you convert — the reviewer's blanket claim is close, not exact

it asserted *"these are all constraint errors."* that holds for the 42 it read; it is **unverified**
for the other 29. two candidates that need a look rather than a sed:

```
behaver/skills/review.behavior.sh:48      "error: claude binary not found (install …)"
dispatcher/skills/radio.uses.operations.sh:29  "error: not in a git repository"
```

an absent `claude` binary is arguably a **MalfunctionError** (the environment is broken) rather than
a ConstraintError (the caller must fix). ⇒ **the exit codes decide it, not the prose**: a constraint
owes `exit 2`, a malfunction `exit 1` (`rule.require.exit-code-semantics`). read each site's own exit
code first, then match the header to it.

### 2. then one sweep, over all 71

```sh
# 🔴 plan FIRST, and read the file count — an excess count is the tell that the
#    pattern was not unique (this route paid for that lesson at i010 with genTempDir)
rhx sedreplace --old 'echo "error: ' --new 'echo "✋ ConstraintError: ' --glob 'src/domain.roles/**/*.sh'
```

⚠️ then hand-correct whichever sites classified as malfunctions in step 1.

### 3. the exit codes travel with it

`git.checkout.sh:74` was repaired in i011 (`exit 1` → `exit 2`) because the file's own comment at
`:62` declared the convention and cited the rule. 🟡 **the same half-finished repair is likely
elsewhere** — that comment says *"the rest of the family said 1 until measured"*, so the audit is a
family-wide one:

```
rhx grepsafe --pattern 'exit 1' --glob 'src/domain.roles/**/skills/*.sh'
```

## .why it is not done in this round

- 🔴 **the correct scope is 71 and 71 is not this stone's scope.** the wish bounds this stone to a
  relocation; a package-wide convention change over files the lift never opened is the
  *"corpus-wide rewrite smuggled into an unrelated change"* that `rule.prefer.wickup-touched-prose`
  grades a **blocker**
- it passes SAFE (an echo string cannot change behavior; no clamp asserts on the prefix — checked)
  and fails CLEAN in both directions: 42 leaves two conventions, 71 leaves the stone's bound
- it arrived as a **nitpick on an APPROVED lane**, and the stone-wide residual tally is under its
  allowance, so the deferral costs the stone naught

🟡 **the honest counter:** 42 of the 71 sit in files already open in this diff, so a partial sweep is
nearly free. it is refused because **a half-converted convention is worse than a consistent wrong
one** — a reader who meets both forms cannot tell which is intended, which is the very ambiguity the
rule targets.
