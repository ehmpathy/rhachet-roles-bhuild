**kind** = `fix` · **owner** = `repo=bhuild/role=supervisor` · **caught** 2026-09-25

## .the cue that fired

a confirmation pass on radio issue `#321`, whose fourth acceptance criterion reads:

> *"any resume path bhuild owns carries forward the permission mode the boot used, with a clamp
> that goes red without it"*

⇒ to check it i grepped `crewwork.sh` for `permission-mode` and found **two comments in one file
that make opposite claims about the same mechanism.**

## .the gap, precisely

| line | the general claim | flag sent? | clamped? |
|---|---|---|---|
| `crewwork.sh:5845` (crew.boot resume) | *"a permission mode is a **LAUNCH flag**, never a property of the conversation, so a resume restores the transcript and **NOT** the mode it ran under"* | ✅ yes | ✅ `crewwork.integration.test.ts:1297` |
| `crewwork.sh:4071` (heal revive) | *"claude's resume **restores the session's own permission mode**, so no `--permission-mode` flag is owed"* | ❌ no | ✅ `…test.ts:1744` — teeth assert the flag is **absent** |
| `crewwork.sh:3936` (heal launch) | *"a resume restores the session's own mode"* | ✅ yes (a fresh clone has no session to restore from) | ✅ `…test.ts:2096` |

**a permission mode is either a property of the conversation or it is not.** two of these say it
is; one says it is not. at most one general claim is true.

### 🔴 what this is NOT — and the correction matters more than the find

my first read called `4073` a defect: *"the heal path drops the flag."* **that was wrong**, and a
read of 30 lines further is what caught it.

- the omission is **deliberate** — line 4055 records it as *"corrected by the human 2026-09-14"*,
  with the verbatim quote *"use the command i gave you verbatum"*
- it is **clamped in the negative direction** — `…test.ts:1756` asserts the exact form, and `:1758`
  asserts the prior double-nudge is gone
- so **all four resume/launch paths are clamped**, each in the direction its own argument chose

⇒ 🔴 **the code is not in contradiction. only the PROSE is.** a grep window showed me a
half-sentence and i nearly filed a false defect against a correct lift — the same
`term=partial-audit` shape this route has now paid for a dozen times, and it landed inside a
*confirmation* pass whose entire job was to not do that.

## .why it still matters

the comments are what a future maintainer reads to decide the **next** resume path. whoever adds
one will grep exactly as i did, land on whichever line is nearer, and inherit a general rule that
is wrong half the time. ⇒ a `term=false-report`: an honest note, confidently stated, about a
mechanism nobody re-measured.

🟡 **and the dates cut against the intuitive answer.** issue `#321` (2026-08-09) states flatly that
*"a resume drops the permission mode … `--continue` restores the transcript, never the launch
flags"*, and says the source notebook fixed it **with a clamp**. but `4071`'s note is dated **2026-09-14** — a
month later, and a human correction. ⇒ the older, more emphatic claim is the one more likely to be
stale, which is the opposite of how a reader weighs two notes.

🟡 one more piece of evidence, and it is **ambiguous rather than decisive**: `__crew_is_healable`
axis 4 (`crewwork.sh:1504`) exists for *"a clone that LOST `--permission-mode acceptEdits`"*. that
proves the loss is **real and observed** — it does **not** prove a resume caused it. a clone booted
without the flag, or one whose mode was changed at the keyboard, lands in the same state.

## .the shape of the fix

1. **measure it** — boot a clone with `--permission-mode acceptEdits`, resume it with the verbatim
   `claude --resume "$who" continue`, and read the mode at the keyboard. one observation settles all
   three comments, and no amount of re-read does
2. **write the answer once**, in a brief or a term cluster, and have all three sites cite it rather
   than each restate it — a claim restated in three places is a cache in three places
3. if `4071` is wrong: add the flag **and** invert its clamp, whose teeth today point the other way
   (`…test.ts:1756` would need to assert presence, not absence)
4. if `5845` is wrong: the boot path's extra flag is harmless, so only its prose needs the repair

## .why it is not done in this round

**SAFE** — ❌. the fix turns on the behavior of an **external tool** (`claude`'s resume) that i
cannot observe from here: it needs a live grove, a tmux pane, and a real session to resume. every
branch is a guess, and a guess that edits crew **recovery** is a guess that can leave a fleet
unrecoverable.

**CLEAN** — ❌. it would ripple into three comment sites, one clamp whose teeth invert, and the
`#321` verdict.

⇒ both answers are no, so this is the row `rule.always.fix-forward-under-scouts-honor` sends to a
dream. 🟡 it does **not** owe a fulcrum: the deferral is for an absent **measurement**, never a
judgment call about ripple cost.
