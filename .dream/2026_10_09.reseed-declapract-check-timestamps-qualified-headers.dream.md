## .the gap, precisely

`src/practices/husky/best-practice/.husky/check.timestamps.sh` on declapract `origin/main`:

- line 41: `printf '💥 check.timestamps: failed to read staged content for %s\n'` — glyph, no class
- line 51: `printf '✋ timestamps are forbidden in snapshots. mask them to prevent permadrift\n'` —
  glyph, no class

the exit codes already match the classes (1 for the read failure, 2 for the forbidden stamp).
only the header words are absent.

`rhachet-roles-bhuild` fixed its own copy, so every other repo that adopts the practice still
prints the unqualified headers. and a declapract upgrade there would revert the local fix.

## .the shape of the fix

```bash
printf '💥 MalfunctionError: check.timestamps failed to read staged content for %s\n' "$file" >&2
printf '✋ ConstraintError: timestamps are forbidden in snapshots. mask them to prevent permadrift\n'
```

and keep git's stderr out of the scanned content (raised by arch-hazards-maintenance, i002
blocker.1): read with `content=$(git show ":$file")`, not `2>&1`, so a git notice on stderr can
never mix into the bytes the scan reads. git's own message then prints above the halt header, so
the `└─ $content` line goes.

and route the constraint branch to stderr, as the malfunction branch already is (raised by
ergo-friction-hazards, i003 nitpick.1): both `✋ ConstraintError` lines gain `>&2`.

and say what the scan covers (raised by ergo-friction-hazards, i004 nitpick.1): the gate scans
every staged file outside `.ts` / `.sh`, so "forbidden in snapshots" misnames the scope a human
just hit. the words become "timestamps are forbidden in tracked files".

and adopt the gate's own test: `rhachet-roles-bhuild` `.husky/check.timestamps.integration.test.ts`
covers the stamp halt (exit 2, masked snapshot), the datestamp pass, the `.ts` exemption, and the
unreadable-blob malfunction (exit 1, git's message above the header).

and list staged paths raw (raised by enroll-impl-arch-defects, i007 nitpick.8): git quotes a
non-ascii path by default (`"lecciones-\303\261.md"`), and `git show ":$file"` cannot find the
quoted form, so the gate fails as a malfunction on a legit file. read the list via
`git -c core.quotepath=off diff --cached --name-only --diff-filter=ACM`. the local test case5
(a non-ascii path, datestamp passes, stamp halts with the raw path) went red before this fix.

then check whether any declapract test or snapshot pins the old text, and update it.
