# 🌙 dream: a boot.yml knob that shrinks the `<also>` roster without an erase

kind: reseed · owner: ehmpathy/rhachet · caught 2026-10-22

## .the cue that fired

i008 peer review of `fix-clamp-behaver-boot-budget` (r011 nitpick 2): four symptoms on this branch
trace to one absent option in rhachet's boot.yml schema.

## .the gap, precisely

- the schema is `say · ref · not` only (`RoleBootSpec.js`); `<also>` is every resource no list
  claimed (`computeBootPlan.js:224-229`)
- the one way to shrink `<also>` is `not`, and `not` erases a resource from every destination —
  it is subtracted before the say/ref split (`computeBootPlan.js:297-302`), so a name in both
  `say` and a `not` glob boots nowhere
- the symptoms it forces here:
  - ten inverse extglobs `!(a|b|c)` in `supervisor/boot.yml`, hand-synced against `say:`
  - dead `not:` entries in the decomposer, prioritizer, and supervisor boots
  - the hand-written `briefs/catalog.of=supervisor.briefs.md`
  - the clamps that guard the hand sync: `[case7]` and the said-entry check in `[case5][t1]`

## .the shape of the fix

- add a boot.yml option that drops unclaimed resources from `<also>` only — e.g. `also: omit`, or
  an `also: not:` list — and leaves `say` and `ref` untouched
- or: apply `not` after the say/ref split, so an explicit `say` wins over a glob
- then here: replace each inverse extglob with plain `say:` entries plus `also: omit`, and drop the
  dead `not:` lines. the said-entry clamp stays as a guard

## .why it is not done in this round

the fix lives in another repo (rhachet). this branch pins an ehmpathy-owned rhachet sha; a schema
change there is its own release. the said-entry clamp in `[case5][t1]` holds the silent-cut hole
shut until then.
