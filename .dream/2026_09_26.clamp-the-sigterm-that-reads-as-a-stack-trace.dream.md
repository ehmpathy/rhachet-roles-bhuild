# 🌙 dream: a review killed by SIGTERM reports a Node stack trace, not a diagnosis

- **kind** = `reseed` — the defect is `rhachet-roles-bhrain`'s review engine, plus its guard schema
- **owner** = `ehmpathy/rhachet-roles-bhrain`
- **caught** = 2026-09-26, from `ehmpathy/rhachet-roles-bhuild` route
  `v2026_09_22.feat-lift-supervisor-and-prioritizer-roles`, stone `5.1.execution.from_vision`, i006

## .the cue that fired

six of nine peer-review lanes went dark in one round. the only output a human was handed:

```
file:///…/@anthropic-ai/claude-agent-sdk/sdk.mjs:13248
   return new Error(`Claude Code process exited with code ${code}`);
Error: Claude Code process exited with code 143
    at ProcessTransport.getProcessExitError (…)
    at ChildProcess.exitHandler (…)
    at Object.onceWrapper (node:events:634:26)
```

⇒ it took a read of **three engine source files** to learn that this meant *"too many reviewers ran
at once."* every fact needed for that diagnosis exists in the codebase already. none of it is in
the message.

## .the gap, precisely — three halves, each checkable

### 1. 🔴 the SIGTERM path falls past the engine's own good error

the engine renders its **own** timeout kill beautifully:

```js
// runOneReview.js:104
stderr: `💥 malfunction: review timed out after ${formatTimeoutForHuman({ ms: input.timeoutMs })}`,
```

with a comment at `:96-98` that cites `rule.forbid.failhide` by name and states the invariant: *"one
place owns the 'killed → timeout message, else use the exit code' rule."*

🔴 **but a SIGTERM that arrives from INSIDE the agent SDK never reaches that branch.** it surfaces
as a raw `Error` from `sdk.mjs:13248` and propagates out untranslated. so one failure class has two
exits — one legible, one a stack trace.

> ⇒ **the ask is not "write a good error." it is "route this case through the good error you already
> wrote."**

### 2. 🔴 `code 143` is decode-friction with five uncarried steps

| step | what a human must supply |
|---|---|
| 1 | `143` is no application exit code |
| 2 | POSIX encodes a signal death as `128 + signum` |
| 3 | `143 - 128 = 15` |
| 4 | signal 15 is `SIGTERM` |
| 5 | SIGTERM ⇒ hunt an external killer, never an internal bug |

this breaks, by name:
- `rule.require.errors-name-the-fix` (ergonomist) — *"a stack trace shown to a human as the only
  error output = blocker"*
- `rule.require.qualified-error-headers` (mechanic) — no `💥 MalfunctionError:` opener, no class
- `rule.require.named-transformers` (mechanic) — a bare POSIX wait status is the most general
  primitive there is, and it is handed to a human unwrapped

### 3. 🔴 the bound that CAUSED it is undiscoverable from the artifact a human authors

the level concurrency bound defaults to **10** and is settable only via
`RHACHET_LEVEL_CONCURRENCY`. it is:

| surface | carries it? |
|---|---|
| a `.guard` key | 🔴 no — deliberately |
| `rhx review --help` | 🔴 no |
| the error, when it bites | 🔴 no |
| a `.d.ts` comment in `node_modules` | ✅ yes — and only there |

the schema concedes the gap in its own words:

> *"it is stated here because a guard author who reads only this key would take a group bound for
> the whole story."* — `RouteStoneGuard.d.ts:161-168`

⇒ a guard author writes nine level-1 lanes, gets no signal, and learns the bound exists by way of
six dark lanes and an SDK source read. `rule.require.discoverability`: *"a step a human cannot find
is a step a human cannot take."*

🟡 the **design** is defensible and reasoned (an operator dial that must move with no snapshot
re-baseline). the **silence** is the defect.

## .the shape of the fix

### a — translate the signal, at the one seam that already owns translation

`runOneReview.js` already has the "killed → message" seam. widen it so an SDK-originated signal
death lands there too, and render it in the same shape:

```
💥 MalfunctionError: review was signalled (SIGTERM, exit 143) — the process did not finish

  why: a peer review process was ended from outside. the usual cause is too many
       reviewers in flight at once on one host.
  fix: bound the level with a concurrency group in the .guard —
         reviews:
           groups:
             <name>: { concurrency: 3 }
       and add `group: <name>` to each lane that shares the resource.
  see: RouteStoneGuard `group:` / `reviews.groups`
```

three properties, each from an extant rule: a **qualified header** (`rule.require.qualified-error-headers`),
a **what/why/fix** anatomy (`rule.require.errors-name-the-fix`), and a **signal name** so no decode
chain is owed.

### b — an `asExitCodeReason`-shaped transformer, used everywhere an exit code is rendered

`128 + signum → name` is a domain cast. one named transformer kills the decode at every call site
rather than at this one.

### c — make the level bound legible, without a move into the `.guard`

the design reason to keep it out of the `.guard` stands. legibility does not need it to move there:

- **emit it** in the review preamble beside the other resolved facts (`brain:`, `focus:`, `scope:`),
  so a route author sees `level concurrency: 10` on every run
- **warn** when a level's lane count approaches the bound (*"level 1 carries 9 lanes; the bound is
  10"*) — the pit-of-success rung `rule.prefer.prevent-over-correct` calls "catch it early"
- 🔴 or a **per-brain-class default**: the bound of 10 was safe for atom brains and became unsafe
  the moment `--focus pull` forced a **repl**, which spawns a full claude-code process. a default
  that is safe for one class and unsafe for another should key on the class

### d — the clamp

a test that spawns more repl-brain lanes at one level than a group bound permits, and asserts the
rendered stderr carries `SIGTERM`, a `💥 MalfunctionError:` header, and the `groups:` fix. it goes
**red today** — the current path renders a stack trace.

## .why it is not done in this round

the SAFE/CLEAN test, both halves:

- **not SAFE** — the change is inside `rhachet-roles-bhrain`'s review engine, which every route in
  every repo runs. an error-path edit there is a cross-repo behavior change
- **not CLEAN** — it is three files in a package this repo only consumes, plus a schema-doc change.
  it lands in no diff this route already has open

⇒ and the route's own yield calls this PR *"too big to review well"* (77,742 lines). to smuggle a
cross-package engine fix into it is the exact `rule.require.review-test-changes` violation
scouts-honor's CLEAN question refuses.

## 🟢 .what WAS repaired here, in scope

the guard now declares the valve:

```yaml
  groups:
    claude-code-host:
      concurrency: 3
```

with `group: claude-code-host` on all eleven lanes — the nine at level 1 and both `enroll` lanes at
level 3, per the schema's own membership check (*"does this one share that group's resource?"*).

⇒ that repairs **this** route. it repairs no other route, and the error stays just as illegible for
the next author who meets it. hence this dream.
