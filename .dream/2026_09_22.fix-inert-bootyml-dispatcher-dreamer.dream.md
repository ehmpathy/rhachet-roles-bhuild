# 🌙 dream: declare `boot:` for dispatcher and dreamer, or delete their `boot.yml`

- **kind** — fix
- **owner** — `ehmpathy/rhachet-roles-bhuild`
- **caught** — 2026-09-22

## .the cue that fired

a self-review at the `1.vision` stone of
`v2026_09_22.feat-lift-supervisor-and-prioritizer-roles` went to verify a subagent's claim about
how `boot.yml` is wired, because the lift's most expensive artifact is 426 lines of boot curation
and `case=3` turns on whether it actually loads.

the check was meant to protect the **new** roles. it found the defect in the **extant** ones.

## .the gap, precisely

`boot` is an **explicit field** on `Role.build`, not a convention over the role directory. measured
on this branch:

```
$ rhx globsafe --pattern 'src/domain.roles/*/boot.yml'
src/domain.roles/behaver/boot.yml
src/domain.roles/decomposer/boot.yml
src/domain.roles/dispatcher/boot.yml
src/domain.roles/dreamer/boot.yml          → 4 files

$ rhx grepsafe --pattern 'boot:' --glob 'src/domain.roles/*/get*Role.ts'
src/domain.roles/behaver/getBehaverRole.ts:8:      boot: { uri: __dirname + '/boot.yml' },
src/domain.roles/decomposer/getDecomposerRole.ts:8: boot: { uri: __dirname + '/boot.yml' },
                                            → 2 declarations
```

⇒ **`dispatcher/boot.yml` and `dreamer/boot.yml` are never read.**

🟡 **it is latent, not live.** both files are currently empty curation
(`always: briefs: { say: [], ref: [] }`), so to activate them today is a no-op. the defect is that
the *next* person to add a `say` entry to either file will watch it do naught, with no error and
no failed test to explain why.

## .the shape of the fix

one of two, and the choice is the whole decision:

| option | change | argues for |
|---|---|---|
| **A — declare it** | add `boot: { uri: __dirname + '/boot.yml' },` to `getDispatcherRole.ts` and `getDreamerRole.ts` | the files exist and were clearly meant to work; symmetry with behaver/decomposer |
| **B — delete them** | remove both `boot.yml` files | an empty, unreferenced file is a phantom |

⇒ 🔴 **`#234` likely settles it toward A** — *"docs(dispatcher): add say-level howto in boot.yml
teaching how to use the radio skills"*. that issue cannot be satisfied at all while the file is
inert, and whoever works it will hit this defect head-on. **cross-link the two.**

a guard is worth more than either fix: a unit test that asserts *every role dir with a `boot.yml`
has a role declaration that references it*. that turns a silent class of defect into a red test,
and it would also protect the two roles this lift is about to add.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **safe?** ✅ yes — both files are empty, so to declare them changes no behavior today
- **clean?** 🔴 **no** — it lands in `getDispatcherRole.ts` and `getDreamerRole.ts`, two files the
  lift does not otherwise touch, inside a PR that already holds ~77,742 lines and 304 brief files

a two-line fix smuggled into that diff is invisible, and the guard-test version is real work with
its own design call (A vs B). deferred deliberately, not forgotten.

⚠️ the deferral is a **judgment about ripple cost**, so it also earns a fulcrum row in the lift's
inventory rather than this dream alone.
