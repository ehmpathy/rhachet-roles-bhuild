# 🌙 dream: `clone say` should name a mid-turn pane apart from an unrecognized screen

kind: reseed · owner: ehmpathy/rhachet (clone say precheck) · caught 2026-10-25

## .the cue that fired

the live phone demo: two replies to a clone whose pane was mid-turn were withheld as
`focus-unrecognized`, so the phone told the senders "peer screen unrecognized" for a peer that
was only busy.

## .the gap, precisely

`rhachet@1.50.0` `computeCloneDispatchPrecheck.d.ts:15` holds three withheld reasons:
`modal-holds-focus`, `focus-unrecognized`, `input-region-dirty`. a brain mid-turn shows no prompt
the precheck recognizes, so it falls into `focus-unrecognized`. a caller can not tell "busy, will
take it soon" from "the screen is in a state rhachet does not know".

## .the shape of the fix

add a fourth reason, e.g. `turn-in-flight`, when the precheck sees the brain's own busy marker;
keep `focus-unrecognized` for screens it truly can not read. no force path for either. the phone
then maps `turn-in-flight` to `peer mid-turn` and keeps its current wide reason for the rest.

## .why it is not done in this round

the reason set is rhachet's. this pr words the phone's reason to cover both cases
(`peer not at its prompt (mid-turn, or an unrecognized screen)`), which is honest with the signal
it gets today.
