## .the gap, precisely

`src/domain.roles/supervisor/skills/git.grove.saturation.sh:321-324` — four emits of this shape:

```bash
echo "oom_klines=$(journalctl -k -q --no-pager 2>/dev/null | grep -v '^-- ' | grep -c . || echo 0)"
#                                                                            ^^^^^^^^^^^^^^^^^^^^
```

🔴 **`grep -c` prints its count AND exits 1 when that count is zero.** so on the common path — an
empty or unreadable journal — the substitution yields `0`, the `||` arm then fires on the exit
code, and `echo 0` appends a **second** `0`:

```
oom_klines=0
0
```

⇒ the `|| echo 0` was written to defend against `journalctl` itself breaking. it triggers on
`grep`'s no-match exit instead, and it is `grep`'s **success** case that sets it off.

the `kv` reader at `:1114` takes the first line, so the value it parses is right **by luck** —
`#378`'s own words. a reader that takes the last line, joins the lines, or counts fields gets `00`,
`0 0`, or a field count that is off by four.

⚠️ and `procs_zombie` is named in the same report, so the shape is likely wider than these four
lines. **the sweep is part of the repair, never assumed complete at four.**

## .the shape of the fix

`grep -c` already prints a number on every path, so the fallback belongs on `journalctl`, never on
the pipeline's exit. bind, then emit:

```bash
klines=$(journalctl -k -q --no-pager 2>/dev/null | grep -v '^-- ' | grep -c .)
echo "oom_klines=${klines:-0}"
```

this keeps `set -e` honest, and it makes the zero case a **value** question rather than an
exit-code one.

⇒ the clamp it owes: a case that runs the emit arm with **no journal**, and asserts the field
appears exactly once. today's 212 green tests do not cover it — which is why the defect survived a
full suite run in this repo on 2026-09-25.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| question | answer |
|---|---|
| **CLEAN?** | ✅ mostly — four adjacent lines in one file |
| 🔴 **SAFE?** | ❌ **no.** it changes what a ported diagnostic skill emits, and this box is not a grove. the empty-journal path cannot be exercised here, so the fix would ship **unverified on the one path it exists to repair** |

⇒ a wrong count in a saturation read does not fail loud — it tells a supervisor the box is healthy.
that is the exact failure the whole `catalog.of=saturator` family exists to prevent, so an
unverified repair is worse than a known defect with a dream beside it.

the right place is a follow-up **on a grove**, where the empty-journal and populated-journal paths
can both be run, and where the `procs_zombie` sweep can be completed rather than guessed.
