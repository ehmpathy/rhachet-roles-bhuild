# 🌙 dream: the driver's route permissions emit a `Write(...)` file rule claude code ignores

kind: reseed · owner: rhachet-roles-bhrain (driver role init) · caught 2026-10-22

## .the cue that fired

i007 peer review, r011 nitpick 10, and the stderr of every reviewer run in this tree:

> Permission allow rule (.../settings.of.repo.json): Write(.route/**) is not matched by file
> permission checks — only Edit(path) rules are. Use Edit(.route/**) instead (…)

## .the gap, precisely

- source: `rhachet-roles-bhrain@0.42.1`,
  `dist/domain.roles/driver/inits/init.claude.permissions.route.jsonc`, its `allow` block lists
  `"Write(.route/**)"` beside `"Edit(.route/**)"`
- effect in this tree, read with `rhx git.diff.reorder` on
  `.agent/.actors/actor.via.repo=ambient/brain/.claude/settings.of.repo.json`: the regenerated
  `allow` list lost `"Edit(*/**/.route/**)"` and gained `"Write(.route/**)"`. the first was the
  allow for a `.route/` dir nested under a route (`.behavior/<route>/.route/`); the second matches
  naught. so a driver's edit inside a nested `.route/` now falls to a prompt or a deny
- the same regeneration also moved a hook `"timeout"` from 25 to 120 and swapped a home path; both
  are per-machine and out of this dream's scope

## .the shape of the fix

in `init.claude.permissions.route.jsonc`, allow `Edit(...)` forms only, for every depth the deny
block names: `Edit(.route/**)`, `Edit(**/.route/**)`, `Edit(*/**/.route/**)`. drop the `Write(...)`
allows (an `Edit` rule already covers every file-edit tool). clamp: a test that renders the init
and asserts no `Write(` file rule in `allow`, and that each deny depth has its `Edit` allow twin.

## .why it is not done in this round

it belongs to another repo, and the director ruled (F23): the file is written per machine by the
role init, so it is left out of this commit and not restored; the defect is the init's, and the
cure goes upstream.
