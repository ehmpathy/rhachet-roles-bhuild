## .the gap, precisely
- `saturation.sh` and `saturation.spend.sh` each hold the same row fold (five associative arrays,
  camper displaces ground) and the same ssh probe arm
- three classifiers of ssh's words — `ductwork.uri.sh` `__duct_say_unreachable`, saturation's
  unread arm, and the wake's refusal branch — hold different pattern sets
- the ssh alias block is rendered inline in wake; no other verb can read whether an alias drifted
- `__grove_reach_of` returns a positional tab line, read at seven call sites
- the sweeps ride `user@host` with no `-i`, so a non-default `--identity` reads as "unread"
- the cure runs once per crew row and per seat in pollwork; each call scans the registry
- `git.grove.list` probes serially; a dropped peer costs the full timeout per grove
- no snapshot of: the saturation asleep row, the crew.poll caveat, the duct.poll footer, the
  send failure line; no test of the wrong-account, ground-only-fold, or stale-port cells

## .the shape of the fix
- `__grove_fold_rows` + `__grove_reach_ssh <row> <cmd>` (one communicator, carries `-i`) in grovework
- `asGroveUnreachedKind <ssh said>` → one kind per cause; each site maps the kind to its render
- `asGroveSshAlias` (pure) + `setGroveSshAlias`; list flags an alias that differs from its row
- `__grove_reach_of` emits named fields (`key=value` per line, or json), one parse function
- compute the cure once per grove in pollwork, as `pollwork.read.sh` already does
- probe groves in parallel in list, bounded, as saturation does
- the render snapshots and cell tests named above

## .why it is not done in this round
each is a refactor of correct code or a snapshot of a render already clamped by assertion; the
route's done-means are a live hetzner + ec2 run and a green pr on a deadline, and the refactor
re-opens every saturation, duct, poll and wake suite (fulcrum F14).
