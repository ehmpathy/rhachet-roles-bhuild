# 🌙 dream: a status-only push leaks the source branch name to a public repo

kind: fix · owner: dispatcher · caught 2026-11-17 · urgent class (reputation / security)

## .the cue that fired

l3 peer round 4 (enroll-blueprint-behavior-intent) on the public-repo promise blueprint.

## .the gap, precisely

a status-only CLAIMED or DELIVERED passes the promise gate by design (issue #675 row 7: no new
text). but the extant send derives text anyway:
- `setPartRadioTask.ts` L127–145 stamps `branch` (`getCurrentBranch()`) and `claimedBy`
- `composeTaskIntoGhIssues.ts` L18–21 writes `🌲 tree planted at <branch>` / `delivered at <branch>`
- `daoRadioTaskViaGhIssues.ts` L316–331 rewrites the whole body via `issue edit --body-file`, so the
  edit history keeps it; L340–355 sets `claimedBy` as assignee

a private branch name (a feature slug, a ticket, a customer) goes public, forever, with no nudge.

## .the shape of the fix

one of:
1. withhold derived text on public targets: the per-record send reads visibility for a status-only
   gh.issues record too (one `repo view`), and on PUBLIC or unreadable composes the body with no
   branch line and no assignee
2. gate CLAIMED / DELIVERED on a public repo like text: the branch is text, so it owes the promise

option 1 keeps row 7's "claim never stalls on a promise". J5 in the promise play test already snaps
the body a status-only push writes; flip that snap.

## .why it is not done in this round

not clean: it reaches the compose and claim paths, outside #675's rows, on a p0 with a deadline.
the window is named in the pr for the commander.
