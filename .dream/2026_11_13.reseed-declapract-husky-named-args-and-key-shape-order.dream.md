# 🌙 dream: the declapract husky practice owes named args and a key-shape order fix

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (the `husky` practice)
- caught 2026-11-13

## .the cue that fired
peer review of `rhachet-roles-bhuild` route `v2026_11_13.feat-supervisor-reach-over-tailnet`, stone
5.1, raised two defects in husky files that `npx declapract apply --practice husky` renders.

## .the gap, precisely
- `.husky/check.timestamps.lock.sh` — `timestamps_lock_halt` reads `found` and `where` as `$1`/`$2`.
  both are plain strings, so a transposed call prints a plausible wrong diagnostic and still exits 2
- `.husky/check.secrets.sh` — the `openai-style key` shape (`sk-(proj-)?[A-Za-z0-9_-]{20,}`) sits
  above `anthropic key` (`sk-ant-…`), and the first match wins, so every anthropic key reports as
  an openai-style key
- `.husky/check.timestamps.sh` — the `.eco/*` exemption is gone. the prioritizer's `.eco/*.csv`
  rows carry `createdAt`/`updatedAt` by design, so any commit that stages one now halts, and the
  halt text tells the reader to strip the record's event time
- `.husky/check.timestamps.lock.sh` — `git ls-files -s` is guarded into `timestamps_lock_malfunction`,
  but its peer read `git hash-object` is not, so a failed object read reports a false "hook was
  changed" with an empty `found`

## .the shape of the fix
- `timestamps_lock_halt found="$digest" where='in the index'`, parsed by name, unnamed arg fails loud
- move `anthropic key` above `openai-style key` in SHAPES, with a test that an `sk-ant-` value reports `anthropic key`
- restore `.eco/*) continue ;;` with its reason, plus a test that stages a `.eco/*.csv` row and passes
- `git hash-object ... || timestamps_lock_malfunction`, the same guard as its peer read

## .why it is not done in this round
the files are declapract artifacts; a hand edit here is overwritten by the next apply. the fix
belongs at the practice, so every repo that adopts it gets it.
