# 🌙 dream: git.release --watch reports the prior head's checks as passed

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, skill git.release)
- caught 2026-11-22

## .the cue that fired

right after a push of a new head to pr #661, `rhx git.release --watch` printed `👌 all checks
passed` and `✨ done! 0s in action, 0s watched`, with a blank release title. `gh pr view` at the
same moment showed the new head `ea5680e` with checks still in progress.

## .the gap, precisely

the watch does not key its read on the pushed head sha. in the gap after a push and before the
new run registers, it reads the prior head's checks (or none) and calls the release green. a
caller who trusts it would report a red pr as green.

## .the shape of the fix

- look up the pr's current head sha first, and read only check runs for that sha
- no check run yet for the head → wait (status: queued), never pass
- clamp: push a fresh head, watch at once, assert the watch waits until that head's run ends

## .why it is not done in this round

the skill lives in another repo; a fix there is its owner's round. here, `gh pr checks --watch`
plus a read of the head sha gave the true state.
