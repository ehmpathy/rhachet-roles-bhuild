# 🌙 dream: the cli arg reader reads `--flag ''` as a bare flag

- kind: fix (owner: rhachet-roles-bhuild, `src/infra/cli/getCliArgs.ts`)
- caught 2026-11-20, in route `v2026_11_08.feat-vision-root-purpose`, stone 5.3

## .the cue that fired

a new acceptance case, `review.vision.root-purpose --vision ''`, exited 1 with
`--vision must be a string, got undefined` where every other bad input exits 2.

## .the gap, precisely

`getCliArgsRaw` tests `if (next && !next.startsWith('--'))`. an empty string is falsy, so
`--flag ''` stores `true` and leaves `''` unread. every skill whose schema says `z.string()` then
fails its schema at exit 1 with a message that names the wrong cause.

## .the shape of the fix

- test `next !== undefined && !next.startsWith('--')`, so `''` is a value
- each skill then meets `''` as a string, and its own guard (or a `z.string().min(1)`) refuses it
- clamp: `getCliArgs.test.ts` case for `['--name', '']` → `{ name: '' }`
- drop the boolean admit in `src/contract/cli/review.vision.root-purpose.ts` once it lands

## .why it is not done in this round

the reader serves every cli in the package; a change to how it reads `''` reaches each skill's
schema at once. the vision skill refuses the case itself (exit 2), so this round holds its contract
without a package-wide change.
