# 🌙 dream: two acceptance runs in one worktree blank each other's dist

kind: fix · owner: this repo (rhachet-roles-bhuild) · caught 2026-11-17

## .the cue that fired

two acceptance runs in one worktree, seconds apart, each failed en masse (76/94, then 116/116) with empty stdout and exit 2. the skills under test could not import `dist/index.js`.

## .the gap, precisely

`rhx git.repo.test --what acceptance` runs `npm run test:acceptance`, which starts with `npm run build`, whose first step is `rm -rf dist/`. a second run in the same worktree deletes `dist/` while the first run's skills import from it. the `roleArtifacts` integration clamp, which boots a linked copy, may rebuild as well.

evidence: route `v2026_11_16.fix-radio-push-public-repo-promise`, a recorder acceptance run (76 failed) and a promise journey run (116 failed), each overlapped by another. case1 alone, with no overlap, passed 33/33.

## .the shape of the fix

- build into a temp dir, then swap it into `dist/` with one rename, so `dist/` is never absent; or
- take a worktree-scoped lock around build + acceptance (`.temp/acceptance.lock`), and fail loud with the holder's pid when a second run starts; and
- have `git.repo.test --what acceptance` skip the build when `dist/` is newer than every `src/` file.

## .why it is not done in this round

not SAFE nor CLEAN here: it changes the build command and the test skill, both outside #675. the round avoided it by one run at a time.
