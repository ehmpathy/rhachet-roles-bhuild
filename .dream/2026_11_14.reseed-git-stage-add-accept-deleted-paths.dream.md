# 🌙 dream: git.stage.add stages a tracked path that was deleted

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic) · caught 2026-11-14

## .the cue that fired

a pr cut to its base layer deleted a tracked route dir; `rhx git.stage.add <deleted path>` refused
with `file not found`, so the deletion could not be staged through the paved skill.

## .the gap, precisely

`git add <path>` stages a deletion when the path is tracked and absent. `git.stage.add` checks
that the file exists on disk first, so a deletion has no paved stage path, and no paved
`git rm --cached` exists either.

## .the shape of the fix

in `git.stage.add`, accept a path absent on disk when `git ls-files --error-unmatch` finds it
tracked; stage it as a deletion. optionally add `--untrack` (`git rm --cached`) for a path that
must leave the index but stay on disk.

## .why it is not done in this round

the skill lives in another repo; this tree carried a local `git.layer.cut --untrack` instead.
