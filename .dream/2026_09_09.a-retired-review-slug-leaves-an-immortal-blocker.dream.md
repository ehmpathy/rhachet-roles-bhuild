## .the gap, precisely

`route.js:1163` enumerates **every** peer given the stone ever produced, across every hash.
`getLatestReviewFilesPerSlug` then picks the latest per **slug**. that pick is deliberate and
correct for a slug that still exists — its comment says so, and cites `routeStoneJudgeTally`.

🔴 **it has no exit for a slug that was RETIRED.** a lane cut from the guard never runs again,
so its last verdict is frozen — and the judge counts it forever.

`getNonOverruledReviewFiles` is the only filter between the pick and the tally, and it filters by
**level**, never by roster membership:

```js
const reviewLevel = levelByReviewIndex.get(reviewIndex) ?? 1;
return !input.overruledLevels.has(reviewLevel);
```

⇒ a retired slug's `rN` maps through the *current* roster's declaration order, so it lands at
level 1 alongside the live lanes. **the one lever that removes it also forgives every live lane at
that level**, and it is human-only.

## 🔴 .why it is worse than a stale count

a rename is the ordinary way a lane evolves — `yield-density` → `dense-of-yields`,
`prose-of-briefs` → `struct-of-briefs` → `dense-of-briefs`. each rename was a refinement, and
each **silently minted a permanent blocker**.

the driver cannot see it: the guard tree prints the roster, and the roster is clean. the judge
prints a sum with no attribution. ⇒ **the two readers disagree, which is the exact defect the
cross-hash comment says the latest-per-slug pick was introduced to fix** — it closed the hash
seam and opened a roster seam.

## .the shape of the fix

**intersect the tally with the declared roster.** `peerReviews` is already threaded into
`getNonOverruledReviewFiles` and used only for the level lookup:

```js
const declaredSlugs = new Set(input.peerReviews.map((r) => r.slug));
return input.reviewFiles.filter((filePath) => {
  const slug = getReviewSlugFromFileName({ filePath });
  if (!declaredSlugs.has(slug)) return false;   // ← retired lane: no longer a reviewer
  ...
});
```

🟡 **and print the attribution.** the judge should name which slug contributed each blocker — the
sum alone cost a full diagnostic round here. a one-line-per-file tally would have made it a
ten-second read.

🟡 the bound: this must NOT let a driver clear a real blocker by a cut of the lane that raised it.
the two are distinguishable — a lane cut from the guard is a **guard edit**, already visible in
the diff and already gated behind the mutate privilege. name the cut in the judge's output so it
cannot be silent.

## .why it is not done in this round

**SAFE: no. CLEAN: no.** it is another repo's engine, on the passage path, and the fix turns on a
policy call this route does not own — whether a retired lane's blocker should evaporate or should
require an explicit acknowledgement. that is bhrain's to settle.
