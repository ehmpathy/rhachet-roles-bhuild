# 🌙 dream: rhachet `clone say|get|list` should accept `--repo <dir>`

kind: reseed · owner: ehmpathy/rhachet · caught 2026-10-21

## .the cue that fired

`phone.text` (bhuild dispatcher) must say into a clone in another repo's tree on the same box.
rhachet offers no way to name that tree.

## .the gap, precisely

- `clone say|get|whoami|list` read actors from `getOneRepoPath({ from: process.cwd() })`, which is
  `realpathSync(cwd)` — not even the git root (`dist/infra/host/getOneRepoPath.js:19-31`;
  `dist/contract/cli/invokeCloneSay.js:78`)
- the address grammar takes `@:<slug|serial>` only (`dist/domain.operations/clone/asCloneRef.js:22-50`)
- no exported api for say (`dist/index.d.ts:1`)
- ⇒ a caller must spawn rhachet with `cwd` at the peer tree, which bends bhuild's
  `rule.forbid.cwd-override` (fulcrum F1 of route `v2026_10_21.feat-phone-text`)

## .the shape of the fix

- add `--repo <dir>` to `clone say|get|whoami|list`; default `process.cwd()`; derive the git
  root of `<dir>` (`git rev-parse --show-toplevel`), and refuse loud if not a repo
- optionally export `sayClone({ repoPath, ref, message, await })` from `rhachet` so a node caller
  needs no spawn
- then bhuild's phone swaps its spawn cwd for `--repo` (one communicator)

## .why it is not done in this round

it belongs to another repo (rhachet); a tree adopts only what is scoped to itself.
