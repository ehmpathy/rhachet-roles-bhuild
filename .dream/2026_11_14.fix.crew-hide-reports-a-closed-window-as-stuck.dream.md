# 🌙 dream: crew.hide reports a window it closed as one that would not close

- kind: fix
- owner: rhachet-roles-bhuild, supervisor (`term.stop` in `work/termwork.sh`)
- caught 2026-11-14

## .the cue that fired
5.3 of `v2026_11_13.feat-supervisor-reach-over-tailnet`, twice on a hetzner grove crew:

```
Error: Failed to connect to unix:/tmp/kitty-duct-<host>_<tree>-<pid> … connect: connection refused
💥 term.stop: terminal <pid> is alive but its window would not close
🦫 tail slap — the tabs would NOT close (rc=1); the crew is still in view
```

seconds later `/proc/<pid>` was gone and no socket of that name was bound: the window HAD closed.

## .the gap, precisely
`term.stop` reads "alive" before the close lands, then a remote-control call races a kitty on its
way out, and its socket refusal reads as "would not close". the verdict is a false failure, exit 1,
with a `💥` on it — a reader re-runs, or escalates a defect that did not happen.

## .the shape of the fix
- after the close, re-read the process table for the pid with a short bound before any verdict
- a refused socket of a kitty that has exited reads as closed, never as stuck
- a clamp: a fake kitty that exits on close → term.stop exits 0

## .why it is not done in this round
it is a view-axis race unrelated to reach; whether it is grove-only was not measured, and the fix
sits in term.stop's contract.
