| the file's 46 families | state | in the required gate? |

## .the shape of the fix

the reviewer named four steps. step 3 is the one a reader skips:

1. **measure** the red set per family — run the held-out file and record which of the 46 fail,
   by name. do NOT derive it from `F9`'s count

   🔴 **and step 1 needs a mechanism it does not have.** measured 2026-09-25: an excluded file
   is unreachable through `rhx git.repo.test` by EITHER scope —

   | the attempt | what came back |
   |---|---|
   | `--scope path://ecowork.integration` | `matched: 0 files`, exit 2 |
   | `--scope name://case57` | 19 suites matched; **`ecowork.integration.test.ts` absent** |

   ⇒ a `--scope` run does NOT bypass the exclusion, which is a correct design and an
   inconvenient one here: the file the split must measure is the one file the runner refuses
   to reach. so step 1 owes a route of its own — a temporary config edit, or a bare `jest`
   invocation with an explicit path. **that is a second reason the split is not SAFE today:
   the measurement itself is off the paved path.**

   ⚠️ the same fact makes every edit to `ecowork.sh` and `ecowork.db.mjs` unverifiable through
   the normal runner while the hold-out stands — the darkness is not only the 26 families, it
   is the whole file's feedback loop.
2. **move** the 26 green families into a file the required gate runs, with the two test
   operations they lean on (`eco`, `genDbPath`) carried across verbatim — the same move
   `ecoworkGain` already made
3. 🔴 **update `suitesGated`'s `GATED_OUT` alongside `jest.integration.config.ts`** — the
   ratchet enumerates the held-out set BY NAME, so a config edit with no ratchet edit turns
   `suitesGated` red, and a ratchet edit with no config edit lets a later drop pass silently
4. **leave** the 18 red families behind, still held out, still pointed at `F9`

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), both halves answered:

- **SAFE? no.** the split needs a per-family red/green enumeration, and the cheap way to get
  one is to derive it from `F9`'s root-cause count rather than measure each family. a single
  misclassification puts a red family into the required gate, and the required gate is what
  `main` is protected by. ⇒ the failure mode of a wrong split is a **red `main`**, not a
  missed guard
- **CLEAN? no.** it edits three files in concert (the suite, the jest config, the ratchet) and
  the diff lands in a round whose lanes are already dark for size

⇒ unsafe **and** unclean, so it defers.

🟡 **and the `F1` half was NOT deferred with it, deliberately.** its two families are the only
proof that `#389` reversed `#386`, so their darkness carried a named prioritization harm
(`rule.forbid.overzealous-blockers`) that the other 26 do not. the split of one from the
other is the whole content of this round's repair.
