## .the gap, precisely

1. pull's gh 401 error ends with a json metadata dump: the raw `gh issue list …` command,
   `"role": "as-robot"`, and a `"detail"` block. that is debug metadata in a human nudge
2. stderr differs between push and pull on one failure. pull's stderr holds the full message plus
   a final `{ "auth": … }` block. push's stderr says only `✋ blocked by constraints`, and the
   cause lives in stdout under `fix it:`. a reader of stderr alone (a ci log) gets no cause
3. the held-output tree nests `checked` and `fix` inside `fix it:`, then sets `amend it:`,
   `or drop it:`, and `then the next push…` beside them. the word `fix` names two levels
4. `recorded: .behavior/.radio/` names a directory, never the record file or its uuid
5. the same as-ehmpath miss renders two ways. push nests its `checked` / `fix` sections in the
   held tree; pull (walk case3 stderr, cli case10) prints them as bare headers with no glyph root,
   then the `{ "auth": … }` dump of item 1. one miss should render one way: the fix for item 1
   and item 2 should carry the pull miss render with it

## .the shape of the fix

- render error metadata as a `hint`/`fix` branch, never a json dump; keep the json in the log
- one stderr contract across push and pull: the headline cause on stderr, the tree on stdout
- rename the outer `fix it:` to a label that holds every move (e.g. `next moves`), and keep `fix`
  for the inner spot fixes only
- print `recorded: .behavior/.radio/record.<uuid>.json`

each change resnaps the recorder, push, pull, and queue snapshots, so it is its own pass.

## .why it is not done in this round

each shape predates this route and spans every radio skill's output, not the auth values. a
reshape here would ripple across the whole recorder snapshot set and mix a cosmetic pass into an
auth change (`rule.always.fix-forward-under-scouts-honor`: safe, not clean).
