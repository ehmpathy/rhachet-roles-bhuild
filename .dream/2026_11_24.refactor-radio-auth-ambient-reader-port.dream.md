# 🌙 dream: one ambient-reader port for the radio auth

- kind: refactor
- owner: rhachet-roles-bhuild (radio auth)
- caught 2026-11-24, in route `v2026_11_09.feat-radio-auth-as-ehmpath-via-keyrack-or-ambient`

## .the cue that fired

the 5.1 peer review (enroll-impl-arch-defects, blocker 1) named the test guard a scope leak: prod auth code reads `NODE_ENV`, `JEST_WORKER_ID`, `RADIO_GH_STUB` through `isTestEnv` and `isAmbientReadAllowed`.

## .the gap, precisely

- three paths treat a test env three ways: `getAmbientReadOrNone` refuses; `getGithubTokenByAmbientFirst` falls to keyrack (F17); `as-human` refuses on `isTestEnv` and ignores the stub
- `getAmbientReadOrNone` trusts `context.env` and `context.shx` to agree; naught enforces it
- a real box that exports `NODE_ENV=test` takes the keyrack default, not its ambient identity

## .the shape of the fix

- a `context.ambient.read(command)` port: prod wires the real shell; tests wire a stub
- the env guard and the env/shx pair leave the domain; the stub harness (see `refactor-radio-tests-one-stub-gh-harness`) supplies the port
- one guard, if any must stay: `assertNoRealGhInTest`, used by every path
- clamp: a unit suite that runs every --auth value against a port that records reads, and a test env with no port fails loud on each

## .why it is not done in this round

the port changes the context contract of every radio auth op, both context builders, and three cli entries, plus every test that stubs gh. that ripple fails CLEAN, and the extant guard is fail-safe (no real gh in a test); see fulcrum F22
