# 🌙 dream: the radio reads typed faults, from one closed reason table

kind: refactor · owner: dispatcher · caught 2026-10-25

## .the cue that fired

5.1 l3 review (enroll-impl-arch-defects, i004) on `beav/feat-radio-task-queue`: reason codes live as strings in five files, and a bare HTTP 429 fell through to `upstream:fault`.

## .the gap, precisely

- codes in `asRadioUpstreamReason`, `isRadioUpstreamReasonHalt`, `asRadioQueueFixLines` (set + `=== 'upstream:fault'`), `setRadioTaskRecordUpstream` (`'upstream:auth'`), `asRadioTaskRecordState` (`startsWith('upstream:')`)
- `record.reason` holds codes, refusal headlines, `dropped: …` and gate text
- `daoRadioTaskViaGhIssues` flattens gh errors to text; four domain transformers re-parse it
- `authOverride` travels as an optional context field through four drain operations
- `drain --auth` applies to every record; no `drain --key`
- the drain lock: `drain` waits (no try-acquire); `set` / `del` wait behind a whole drain

## .the shape of the fix

1. `RadioUpstreamFault` kinds (`rate-limit | auth | access | not-found | transient | refused`), thrown by the dao, mapped in one table `{ code, halts, curedByAuth }` that every consumer reads
2. split `record.reason` into `faultCode` + `faultWhy`; shed the old field on read
3. `authOverride: string | null` in the drain input; one named `ContextRadioDrain` type
4. `drain --key K`; try-acquire for drain, per-record lock for set / del
5. consider 401 as a halt (token-wide), once measured

## .why it is not done in this round

dirty: it ripples across the dao contract and 5+ domain files, past the pr's nano size. the shipped harms (429 not halted, a raw lock timeout) got stopgaps with clamps in this pr. fulcrum: F13.
