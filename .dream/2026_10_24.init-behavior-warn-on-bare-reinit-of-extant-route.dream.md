# 🌙 dream: init.behavior warns on a bare re-init of an extant route

kind: fix · owner: rhachet-roles-bhuild (behaver, `init.behavior`) · caught 2026-10-24

## .the cue that fired

the #590 blueprint review (i005, `enroll-blueprint-behavior-intent` nitpick 4): the remedy for a
pre-tail route is a re-init, and a re-init without `--size` defaults to `medi`.

## .the gap, precisely

- `init.behavior.ts:89` defaults `--size` to `medi`
- a route does not record the size it was inited at
- so `init.behavior --name <extant nano route>` with no `--size` findserts every medi stone into a
  nano route. the stdout lists them as created, but no line says the size was a default guess

- a second edge of the same re-init: findsert writes every absent file of the size
  (`initBehaviorDir.ts:83`), so a stone the human removed with `route.stone.del` comes back

## .the shape of the fix

when the named route already exists and `--size` was not passed, refuse (exit 2) with the hint
`pass --size <the route's size>` — or record the size at first init (one line in `.route/`) and
reuse it on re-init. the second removes the footgun; the first only names it.

## .why it is not done in this round

not clean: it changes `init.behavior`'s contract (a refusal, or a new route-record file) for every
caller, and #590's scope is the tail. the #590 blueprint says the release note and case=14 name
`--size`, which covers the gap until this lands.
