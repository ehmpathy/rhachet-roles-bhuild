# 🌙 dream: a retention pass for settled radio records

kind: fix · owner: bhuild/dispatcher · caught 2026-09-29

## .the cue that fired

peer review i005 r011 nitpick 1 (5.1.execution of `v2026_09_28.fix-radio-recorder`): records
grow forever, and each push plus each stop hook reads them all.

## .the gap, precisely

`daoRadioTaskRecord.get.all` reads every `record.*.json` in every `.behavior/**/.radio/`.
DELIVERED and REFUSED records are never moved or removed, so a long-lived worktree pays a read
per settled record on every push and every stop.

## .the shape of the fix

- move a record settled longer than N days into `.radio/.settled/` (still one file per key)
- `get.one.byUnique` checks `.settled/` too, so a verbatim re-push still reads
  `already delivered as #N` (C3/C9) and never re-sends
- `get.all` (the drain + stop sweep) skips `.settled/`
- clamp: a re-push of an archived delivered record stays a no-op

## .why it is not done in this round

a new store layout with its own identity rule is a design call, not a ride-along; the route-local
lifespan (F8) bounds growth today. fulcrum: F22.
