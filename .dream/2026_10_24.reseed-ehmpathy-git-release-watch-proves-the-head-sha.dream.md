# 🌙 dream: git.release --watch reports done before it sees the head just pushed

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, skill git.release) · caught 2026-10-24

## .the cue that fired

the 6.preship design (rhachet-roles-bhuild#590) leans on `rhx git.release --watch` to prove the
pull is green for the commit just pushed. the director asked to prove that from source. it does not.

## .the gap, precisely

- `get_pr_status` (`git.release.operations.sh`) reads `gh pr view --json statusCheckRollup,…` — the
  rollup of whatever head github holds at that instant. it never reads `headRefOid`, and never
  compares it to `git rev-parse HEAD`
- `parse_check_counts` returns `0/0/0` on an empty rollup
- `_watch_pr_transport` (`git.release._.emit_transport_watch.sh`): with no automerge and
  `progress == 0`, it prints `🫧 no runs inflight`, then `done`, and returns 0

⇒ `git.commit.set --push` then `git.release --watch` at once: github has not yet moved the pull's
head, or has not registered its checks. the watch reads the old head's green, or an empty rollup,
and reports done. `rule.require.watch-release-after-push` then certifies a push no check has run on.

## .the shape of the fix

- in the watch loop, read `headRefOid` beside `statusCheckRollup`
- while `headRefOid != git rev-parse HEAD` (local branch pushed), or the rollup is empty, render
  `🫧 await the pushed head (<sha7>)` and poll again — never `done`
- bound the wait (the extant 15 min timeout); on timeout, fail with `✋ ConstraintError` that names
  the pushed sha and the head github holds
- clamp: a temp pull whose head lags the local sha must not report done (red before, green after)

## .why it is not done in this round

the skill lives in another repo (`rhachet-roles-ehmpathy`); this route may only edit
`rhachet-roles-bhuild`. so it is not clean here. in this repo, the 6.preship text carries the
driver's own check (`headRefOid` vs `git rev-parse HEAD`, rollup non-empty) until the cure lands.
