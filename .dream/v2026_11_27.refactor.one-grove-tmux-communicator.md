## .the cue that fired

r011 found that the duct verbs splice values into ssh text by hand. `__duct_tmux_cmd` returns a text prefix, so each of ~20 sites writes its own quote. rounds i005, i006 and i007 each found one more unquoted value.

## .the gap, precisely

- the sink contract holds today, by three parts:
  - each sink single-quotes `'$DUCT_SESSION'`, and `__duct_parse_uri` refuses a `'` or a control char in it
  - every other spliced value has a guard at its own parse: `--keys`, `--lines`, `--cwd` (`%q`), the pane path (`%q`), the tty, and the crewwork tree lookup
  - the clamp `work.surface.layout` case20 fails on any `ssh` call or `$(__duct_tmux_cmd)` line whose splices are not a vetted form
- what stays is the shape: the quote rule lives at each sink, not in one communicator. a new verb has to pick a vetted form, or the clamp goes red

## .the shape of the fix

1. add `__duct_tmux_on_grove <host> <tmux args…>` to `ductwork.host.sh`. it `%q`-quotes each arg and rides `__duct_bash_on_grove` (base64 over the wire)
2. route every `ssh -n "$DUCT_HOST" "$(__duct_tmux_cmd)…"` site in `ductwork.{io,life,pane,uri,host}.sh` through it, one part per commit
3. narrow the case20 vetted list to the communicator alone, so a raw `$(__duct_tmux_cmd)` splice anywhere is red
4. keep the parse wall as a second layer
5. give each `-t` target tmux's exact-match form (`-t =<session>`), so a gone duct's `kill-session` can never prefix-match a peer (`a/mech` → `a/mechanic`). raised in round i008, not yet verified

## .why it is not done in this round

- it is ~20 sites over 5 files, and each changes how a live duct verb reaches its grove. that is a ripple past this route's diff, so it fails CLEAN
- this route's wish is the move promotion and the hetzner bar. the injection is closed today, by the wall, the per-value guards and the clamp
