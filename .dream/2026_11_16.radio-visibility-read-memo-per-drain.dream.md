# 🌙 dream: one visibility read per (repo, auth) per drain

kind: refactor · owner: dispatcher · caught 2026-11-16

## .the cue that fired

l3 peer round 2 on the public-repo promise blueprint (both lanes) flagged that a drain re-reads
`gh repo view --json visibility` once per held text record.

## .the gap, precisely

a backlog of N text records to one repo costs N `repo view` calls per drain. each spends the drain
deadline (`genRadioGhSendLimitForStep`) and github's rate limit, and a stuck public backlog taxes
every later push in the worktree, private ones included.

## .the shape of the fix

the drain context carries a read-only map `visibilityByRepoAuth`, built by a fold over the records:
`setRadioTaskRecordsInLine` returns the reads it made, and `getOneRadioPromiseHold` takes a prior read
for `(repo, auth)` before it calls `getOneGhRepoVisibility`. no mutable cache state; the map rides the
fold. J6's `repo view` count assertion then drops from N to 1.

## .why it is not done in this round

not clean: it threads a new value through the drain fold (InLine → NextInLine → Upstream), a ripple
outside the promise gate, under a commit window deadline. safe to defer: the cost is calls, never a
leak.
