# 🌙 dream: one stub-gh harness for the radio tests

- kind: refactor
- owner: rhachet-roles-bhuild (radio tests)
- caught 2026-11-22, in route `v2026_11_09.feat-radio-auth-as-ehmpath-via-keyrack-or-ambient`

## .the cue that fired

the has-consistent-mechanisms self review found two stub gh setups that each put a fake `gh` first on the PATH: the new `src/.test/utils/withAmbientStub.ts`, and an inline one in `src/contract/cli/radioTaskQueue.integration.test.ts` (the fault journey, `STUB_GH` + `STUB_GH_DIR`).

## .the gap, precisely

- both write a gh shim into a temp bin dir, prepend it to `PATH`, and restore it after
- only `withAmbientStub` proves the shim is the gh the subprocess resolves (`assertStubGhOnPath`) and isolates git identity; the queue stub does neither
- the queue stub carries per-repo fault modes and a call log with the token each call carried; the ambient stub carries only `auth token` + `issue list|create` and a token log

## .the shape of the fix

- lift a `withStubGh({ answers, log })` core into `src/.test/utils/`, with the PATH guard built in
- `withAmbientStub` composes it plus the git identity overlay; the queue journey composes it with its fault-mode answers
- clamp: both suites green, and the queue journey now fails loud if its stub is not first on the PATH

## .why it is not done in this round

the queue suite is ~1400 lines of extant fault journeys outside this wish; a rewrite of its harness is a refactor no stone asks for, and its risk sits on tests this route did not author
