# 🌙 dream: rhachet's exit-2 footer reads a held push as "blocked"

kind: reseed · owner: ehmpathy/rhachet · caught 2026-09-30

## .the cue that fired

self review has-critical-paths-frictionless (5.3.verification of `v2026_09_28.fix-radio-recorder`),
a live held push:

```
🦫 held for the radio
   ├─ task    = fix(brain): port the seven skipped brain suites to rhachet-brains-xai
   ├─ status  = QUEUED (radio.uses:blocked — global)
   …
   └─ lift it (human): rhx radio.uses --global allow

🪨 run solid skill repo=bhuild/role=dispatcher/skill=radio.task.push
   └─ ✋ blocked by constraints
```

## .the gap, precisely

rhachet frames every exit-2 skill with `└─ ✋ blocked by constraints`. exit 2 means "the caller
must act", which is true of a held push (a human must lift the gate) — but the word "blocked"
after a task that was *kept* invites the read "failed, lost". the skill cannot change the frame;
exit 0 would mislead a caller that the push was delivered (bhuild fulcrum F3).

## .the shape of the fix

one of, for the rhachet maintainers to pick:
- let a skill name its own exit-2 footer (e.g. a last stderr line the frame adopts), or
- word the generic footer as the caller's act, not the skill's state: `└─ ✋ awaits your move`
- or no footer when the skill's own stdout already ends in a tree

## .why it is not done in this round

the frame lives in `ehmpathy/rhachet`, not this repo; a tree adopts only what is scoped to itself.
the held output above the footer already says held, QUEUED, and the lift, so no human is stuck.
dispatch it via the radio once it opens.
