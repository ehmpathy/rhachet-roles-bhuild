## .the cue that fired

5.3 peer review i001, lane `mech-given-when-then`, blocker.1: `initBehaviorDir` re-runs in each

## .the gap, precisely

the file's `beforeEach` mints a fresh temp dir per test, so each `then` calls `initBehaviorDir`
itself. case1/t0 is fixed on this route (one `useBeforeAll` per `when`). the rest keep the shape:

- case1/t1 · case2/t0 (4 thens) · case3/t0 (4) · case4 · case5/t0 (5) · case6/t0 (3) · case7/t0 (5)
- the nested `[case5] guards carry self-referential provenance` t0 and t1

## .the shape of the fix

per `when`: a `useBeforeAll` that mints its own temp dir, calls `initBehaviorDir` once with that
`when`'s guard arg, and returns `{ tempDir, behaviorDir, result }`; an `afterAll` that removes the
dir. each `then` reads `scene.result` and `scene.behaviorDir`. then drop the file-level
`beforeEach` / `afterEach` once no `then` reads the outer `behaviorDir`. case4 (a re-init after a
first init) keeps two calls in its `useBeforeAll`, since the second call IS its subject.

## .why it is not done in this round

the other cases predate this pr and test templates it does not touch. the refactor is safe, but
it is not clean: it rewrites ~30 tests in a pr whose diff should show the wisher-how rule.
