## .the cue that fired

the l3 arch lane (i006, r011, defects 4, 5, 6) named three dispatchers that do their leaves' work inline. each has no change in output; each touches every radio auth test harness.

## .the gap, precisely

- `getEhmpathTokenByVia` walks the spots, names `'keyrack'` by hand to pull `keyrackFound` for the miss metadata, takes `auth` only to word the message, and builds the throw
- its `identity: AmbientIdentity | null` input carries two behaviors: `null` means the ambient spot reads it, a value means already read
- `getGithubTokenByAuthArg` holds the `shx`, `env`, `via-keyrack` and `as-human` leaves inline, ~170 lines

## .the shape of the fix

- a pure `walkSpots` → `{ token, spot } | { founds }`; a separate miss builder the caller composes; each found carries its own `cause`, so no spot name is special
- one memoized `readIdentity()` per send, passed to the ambient spot and the default alike; `getAmbientIdentity` loses its `Record<string, never>` input
- `getTokenFromShx`, `getTokenFromEnv`, `getTokenFromKeyrackOwner` leaves, so the dispatcher is one switch on `mode.kind`, and `as-human` owns its guard
- land after `refactor-radio-auth-one-context-and-provenance`, since both reshape the same return

## .why it is not done in this round

each change reshapes a contract across the auth folder and every radio test harness, with no change in any output a human reads; it fails CLEAN for a stone whose deliverable is the four `--auth` values (F22).
