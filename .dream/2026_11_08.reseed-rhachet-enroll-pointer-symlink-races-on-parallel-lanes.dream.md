# 🌙 dream: rhachet enroll must findsert its brain-dir pointer symlinks

- kind: reseed
- owner: ehmpathy/rhachet
- caught 2026-11-08

## .the cue that fired

`skill.init.behavior.guards.journey.blueprint.acceptance` went red on 4 of 6 tests (local, 2026-11-08). a rerun of the one suite passed 6 of 6, with no change.

## .the gap, precisely

- two l3 review lanes (`enroll-blueprint-arch-defects`, `enroll-blueprint-behavior-intent`) run `rhachet enroll` in parallel
- both compute one actor dir: `.agent/.actors/actor.via.hash=<h>/brain/`
- `setBrainDirPointerFiles.ts:52` calls `symlinkSync('AGENTS.md' → .claude/CLAUDE.md)` with no existence check
- the second lane throws `EEXIST`, an unclassified `MalfunctionError`, and the guard marks that reviewer `malfunction 💥`

## .the shape of the fix

- findsert the pointer: when the link already exists and points at the same target, return it. a different target is a `MalfunctionError` that names both
- or catch `EEXIST` and re-read the link with `readlinkSync`
- clamp: two concurrent `setBrainDirBoot` calls on one dir both succeed

## .why it is not done in this round

the defect lives in a dependency's source, so the fix belongs to rhachet. a patch here would be a workaround, and #513 is bounded to radio auth.
