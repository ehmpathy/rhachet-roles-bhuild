# 🌙 dream: `invokeBrainRepl` shells `claude --print` inside a hook-laden repo

- **kind** — `fix`
- **owner** — this repo (`ehmpathy/rhachet-roles-bhuild`), then `ehmpathy/rhachet`
- **caught** — 2026-09-28, at `5.3.verification` of
  `v2026_09_22.feat-lift-supervisor-and-prioritizer-roles`

## .the cue that fired

peer reviewer `mech-external-contracts` (i005 r003) raised **blocker.2**: the
`imaginePlan.brain.case1` suite is `describe.skip`, so the brain contract for behavior
decomposition has no live coverage. its suggested remedy — *"rewire onto Fireworks, the way
`imagineReviewSelfVerdict` does"*.

⇒ I lifted the skip and ran it for real, rather than argue from the comment. **both the
skip's stated reason AND the reviewer's remedy turn out to be false**, and the true cause is
neither.

## .the gap, precisely

### 1 — the skip's stated reason named the wrong credential

```ts
// .note = deprecated: anthropic api key disabled, pending xai brain integration
describe.skip('imaginePlan.brain.case1.integration', () => {
```

`imaginePlan` calls `brain.repl.imagine`, which the suite wires to `invokeBrainRepl`:

```ts
// src/infra/brain/invokeBrainRepl.ts:37
const output = execSync(`claude --print -p '${promptEscaped}'`, { … });
```

⇒ a **claude CLI shell-out on an OAuth session** — `ANTHROPIC_API_KEY` is not in the path at
all. so the named blocker was never the blocker.

### 2 — an xai/fireworks swap could never have fixed it

`imaginePlan` needs a brain **repl**. `imagineReviewSelfVerdict` — the peer the reviewer
points at — takes a `ContextBrain<BrainAtom>` and calls `getBrainAtomsByFireworksAI()`.

| | mechanism | ships a repl? |
|---|---|---|
| `imagineReviewSelfVerdict` | `BrainAtom` — one stateless call | n/a |
| `imaginePlan` | `brain.repl` — a tooluse loop | 🔴 fireworks: **no** · xai: **no** |

⇒ only `anthropic/claude/code/*` ships a repl (4 of them). so the comment's own remedy
pointed at a destination that cannot host this operation, and the reviewer's remedy inherits
the same defect.

### 3 — the REAL cause: the child `claude` boots this repo's hooks

with the CLI freshly authenticated, the run took **432 seconds** and exited non-zero. its
captured stderr holds **no auth error** — only this repo's own hook warnings:

```
Permission allow rule (.claude/settings.json): Write(.agent/.notes/**) is not matched …
Permission deny  rule (.claude/settings.json): Write(.meter/*) is not matched …
```

`execSync` inherits the repo root as cwd, so the child `claude` reads `.claude/settings.json`
and boots every `SessionStart` hook this repo declares — ~150 briefs across six roles, each
with its own timeout, plus the `route.drive` Stop hook.

⇒ **a bare `claude --print` from inside a hook-laden repo is not a usable brain seam.** the
file says as much about itself already:

```ts
* .todo = liftout generalized into rhachet repo
```

## .the shape of the fix

| # | the move | owner |
|---|---|---|
| 1 | isolate the child: run it from a clean cwd, or with hooks off, so a brain call does not boot the caller's whole role set | this repo |
| 2 | better — replace the shell-out with a real repl brain from `rhachet/brains`, the way `imagineReviewSelfVerdict` uses an atom. that is the `.todo` the file already carries | `ehmpathy/rhachet`, then here |
| 3 | then drop the `describe.skip` and let the suite prove the contract | this repo |

⚠️ #1 collides with `rule.forbid.cwd-override`, which forbids a cwd override anywhere in
`src/`. so the honest fix is #2, and #1 is at best a stopgap that owes its own exception.

## .why it is not done in this round

**SAFE?** 🔴 no — it changes the brain seam every decomposition path runs through.
**CLEAN?** 🔴 no — it reaches into `src/infra/brain/`, a subsystem this lift never opened, and
its proper home is another repo entirely.

⚠️ and the alternative is worse: a **7-minute deterministic failure** in ci, on every run,
for every contributor. a recorded skip with a true cause beats that.

⇒ so the skip stands, and its comment now carries a cause a reader can act on rather than one
that sends them to a destination which cannot host the operation.
