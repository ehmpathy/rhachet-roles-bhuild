# 🌙 dream: the cli zod gate exits 2 behind a qualified header

- kind: fix
- owner: dispatcher (and every skill that calls `getCliArgs`)
- caught 2026-11-14, on route `.behavior/v2026_11_14.radio-task-comment` (5.3 ergonomics review)

## .the cue that fired

a live capture of `rhx radio.task.comment --via gh.discussions ...` printed:

```
⛈️  error: input invalid
   └─ --via invalid option: expected one of "gh.issues"|"os.fileops"
exit=1
```

## .the gap, precisely

`src/infra/cli/getCliArgs.ts` prints a schema miss behind `⛈️  error: input invalid` and exits 1.
bad input is the caller's to fix: `rule.require.exit-code-semantics` says exit 2, and
`rule.require.qualified-error-headers` says `✋ ConstraintError:`. every skill on `getCliArgs`
(push, pull, queue, comment, decompose, ...) shares the miss.

## .the shape of the fix

- print `✋ ConstraintError: input invalid` and exit 2 in `getCliArgs`
- resnap `getCliArgs.test.ts.snap` and any acceptance snap that pins the old header
- note the exit-code change in the release notes: a caller that keys on exit 1 for bad input sees 2

## .why it is not done in this round

a change to the exit code of every skill is a contract change beyond the comment path. F18.
