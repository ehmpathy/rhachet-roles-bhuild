# 🌙 dream: `git.release --watch` reports "all checks passed" while checks have not yet run

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, `git.release`)
- caught 2026-11-22, in route `v2026_11_09.feat-radio-auth-as-ehmpath-via-keyrack-or-ambient`

## .the cue that fired

on pr #712, `rhx git.release --watch` printed `👌 all checks passed` and `🫧 no runs inflight` twice, 0s watched. `gh pr checks 712` at the same moment listed 21 checks: 3 passed, 18 queued and not yet started (test-unit, test-lint, test-types, the integration and acceptance shards).

## .the gap, precisely

- the watch treats "no run inflight" as "all checks passed", but a queued check is neither inflight nor passed
- a caller who trusts the line ships a pr as green before a single test has run

## .the shape of the fix

- read the pr's check rollup; a check counts as passed only on `conclusion = success`; any check not yet concluded keeps the watch alive
- clamp: a fixture rollup with one passed and one queued check must report that it still waits, never "all checks passed"

## .why it is not done in this round

the skill lives in the ehmpathy role package; this route watched with `gh pr checks 712 --watch` instead
