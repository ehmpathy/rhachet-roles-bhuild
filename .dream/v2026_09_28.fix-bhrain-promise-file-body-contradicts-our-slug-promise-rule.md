# 🌙 dream: the bhrain promise file's body contradicts our own slug-promise rule

- **kind** — `reseed`
- **owner** — `ehmpathy/rhachet-roles-bhrain` (the `route.stone.set --as promised` emitter)
- **caught** — 2026-09-28, at `5.3.verification` of
  `v2026_09_22.feat-lift-supervisor-and-prioritizer-roles`

---

## .the cue that fired

a peer reviewer (`repo-rules`, i006) raised a blocker against **21** promise files under `.route/`
and cited this repo's own `rule.require.slug-promise-format`. every one reads:

```
i promise i have completed the review.self for "has-fixed-all-gaps".
```

the rule's whole point is that a promise reads as **`i promise that it $slug`**, so the sentence
and the rule disagree in the one place the rule is about.

⇒ the blocker is **refuted for this stone** — the files are engine-generated and gitignored, so
they are not this PR's artifact (see `F27`). but the observation underneath it is real, and it
belongs to the emitter.

---

## 🔴 .the gap, precisely

the **slugs are right** and the **sentence is wrong**:

| what the rule governs | this repo's 21 slugs | verdict |
|---|---|---|
| the slug reads as `i promise that it $slug` | `has-fixed-all-gaps`, `has-zero-test-skips`, `has-behavior-coverage`, … | ✅ every one |
| — | `behavior-declaration-coverage`, `role-standards-adherance` | ✅ (`i promise that it role-standards-adherance`) |

so the slug half is already correct wherever a guard author chose one. the **body** the engine
writes is what reads oddly — it says *"i have completed the review"*, which is a claim about an
ACT, where the rule asks for a claim about the ARTIFACT.

⚠️ that distinction is the point of the rule. *"i completed the review"* is satisfied once the
review has happened; *"it has-fixed-all-gaps"* is satisfied only once the artifact is in that
state. one is a timesheet, the other is a promise.

---

## .the shape of the fix

in whatever emits `<stone>.guard.promise.<slug>.md`, swap the body line:

```diff
- i promise i have completed the review.self for "<slug>".
+ i promise that it <slug>.
```

the slug already sits in the filename and the header, so no new input is needed — it is a
rewrite of one template string.

⚠️ what must NOT happen: a rename of the **slugs** to fit the current sentence. the slugs already
satisfy the rule; it is the sentence that drifted.

---

## .why it is not done in this round

**owner.** the string is not in this tree:

```sh
rhx grepsafe --pattern 'i promise i have completed|i promise that it' --glob 'src/**/*'
# → 0 matches
```

it is written by `rhx route.stone.set --as promised`, which lives in `rhachet-roles-bhrain`. and
the files it writes are gitignored here (`.route/.gitignore:2:*`), so a hand-edit would be both
overwritten on the next promise and invisible to the PR.

⇒ a tree adopts only what is scoped to itself (`rule.always.catch-dreams-for-followups`).

## 🟡 .the second-order note worth a record

`rule.require.slug-promise-format` lives in **this** repo, at
`.agent/repo=.this/role=any/briefs/`, and the engine that writes against it lives in another. a
rule whose enforcement surface sits in a different package than its text will drift — this is the
first measured instance of that drift, and it will not be the last.
