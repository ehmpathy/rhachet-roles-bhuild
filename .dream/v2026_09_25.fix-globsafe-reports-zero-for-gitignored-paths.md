# 🌙 dream: make `globsafe` say when a gitignore filter hid the matches

| field | value |
|---|---|

| **owner** | `ehmpathy/rhachet-roles-ehmpathy` |

## .the cue that fired

mid self-review i asked whether a gitignored scratch clone carried unit tests:

```sh
rhx globsafe --pattern '.temp/source-lift-src/**/*.test.ts'
```

```
🐢 crickets...
   ├─ pattern: .temp/source-lift-src/**/*.test.ts
   ├─ path: .
   └─ files: 0
```

a non-gitignore-aware glob over the identical pattern returns **8 files**.

## .the gap, precisely

`globsafe` excludes gitignored paths — a sane default, and not the defect.

🔴 **the defect is that it reports the filtered result as an ordinary zero.** `files: 0` is the exact
same output a pattern that genuinely matches naught produces, so the caller cannot tell:

| the true state | what globsafe prints |
|---|---|
| the pattern matches no file anywhere | `files: 0` |
| the pattern matches 8 files, all gitignored | `files: 0` |

⇒ **a glob that silently matches naught is indistinguishable from one that correctly matches
naught**, and the caller reads the second as the first.

## .why it is more than a nitpick

it produced a **wrong verdict in a review, before the second read caught it.** i was one sentence
from the claim *"the clone carries no unit tests, so two of my three config edits are speculative"* —
the opposite of the truth, and it would have shipped as a recorded finding.

⇒ `rule.forbid.surprises` and `rule.require.status-feedback`: a filter that changes the answer must
say so. silence here is not neutral — it is a **confident wrong answer**.

⚠️ it is the same class as `rhx git.repo.get --words`, which returns `found: 0`, exit 0, for words
certainly present (`.dream/2026_09_22.fix-git-repo-get-words-returns-zero-silently.md`). **two safe*
tools, one failure shape** — which suggests the fix belongs to the family, not to one skill.

## .the shape of the fix

a line in the tree output whenever the gitignore filter actually removed a match:

```
🐢 crickets...
   ├─ pattern: .temp/source-lift-src/**/*.test.ts
   ├─ path: .
   ├─ files: 0
   └─ 🟡 8 matches were hidden — they are gitignored
      └─ to include them: --include-ignored
```

three parts, each load-central:

1. **the count of hidden matches** — proves the pattern was not the problem
2. **the reason** — names gitignore as the filter, so the caller stops debug on the pattern
3. **the escape** — `sedreplace` already ships `--include-ignored`, so the flag name is settled by
   precedent rather than invented

⚠️ **do not flip the default.** the gitignore exclusion is correct — `node_modules` alone justifies
it. the fix is about what the tool **says**, never what it matches.

⇒ and the sweep is wider than one skill: `grepsafe` likely shares the shape, and `git.repo.get` has
its own dream. worth one pass over the `claude.tools/` family.

## .why it is not done in this round

**SAFE?** no — it edits a tool in **another repo**, one every role on every box calls.

**CLEAN?** no — it lands in no diff this branch has open, and the right scope is the whole safe-tool
family rather than the one skill that bit.

⇒ both answers are no, so it defers, and a cross-repo fix is a `reseed` by definition — a tree adopts
only what is scoped to itself (`rule.always.catch-dreams-for-followups`).
