# 🌙 dream: `review.sh --help` documents a comma form the parser rejects

**kind** — `reseed`
**owner** — `ehmpathy/rhachet-roles-bhrain`, role=reviewer (the skill) + role=driver (the guards)
**caught** — 2026-09-08, from `ehmpathy/rhachet-roles-bhuild`, route
`.behavior/v2026_09_04.feat-behavior-route-upgrades`

## .the cue that fired

a new peer lane was written against the documented flag form and threw on its first run:

```
BadRequestError: --rules glob was ineffective
```

the driver had copied the form straight out of the skill's own header.

## .the gap, precisely

**the help text names a form the parser does not support.**

```sh
# src/domain.roles/reviewer/skills/review.sh:12,14
#   --rules   glob pattern(s) for rule files (comma-separated)
#   --paths   glob pattern(s) for target files (comma-separated)
```

```ts
// src/domain.operations/review/stepReview.ts:298
const ruleGlobs = Array.isArray(input.rules) ? input.rules : [input.rules];
```

```ts
// src/contract/cli/review.ts:154
rules: options.rules as string,
```

⇒ **no comma split anywhere.** `'globA,globB'` becomes ONE glob whose literal text holds a comma, it
matches zero files, and `stepReview.ts:328` throws.

🟡 **it fails loud by luck, not by design.** the throw fires only because a comma-carried pattern
happens to match zero files. a pattern where **one** member is still reachable would run on a
partial rubric and render a verdict — the silently-partial shape.

🔴 **and a sibling flag makes the doc's claim more persuasive, not less.** `review.ts:129-141` gives
`--refs` and `--optional` a collector, so those two DO take several values — by repetition. `--rules`
has no collector and is `as string`, so a repeat is last-wins. ⇒ a driver sees a multi-value idiom
work for `--refs`, reads *"comma-separated"* on `--rules`, and has two reasons to believe a form the
parser refuses.

⇒ **the call site was fixed twice and the doc that produced the error was fixed zero times.** so the

same constraint. two repos, three months apart, same one-line cause.

## .the shape of the fix

three parts, and the first is the whole point:

1. **repair the help text** — `review.sh:12,14`, and `review.ts:45` if it carries the same claim.
   state the supported forms:
   ```
   --rules <glob>   glob for rule files. ONE glob — use brace expansion for several
                    dirs, e.g. 'a/{x,y}/rule.*.md'. a comma is a LITERAL, not a separator.
   ```
2. **name the fix in the error** — `stepReview.ts:320-328` prints *"verify the glob pattern matches
   files in your repo"*. where the glob **holds a comma**, that hint points the reader away from the
   cause. add:
   ```
   └─ hint: this glob holds a comma. --rules takes ONE glob — a comma is a literal.
            for several dirs, brace them: '.agent/repo={a/briefs,b/briefs}/rule.*.md'
   ```
   ⇒ `rule.require.errors-name-the-fix` — the extant hint names the symptom.
3. **decide the contract, then make the doc match it.** either the parser splits on commas (and the
   doc becomes true), or it never will (and the doc must say so). the present state is the worst of
   the two: the doc promises a behavior the code refuses.

🟡 **option 1 alone discharges the dream.** the split is a design call bhrain owns; the doc is a lie
either way, and it costs a driver a round every time it is believed.

## .why it is not done in this round

  part 3 is a contract decision bhrain owns.

⇒ so it is a `reseed`, and the bhuild-side repair is already in place: this route's `yield-density`
