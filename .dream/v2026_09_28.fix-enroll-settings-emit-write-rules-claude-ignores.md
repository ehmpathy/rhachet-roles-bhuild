# 🌙 dream: enroll settings emit `Write(...)` rules that claude ignores

- **kind** — `reseed`
- **owner** — `ehmpathy/rhachet` (the enroll-settings generator), **not** this repo
- **caught** — 2026-09-28, at `5.3.verification` of
  `v2026_09_22.feat-lift-supervisor-and-prioritizer-roles`

---

## .the cue that fired

a peer reviewer lane (`enroll-verif-test-intent`, r012) returned a **session transcript instead of
a review**. its first six lines say why, and claude says it in its own words:

```
Permission allow rule (…/settings.enroll.9366365e.local.json): Write(.agent/.notes/**) is not
matched by file permission checks — only Edit(path) rules are. Use Edit(.agent/.notes/**)
instead (Edit rules cover all file-editing tools).
```

**six rules, all ignored** — three `allow`, three `deny`:

| verdict | rule as emitted | rule as claude would honor |
|---|---|---|
| allow | `Write(.agent/.notes/**)` | `Edit(.agent/.notes/**)` |
| allow | `Write(.route/**)` | `Edit(.route/**)` |
| allow | `Write(**/.test/**)` | `Edit(**/.test/**)` |
| deny | `Write(*/**/.route/**)` | `Edit(*/**/.route/**)` |
| deny | `Write(.branch/.bind/*)` | `Edit(.branch/.bind/*)` |
| deny | `Write(.meter/*)` | `Edit(.meter/*)` |

---

## 🔴 .the gap, precisely

**the `deny` rows are the dangerous half, and they fail OPEN.**

an `allow` rule that claude drops costs a permission prompt — a nuisance, visible, recoverable. a
**`deny`** rule that claude drops costs the guarantee it was written to make: `.route/`,
`.branch/.bind/`, and `.meter/` are each meant to be off-limits to a clone, and each is currently
unprotected against every file-edit tool.

⇒ the emitted config **reads as a guardrail and functions as none** — the exact shape
`rule.forbid.failhide` names, one layer up from code.

⚠️ and the emitter is not confused about the concept: it gets the *paths* right and the *verdicts*
right. only the tool name is wrong, and it is wrong uniformly — so this is one substitution, not
six judgments.

---

## .the shape of the fix

in whatever emits `settings.enroll.<hash>.local.json`, swap the tool name on every **path-shaped**
rule:

```
Write(<path-glob>)  →  Edit(<path-glob>)
```

claude's own message states the reason, and it is the whole justification: *"Edit rules cover all
file-editing tools."* so `Edit(...)` is strictly broader than the `Write(...)` that was intended —
no rule loses reach, and every dropped rule starts to bind.

⚠️ what must NOT happen: a swap of `Write` → `Edit` on a **non-path** `Write` rule, if any exists.
the message is specific — it fires on `Write(path)` forms, where a file permission check is what
the rule wanted.

---

## .why it is not done in this round

**owner.** the file lives at
`.agent/.actors/actor.via.slug=.default/brain/.claude/settings.enroll.<hash>.local.json` and is
**generated** — a hand-edit is overwritten on the next enroll. the generator is in
`ehmpathy/rhachet`, and a grep of this repo finds not one of these strings:

```sh
rhx grepsafe --pattern 'Write\(\.agent/\.notes|Write\(\.route/' --glob 'src/**/*'   # 0 matches
```

⇒ a tree adopts only what is scoped to itself (`rule.always.catch-dreams-for-followups`), so this
is caught as a **reseed** rather than fixed here.

this workspace has not been trusted. Run Claude Code interactively here once and accept the

granted itself trust. it is recorded in the stone's handoff as a human-owed item instead.
