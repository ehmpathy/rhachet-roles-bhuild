## .the gap, precisely

two code paths strip the `.light` / `.heavy` guard-variant suffix, with different semantics:

- `computeTemplatesToProcess` (in `initBehaviorDir`) strips only the CHOSEN variant's suffix, and
  skips the other variant
- `isTemplateInSize` (`getAllTemplatesBySize.ts:148-152`) strips EITHER suffix via
  `replace(/\.(light|heavy)$/, '')`

`initBehaviorDir` is the only production caller of `isTemplateInSize`, and it always hands over an
already-stripped name. so the regex branch never runs in production. it runs only in
`getAllTemplatesBySize.test.ts`, which calls it directly with `'1.vision.guard.light'`. a third
variant, or a change to either strip, can drift with no test able to catch it.

## .the shape of the fix

pick one owner of the strip:
- either `computeTemplatesToProcess` delegates to one named transformer
  (`asManifestNameOfTemplateFile`, the same one `getAllTemplatesBySize.manifest.integration.test.ts`
  declares locally), and `isTemplateInSize` drops its variant branch,
- or `isTemplateInSize` becomes that owner and `computeTemplatesToProcess` stops its own strip

then update `getAllTemplatesBySize.test.ts` so it covers the path production takes, not a direct
call with a suffixed name.

## .why it is not done in this round

not SAFE in this round: it changes prior behavior and a unit test that asserts it
(`rule.require.review-test-changes`), in code the wish never touched. the brain-per-stage change
added only one manifest entry here.
