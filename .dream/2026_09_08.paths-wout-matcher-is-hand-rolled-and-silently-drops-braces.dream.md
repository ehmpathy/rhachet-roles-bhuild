**kind** — `reseed`
**owner** — `ehmpathy/rhachet-roles-bhrain`, role=reviewer

## .the gap, precisely

`--paths-wout` is matched by a hand-rolled transformer, never by a glob library:

```js
// dist/domain.operations/review/isPathMatchedByGlob.js
if (filePath === glob) return true;                    // exact
if (filePath.endsWith(`/${glob}`)) return true;        // suffix
if (glob.includes('*') || glob.includes('?')) {        // wildcard
    const source = glob.replace(/\*/g, '.*').replace(/\?/g, '.');
    return new RegExp(`^${source}$`).test(filePath);
}
return false;
```

two defects, and they fail in opposite directions:

🔴 **1. a brace matches naught, silently.** `{a,b,c}` reaches the wildcard branch (it holds a `*`),
and every char but `*` and `?` is spliced **raw** into the regex. `{` is then a literal, no path
holds one, so the pattern matches zero files and the exclusion is a no-op. **it fails OPEN** — the
lane runs on a wider corpus than configured and reports a normal verdict.

🔴 **2. `.` is not escaped, so a pattern OVER-reaches.** `$route/*.yield.md` compiles to
`^…/.*.yield.md$`, whose `.` before `yield` matches any char — so it also swallows
`…case=001.prose-gate-blocks-a-bloated-yield.md`. **it fails CLOSED**, and a file the rubric needed
is dropped with no report.

⇒ so the same matcher can under-exclude or over-exclude, and neither is announced.

🟡 **and `**` works only by accident** — it becomes `.*.*`, equivalent to `.*`, with no
path-segment awareness at all.

## 🔴 .the flag takes ONE value, so a workaround is unreachable

`review.ts:158` is `pathsWout: options['paths-wout'] as string | undefined`. only `--refs` and
`--optional` have collectors (`review.ts:129-141`), so a repeat is last-wins.

⇒ a driver who must exclude three unrelated paths has **one glob and no alternation**, and the
matcher's only tool is `*`. the three exclusions this route needs are not expressible.

🟡 **an injection does exist and is deliberately NOT taken.** since the glob is spliced raw,
`(a|b|c)` would compile and work — but it depends on the matcher remaining hand-rolled, and it
breaks the day this dream is discharged. a driver should not have to write a regex into a flag
named `glob`.

## .this is the SIXTH scope-flag instance on one route

| the flag | how it misparsed | how it read |
|---|---|---|
| `--paths-without` | parsed and **discarded** — bhrain reads `paths-wout` | as though the exclusion applied |
| `--paths-with` ×2 | **last wins** — the first bind is dropped | as though both scopes applied |
| `--goal` (absent) | defaults to **`representative`** — a sample, not a sweep | identical to a swept verdict |
| `--rules 'a,b'` | one literal glob **with a comma in it** | ✅ threw — the one that failed loud |
| `--rules` ×2, in 4 templates | **last wins** — the architect half is dropped | as though both rubrics applied |
| **`--paths-wout '{a,b,c}'`** | **matcher has no braces** — zero matches | as though the exclusion applied |

⇒ five of the six read as configured and were not. the class is a **scope flag that accepts a
value it cannot honor**, and every instance is silent.

## .the shape of the fix

1. **use a real glob library.** `globby`/`picomatch` already ship in this package — the positive
   side (`enumFilesForReviewSubjects`) uses one. the negative side should use the same matcher, so
   the two sides cannot disagree about what a pattern means.
2. **give `--paths-wout` a collector**, as `--refs` has, so several exclusions are expressible
   without alternation.
3. **fail loud on a zero-match exclusion.** a `--paths-wout` that excludes no file is almost always
   a typo; `--rules` already throws on the same condition (`stepReview.ts:328`). the asymmetry is
   the defect — one side refuses an ineffective glob and the other accepts it.

🟡 **part 1 alone discharges the dream.** parts 2 and 3 are ergonomics on top.

## .why it is not done in this round

- **safe?** ✅ yes — swap one transformer for a library already in the dependency tree.
- **clean?** 🔴 **no.** the file is `ehmpathy/rhachet-roles-bhrain`'s, not this repo's
  (`rule.always.scope-onetime-lessons-to-the-behavior`), and part 1 changes match semantics for
  every extant `--paths-wout` bind across every consumer repo.

⇒ the bhuild-side repair is in place: the guard binds the **exact path** rather than a wildcard, and
the two exclusions that need alternation are recorded as owed in the guard comment beside it.
