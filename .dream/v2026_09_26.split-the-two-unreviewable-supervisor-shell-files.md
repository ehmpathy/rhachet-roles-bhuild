## .the cue that fired

nine peer review lanes malfunctioned across four rounds (i005–i008) with no legible error. the
diagnosis at i008 pinned the mechanism: under `--focus pull` the reviewer opens files itself, so
the corpus lands in a tool loop no estimate bounds, and a whole-file read of a large file kills the
child mid-run.

⇒ the cue was not a complaint about file size. it was **four rounds of illegible deaths** whose
cause turned out to be file size.

## .the gap, precisely

measured against the live 200,000-token window of `anthropic/claude/code/sonnet`, the brain every
peer lane runs (`140,636 / 0.703 = 200,051`, from the i008 given):

| file | tokens | share of the window |
|---|---|---|
| `src/domain.roles/supervisor/skills/work/crewwork.sh` | **181.5k** | **91%** |
| `src/domain.roles/supervisor/skills/git.crew.poll.sh` | **175.1k** | **88%** |

**neither can be reviewed by `rhx review` under any option now available:**

| option | outcome |
|---|---|
| `--focus push` | refuses — 91%/88% is over its own 75% failfast |
| `--focus pull` | the child dies mid-read, as a bare exit code with the stderr discarded |
| a tighter `--paths-with` | sheds the file itself, so the lens is lost rather than gained |
| another `--brain` | the repl set is `anthropic/claude/code{,/haiku,/sonnet,/opus}` — no larger window |

🔴 **and the defect hides from its own detector.** `arch-hazards-maintenance` is the rubric that
would grade a 4,500-line shell lib as a maintenance hazard, and it is one of the lanes the file's
size defeats.

## .the shape of the fix

two candidate seams, both preserve the `source` contract so no caller changes:

### `crewwork.sh` — split by SUBJECT, per its own internal prefixes

the file's functions already cluster by the noun they act on (`__crew_ledger_*`, `__crew_duct_*`,
`__crew_seat_*`, `__crew_view_*`). so the seam is extant and named:

```
crewwork.sh                 # stays; sources the parts, keeps the public surface
├─ crewwork.ledger.sh       # __crew_ledger_*
├─ crewwork.seat.sh         # __crew_seat_*
├─ crewwork.view.sh         # __crew_view_*
└─ crewwork.duct.sh         # __crew_duct_*   ⚠️ note the overlap with ductwork.sh
```

### `git.crew.poll.sh` — split ENTRYPOINT from CLASSIFIERS

its bulk is the husk/idle/live classifier set and their verdict renders, not the poll loop. the
classifiers are the half with the 51 verbatim pane fixtures behind them, so they are the half that
most wants an independent review.

```
git.crew.poll.sh            # stays; the poll loop and the arg surface
└─ work/pollwork.classify.sh   # the classifiers the pane fixtures clamp
```

## .the cost, so it is not re-derived

- **46 entrypoints** `source` the `work/` libs; a split that keeps the original file as a
  re-exporter costs them naught, and that is why the seam above is chosen over a flat move
- **145 clamps** in `crewwork.integration.test.ts` (234.0k tokens) bind to function names. they do
  not change if the functions keep their names — but the suite must be re-run whole
- **every peer lane re-runs.** a bind that names `crewwork.sh` now matches four files
- ⚠️ `crewwork.duct.sh` vs the extant `ductwork.sh` is a **naming hazard** the split creates: two
  files whose names claim the same subject. decide it before the split lands, or the lift trades an
  unreviewable file for an ambiguous label (`rule.forbid.ambiguous-labels`)

## .why it is not done in this round

the SAFE/CLEAN test of `rule.always.fix-forward-under-scouts-honor`:

| question | answer |
|---|---|
| **safe?** | 🔴 **no.** a split of a 4,500-line shell lib touches behavior across 46 entrypoints and 145 clamps |
| **clean?** | 🔴 **no.** it ripples into `source` lines, test binds, and every peer lane's scope |

⇒ unsafe AND unclean is the row the rule marks *defer, and raise a fulcrum*. the fulcrum is `F13`.

🟡 **and the files are not unreviewed, only incompletely reviewed** — lanes that lit at i003 and
i007 raised real blockers *inside* `crewwork.sh` (r011's, and all three i007 race blockers). so the
deferral ships a partial read, never a blind one.
