## .the shape of the fix

two different fixes, because the rows split on ownership:

**rows 1–6 — upstream, in `declapract-typescript-ehmpathy`.** these are template-managed, so a
local strike is reverted or conflicts on the next `rhx declapract.upgrade`. the fix belongs in the
template: either drop the directives (the repo type no longer ships eslint) or swap them for
biome's own `// biome-ignore <rule>: <reason>` form, which biome *does* read.

**row 7 — local.** `src/infra/cli/getCliArgs.ts:191` sits above an `any`. strike the directive and
either replace it with a real `.note` that records why the `any` is load-bearing, or with a
`// biome-ignore lint/suspicious/noExplicitAny: <reason>` if biome flags it.

**the general lesson, worth a rule:** the correct reach when biome objects is not a suppression at
all — it is a fix at cause. both of my own instances were cured by a shape biome never objects to:

```ts
// before — a control char in a regex literal, plus an inert directive
// eslint-disable-next-line no-control-regex
const REGEX_ANSI = /\x1b\[/;
expect(result).not.toMatch(REGEX_ANSI);

// after — a plain string, no suppression owed to anyone
const ANSI_CSI = '\x1b[';
expect(result).not.toContain(ANSI_CSI);
```

`toContain` is exactly as strong as the regex here. the suppression was never the price of the
assertion; it was the price of an unnecessary regex.
