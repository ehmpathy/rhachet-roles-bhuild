# 🌙 dream: cli input errors read as qualified trees, not json blocks

kind: fix · owner: bhuild (all roles, via `src/index.ts`) · caught 2026-09-30

## .the cue that fired

self review has-ergonomics-validated (5.3.verification of `v2026_09_28.fix-radio-recorder`),
from a live capture:

```
$ rhx radio.task.push --into @this --title 'ergonomics probe, no via' --description 'x'
✋ BadRequestError: --via is required

{
  "hint": "specify a channel: --via gh.issues  or  --via os.fileops"
}
exit=2
```

## .the gap, precisely

- **the fix hides in a json block.** helpful-errors embeds metadata into `error.message`, and the
  `asCli` wrapper in `src/index.ts` prints the message as is. the fix is there, but a human reads
  `{ "hint": "…" }` — braces and quotes around a command they must copy. the held output already
  shows the better shape: `└─ fix: … ├─ hint: …` (`asRadioErrorDetail`)
- **the header is not a qualified class.** caller-fixable input reads `✋ BadRequestError:`;
  `rule.require.qualified-error-headers` (mechanic) wants `✋ ConstraintError:`. ~50
  `new BadRequestError(` sites across behaver and radio (`rhx grepsafe --pattern 'new BadRequestError\('`)

## .the shape of the fix

- in `asCli` (`src/index.ts`): render a caller error as a tree — the header line, then each
  metadata `hint` as a `├─ hint:` line, never the raw json; reuse `asRadioErrorDetail` /
  `asRadioErrorHint` (lift them from `radio/record/` to `infra/cli/`)
- the class: migrate caller-input throws to `ConstraintError`, file by file, **except** upstream
  refusals in `setPartRadioTask` (`task not found`, `already claimed`, transitions) — the recorder
  reads "a `BadRequestError` that is not a `ConstraintError`" as REFUSED (closed, never retried).
  a blanket rename would turn every refusal into a held retry. name that rule in a transformer
  (`isRadioUpstreamRefusal`) before the migration, so it survives it
- resnap the behaver + dispatcher error snaps; each change is header + hint shape only

## .why it is not done in this round

not CLEAN: it ripples into every skill's error output and ~50 throw sites, and a careless class
migration would break the recorder's refused-vs-held rule. the radio skills are not worse than
the rest of the repo — the hint is present on every error I captured. fulcrum: F29.
