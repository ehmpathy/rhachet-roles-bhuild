# 🌙 dream: the gh send-timeout test counts 0 calls under a loaded full run

- kind: fix
- owner: bhuild/dispatcher
- caught 2026-11-02

## .the cue that fired

the full integration run of fix-radio-refusal-parks-its-own-task (122 files, ~560s) failed
`daoRadioTaskViaGhIssues — shell safety and send timeout [case1] [t0] gh was called once, never
retried`: expected 1 call, received 0. alone, the file passes 12/12; an earlier full run on the
same branch passed it too. the branch does not touch `src/access/daos/daoRadioTask/`.

## .the gap, precisely

the test runs the stub gh under a 300ms timeout. on a loaded host, the timeout can kill the
stub before bash starts and appends `---` to `argv.log`, so the call count reads 0. the
assertion measures host load, not "never retried".

## .the shape of the fix

either raise the timeout to ~2000ms (the stub still sleeps 20s; the `< 5_000` elapsed bound
still proves "never hangs"), or have the stub mark its start as its first act and assert
`calls <= 1` paired with a separate proof that a retry would log a second `---`.

## .why it is not done in this round

another domain's test, outside this wish; the last review round held an out-of-wish edit as a
change to locked criteria.
