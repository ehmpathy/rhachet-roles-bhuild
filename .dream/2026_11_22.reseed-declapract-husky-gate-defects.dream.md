# 🌙 dream: the declapract husky practice ships gate defects that its consumers cannot fix in place

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy (the `husky` practice)
- caught 2026-11-22, in route `v2026_11_09.feat-radio-auth-as-ehmpath-via-keyrack-or-ambient`

## .the cue that fired

two peer review rounds on this route raised the same gate defects against uncommitted `.husky/` files in the worktree. the lock (`.husky/check.timestamps.lock.sh`) pins the hook's blob id and names its own fix as `npx declapract apply --practice husky`, so a local edit is reverted by the practice and cannot be the fix.

## .the gap, precisely

- `check.timestamps.sh` carries no `.eco/*` arm, and its header forbids any exemption; this repo's `rule.forbid.timestamps-in-tracked-files` names `.eco/*` as an allowed home. the rule and the gate disagree
- `check.timestamps.lock.sh`: `git hash-object` reads with no `|| timestamps_lock_malfunction` guard, so a read fault exits bare (the index read beside it is guarded); `timestamps_lock_halt` says "was changed / revert" for the absent case too
- `check.secrets.sh`: the `openai-style key` shape (`sk-(proj-)?…`) precedes `anthropic key` (`sk-ant-…`) and shadows it, so an anthropic key is named "openai-style"; the scan pipeline (`grep | head | cut`, no `pipefail`) reads a grep error as no match
- neither new gate has an integration test with a snapshot of its halt output

## .the shape of the fix

- in the practice: guard the disk read; split absent from changed; order `sk-ant-` before `sk-`; `set -o pipefail` (or split grep from head) and halt on grep exit 2; add an integration test per gate that stages a bad blob and a clean one and snaps stderr + exit code
- for `.eco/*`: decide upstream whether a consumer may declare a data-store exemption (e.g. a repo-local allowlist file the lock does not pin), then reconcile `rule.forbid.timestamps-in-tracked-files` here with that decision
- then `npx declapract apply --practice husky` in this repo

## .why it is not done in this round

the files are another actor's practice upgrade, uncommitted in this worktree before the route began; the lock reverts any local edit; the fix lives in the practice repo
