# 🌙 dream: guard `RadioTaskRecordStatus` transitions at write time

kind: fix · owner: bhuild/dispatcher · caught 2026-09-29

## .the cue that fired

peer review i006 r011 nitpick 4 (5.1.execution of `v2026_09_28.fix-radio-recorder`).

## .the gap, precisely

`RadioTaskStatus` has `applyStatusTransition`; `RadioTaskRecordStatus` has none. its rules live in
`isRadioTaskRecordRequeuedByPush` and the settle branches of `setRadioTaskRecordUpstream`. an
invalid record (DELIVERED with a null `deliveredExid`) is caught only when the push output renders.

## .the shape of the fix

- `asRadioTaskRecordTransitioned({ record, to })`: allows QUEUED → DELIVERED (exid required),
  QUEUED → REFUSED, DELIVERED | REFUSED → QUEUED (requeue); all else throws `MalfunctionError`
- every record write passes through it; a data-driven unit test per edge

## .why it is not done in this round

a design addition, not a defect: each transition today has one writer and an integration case.
fulcrum: F26.
