# 🌙 dream: declapract writes a check placeholder as a dependency version

kind: reseed · owner: ehmpathy/declapract-typescript-ehmpathy (or ehmpathy/declapract) · caught 2026-11-09

## .the cue that fired

boot of this tree: `npx declapract apply --practice rhachet` (declapract 0.13.27, practices 0.50.0) wrote into `package.json` devDependencies:

```
"rhachet-roles-bhrowser": "@declapract{check.minVersion('0.1.0')}",
"rhachet-roles-ghlitch": "@declapract{check.minVersion('0.3.0')}"
```

a literal check expression, not a version. pnpm cannot install it.

## .the gap, precisely

when a practice declares a `check.minVersion(...)` for a dependency the repo lacks, the automatic fix copies the check template into the field instead of a concrete version. the fix then leaves the repo uninstallable.

## .the shape of the fix

in the fix path for a dependency the repo lacks, map `@declapract{check.minVersion('X')}` to a concrete pinned version (`X`, or the latest that satisfies it), never the template text. clamp: a fixture repo with no such dependency; apply; assert the written value matches a semver.

## .why it is not done in this round

it lives in another repo (the practices package / declapract). in this tree the two values were set by hand to 0.1.0 and 0.4.0.

## .also seen in the same boot

- the boot failed first because the repo pinned `declapract@0.13.13`, while `declapract-typescript-ehmpathy@0.50.0` peer-requires `>=0.13.26`; 0.13.13 rejects the zero-check `environments-aws` practice. upgraded here to 0.13.27. a boot that bumps the practices package should bump declapract with it.
