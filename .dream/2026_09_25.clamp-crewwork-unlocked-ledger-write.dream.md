## .the gap, precisely

`src/domain.roles/supervisor/skills/work/crewwork.sh:2091-2116`, `__crew_ledger_set`:

| line | the step |
|---|---|
| 2102–2105 | reads `bootedFirst` out of the extant file — **no lock** |
| 2107–2115 | `cat > "$file" <<EOF` — unconditionally truncates, then rewrites the whole row |

a check-then-act with a gap between the read and the write, against a file any clone on the
grove may write. two concurrent writers — a boot that races a heal, or two clones that
re-register one tree — take one of two losses:

```
A: first=$(jq -r '.bootedFirst' crew.json)   # 1700000000000
B: first=$(jq -r '.bootedFirst' crew.json)   # 1700000000000
A: cat > crew.json <<EOF ... bootedLast: T1  # row rewritten
B: cat > crew.json <<EOF ... bootedLast: T2  # A's bootedLast is GONE
```

or worse — two interleaved `cat >` truncations produce **invalid json**, and every subsequent
read of that row then fails rather than merely serves a stale figure.

⚠️ **and this row is higher-stakes than its peer in ductwork.** the file's own adjacent
comment (`:118-124`) says the ledger row is *"the only record a crew ever existed"*. the
ductwork instance loses a `lastSeen` on one host; this one can lose the existence record for
a whole crew.
