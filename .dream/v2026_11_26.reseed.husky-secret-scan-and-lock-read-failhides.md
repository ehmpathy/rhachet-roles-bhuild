## .the cue that fired

## .the gap, precisely

1. `.husky/check.secrets.sh`: the detection line ends its pipeline in `cut`, so grep's own rc is lost
   - `printf '%s\n' "$content" | grep -nIE -e "$regex" | head -n 1 | cut -d: -f1`
   - a grep that FAILED (rc 2: a bad shape regex, a short read) reads the same as no match (rc 1), so a broken shape disables its detector for the whole hook
   - `-I` reads a blob with a NUL byte as no match, so a key in such a file stages clean
2. `.husky/check.timestamps.lock.sh`: the disk hash read has no status check
   - `TIMESTAMPS_LOCK_DISK=$(git hash-object -- "$TIMESTAMPS_LOCK_HOOK")`
   - a git that fails yields an empty capture, and the hook halts with `✋ ConstraintError: … was changed … found:  (on disk)` and a fix (`npx declapract apply --practice husky`) that cannot cure a broken git. the file's own `timestamps_lock_malfunction` already draws this line for the index read

## .the shape of the fix

1. secrets: capture grep's rc per shape (`grep -a`, not `-I`); 0 = hit, 1 = clean, any other rc = `💥 MalfunctionError` that names the shape and the file, exit 1. clamp: a malformed shape and a NUL-byte blob with a key each go red
2. lock: read the disk hash under the index read's discipline (a non-zero `git hash-object` → `timestamps_lock_malfunction`, exit 1); `set -eu`. clamp: a PATH with no git halts with the malfunction, never "was changed"

## .why it is not done in this round

the files are the practice's, carried in by an upgrade this route does not ship (F10). a fix here would fork the practice; the next `declapract apply` would overwrite it, and every other repo on the practice would keep the defect.
