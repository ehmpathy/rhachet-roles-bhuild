# 🌙 dream: init.behavior's wish errors carry a qualified header

kind: fix · owner: ehmpathy/rhachet-roles-bhuild (its own tree) · caught 2026-11-17

## .the cue that fired

5.3 snap review of `fix-radio-push-public-repo-promise`. F19 made `--wish ""` reach the skill's own guard, and its stderr snap became `"error: --wish requires content"`. That is the same text as the `@stdin` twin. The old zod message carried a `⛈️  error: input invalid` header; the skill's own text carries none.

## .the gap, precisely

`src/domain.operations/behavior/init/findsertWishFromInput.ts` emits two human-read errors with a bare `error:` opener, each on exit 2:
- L14 `error: --wish requires content`
- L35 `error: wish file has been modified` (its fix hint reads `rm <path>`, not `rhx rmsafe`)

`rule.require.qualified-error-headers` wants `✋ ConstraintError: <what>` for an exit-2 error, followed by the fix (`rule.require.errors-name-the-fix`). Snaps pin both texts: `skill.init.behavior.wish.acceptance.test.ts.snap` [case3], [case3b], and the modified-wish case.

## .the shape of the fix

1. throw `ConstraintError` from `helpful-errors` (or print `✋ ConstraintError: …` and exit 2), and name the fix in the message:
   - empty wish: pass text inline, or pipe it to `--wish @stdin`
   - modified wish file: `rhx rmsafe <path>`, then re-run
2. resnap the three init.behavior.wish stderr snaps, and assert the `✋ ConstraintError:` opener beside each snap

## .why it is not done in this round

SAFE: yes. CLEAN: no. It changes the error contract of `init.behavior`, a behaver skill outside #675 (the radio promise gate). It also moves three snaps of that skill and its fix hints. The ripple sits in a contract this pr never set out to open; F19 already touched it once, and that touch is flagged for the council.
