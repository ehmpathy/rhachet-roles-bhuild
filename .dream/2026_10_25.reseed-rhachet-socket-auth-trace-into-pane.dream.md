# 🌙 dream: the clone socket server must not write its auth fault into the pane

kind: reseed · owner: ehmpathy/rhachet (clone socket) · caught 2026-10-25

## .the cue that fired

the live phone demo on `beav/feat-phone-text`: an inbound `rhx clone say` from the tree's phone
daemon hit an auth-gate fault on the receiver, and the line
`clone socket auth error: <ss -xp | grep … failed>` appeared inside this clone's prompt box. the
seat read it as typed input and froze for the poll; the director had to tell the clone to ignore
it.

## .the gap, precisely

`rhachet@1.50.0` `dist/domain.operations/clone/socket/genCloneSocketServer.js:248`:

```js
if (outcome.fault)
  trace(`clone socket auth error: ${outcome.fault.message}\n`);
```

`trace` defaults to `getCloneTraceSink()`, which writes to the clone host's stderr. that stderr is
the pane's pty, so a diagnostic lands in the human's and the brain's input region. the fault
comes from the async `ss -xp | grep -E …` peer-cred lookup (`getSocketPeerCred.js:59`). the
phone is only a `clone say` client here; no phone code writes to a pane.

## .the shape of the fix

- route the clone socket trace to a log file beside the clone's socket, never to the pty; a pty
  write of any kind is an input the brain may read as its own
- the say client already gets a classed NACK (`auth-denied`, `auth-gate-timeout`); the fault
  detail can ride that NACK so the caller (the phone daemon) logs it, which is where it is useful
- clamp: a forced cred-lookup fault leaves the pane's input region untouched, and the fault text
  appears in the trace file and in the caller's reject reason

## .why it is not done in this round

the writer is rhachet's clone host, not this repo; a fix here could only hide the cause.
