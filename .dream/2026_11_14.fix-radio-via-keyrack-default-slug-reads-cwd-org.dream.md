# 🌙 dream: the radio via-keyrack default reads its keyrack slug from the cwd repo's org

- kind: fix
- owner: rhachet-roles-bhuild (dispatcher / radio auth)
- caught 2026-11-14, in route `v2026_11_09.feat-radio-auth-as-ehmpath-via-keyrack-or-ambient`

## .the cue that fired

an integration test of `--auth as-ehmpath` ran in a temp repo with no `keyrack.yml`. `keyrack.get` with a bare key threw a ConstraintError (no org to slug under) instead of a status miss, so as-ehmpath never reached its ambient spot.

## .the gap, precisely

- `getGithubTokenByAuthArg`'s `as-robot:via-keyrack(owner)` branch (the default, no `--auth`) calls `genAuthFromKeyrack` with `org: null`
- a bare key slugs under the org named in the cwd repo's `keyrack.yml`
  - no `keyrack.yml` → keyrack throws, from rhachet's own helpful-errors copy, so an `instanceof ConstraintError` check misses it
  - a `keyrack.yml` of another org → the slug points at that org's vault, not the ehmpathy robot token
- the as-ehmpath path pins `org: 'ehmpathy'` (fulcrum F12); the default path does not

## .the shape of the fix

- pin the org on the default branch too: `org: 'ehmpathy'` when `owner === 'ehmpath'`, or a new `as-robot:via-keyrack(owner, org)` form for other owners
- clamp: a temp repo with no `keyrack.yml` and one with a foreign org; the default `--auth` must miss honestly (status row) in both
- upstream: a reseed to rhachet so its keyrack throws an error class a consumer can catch (or exports one)

## .why it is not done in this round

the default path's slug is a contract every extant caller resolves; to change it is outside the as-ehmpath wish, and its rework touches callers this route cannot see
