# 🌙 dream: radio renders take cwd as an input

kind: refactor · owner: rhachet-roles-bhuild · caught 2026-11-17

## .the cue that fired

peer review 5.1 i003 (arch-opport-decomposition nitpick.1) on `fix-radio-push-public-repo-promise`: three render transformers read `process.cwd()` to build a record path.

## .the gap, precisely

- `asRadioPushOutput.ts` (`asHeldFixBranch`), `asRadioHeldOutput.ts`, `asRadioDrainHeldRow.ts` each call `asRadioTaskRecordPath({ dir, key }, { cwd: process.cwd() })`
- the orchestrator `getOneRadioPushDrainWithBacklog` already threads `context.cwd` into the same transformer
- so a unit test cannot pin the cwd of the rendered path; it renders relative to wherever jest runs

## .the shape of the fix

- add `cwd: string` to the input of `asRadioDrainHeldRow`, `asRadioDrainSections`, `asRadioDrainOutput`, `asRadioPushOutput`, `asRadioPushBacklogBranches`, `asRadioHeldOutput`
- the contracts (`radioTaskPush.ts`, `radioTaskQueue.ts`) pass `context.cwd`, which is `process.cwd()` by contract
- in `asHeldFixBranch`, compute `asRadioQueueFixLines` only in the two branches that render it
- every unit test of those renders passes a fixed cwd

## .why it is not done in this round

safe, but not clean: six renders, two contracts, and dozens of test call sites change for no behavior change; the value at runtime is `process.cwd()` either way (rule.forbid.cwd-override). fulcrum F17 holds the call.
