# 🌙 dream: grepsafe reports `matches: 0` on a path it never searched

- **kind** = `solve`
- **owner** = `ehmpathy/rhachet-roles-ehmpathy` · `role=mechanic` · skill `grepsafe`
- **caught** = 2026-09-25

## .the cue that fired

a spot-check of nine freshly-written `.taken` artifacts under
`.behavior/…/.reviews/peer/`, to confirm a delegated pass had used the right figures.

```
$ rhx grepsafe --pattern '229' --glob '.behavior/…/….r003._.taken.by_self.mech-decode-friction.md'
   ├─ pattern: 229
   ├─ path: .
   ├─ glob: .behavior/…/….r003._.taken.by_self.mech-decode-friction.md
   └─ matches: 0
```

the file **certainly contains `229`** — twice, at lines 9 and 30, confirmed by a direct read:

```
9:   ├─ 229.8% of 1048576 tokens
30:| window | 317.3% | 227.1% | **229.8%** |
```

⇒ `matches: 0`, exit `0`.

## .the gap, precisely

`grepsafe` honors `.gitignore`, and `.behavior/…/.reviews/peer/` carries its own `.gitignore`.
so the dir is invisible to the search.

🔴 **that behavior is defensible. the REPORT is not.** the output is byte-identical in two cases
that mean opposite things:

| what happened | what the output says |
|---|---|
| searched 40 files, found no match | `matches: 0` · exit 0 |
| searched **zero** files, because all were ignored | `matches: 0` · exit 0 |

⇒ a negative result is indistinguishable from an un-run search. and a negative is exactly the
shape a human cannot audit — **an absent item produces no evidence to contradict it.**

### 🔴 why this is expensive rather than merely untidy

the whole purpose of the call was to **verify a delegated claim**. a quiet zero reads as
confirmation of whatever the caller already believed:

- grep for a stale figure → `0` → *"clean, the correction landed"*
- grep for a banned glyph → `0` → *"the cutover is complete"*
- grep for a forbidden import → `0` → *"no leaks"*

⚠️ **the tool misleads hardest at the exact moment it is trusted most** — when it is used to
disprove a claim. this route ran that exact call three times today, against `.log/` and twice
against `.reviews/peer/`, and each `0` was false.

### ⚠️ and this is the THIRD instance of one class in this route

| tool | symptom | verified |
|---|---|---|
| `rhx git.repo.get --words` | `found: 0`, exit 0, for words certainly present | earlier this route; dream on file |
| a sub-agent's non-recursive glob | reported an extant acceptance test as absent | `r010` i003, self-corrected |
| `rhx grepsafe` | `matches: 0` on a gitignored path | this dream |

⇒ **a quiet search is indistinguishable from an empty result**, and three independent tools in one
route have now produced that shape. it is a **class**, not three coincidences.

## .the shape of the fix

the bug is not the scope; it is that the scope is invisible. **report the denominator.**

```
🐚 grepsafe
   ├─ pattern: 229
   ├─ glob: .behavior/…/….mech-decode-friction.md
   ├─ scanned: 0 files          ← THE new line
   ├─ skipped: 1 file (gitignored)
   └─ matches: 0

   ⚠️ every candidate was skipped — this is an UN-RUN search, not an empty result.
      to include ignored paths: --include-ignored
```

three parts, in order of value:

1. 🔴 **a `scanned:` count.** with it, `scanned: 0 · matches: 0` can never be misread as a clean
   negative. this alone closes the defect.
2. **a loud warn when `scanned == 0` but the glob matched files on disk.** that is the precise
   signature of a fully-skipped search, and it should never pass silently
   (`rule.require.status-feedback`, `rule.forbid.failhide`).
3. **an `--include-ignored` flag**, named in the warn so the error teaches its own fix
   (`rule.require.errors-name-the-fix`). `sedreplace` already ships exactly this flag, so the
   vocabulary exists and the peer precedent is set.

🟡 an exit-code change is **not** wanted. a zero-match search is not an error, and `grepsafe` is
routinely piped. the fix is legibility, never a new failure mode.

## .the clamp it owes

an integration test that drives the real skill against a temp repo:

- a `.gitignore`d file that **contains** the pattern → assert the output names `scanned: 0` and
  carries the warn, and assert it does NOT read as a plain `matches: 0`
- the same file, un-ignored → assert a real match
- ⚠️ **dogfood it**: revert the `scanned:` line, watch the first case go red. a report test that
  passes against the old output asserted on the wrong string.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| question | answer |
|---|---|
| **safe?** | 🟡 yes — a new output line and a warn change no search semantics |
| **clean?** | 🔴 **no.** `grepsafe` lives in **`rhachet-roles-ehmpathy`**, a different repo |

⇒ clean = no, on the hardest axis there is: **the file is not in this worktree.** this route's diff
is a supervisor/prioritizer lift into `rhachet-roles-bhuild`; a mechanic-skill repair belongs to its
own PR in its own package.

🔴 and there is a second reason the deferral is right rather than merely forced: **this defect
already bit this route three times and each bite was caught by a human-or-peer re-read, never by a
tool.** that is evidence the fix is worth real care and its own review — not that it should be
smuggled into a 77,742-line graduation.
