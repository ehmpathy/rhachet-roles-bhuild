## .the gap, precisely

- `templates/5.1.execution.from_vision.guard` and `templates/5.1.execution.phase0_to_phaseN.guard`
  differ only in a header uri and a few words of prose
- each sweep lane repeats `--paths-with '**/*.{ts,sh,md,snap}' --paths-wout '.behavior/**' --paths-wout '.dream/**' --join intersect`
- `1.vision.guard.heavy` is `.light` plus extra blocks, shared lanes byte-identical
- bhrain's guard yaml has no include, so no source-level share exists today
- the arch lanes bind `**/*.{ts,sh,md,snap}`, so no lane reads a `.guard` or `.stone` template

## .the shape of the fix

- hold lane fragments under `templates/.lanes/` (one file per lane), and variant manifests that
  list which fragments each guard takes
- a build step (`npm run build` hook) stamps the flat `.guard` files from the manifests, so
  `initBehaviorDir` and the published `dist/` are unchanged
- `[case13]` and `[case18]` stay as they are; a new clamp asserts the stamped output matches the
  committed guards, so a hand edit to a stamped file goes red
- widen the three arch lanes to `**/*.{ts,sh,md,snap,guard,stone}` once the copies are one source
