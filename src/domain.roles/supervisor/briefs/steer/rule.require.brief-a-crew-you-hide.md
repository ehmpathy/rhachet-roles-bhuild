# rule.require.brief-a-crew-you-hide

## 🔴 SUPERSEDED — do NOT send the order this rule used to mandate

`rule.forbid.steer-a-clone-beyond-a-permission-key` governs now: approve or reject a
permission modal is the whole channel. a carry-on order is a message the supervisor
originates, which that rule forbids.

the diagnosis below still holds — a clone genuinely reads a closed tab and a dead
operator as the same silence. but the cure was wrong: that read is a **boot defect**,
fixed in the boot so a clone wakes already with the carry-on posture. no message is
owed. read the rest of this file as a defect report against the boot, never as an
instruction to send.

## .the diagnosis

`crew.hide` is free and reversible on the view axis — for the supervisor. the clone
experiences otherwise: a closed tab and a dead operator are byte-identical silence,
and silence is the input a clone most often misreads.

| the clone concludes | what it does | why nobody notices |
|---|---|---|
| "it broke" | halts, waits to be told | no window to see the halt in |
| "i should confirm this fork" | parks on a design question | the ask lands on an unwatched keyboard |
| "a reviewer blocked me — that is a gate" | escalates a driver-owned lever | the escalation goes to no one |

a hidden crew is the crew you are least able to catch.

## .what the boot fix must restore

a clone that wakes already with this posture needs no message:

- its view can go down while its work does not — a closed window is no stop signal
- it converges with reviewers rather than wait (`rule.always.converge-with-reviewers`)
- it escalates only for NAMED human-only gates — stone approval, commit quota,
  release auth. an unenumerated "only when necessary" is read as broadly as the
  clone's caution allows
