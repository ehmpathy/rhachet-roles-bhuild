# rule.forbid.trust-of-wisher-how

> trust a wisher's **why**. trust the **contract** they ask for roughly — its verbs and rough shape. never trust their **how**.

a how in a wish is evidence to learn from, never a spec: a poc or prior command · a parity target set by a prior tool · a named mechanism, field list, flag set, or storage layout · a done-when phrased by a prior tool.

at vision and criteria: restate each how in the domain's own terms, then challenge it. keep what holds, drop what doesn't, mark open what only the wisher can settle, and record which in the vision yield's `## .the wisher's how` table: the how · its domain restatement · keep, drop, or open · the domain why. an open how is also a `[wisher]` open question. a wish with no how says so there. with no vision, the blueprint records it.

a how in the wish, and a prior tool named in that table, are the evidence and its record: never a violation. grade what is built from them.

test: **strike the prior tool or poc from the repo. does each requirement still read, and still look right?** no → it copied a how.

worked case: ehmpathy/rhachet#760 defined `get` as "shows what `brains.auth.usage` shows"; strike that tool and the requirement says naught (→ `rule.forbid.trust-of-wisher-how.example=rhachet-760.md`).

a how the wisher ties to a domain why is a constraint: keep it, stated with its why.

the inverse slip: a verb the wisher asked for, dropped as "a how". the verbs stand; only the inputs, defaults, and scope behind them are open.

blocker: a requirement whose sense depends on a prior tool, poc, or wisher-named implementation · a vision or blueprint that adopts a poc's design with no skeptic's pass recorded · a verb the wisher asked for, dropped as a how.
nitpick: a comment or doc that cites a prior tool as a choice's reason.

⇒ the argument: `rule.forbid.trust-of-wisher-how.reason.md`
