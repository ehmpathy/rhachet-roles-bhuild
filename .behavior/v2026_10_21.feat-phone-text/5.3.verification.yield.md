### gaps found in this stone, and fixed

- a no-op revoke printed `revoked: <address>` beside "no change, they were not in the pond", a label
  that names an act that did not happen. fixed: `asPhoneContactsSetOutput.ts` labels a no-op
  `not a contact:` / `already a contact:`; the unit test asserts the label per case; the
  acceptance case11 [t2] asserts one del block per distinct address, each named once
- a repeated `--address` printed its blocks with no gap between them. fixed:
  `phoneContacts.ts` prints a blank line between blocks
- **a held text kept the daemon awake with no sleep, on any grove west of utc** (found by a live
  walk on this grove, US Central; ci runs in utc, where the skew is zero). cause: `iso-time@1.11.3`
  cast a stamp by a format of local time with a literal `Z`, so `now()` read hours off and
  `addDuration` applied the skew twice; the idle clock landed 9.5h in the past, each tick
  returned at once, and the daemon re-read the roster and logged `lock reclaimed` in a tight
  loop. fixed at the source: `iso-time@1.11.7` casts via `toISOString`. clamp:
  `getOnePhoneIdleExitAt.integration.test.ts` reads the clock in a child under `UTC`,
  `America/Chicago`, `Asia/Tokyo` — red on 1.11.3 (`Received: -34200065`, `66599892`), green on
  1.11.7. the same cast fed the young-lock check in `daoPhoneDaemon`
- **`phone.text set` reported `no daemon was seen to swim` for a daemon that did start**, and
  `phone.daemon set` would exit 1 for it. cause: the start waited 3s for the lock, and a fresh
  node that loads the package takes longer on a loaded grove. fixed: `genPhoneDaemon.ts` waits a
  named 30s (`START_WAIT`), polled each 150ms, and ends the moment the lock shows; the live
  re-walk read `a daemon started (was down)`. 10s proved short too: at a load average of ~90 the
  acceptance case10 reply read `no daemon was seen to swim` for a daemon that then delivered it
- **a corrupt `phone.contacts.uses` meter could not be repaired with the tool**: `allow` and
  `block` read the meter first, so they threw on the same file they were meant to fix. fixed: the
  setter reads it as found (`unreadable`) and overwrites it; every gate still fails loud on it,
  and the error now names the cure. acceptance case2 [t2] corrupts the meter, reads the
  malfunction, repairs it with `block` (`state: unreadable → blocked`), and reads it back
- **peer review i001 found render and coverage gaps**, each fixed:
  - `phone.daemon set` UNCONFIRMED printed a bare root under a malfunction; it now reads
    `🦫 bummer, the daemon never showed` / `💥 MalfunctionError: ...` and its tree
  - `phone.text set` with no peer printed a bare root; it now names `naught sent; no peer was named`
  - an address refusal listed the accepted forms but not its fault; it now names it
    (`fault: the clone key takes a bare name: clone=director, not clone=@:director`, an empty
    clone, an absent scheme, a bad key set)
  - a `phone.contacts.uses` re-run printed `allowed → allowed`; it now reads `allowed (unchanged)`
  - acceptance masked every text as one `<text>`; it now masks by position, `<text1>`, `<text2>`,
    across every step, so a reply's `re <text1>` links to the text it answers
  - acceptance had no journey for `phone.text get --text` / `del --text` by a real clone; case11
    [t3] now sends, reads by alias, withdraws, re-withdraws, and proves the text is never said
  - acceptance had no step for a `phone.contacts.uses` re-run or a corrupt meter; case2 [t2] now
    covers both (the corrupt meter exits 1, `💥 MalfunctionError`, and names the file)

### exit codes, by design

`phone.text set` exits 0 when no daemon was seen (UNCONFIRMED); `phone.daemon set` exits 1. the
asymmetry is deliberate: the send's own act, a durable QUEUED record, succeeded, and its output
names the cure (`start one: rhx phone.daemon set`); the daemon set's own act, a live daemon, did
not.
