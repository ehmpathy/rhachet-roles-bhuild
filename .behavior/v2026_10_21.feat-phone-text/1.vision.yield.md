## .the outcome world

### before

- a director reaches a crew only via `git.crew.send`: a keystroke typed into the crew's tmux pane.
  it races the human's own typed text, it lands in a modal, and the commander will not keep it.
- a crew cannot reach its director at all. one crew wrote an asks file and hoped.
- `rhx clone say` is two-way but stops at one tree's `.agent/.actors/`, and each caller must
  hand-build the exchange.

### after

- a director texts its crew mechanic in another tree with one verb, and goes back to work:

  ```sh
  rhx phone.text set --to phone://grove=local/tree=svc-lessons.beav.feat-book-a-lesson/clone=mechanic --what 'where is book-a-lesson?'
  ```

- the text is a file in the director's tree. a per-tree daemon hands it to the mechanic over
  `rhx clone say`. it lands as the next message in the mechanic's session, signed, with the exact
  reply command. no pane keystroke, no human relay.
- the mechanic replies with the same verb. the reply lands in the director's session — that is
  the notification — and in the director's mailbox, beside the text it answers.
- every text and reply is a file under `.agent/.cache/repo=bhuild/role=dispatcher/skill=phone.text/`
  in each tree it touched: in write order, named by uuid, marked DELIVERED once, readable as the
  audit trail.

### a day in the life

first, a director boots three crews; each boot grants contacts both ways. second, the svc-lessons
mechanic hits a judgment call and texts `@:foreman` in its own tree; the foreman, mid-turn, reads it
when its turn ends and answers. third, coachbook changes a slot shape; the director sends one group
text to all three crews, and three replies come back. last, a crew says "i warned the foreman"; the
director opens the crew's mailbox and reads text a1b2c3d4, DELIVERED.

### the aha

the crew can **answer**. the director stops its reach into panes, and the crew stops its notes on
disk that nobody reads. the conversation is the record.

## .the contract

the phone is three nouns, each with get · set · del:

| noun | set | get | del |
|---|---|---|---|
| `phone.text` | send a text (async) | the thread, or one text via `--text` | withdraw a text still QUEUED |
| `phone.contacts` | grant a peer | who this clone may reach | revoke a peer |
| `phone.call` | place a call (sync) | the call log | hang up |

`phone.call` is not in this delivery; it stays a caught dream, and the noun is reserved for it.

### phone.text

```sh
rhx phone.text set --to <address> [--to <address> ...] --what <text|@stdin> [--re <uuid>]
rhx phone.text get [--text <uuid>]   # this clone's thread: every text in and out, status, reason
rhx phone.text del --text <uuid>     # withdraw a QUEUED text; a DELIVERED one can not be unsaid
```

- a text has one name: a **uuid**, minted at send and shared by its `out` copy and every `in` copy.
  the same text reads `7f3e9a02` in every mailbox, every view, every hint
- a reference takes the uuid's first 8 chars (`7f3e9a02`) or the full uuid, and naught else. a
  number is refused, exit 2, and the refusal shows the alias form. an 8-char alias that matches two
  texts in one mailbox is refused; the refusal lists both by full uuid
- no auto-incremented id names a text: an ordinal is easy to mistype into a valid neighbor, and it
  differs per mailbox. the mailbox keeps one internal ordinal in each file name, for order alone; no
  view prints it and no flag accepts it
- texts are **per clone**: each clone sends from, reads, and withdraws in its own mailbox alone. two
  clones in one tree never see each other's texts (F12)
- `--to` repeats for a group: one record per peer, one group id, all-or-none admission
- `--re <uuid>` links a reply to the text it answers; `--text <uuid>` names the text a `get` or
  `del` targets (F9)
- a peer is admitted if it is one of this clone's contacts, a clone in this tree, or the sender of
  an `in` text in this clone's mailbox (an inbound text proves this clone was made aware of it)
- returns at once with each text QUEUED; findserts the tree's daemon if none holds the lock
- on a terminal failure (REFUSED, FAULTED) the daemon says a notice into the sender's own clone,
  so an async failure is loud, not merely on record
- must run inside an enrolled clone (sender = this tree + `clone whoami`: its serial keys the
  mailbox; its slug, when it has one, names it in the address)
- `del` withdraws only a QUEUED text, which settles WITHDRAWN and is never said. a DELIVERED,
  REFUSED, or FAULTED text is already settled; `del` on it fails loud (exit 2). a second `del` of a
  WITHDRAWN text is a no-op

### phone.contacts

```sh
rhx phone.contacts get                       # this clone's contacts + own tree, with reach state
rhx phone.contacts set --address <address>   # grant; idempotent
rhx phone.contacts del --address <address>   # revoke; idempotent, no-op if absent
```

- a contact is its address, in the full form. the address's grove and tree are checked at grant
  time (the lookup `crewwork` already does), and refused loud if absent
- contacts are **per clone** (F12): a grant always changes the contacts of the clone it runs as,
  and only that tree's meter gates it. no flag points a grant at another clone or another tree
  (F11): a booter grants each seat in that seat's own boot, and a director grants its own in its
  own shell. a seat left out of the boot grant cannot reach out — a gap a `get` shows at once
- `get` is open to every clone. `set` and `del` are gated by the meter below

### phone.contacts.uses

```sh
rhx phone.contacts.uses allow | block | get     # human only (a tty, or __I_AM_HUMAN=true)
```

- the meter decides whether the clones of a tree may manage their own contacts; state in
  `.meter/phone.contacts.uses.jsonc`, the `radio.uses` pattern
- **blocked by default, always**, for every clone, every role. unset reads as blocked
- a director gets the grant from its own boot hooks, which run `phone.contacts.uses allow` beneath
  the clone. no role is allowed by detection
- a human (or a boot verb run beneath the clone) may always `set` / `del`, whatever the meter says
- a blocked `set` or `del` from a clone fails loud (exit 2) and names who may lift it

### phone.daemon

```sh
rhx phone.daemon get | set | del       # one per tree, held by a lock; set finds the live daemon or starts one
```

- one daemon serves every clone mailbox in its tree; the meter, too, is per tree. only texts and
  contacts are per clone

### the address

```
phone://grove=<grove>/tree=<tree>/clone=<clone>    # the full form: every stored address, every hint
phone://grove=local/tree=<tree>/clone=<clone>      # input only: `local` = this grove
@:<clone>                                          # input only: a clone in one's own tree
```

- the keys come in one fixed order — grove, tree, clone — so a peer has exactly one written form,
  and contacts compare by string. any other order is refused, and the refusal prints the canonical
  form (F2)
- `clone=` takes the clone's slug (`clone=mechanic`), or, for a clone with no slug, its full serial
  (`clone=4c1e8b27-…`) — the same two names rhachet's `@:<slug|serial>` takes. on input, `@:` and
  the 8-char short serial rhachet prints (`@:4c1e8b27`) are accepted, looked up, and refused if two
  clones match; a stored address or hint always holds the slug or the full serial, never the short
  one. admission looks up each address's clone serial before it compares, so a clone that
  gains a slug later is still the same contact (F10, F12)
- `@:` is rhachet's shell shorthand for a clone in one's own tree; it is never part of a stored
  address (F10)

three grains, one canonical word each (`.agent/repo=.this/role=any/briefs/define.grains.grove-tree-clone.md`):

- **grove** — where a tree runs: a name `rhx git.grove.list` knows, or `local`
- **tree** — a worktree, by its dir name (`svc-lessons.beav.feat-book-a-lesson`); unique on its
  grove, so it already pins the repo and the branch
- **clone** — an enrolled actor in that tree, by its slug (`mechanic`), or by its serial when it has
  no slug. each clone holds its own mailbox and contacts

`local` is relative — on a remote grove it means that grove — so before an address is written into
a record or printed in a hint, `local` is cast to this grove's own name. every grove a phone runs
on therefore has a name, the director's own laptop included (`bert-laptop` in the examples): the
registry name where one is registered, else the hostname.

no org, no repo, no branch in the address: a tree names all three. the grains are the ones the
supervisor's duct uri names, so a human reads one vocabulary across both.

three reaches, one verb:

| reach | how the daemon says it | how the `in` copy lands |
|---|---|---|
| same tree | `rhx clone say` from this tree | a local write |
| cross-tree, same grove | `rhx clone say` run from inside the peer tree | a local write into the peer tree |
| cross-grove | the same, over the grove's ssh alias (the tunnel `git.grove.wake` opens) | over the same ssh, content on stdin, never parsed (the `git.grove.send --file` discipline) |

### the reply leg across a grove — the side with the tunnel pulls

a tunnel opens one way: the director's grove reaches the remote grove; the remote grove has no
route back. so the daemon on the side that holds the tunnel does both legs:

- **push** — it says this tree's QUEUED texts into remote peers
- **pull** — on each tick it reads the remote peers' mailboxes for texts addressed to this tree,
  says each into this tree's own clone, writes the local `in` copy, and marks the remote copy
  DELIVERED

a remote clone that texts a peer on the tunnel holder's side just writes its text QUEUED with
reason `awaits pull from <grove>`; it never needs a route out. the reply still lands in the
sender's session, so the sender is still notified.

a grove whose tunnel is down: the text stays QUEUED, reason `grove unreached`, and
`phone.text get` names the cure, `rhx git.grove.wake <grove>`. never dropped, never FAULTED for a
tunnel the next wake repairs.

### the mailbox

scoped **per clone**: each clone has its own mailbox and its own contacts, keyed by its serial
(rhachet's `serial=<serial>` grain; a slug is a name for a serial). the daemon is per
tree, and serves every clone in it.

```
.agent/.cache/repo=bhuild/role=dispatcher/
  ├─ skill=phone.text/
  │  └─ clone=<serial>/
  │     ├─ text.0001.out.json   { uuid, way: out, group, re, from, to, what, status, reason }
  │     └─ text.0002.in.json    { uuid, way: in,  ... the copy a peer delivered here }
  ├─ skill=phone.contacts/
  │  └─ clone=<serial>/
  │     └─ contacts.json        [ full-form addresses ]
  └─ skill=phone.daemon/        (lock + log, one per tree; never a text)
```

the `0001` in a file name is a storage ordinal, for order alone: no view prints it, no flag takes
it. it is claimed by an exclusive create of the file, so two writers in one mailbox that race for
the same ordinal cannot both win, and the loser takes the next. two `phone.text set` calls at once,
or a `set` beside a daemon that writes an `in` copy, never collide and never reorder.

status, reused from the radio's record vocabulary plus two:

| status | sense | retried by the daemon? |
|---|---|---|
| QUEUED | written, not yet said; `reason` names why it waits | yes |
| DELIVERED | `clone say` returned `released` or `enqueued` | never again |
| REFUSED | the peer cannot exist (no clone answers to that slug in that tree) | no |
| FAULTED | rhachet could not confirm the say (`buffered`, `absent`, `unreadable`, wedged); a resend could duplicate | no — the sender decides |
| WITHDRAWN | the sender ran `phone.text del` while it was QUEUED; never said | never |

how each `clone say` outcome maps:

| rhachet outcome | phone status · reason |
|---|---|
| `released`, `enqueued` | DELIVERED |
| `withheld` · `modal-holds-focus` | QUEUED · peer at a modal |
| `withheld` · `input-region-dirty` | QUEUED · peer input box holds typed text (never `--force`) |
| `withheld` · `focus-unrecognized` | QUEUED · peer screen unrecognized |
| reach DEAD or DEAF | QUEUED · peer clone is dead |
| `no clone answers to` | REFUSED |
| `buffered`, `absent`, `unreadable`, wedged, exited-mid-dispatch | FAULTED · rhachet's own reason |

## .mental model

- **to a friend**: "the crews have phones now. the director texts a crew, the crew texts back. it's
  all in a log."
- **analogy**: sms with an address book. the radio is a bulletin board anyone may read and claim;
  the phone is a text to a person whose number you were given.
- **their words vs ours**: users say "message the mechanic", "buzz the director". we say `text`
  (async) and keep `call` for the synchronous future. `contacts` is the address book. `socket` stays
  rhachet's word for the channel beneath; `phone` is the dispatcher's word for what travels over it
  (boundary-qualified `term=dispatcher.phone`, per #491).

## .evaluation

### goals

| want (from the wish) | met by |
|---|---|
| `phone.text` async, one-to-one and group | `--to` repeats; one record per peer, one group id |
| `phone.contacts` | `get` / `set` / `del`, each by `--address`; `phone.contacts.uses` gates self-management, blocked by default |
| only a contact or own-tree clone; unknown refused loud, names how to add | `case=4`; exit 2, lists reachable peers, prints the grant command |
| contacts at boot; crew reaches director; director reaches crews | `case=7`; granted both ways at boot |
| every text a file under `skill=phone.*`; durable, ordered, once, auditable | one mailbox per clone; write order, uuid identity; DELIVERED is terminal |
| daemon delivers over `clone say`; reply same way; sender notified | per-tree daemon; reply lands in the sender's session + mailbox |
| peer cannot take it: queued or fails loud with the reason, never dropped | the status map; `case=5` |
| no keystroke into a peer terminal; no broadcast; no `phone.call` | `clone say` only, never `--force`; one address per record; call is a dream |
| critical path demoed in a test | `case=1`, as an integration test with two real trees and real clones |

### pros

- the paved path rides on rhachet's own reach (socket + pty), which already refuses modals and a
  dirty input box — the phone inherits that safety for free
- the file is the queue, so a dead daemon or a reboot loses no text
- each clone's mailbox reads as its own full thread, in and out; no seat reads another's
- one address names a peer on any grove; the grains match the supervisor's

### cons

- cross-tree reach means the phone must run `rhx clone say` from inside the peer's tree (see
  fulcrum F1). this is the one spot that bends `rule.forbid.cwd-override`
- cross-grove reach leans on a live tunnel, and the reply leg on a pull from the tunnel holder
- delivery needs a daemon per tree: one more process to keep alive
- FAULTED texts need a human or sender to decide; rare, but not automatic
- per-clone contacts mean a boot grants each seat on its own; a seat left out is mute until
  granted (F12)

### pit of success

- all-or-none group admission: a typo never yields a half-sent group
- one canonical address form: keys in a fixed order, `local` cast before it is written, so a peer
  is never two contacts and a hint never names the wrong grove
- a text named by uuid in every hint that crosses trees, so a reply never links to the wrong text
- an 8-char alias that matches two texts is refused, never guessed
- a number never names a text, so a typo of one digit can not hit a valid neighbor
- the phone never passes `--force`, so a text never fuses with a human's half-typed turn
- one daemon per tree via a lock, so delivered-once holds under a double start

## .what is awkward

- **cwd into a foreign tree.** the only path to cross-tree reach today is to run rhachet from the
  peer's tree. it is correct and contained, but it bends a repo rule. the real fix is upstream
  (`clone say --repo <dir>`); caught as a dream.
- **the reply leg across a grove is a pull.** a remote clone's reply waits until the tunnel holder's
  daemon ticks. delivery is sure, but it is not instant, and a closed tunnel holds it until a wake.
- **`--text` on a noun named `phone.text`.** `phone.text del --text a1b2c3d4` reads a touch doubled;
  it buys one flag name per argument (F9).
- **a uuid to type.** a reply or a withdraw names 8 hex chars where a small number would be shorter.
  the cost is a copy from the hint; the gain is that a slip can not name a neighbor.
- **a grant per seat.** with contacts per clone, a crew boot grants the mechanic and the foreman on
  their own. it is two lines in the boot hook, and a seat left out is mute until granted (F12).
- **the meter trusts the human check.** a clone may lift `phone.contacts.uses` only if it can pass
  as human (a tty, or `__I_AM_HUMAN=true`). the boundary is as strong as that check — the same as
  `radio.uses` and `git.commit.uses`.
- **FAULTED needs judgment.** at-most-once beats a duplicate, but it leaves a rare text that a
  sender must look at. it is loud in `phone.text get`, never silent.
