# case=1 — the size gate refuses, then spends a grant once

**feel:** sharp → happy · **care:** critipath (every sprout crosses it; a wrong size costs a human a re-size)

## .narrative

the supervisor clone in `sandpine/svc-lessons` reads a wish for lesson-reminder sms and judges it
needs a `mini` behavior. it asks the tree to sprout at `mini`. the sprout is refused at once: size
`mini` needs a human grant, and the error prints the exact command the human should run. the clone
relays it. bert types `! rhx git.tree.size.uses allow --name beav/feat-lesson-reminders --size mini --approval 'ok, mini'`
at his claude prompt — a `!` command runs with no tty, so his own words ride along as `--approval`.
(at a real terminal, the bare `allow` serves.)
the clone retries and the sprout lands at `mini`. a second `mini` sprout on the same name is
refused again — the grant bought one sprout, and it is spent.

## .timeline (sketch)

```
given a published supervisor in a consumer repo, no grants on record
  when [t0] the clone runs `rhx git.tree.init behavior --name beav/feat-lesson-reminders --size mini`
    then it exits 2 with `✋ size 'mini' is above nano, and no human has granted it for '…'.`
    then the error names `! rhx git.tree.size.uses allow --name … --size mini`
    then the error cites `rule.forbid.sprout-above-nano-without-a-human-grant`
    then no tree is sprouted
  when [t1] the human runs `rhx git.tree.size.uses allow --name beav/feat-lesson-reminders --size mini` at a real terminal
    then `.meter/git.tree.size.uses.jsonl` holds one grant for that name + size
  when [t1*] the human runs the same `allow` at their claude prompt, as `! rhx … --approval '<their words>'`
    then the `!` command has no tty, so the bare form refuses and names `--approval`
    then with `--approval`, the grant lands and records their words verbatim
  when [t1'] the clone runs the same `allow` from its own shell
    then claude code refuses it by the supervisor's permissions deny
    then even where the deny is absent, off a tty `allow` refuses: a size grant needs a human — at a terminal, or their words via `--approval '<their exact words>'`
    then with `--approval`, the grant records those words verbatim, so every grant says whose words opened it
  when [t1''] the clone tries to write `.meter/git.tree.size.uses.jsonl` directly
    then claude code refuses the Edit/Write by the same deny
  when [t2] the clone retries the sprout at mini
    then the tree sprouts at mini
    then the grant is spent
  when [t3] the clone sprouts mini on that name again
    then it is refused, as at [t0]
  when [t4] the clone sprouts at nano
    then it sprouts with no grant asked
```

## .fails safe

the refusal is fast (before any tree work), loud (exit 2, ✋ glyph on stderr), and teaches the
fix (the copy-paste grant command). the wording is the source's, kept verbatim so the next delta
applies cleanly — only the verb moves to `git.tree.init behavior` (F7); the source's header carries the ✋ glyph without the `ConstraintError:` word that
`rule.require.qualified-error-headers` asks for — a gap to raise upstream, not to fork here. two walls stand between a clone and a self-minted grant:

1. **the permissions deny** — new in the package (F6, ruled by the wisher). the supervisor's
   `inits/init.claude.permissions.jsonc` denies the clone `allow` / `revoke` and any Edit/Write on
   the meter file. nheuron's header claimed this deny, but no tracked file there declares it
   (its `settings.json` was deleted in `ee30458`)
2. **the tty guard** — kept from the source. off a tty, `allow` demands the human's verbatim words
   and records them, so an invented grant is a visible fabrication, not a shortcut

the header's stale claim is corrected to name the deny that now exists.
