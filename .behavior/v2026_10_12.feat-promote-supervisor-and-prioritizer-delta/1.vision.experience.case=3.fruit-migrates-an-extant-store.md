# case=3 — an extant pre-fruit store migrates with no row lost

**feel:** happy (sharp risk) · **care:** critipath (a lost row is a lost priority — irreversible for a human's queue)

## .narrative

bert upgrades the package. his `.eco/` store was written before fruit existed: 116 priority rows
in `priority.csv`, mirrored into `priority.db`. the next `eco.priority get` opens the store, adds
the `fruit` and `fruit_why` columns, leaves them empty, and renders all 116 rows as before — each
now shows 🍃 unsized where it holds a cash gain. a second open changes naught.

## .timeline (sketch)

```
given a copy of nheuron's own store at d121127 (116-row priority.csv, no fruit columns)
  when [t0] the published `eco.priority get --output json` reads it
    then the db has columns `fruit` and `fruit_why`, both null on every row
    then the row count is 116, same as before
    then every pre-extant column value is byte-equal to before
    then the csv mirror header ends `…,set_at,fruit,fruit_why`
  when [t1] it reads the store again
    then no schema change occurs and the rows are unchanged
  when [t2] the clone runs `rhx eco.priority set --slug <a cash row> --fruit low`
    then that row reads fruit=low; all other rows are unchanged
  when [t3] the migration is interrupted after `fruit` is added but before `fruit_why`, then re-run
    then only `fruit_why` is added, and `fruit` and every row are untouched
  when [t4] the clone runs `rhx eco.priority set --slug <a cashless row> --fruit low`
    then it is refused: record the cash gain first; the row is unchanged
```

## .fails safe

the migration is additive (`ALTER TABLE … ADD COLUMN`, nullable) through the store's extant
column list, so it cannot drop data. `setSchemaMigrated` asks `PRAGMA table_info(priority)` for the
columns held and adds only the absent ones — no version number to drift, so an interrupted run
resumes by construction ([t3]).

## .two proofs, two homes

| proof | input | where it lives | why |
|---|---|---|---|
| **the wish's proof** | a copy of nheuron's own store at `d121127` | out of tree (`.temp/`, gitignored); the yield records row counts and per-column checksums before/after, never a row | 67 of its 116 rows name a private term — a committed copy would ship the operator's queue |
| **the package clamp** | a synthetic pre-fruit store, sandpine rows, same column set as `d121127` | a new case in the published `ecowork.migrate.integration.test.ts` | keeps the migration green on every future run, with no private data |

the first proves it works on the real thing once; the second keeps it from regressing.
