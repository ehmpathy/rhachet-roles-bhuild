# case=2 — list a repo's trees from a consumer repo

**feel:** happy · **care:** critipath (the only paved answer to "which trees exist for repo X?"; its absence sent a supervisor to the wrong axis)

## .narrative

a supervisor clone runs in a repo that installed `rhachet-roles-bhuild` and holds no
`.agent/repo=.this/`. bert asks which trees exist for `sandpine/svc-lessons`. the clone runs
`rhx git.tree.list --in svc-lessons` (the filter is `--in`; `--repo` is rhachet's own reserved
flag and would resolve the skill against another repo) and sees every local worktree of that repo — the crewed ones and the crewless
one a ledger would never show. it answers in one call.

## .timeline (sketch)

```
given a consumer repo with the published supervisor linked and no `.agent/repo=.this/`
  given two worktrees of sandpine/svc-lessons on this box, one crewed, one not
  when [t0] the clone runs `rhx git.tree.list --in svc-lessons`
    then both trees are listed
    then the crewless tree is marked `crew: (none)`
    then no path under `.agent/repo=.this/` is read
  when [t1] the clone runs `rhx git.tree.size.uses get`
    then it reports the grants on record (none) and exits 0
```

## .why this cell covers `R=source-like` too

seven code files in the delta name `repo=.this`. each is rewritten to the package path, as the lift
did. if case 2 passes from a repo with none, no skill leans on the source's local tree.
