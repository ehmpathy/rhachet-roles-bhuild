## .what I tried

1. **read the keyrack** — `rhx keyrack status --owner ehmpath` lists 15 keys; none is
   `EHMPATH_BEAVER_GITHUB_TOKEN`, in any env
2. **ruled out a self-inflicted cause** — this branch modifies `.agent/keyrack.yml` (the boot
   upgrade, F5). `git diff origin/main -- .agent/keyrack.yml`: the key is still declared under
   `env.test` and `env.prep`; only `extends` grew and a note dropped (now restored). the absence is
   the host's, not the declaration's
3. **ruled out this branch's code** — the three suites live in `src/domain.operations/radio/auth/`
   and `blackbox/role=dispatcher/`; this branch touches neither
4. **considered `--auth as-human`** — the suites assert the robot path (`ghs_*` tokens via the
   keyrack) by design; to swap the auth would change what they test, which the stone forbids
5. **considered the human keyrack** — forbidden: without `--owner ehmpath` the keyrack hits the
   human's yubikey
