# case=2 — `as-ehmpath` refuses a human's ambient login

feel: sharp · care: critipath (the safety bound: never act as a human under an ehmpath label)

## .narrative

bert runs a clone on his own laptop. keyrack is locked, and his gh login is his own. the clone pushes with `--auth as-ehmpath`. keyrack misses; the ambient email reads `bert@example.com`, not ehmpath. the skill refuses: it names both spots it checked, what each held, and two fixes — unlock the robot token, or push as bert on purpose with `--auth as-human`. the push is held, never lost, and never sent under bert's name by surprise.

## .timeline (sketch)

```
given('a box whose keyrack holds no granted ehmpath token')
  given('git config user.email is bert@example.com, and gh is logged in as bert')
    when('[t0] rhx radio.task.push ... --auth as-ehmpath')
      then('exit 2, and the push is held QUEUED')
      then('the held-push block reads:')
           ├─ status  = QUEUED (upstream:auth)
           └─ fix it: ✋ ConstraintError: --auth as-ehmpath found no ehmpath token
              ├─ checked
              │  ├─ keyrack: not granted (status: locked)
              │  └─ ambient: git config user.email = bert@example.com, not an ehmpath email
              ├─ unlock the robot token: rhx keyrack unlock --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env prep
              └─ or send as yourself, on purpose: --auth as-human
      then('gh auth token is never read for the send; no token from bert is used')
```
