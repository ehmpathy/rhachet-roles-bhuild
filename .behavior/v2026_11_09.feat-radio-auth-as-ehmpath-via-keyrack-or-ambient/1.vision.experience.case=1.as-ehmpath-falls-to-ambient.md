# case=1 — `as-ehmpath` falls to the ambient ehmpath login

feel: happy (+ one sharp alterpath) · care: critipath (the reason the wish exists)

## .narrative

a clone runs on a fresh box. its keyrack holds no beaver token yet, but the box is logged into gh as the clone's own account, and git config names the clone's ehmpath address. the clone pushes a task with `--auth as-ehmpath`. keyrack misses; the skill reads the ambient identity, sees an ehmpath email, takes the gh login's token, and the issue lands. the output names which spot supplied the token, so the clone knows keyrack was skipped.

on a box with the same ehmpath email but no gh login yet, the same push is held: the miss names keyrack's status, then "gh login: none", and the fix is `gh auth login`.

## .timeline (sketch)

```
given('a box whose keyrack holds no ehmpath token')
  given('git config user.email is an ehmpath email, and gh is logged in')
    when('[t0] rhx radio.task.push --via gh.issues --into sandpine/svc-lessons --title "book-a-lesson reminder" --description "..." --auth as-ehmpath')
      then('keyrack is checked first, and misses')
      then('the ambient gh token is used')
      then('the issue is created')
      then('the output adds one line: auth = as-ehmpath (via ambient)')
  given('git config user.email is an ehmpath email, and gh holds no login')
    when('[t1] the same push')
      then('exit 2; the push is held QUEUED (upstream:auth)')
      then('the fault reads:')
        └─ fix it: ✋ ConstraintError: --auth as-ehmpath found no ehmpath token
           ├─ checked
           │  ├─ keyrack: not granted (status: absent)
           │  └─ ambient: ehmpath email, but gh holds no login
           ├─ log in on this box: gh auth login
           └─ or set the robot token: rhx keyrack set --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env prep
```
