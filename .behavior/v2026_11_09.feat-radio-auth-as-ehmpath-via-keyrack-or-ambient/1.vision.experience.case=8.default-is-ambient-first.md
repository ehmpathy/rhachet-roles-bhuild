# case=8 — the no-`--auth` default sends as the box's own identity

feel: happy + sharp · care: critipath (the default is the send most callers make: it must pick the right identity unasked, and say which)

## .narrative

a clone on its own box pushes with no `--auth`. the ambient email is its ehmpath address and gh holds its login, so the push sends under that login and names the source: `auth: as-ehmpath (via ambient)`. keyrack is never read, even if it would grant.

bert runs the same command on his laptop. his email is `bert@example.com`, so the push sends as bert, and the output says so: `auth: as-human (via ambient email bert@example.com)`. no send leaves a box under an identity the output does not name.

bert's gh is logged out on another day. the push does not reach gh and fail there; it misses at once with the fix: log in with `gh auth login`, or name the robot on purpose with `--auth as-ehmpath-via-keyrack`.

## .timeline (sketch)

```
given('a box whose git email is an ehmpath one, and gh holds its login')
  when('[t0] rhx radio.task.push ... (no --auth)')
    then('the push sends under the gh login; keyrack is never read')
    then('the output names the source:')
         ├─ auth: as-ehmpath (via ambient)

given('a box whose git email is bert@example.com, and gh holds bert login')
  when('[t1] rhx radio.task.push ... (no --auth)')
    then('the push sends as-human, and the output names it:')
         ├─ auth: as-human (via ambient email bert@example.com)

given('a box whose git email is bert@example.com, and gh holds no login')
  when('[t2] rhx radio.task.push ... (no --auth)')
    then('exit 2, held QUEUED (upstream:auth), with the fix:')
         └─ fix it: ✋ ConstraintError: the default auth (no --auth) reads a human email (bert@example.com), so it sends as-human; but gh holds no login
            └─ hint: gh auth login, or --auth as-ehmpath-via-keyrack
```
