# case=5 — a held `as-ehmpath` record replays on drain

feel: happy + sharp · care: critipath (a held push is never lost, never stuck, and never sent under a human by surprise)

the densest walk: held record × stored replay × keyrack × ambient × email bar, in one drain.

## .narrative

a clone pushed with `--auth as-ehmpath` while radio was blocked, so the push was held. later radio is allowed, and the clone drains on its fresh box, where keyrack holds no token. the drain reads the stored auth; `as-ehmpath` names a mode, never a command, so a drain may replay it. keyrack misses, the ambient email is ehmpath, the gh login pays, the record is delivered.

the same record, merged onto bert's laptop and drained there, meets bert's email. it stays held, and `queue get` names the miss and its fix — it is never sent under bert's login.

a human can also amend a held record onto a new value: `queue set --uuid <uuid> --auth as-ehmpath-via-keyrack`.

## .timeline (sketch)

```
given('a record held QUEUED with auth as-ehmpath')
  when('[t0] rhx radio.task.queue get')
    then('the row shows auth: as-ehmpath')
  given('a box whose keyrack misses; ambient email ehmpath; gh logged in')
    when('[t1] rhx radio.task.queue drain')
      then('keyrack is checked, then ambient')
      then('the record is delivered, auth = as-ehmpath (via ambient)')
  given('a box whose keyrack misses; ambient email bert@example.com')
    when('[t2] rhx radio.task.queue drain')
      then('exit 2; the record stays held')
      then('its fault names keyrack status, the ambient email, and the two fixes')
      then('gh auth token is never read')
given('a record held with auth as-human')
  when('[t3] rhx radio.task.queue set --uuid <uuid> --auth as-ehmpath-via-keyrack')
    then('the record now stores as-ehmpath-via-keyrack')
```
