# case=4 — `as-ehmpath-via-ambient` refuses a non-ehmpath identity

feel: sharp · care: critipath (the explicit ambient value must hold the same bound)

## .narrative

bert types `--auth as-ehmpath-via-ambient` on his laptop, as a guess. git config names `bert@example.com` (or no email at all). the skill refuses before it reads gh: the ambient spot only ever counts as ehmpath when its email is an ehmpath one. the error names the email it saw and the two fixes.

## .timeline (sketch)

```
given('git config user.email is bert@example.com')
  when('[t0] rhx radio.task.push ... --auth as-ehmpath-via-ambient')
    then('exit 2')
    then('the held-push block reads:')
         ├─ status  = QUEUED (upstream:auth)
         └─ fix it: ✋ ConstraintError: --auth as-ehmpath-via-ambient found no ehmpath token
            ├─ checked
            │  └─ ambient: git config user.email = bert@example.com, not an ehmpath email
            ├─ use the robot token instead: --auth as-ehmpath-via-keyrack
            └─ or send as yourself, on purpose: --auth as-human
    then('keyrack is never read; gh auth token is never read')
given('git config user.email is unset')
  when('[t1] rhx radio.task.push ... --auth as-ehmpath-via-ambient')
    then('exit 2, and the push is held QUEUED (upstream:auth)')
    then('the checked row reads: ambient: git config user.email unset')
    then('the same two fixes follow; keyrack and gh auth token are never read')
```
