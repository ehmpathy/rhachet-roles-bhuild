# case=6 — classifiers land with their fixtures

> **actor** = `system` (the babysit cron — no human present) · **goal** = `supervise`
> **cells** = 25, 26 (`system × supervise × {origin, consumer}`), sharp leg
> **latent axis** = `has-fixtures?` · **feel** = sharp · **care** = critipath

## .the narrative

a babysit tick runs unattended. it polls every crew, reads each pane, and classifies what it
sees: is this box live, or a husk? is that a cap under compaction, or a fresh one? is this a
picker, or a real input box? every verdict drives an act — a nudge, a reboot, a fell.

`git.crew.poll.sh` is **5,828 lines**, and every pane classifier lives in it. the classifiers are
not hard because the logic is deep. they are hard because a terminal pane is a **verbatim
artifact** with no schema — scrollback bleeds through, a crash leaves stale ui, a compaction
rewrites a date, an option-2 line loses the space after its dot.

`work/.test/.assets/` holds **56 fixture files**, of which **51 are captured panes** (named
`pane.*`). each pane is a real production capture taken with `--raw`, clamped against the verdict
the tick relied on. they encode every way the readers have been wrong:

> husks under stale scrollback · v8-OOM with no exit badge · ghost boxes read as inflight ·
> date-qualified caps under compaction · pickers read as live boxes · option-2 that loses the
> space after its dot

🔴 **every one of those is a bug that already shipped once.** the fixture is the clamp that keeps
it shipped-once.

the sharp edge: a lift that ports 5,828 lines of classifier and leaves a dot-directory of `.log`
files behind will **pass its own test suite** — the tests that reference the fixtures go with
them or fail loudly. the danger is subtler: a partial carry, or a rename. each fixture is named
for the **state** it captures, never for the tree it came from, so none of them go stale — and
that convention is what an eager tidy-up would "improve".

⇒ **the aha**: the classifiers are not the asset. the **56 fixtures** are. the code is a hypothesis;
the fixtures are the evidence that the hypothesis was wrong six specific ways, and got fixed.

## 🔴 .how it fails safe

⚠️ **`[t2]` is not the guard.** a suite that iterates a fixture dir asserts only the fixtures it
finds — so a lift that drops half of `.test/.assets/` yields a suite with half the cases and a
**green** result. the drop is invisible to exactly the test built to catch it.

⇒ so the fail-safe is a **floor on the corpus**, asserted beside the classifier suite:

```gherkin
[t7] given the classifier suite globs work/.test/.assets/
     when it asserts the fixture COUNT before it asserts any verdict
     then the SUPERVISOR floor is met (55 files, 51 pane.*)   ⛔ SUPERSEDED → 56
     and the PRIORITIZER floor is met (1 file, the eco fixture) ⛔ → 0
     and 55 + 1 = the 56 measured at source — no fixture lost to the split
     and the failure names the count found and the count owed
     ⇒ fast (runs with the suite) · loud (red) · teaches the fix (a number pair, one glance)
     ⇒ 🔴 the SPLIT is refuted; the SECOND AXIS is not. a corpus-wide total
       cannot see a cross-role move, because a move conserves it. so the
       per-role census stays — at 56/0. see below
     ⇒ ✅ SHIPPED — `testFixtures.integration.test.ts` [case1] + [case2]

[t8] given `git.grove.saturation.integration.test.ts` sits BESIDE the skills, not in work/
     then the port glob is asserted to have carried it too
     ⇒ 🔴 this names ONE outlier and there are TWO.
       `prioritizer/skills/eco.seed.integration.test.ts` wears the identical
       shape — outside work/, invisible to a work/-scoped glob, and unnamed
       here. ⇒ [t4]'s "the only test outside that dir" is false
     ⇒ so the guard grades the CLASS, never the instance: a census keyed on
       `inside work/ ?`, with the outside set enumerated BY NAME
     ⇒ ✅ SHIPPED — `suitesPorted.integration.test.ts`
```

🟡 the floor is a **lower bound, never an equality** — a later fixture added by
`rule.always.clamp-the-verbatim-pane-your-classifier-judged` must not turn the guard red. it guards
a loss, not a count.

## ⚠️ .the count, corrected

the handoff (§2.3, §7) says **53** pane fixtures. measured on `main` today:

| glob | count |
|---|---|
| `work/.test/.assets/*` | **56** |
| `work/.test/.assets/pane.*` | **51** |

neither is 53. the handoff's instruction — *"carry the whole `.test/.assets/` dir verbatim"* — is
correct and count-independent, so **follow the instruction, not the number**. the discrepancy is
reported rather than settled; see the yield's "where the handoff is off".

### 🔴 the split this section predicted did NOT happen — and the reason is the lesson

this section argued, at i003, that the 56 must split **55/1**: that
`eco.priority.get.truncated-body.log` is *"a **prioritizer** fixture parked in the supervisor's
asset dir"*, and must follow the prioritizer.

⛔ **that premise is false, and a peer reviewer refuted it at i002 of the execution stone.** the
implemented and accepted state is **56 / 0**:

| after the lift | floor | of which `pane.*` |
|---|---|---|
| `role=supervisor` `work/.test/.assets/` | **56** | 51 |
| `role=prioritizer` | **0** | 0 |

the fixture's **sole consumer** is `crewwork.integration.test.ts` `[case29]` — a **supervisor**
test of `__crew_eco_star_verdict`. the supervisor reads the prioritizer's stdout across a CLI
boundary (`case=2`'s whole thesis), and this fixture is a capture of exactly that read. so it is a
**supervisor fixture that wears a prioritizer-shaped name**.

⇒ 🔴 **the rule the refutation establishes, and the reason it is worth more than the count:**

> **a fixture belongs to whoever READS it, never to whoever it is named after.**

the i003 argument keyed on the **name** and reached a confident wrong answer. a census keyed on the
name would have moved the file away from the only suite that opens it — and the suite would have
gone red for a reason no message would explain.

⚠️ and the residue is the durable half: **`[t1]`/`[t7]` above still carry the 55/1 numbers.** they
are left in place deliberately, beside this correction, because the correction is the record. a
reader who trusts the `[tn]` over the test would "fix" a non-defect — which is the identical
failure mode this section warned of at i003, pointed the other way. ⇒ **a number restated in two
places has two chances to be wrong and one record of which copy was checked.**

🟡 what survived the refutation intact is the **shape** of the guard: a corpus-wide total is blind
to a cross-role move, because a move conserves the sum. so `testFixtures` ships **two** asserts —
`[case1]`'s ratchet on the total, `[case2]`'s exact census per role dir. the split premise was
wrong; the need for a second axis was not.
