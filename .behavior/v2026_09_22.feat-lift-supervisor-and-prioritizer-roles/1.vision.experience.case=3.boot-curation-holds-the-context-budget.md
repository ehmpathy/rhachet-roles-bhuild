# case=3 — the boot curation holds the context budget

> **actor** = `clone` (any seat that enrolls a lifted role) · **goal** = `learn` — get the concepts
> **cell** = 08 (`clone × learn × consumer`), sharp leg
> **feel** = sharp · **care** = critipath

## .the narrative

a clone opens in a consumer repo that enrolled both lifted roles. `rhachet` boots them.

the supervisor carries **275 brief files** and **46 skills**. the prioritizer carries **30**. if
the boot says all of it at full length, the session opens already spent — before the human has
typed a word.

**each half was measured separately, at source, in its own `boot.yml` header:**

| half | the uncurated boot | measured against |
|---|---|---|
| supervisor (`role=any`) | **159,698 tokens — 63% of a ~253k window** | 82 briefs + 33 skills |
| prioritizer | **65,049 tokens ($0.20)** | 22 briefs + 7 skills, 260,194 chars, 2026-09-14 |

⚠️ **the two do not share a figure, and i conflated them until this was checked.** a consumer that
enrolls **both** pays both — a floor of **~225k tokens**, which is not 63% of a 253k window but
close to the whole of it. ⇒ the combined case is worse than the headline number suggests, and the
sum is a **floor** rather than a total, since each was measured on a different date against a
brief set that has since grown.

`boot.yml` is what stops that. 284 lines for the supervisor, 142 for the prioritizer, and they
are not a config file — they are **argued curation**. a `say` allowlist of ~25 reflex briefs
(the ones that must be *loaded* to fire at the right moment) against a `ref` claim over the whole
glossary and every `*.reason.md` (the ones a clone can *look up* when it needs them). each `say`
entry carries its own argument for why it earns the slot.

the sharp edge is not that the file is hard to write. it is that the file **looks droppable**. it
is yaml, it is long, it lists paths, and a lift that re-creates the role dirs and forgets it will
pass every test in this repo — the tokens are spent in the *consumer's* session, not ours.

⇒ **the aha**: the expensive half of a role is not its code. it is the verdict about what a
session must already know versus what it can look up. that verdict took two years and it ports
unchanged.

## .the demo

```gherkin
[t0] given a consumer repo with role=supervisor and role=prioritizer enrolled

[t0b] then getSupervisorRole.ts DECLARES  boot: { uri: __dirname + '/boot.yml' }
      and  getPrioritizerRole.ts DECLARES boot: { uri: __dirname + '/boot.yml' }
      ⇒ 🔴 the file on disk is NOT enough — see "the second door" below

[t1] when a clone boots
     then rhachet reads src/domain.roles/supervisor/boot.yml
     and reads  src/domain.roles/prioritizer/boot.yml

[t2] then the SAY set is ~25 reflex briefs, said at full length
     ⇒ these must FIRE, not be found — a rule you look up after you broke it is not a rule

[t3] then the REF set covers the whole glossary and every *.reason.md
     ⇒ 70 term clusters + 139 term files, addressable and NOT loaded

[t4] then boot spend is a small fraction of the window
     — NOT 159,698 (supervisor) + 65,049 (prioritizer)
     and the clone has its context to work in

[t5] when `define.sprout-vs-seed` is consulted
     then it is in the SAY set, never the REF set
     ⇒ `#339` — the word that boots a tree must fire, not be looked up
```

### the negative leg — what a dropped curation looks like

```gherkin
[t6] given boot.yml was NOT ported (or was re-curated from scratch)
[t7] when a clone boots in a consumer repo
     then 305 brief files (275 supervisor + 30 prioritizer)
      and 48 skill entrypoints (46 supervisor + 2 prioritizer) are said at full length
     and the session opens near the WHOLE window spent
       — 224,747 of ~253k ≈ 89%, NOT the 63% the supervisor half alone costs
     ⇒ every consumer pays this, every session, and OUR test suite stays green
```

## 🔴 .the second door — a ported file that is inert

a port can be **perfect** and still do naught. `boot` is an **explicit field** on `Role.build`, not
a convention over the directory. measured in this repo today:

| roles with `boot.yml` on disk | roles that declare `boot:` |
|---|---|
| behaver · decomposer · dispatcher · dreamer (**4**) | behaver · decomposer (**2**) |

```
src/domain.roles/behaver/getBehaverRole.ts:8      boot: { uri: __dirname + '/boot.yml' },
src/domain.roles/decomposer/getDecomposerRole.ts:8  boot: { uri: __dirname + '/boot.yml' },
```

⇒ **`dispatcher` and `dreamer` carry a `boot.yml` that is never read.** two live precedents, in
this repo, of the exact failure this case exists to prevent — and neither is caught by any test.

⚠️ this is the sharper form of the trap. the narrative above warns that the file *looks droppable*.
the worse case is that it **looks ported**: 284 and 142 lines land in the right directories, the
diff reads correct, and the curation is inert because one field was omitted from a `.ts` file
nobody thought of as part of the boot story.

⇒ `[t0b]` exists for this, and it is the cheapest assertion in the whole lift.

## 🔴 .how it fails safe

both doors above fail **silently and off-site**: the tokens are spent in a *consumer's* session,
and this repo's suite stays green either way. so a review read cannot catch it and a human's
attention will not be there when it bites. the fail-safe must be a test, and it must be one test
that shuts both doors:

```gherkin
[t8] given a test that globs src/domain.roles/*/boot.yml
     when it asserts, for each hit, that the role's get*Role.ts declares
          boot: { uri: __dirname + '/boot.yml' }
     then every boot.yml on disk is one a role actually reads
     and the failure names the role dir and the un-declared file
     ⇒ fast (a unit test) · loud (red) · teaches the fix (the message IS the absent line)

[t9] given the symmetric half — a role that declares boot: with no file
     then the test fails too
     ⇒ the pair turns "the file exists" and "the field exists" into one checkable claim
```

🟡 **`[t8]` would go red on `main` today**, against `dispatcher` and `dreamer` — which is the
strongest evidence that the guard is worth its cost. a test that finds a live defect the moment it
is written is not speculative.

⇒ the fix for those two roles is deferred, with its dream and its fulcrum (`F7`). **the guard is
not** — it protects the two roles this lift adds, which is squarely in scope.

## ⚠️ .the trap this case exists to name

**a re-curated boot.yml is worse than a dropped one**, because it looks done. the file's value is
the *argument per entry*, and an author who re-derives the allowlist from scratch re-litigates two
dozen settled calls with none of the evidence that settled them. the wish is explicit: **port both
files unchanged.**

🟡 one genuine amendment is owed, and only one: `false-report` (60K) and `partial-audit` (47K) are
a quarter of the glossary between them and belong at **`ref`** level (§3.2). confirm they are
there; do not promote them to `say`.
