# case=2 — a consumer repo ranks what it never hosted

> **actor** = `clone` (a 🔦 prioritizer seat) · **goal** = `prioritize` — rank the work
> **cell** = 05 (`clone × prioritize × consumer`)
> **feel** = happy · **care** = critipath

## .the narrative

a clone sits in `ehmpathy/sql-dao-generator`. the repo has a backlog: 40 open tasks, a handful
of half-finished refactors, and no sense of which one is worth a tree.

today there is no answer available to it. the 🔦 prioritizer — the `eco` store, the goal graph,
the sponsorship model, the seed verb — lives in nheuron's `.agent/repo=.this/role=prioritizer/`.
a clone in any other repo cannot reach it, so the rank question gets answered the way it always
was: by whoever last read the issue list, from memory.

**after the lift** the clone runs `rhx eco.priority get` and reads a treestruct of ranked rows.
the role ships; **the store does not** — `.eco/priority.csv` is this repo's data, exactly like
`.meter/` and `.route/`. so the first run in a fresh repo finds no store, and that is correct
rather than broken.

⇒ **the aha**: a rank is not a global fact. the *method* is shared and the *ledger* is local —
which is why the role can ship to everyone and still tell each repo a truth about itself.

## .the demo

```gherkin
[t0] given a repo that has NEVER hosted role=prioritizer
     and `rhachet-roles-bhuild` installed, roles linked

[t1] when the clone runs
       rhx eco.priority get
     then the skill RESOLVES  (today: `no skill found`)
     and it reports an EMPTY store — not an error
     ⇒ `.eco/` is per-repo data; the role ships, the store does not (§4.4)

[t2] when the clone records an opine
       rhx eco.priority set --goal 'repo://sql-dao-generator/fix-nullability' \
                            --sev 2 --urg 1 --work 3
     then `.eco/priority.csv` is created as the truth
     and `.eco/priority.db` is derived as a cache
     ⇒ the csv is truth, the db is a cache — the invariant holds unchanged

[t3] when the clone runs
       rhx eco.priority get
     then the rows render as a TREESTRUCT, never a flat list
       (`rule.always.render-priorities-as-treestruct`)

[t4] when a row earns a runner
       rhx eco.seed --goal 'repo://sql-dao-generator/fix-nullability'
     then a radio task is dispatched
     and the prioritizer STOPS
     ⇒ the seed is the whole hand-off (`rule.always.prioritize-never-supervise`)
```

## ⚠️ .the dependency this demo hides

`[t2]` and `[t3]` both reach `ecowork.db.mjs` — and that file has **no include rule in this
package's build manifest**. as written today, `[t1]` would pass in a consumer repo and `[t2]`
would fail. see `case=8`; it is the reason this happy path is not actually happy yet.
