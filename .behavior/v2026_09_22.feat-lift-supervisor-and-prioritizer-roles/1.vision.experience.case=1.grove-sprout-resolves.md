# case=1 — grove sprout resolves

> **actor** = `clone` (a ⛺ supervisor seat) · **goal** = `supervise` — sprout a behavior tree
> **cells** = 03 (`clone × supervise × grove`), 02 (`clone × supervise × consumer`)
> **feel** = happy · **care** = critipath · **boundary-density** = 🔴 highest in the grid

## .the narrative

a supervisor sits in a clone on a grove box — an ec2 instance with a checkout and a `rhachet`
on PATH. a wish landed for `ahbode/svc-jobs`. the supervisor wants one command:

> `rhx git.tree.behavior --into ahbode/svc-jobs --name beav/fix-queue --size nano --wish ./w.md`

**today it answers `no skill found`**, and not by accident. the skill lives in nheuron's
`.agent/repo=.this/role=any/`, and `repo=.this` is linked to exactly one repo — nheuron, on the
laptop. the grove box has no such link, so the verb that exists cannot be reached from the one
place it is most needed. the skill's own header says it plainly:

> *"this is a `repo=.this` skill, so it is not in any linked role on a grove and `rhx
> git.tree.behavior` there answers `no skill found`. it could not run here for want of the flag,
> and could not run there at all."*

so the supervisor did it by hand: **eight commands** — ship the tree, ship the wish, open the
window over ssh, install, upgrade, init the behavior, start the clone, bind the route. the
`--grove` flag exists as the workaround for exactly this, and it is a workaround for a package
defect rather than a feature anyone wanted.

**after the lift**, `rhachet-roles-bhuild` is an npm dependency. the grove box resolves
`git.tree.behavior` the same way it resolves `rhx git.release` — because it is a package role,
not a repo-local one. one command, and the three-rung ladder runs to the end.

⇒ **the aha**: the fix is not a new feature. it is the same verb, reachable. a whole class of
`no skill found` disappears at once, for every repo, because reach was the only lack.

🔴 **and it reaches one step further than a grove — read `#377`'s body.** a reviewer seat sits in a
`_mirrors/` checkout and hits the identical symptom (*"`💥 no unique skill executable found for
'git.tree.sync'`"*). the obvious repair — link the role into the mirror — is **hazardous there**:
*"whatever is written INTO the mirror to provision it becomes the very state that blocks the next
pull."* ⇒ a **package** role resolves from `node_modules` and leaves the mirror byte-identical. so
reach does not merely repair `no skill found` — **it retires a workaround class that existed only
because the one way to gain reach was to write into someone else's tree.** 🟡 conditional: the
crew's own repo must already depend on the package.

### the sharp leg — cells 02 **and 03**, the four gates still bite

reach must not cost refusal. every gate ports.

🔴 **and the gates are COMMAND-level, so `[t6]`–`[t9]` fire from BOTH cells.** the inventory
verdicted cell 03's sharp leg `itemized · alter` for five drafts, as though a grove were exempt —
it is not. `git.tree.behavior` carries the gates wherever it resolves, and this case's own `[t0]`
puts the caller on a **grove**. ⇒ both 02 and 03 are `forbidden` (a rejection invariant), and the
inventory now says so.

### ✅ `[t9]` — the refusal needs no cross-package dependency

a dependency on `rhachet-roles-ehmpathy` would not make the refusal's pointer land, because the
route is not booted through an import. the call site at source:

```bash
200: rhx duct.send --on "$(__crew_duct_uri "$host" "$slug" mechanic)" \
       --what "… && rhx declapract.upgrade init && …"
```

⇒ the route is booted by **a command string sent into a duct on the target box**, looked up against
*that* repo's linked roles. bhuild's `package.json` is not in that path, so a dependency would not
put the verb on the target's PATH at all.

🔴 **this case is its own argument.** `case=1`'s whole thesis is that a skill is found via a
**linked** role, never a merely installed one — which is exactly why a dependency cannot do the job
a link does. ⇒ `[t9]` ports unchanged: the refusal's value is local (it stops the wrong route from
a boot), and its pointer is prose.

🟡 the one residue is a different grain and near-free: **does the refusal tell a reader how to link
the mechanic role?** (`rule.require.errors-name-the-fix`). that belongs to execution.

## ⚠️ .what this demo asserts that is NOT yet settled

  (§2.4, §6.3). the lift is the fix; the flag should be re-read after, not ported unexamined.
- **`$HOME` was pinned** to `/home/vlad` vs `/home/camper` on a grove. `git.tree.duct` was
  repaired; **the rest of the family is unaudited** (§2.4). `[t2]` assumes the audit happened.
- 🟢 **the crew roster is SETTLED, and it was never the open question i took it for.** read at

  ```
  CREWWORK_ROLES_DEFAULT="${CREWWORK_ROLES_DEFAULT:-mechanic,foreman,reflector,reviewer.take,reviewer.give}"
  ```

  mechanic + foreman"* (line 6) and repeats it (line 60); the handoff §2.4 says three
