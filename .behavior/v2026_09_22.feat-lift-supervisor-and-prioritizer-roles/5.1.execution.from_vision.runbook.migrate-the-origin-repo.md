# runbook: migrate `uladkasach/nheuron` off its own registry

> **the fail-safe for `case=9` `[t9]` and `[t10]`.** it lands here rather than in a suite because
> the act runs **once, in another repo**, so no test in this package can reach it.

⚠️ read this whole file before the first command. step 3 is the only one that fails silently, and
it is the one a reader skims.

## .why this repo is the risky one

every other consumer **gains** a role it never had — it cannot regress, because it had naught to
regress from. nheuron **swaps** a role it depends on daily.

and the swap is two commands, of which exactly one fails loud:

| command | on an absent or misnamed role | verified at |
|---|---|---|
| `rhachet roles link` | 🟢 **fails fast** — not-found and ambiguous both throw | `getRolesFromManifests.ts:11` · `getRolesFoundFromSlugs.ts:19` |
| 🔴 `rhachet roles boot … --if-present` | **skips, exits 0, reads as success** | handoff §6.4 |

⇒ **the boot hook is the whole hazard.** the link step needs no change and no vigilance.

## .the steps

### 1 — take the parity measurement FIRST

```sh
# on nheuron, BEFORE any removal
npx rhachet roles boot --repo .this --role any         | tail -8
npx rhachet roles boot --repo .this --role prioritizer | tail -8
```

write down the two `briefs =` counts. they are the only acceptance criterion this migration has,
and they cannot be recovered once the dirs are gone.

🟡 a count is a **weak** check. the strong one — assert the exact brief set — costs a fixture that
goes stale on every brief authored. for a once-ever act, a weak loud check beats a strong absent
one.

### 2 — remove ONLY what the lift took

🔴 **this is a PARTIAL teardown of `.agent/repo=.this/`, never a deletion of it.** the handoff's §5
names the nheuron-bound briefs that stay, and `node.migrate.sh` with them.

⚠️ **§5 is an open set — measured.** this drive found a 21st exclusion §5 does not list
(`rule.always.archive-seeds-in-the-daily-stream`, whose premise is false outside nheuron), and
recorded it as fulcrum `F8`. ⇒ so do not migrate against §5's enumeration alone; migrate against
its **criterion** — *does this brief name one operator's brain, one repo's dirs, or one fleet's
cadence?* if yes, it stays.

the check that does not lean on either list:

```sh
# what the package now ships, by basename
npx rhachet roles boot --repo bhuild --role supervisor   --output json | jq -r '.briefs[].path'
npx rhachet roles boot --repo bhuild --role prioritizer  --output json | jq -r '.briefs[].path'
```

a repo-local brief whose basename appears in neither list is one the lift did **not** take, so it
stays where it is.

### 3 — 🔴 rewrite the boot hooks, and DROP `--if-present`

`.claude/settings.json` reads, today:

```
rhachet roles boot --repo .this --role any         --if-present
rhachet roles boot --repo .this --role prioritizer --if-present
```

it must read:

```
rhachet roles boot --repo bhuild --role supervisor
rhachet roles boot --repo bhuild --role prioritizer
```

**three edits per line, and the third is the one that gets skipped.** the handoff states the
reason outright:

> ⚠️ *"`--if-present` drops. a package role is always present; its absence is a defect to fail loud
> on, not a condition to skip."*

🔴 **the half-edit is the sharp case.** swap `--repo`/`--role`, leave the flag, and a typo, a role
that did not make the lift, or a build that dropped a dir all produce the same outcome: **a green
boot with no material**. the clone does not crash. it opens with zero supervisor briefs and does
the work anyway — `case=4`'s measured ~150 : 0 state, re-created in the one repo that proves the
lift worked.

⇒ and the defect then surfaces as **bad judgment in a session**, never as a failed command.

### 4 — the quieter half: the hook PATHS

those same hook declarations carry `repo=.this/role=any/...` executable paths. **a path survives
the role's deletion as text**, so a hook whose executable is gone fails at the moment it fires
rather than at the moment it broke.

```sh
# every surviving pointer at the removed dirs
rhx grepsafe --pattern 'repo=\.this/role=(any|prioritizer)' --glob '.claude/**'
```

expect **zero** hits before you call step 3 done.

### 5 — link, then re-measure

```sh
npx rhachet roles link --repo bhuild --role supervisor
npx rhachet roles link --repo bhuild --role prioritizer
```

⚠️ **two sources for one slug is its own defect, and the shadow wins in silence.** confirm no
repo-local `role=prioritizer` dir survives the removal in step 2 — the package copy and a local
copy under one slug is worse than either alone.

then re-run step 1's two commands and compare.

| outcome | verdict |
|---|---|
| both counts match, or exceed | ✅ proceed |
| either count is **lower** | 🔴 halt. a brief did not make the lift — name it before you continue |
| either count is **zero** | 🔴 halt, and re-read step 3. that is the `--if-present` failure |

### 6 — the live check

```sh
rhx eco.priority get        # the store answers, from the package
rhx git.crew.poll --help    # the work verbs are found by name
```

then let one babysit tick fire on its normal schedule. **the system actor should never notice the
swap** — that is the target, and it is the last thing this migration can be wrong about.

## ⚠️ .the artifact swap rides along

nheuron's `role=prioritizer/readme.md:1` opens `## 🌿 prioritizer`. the package's opens `## 🔦
prioritizer`, and the supervisor wears ⛺. both retired glyphs are **banned outright** in this
package, decorative uses included, and `glyphsRetired.integration.test.ts` holds that line here.

⇒ a reader who meets 🌿 in nheuron after the migration meets the **retired identity** of a role
that now lives elsewhere. the fix is one edit and it belongs in step 2's diff, not a later one.
