# case=9 — the origin repo leaves its own registry

> **actor** = `human` + `clone` · **goal** = `migrate` — drop `repo=.this`, enroll the package
> **cells** = 10 (`clone × migrate × origin`), 22 (`human × migrate × origin`) — sharp legs
> ⚠️ **NOT cell 34** (`system × migrate × origin`) — see the note below
> **feel** = sharp · **care** = critipath · the only **demoed** cells of the `migrate` column
> ⇒ the column holds **three** live cells — 10, 22, and 34 — and 34 stays `itemized · alter`

## .the narrative

nheuron is the one repo where these roles already work. it is also the one repo the lift can
**break**, and it breaks in a way no other repo can: every other consumer gains a role it never
had, while nheuron *swaps* a role it depends on daily.

the beaver deletes `.agent/repo=.this/role=any/` and `role=prioritizer/`, adds the package, and
re-links. one command later the tree is up, the ticks run, the store answers. the migration is a
two-line diff and it either worked or it silently half-worked.

🔴 **the half-worked case is the whole of this case — and the silent path is narrower than it
first looks.** two commands run at migration, and only one of them can fail quietly:

| command | on an absent / misnamed role | verified |
|---|---|---|
| `rhachet roles link` | 🟢 **fails loud** — *"fail-fast on first error (not found, ambiguous)"* | `getRolesFromManifests.ts:11`, `getRolesFoundFromSlugs.ts:19` |
| 🔴 `rhachet roles boot … --if-present` | **skips, exits 0, output reads as success** | handoff §6.4 |

⇒ so the link step is already safe by construction; **the boot hook is the whole hazard.**
`.claude/settings.json` reads, today:

```
rhachet roles boot --repo .this --role any         --if-present
rhachet roles boot --repo .this --role prioritizer --if-present
```

the migration must rewrite both lines **and drop the flag**. the handoff says exactly why:

> ⚠️ *"`--if-present` drops. a package role is always present; its absence is a defect to fail loud
> on, not a condition to skip."*

🔴 **the sharp case is the half-edit**: the `--repo`/`--role` half swapped to `bhuild`/`supervisor`
and the `--if-present` left behind. then a typo, a role that did not make the lift, or a build that
dropped a dir all yield the identical outcome — **a green boot and no material** — and the clone
does not crash. it boots *fine*, with zero supervisor briefs, and does the work anyway. that is
`case=4`'s measured ~150 : 0 state, re-created in the one repo that proves the lift worked.

⚠️ a second, quieter half: those same hook declarations point at `repo=.this/role=any/...` paths.
those paths survive the role's deletion as **text**, and a hook whose script is gone fails at the
moment it fires, not at the moment it broke.

⇒ **the aha**: the lift's riskiest repo is the one that already works. a consumer gains reach and
cannot regress; the origin swaps a live dependency — and the swap is two edits, one of which fails
loud and one of which does not.

## .the demo

```gherkin
[t0] given nheuron on main, with role=any and role=prioritizer under .agent/repo=.this/
     and the package published with role=supervisor and role=prioritizer

[t1] when the beaver removes the two repo-local role dirs
     and adds rhachet-roles-bhuild at the lifted version
     and runs `npx rhachet roles link`

[t2] then role=supervisor and role=prioritizer link FROM the package
     and no repo-local copy shadows them
     ⇒ two sources for one slug is its own defect — the shadow wins silently

[t3] when a clone boots in a supervisor seat
     then the brief count matches the pre-migration count
     and the babysit cron, crew verbs, and tick contract are in context
     ⇒ the parity check IS the migration's acceptance criterion

[t4] when the babysit cron fires on its normal schedule
     then it polls, classifies, and nudges exactly as before
     ⇒ the system actor never notices the swap — that is the target

[t5] when a `.claude` hook fires
     then its script path resolves into the PACKAGE, never repo=.this
     ⇒ §6.4 — the settings swap rides with the role removal, not after it
```

### the negative leg — the quiet half-migration

```gherkin
[t6] given settings.json was half-edited:
       rhachet roles boot --repo bhuild --role supervisor --if-present
     and the package does not export that slug (typo, absent role, dropped dir)
[t7] when the hook fires
     then it SKIPS the role
     and it exits 0
     and the output reads as success
[t8] when the clone continues
     then it opens with ZERO supervisor briefs and no error
     and it does the work anyway, without the material
     ⇒ case=4's ~150 : 0 state, re-created — and the defect surfaces as bad
       judgment in a session, never as a failed command
```

## 🔴 .how it fails safe

the migration is a **one-time act by one beaver in one repo**, so no test in this repo can run it.
that is exactly why the fail-safe must be carried by the act itself rather than by our suite:

```gherkin
[t9] given the settings.json boot lines are rewritten
     when the edit lands
     then `--if-present` is GONE from both
     and an absent or misnamed role FAILS the boot, loudly
     ⇒ fast (at boot, before the clone does any work) · loud (non-zero)
       · teaches the fix (the slug is the whole diagnosis)

[t9b] given `rhachet roles link` names the two roles explicitly
      when either is absent from the package
      then the link already fails fast — no change owed
      ⇒ verified in rhachet source; this rung is SAFE BY CONSTRUCTION
        and is listed so the migration spends no effort on it

[t10] given a parity assertion run once, at migration
      when it compares the booted brief count before and after
      then the counts match, or the migration halts
      ⇒ a count is a weak check and it is the ONLY one available for an act
        that occurs once; a weak loud check beats a strong absent one
```

⚠️ **`[t9]` is a change to how the migration is run, not a test we author.** it is the one
fail-safe in this vision that lands in a **runbook** rather than a suite — stated plainly so a
reviewer does not read it as a test we owe and then find no file.

🟡 **and `[t9]` is the handoff's own instruction (§6.4), never a discovery of this vision.** it is
restated here as a checkable migration step because a `⚠️` line in a 465-line document and a gate
in a runbook are different things — but the credit is the handoff's.

🟡 the parity check in `[t10]` is deliberately crude. the honest alternative — assert the exact
brief set — is better and costs a fixture that goes stale on every brief added. a count that halts
loudly is the trade i take for a once-ever act.

## 🔴 .what this case does NOT cover — cell 34

this header claimed cell **34** (`system × migrate × origin` — *"ci re-links roles after the
registry change"*) for two drafts. **it does not demo it**, and the inventory was right: 34 is
`itemized · alter` on both legs.

⇒ read the timeline above. every `[tn]` is a **human or clone** act — the beaver's link, the clone's
boot, the cron's *supervise* tick at `[t4]`. **no step asserts a ci re-link.** `[t4]`'s cron is a
`system × supervise` actor, never a `system × migrate` one, and the two are different cells.

🟡 and 34 is genuinely `alter`, which is why this is a correction rather than a gap: if ci's
re-link misbehaves, a human reruns `rhx roles link` and the fallback costs one command. it earns no
demo. what it did not earn is a **claim** of one.

⚠️ **both peer lanes found this independently**, and both named it the same shape as the round-1
defects: a summary written once and restated downstream without a re-read of what it summarizes.
⇒ the yield's *"rows 10, 22, 34, all three carried by `case=9`"* was written **in the round-1
repair** — so a repair introduced the very defect class it set out to cure.

## ⚠️ .why the rest of the `migrate` column is impossible, and this cell is not

rows 11, 12, 23, 24, 35, 36 are void: a repo that never held `.agent/repo=.this/role={any,
prioritizer}/` has no registry to leave. **`origin` is a set of size one**, and this case is its
only member.

⇒ that is why this cell is a critipath despite one single occurrence: `freq × cost` with `freq = 1`
still clears the bar when the **cost** is the one repo that proves the lift worked. if nheuron
half-migrates, the lift has no witness.

## .the bound

this case does **not** cover what nheuron keeps. §5 names ~20 briefs and `node.migrate.sh` as
nheuron-bound — they stay in `repo=.this`, which means the migration is a **partial** teardown of
that dir, never a deletion of it. a migration that removes the whole directory takes §5's material
with it.
