# case=8 — the package ships what the skill runs

> **actor** = `system` (the build, then a consumer's runtime) · **goal** = `learn`
> **cell** = 32 (`system × learn × consumer`), sharp leg
> 🟡 the goal axis is closed at `{supervise, prioritize, learn, migrate}`. the build **ports** an
> asset, and `port` is not a fifth goal — it is what `learn` looks like when the actor is a build
> **feel** = sharp · **care** = critipath
> 🔴 **found at vision; NOT named in the handoff's §6 port hazards**

## .the narrative

the lift lands. `src/domain.roles/prioritizer/skills/` holds `eco.priority.sh`, `eco.seed.sh`,
and `work/` with `ecowork.sh` and `ecowork.db.mjs`. every test in this repo passes — they run
from `src/`.

then `npm run build` runs, and `build:complete:dist` copies assets into `dist/` with an rsync
allowlist that ends `--exclude='*'`:

```
--include='**/skills/**/*.sh'  --include='**/skills/*.sh'
--include='**/skills/**/*.jsonc' --include='**/skills/*.jsonc'
--include='**/briefs/**/*.md'  --include='**/briefs/**/*.md.min'
--include='**/boot.yml'  --include='**/readme.md'  --include='**/keyrack.yml'
--exclude='*'
```

🔴 **there is no `*.mjs` rule.** `tsc` compiles `.ts` only, so `ecowork.db.mjs` has no path into
`dist/` at all. `package.json` ships `"files": ["/dist", "rhachet.repo.yml"]`.

⇒ the published package contains `ecowork.sh`, which at line 138 resolves
`__ECO_DB_MJS="$__ECO_LIB_DIR/ecowork.db.mjs"` — **a file that is not there**. 4,428 lines of
sqlite mirror, absent. every `eco.priority set` and every `get` in every consumer repo fails, and
**no test in this repo can see it**, because the suite never reads `dist/`.

the sharp shape: the failure is invisible at the only place anyone would look. green locally,
green in ci, broken for every consumer on first use.

⇒ **the aha**: a lift crosses a boundary the source never had. nheuron ran these skills straight
from `.agent/`, where every file is simply present. a package has a **manifest**, and a manifest
is an allowlist — so the port hazard is not any one skill, it is the set of file extensions the
allowlist never had to know about.

## .the demo

```gherkin
[t0] given the prioritizer lifted into src/domain.roles/prioritizer/

[t1] when `npm run build` runs
     then dist/domain.roles/prioritizer/skills/work/ecowork.db.mjs EXISTS
     ⇒ requires a new include rule: `--include='**/skills/**/*.mjs'`

[t2] when the package is packed
     then that file is inside the tarball
     ⇒ `files: ["/dist", ...]` carries it

[t3] given a consumer repo installs the package and links roles
     when it runs `rhx eco.priority set --goal … --sev 2`
     then the store is written
     and the skill does NOT fail on an absent db layer

[t4] when the acceptance suite runs
     then it exercises the skill from `dist/`, never from `src/`
     ⇒ this is the ONLY grain that can catch [t1]. a unit or integration test cannot
```

### the negative leg — what ships today

```gherkin
[t5] given no *.mjs include rule was added
[t6] when `npm run build` runs
     then ecowork.db.mjs is silently dropped by `--exclude='*'`
     and the build EXITS 0
     and every test in this repo stays GREEN
[t7] when any consumer runs eco.priority
     then it fails at runtime, in their repo, on their first use
```

## 🔴 .how it fails safe

this is the one case in the lift where the **grain of the test IS the fail-safe**, and where the
usual grains are provably blind:

| grain | reads from | catches `[t5]`? |
|---|---|---|
| unit | `src/` | 🔴 no — the file is right there |
| integration | `src/` | 🔴 no — same |
| **acceptance** | **`dist/`** | ✅ **yes** — the only grain that reads what ships |

⇒ `[t4]` is the guard, and it earns a name of its own rather than one line in the demo:

```gherkin
[t8] given an acceptance test that invokes `rhx eco.priority` through the BUILT artifact
     when the build drops any runtime asset the skill reaches for
     then the test fails on the first invocation
     and the error carries the absent path (`…/work/ecowork.db.mjs`)
     ⇒ fast (one build + one invoke) · loud (red) · teaches the fix
        (the path names the extension the allowlist lacks)
```

⚠️ **the extension audit below is the other half, and it does not substitute.** the audit is a
human read of a list that will grow; `[t8]` holds whatever the list becomes. run the audit to get
this lift right; land `[t8]` so the next asset added does not re-open the same door.

🟡 `rule.require.blackbox-via-selflink` (mechanic) already names the pattern this test needs — the
package self-references through `exports`, so an acceptance test can invoke the built path without
a publish step.

## .the audit this case demands

before the lift lands, walk **every file extension** the two roles carry and check it against the
rsync allowlist:

| extension | where | in the allowlist? |
|---|---|---|
| `.sh` | both roles' `skills/`, `work/` | ✅ yes |
| `.md`, `.md.min` | `briefs/` | ✅ yes |
| `boot.yml` | both roles | ✅ yes |
| `readme.md` | both roles | ✅ yes — ⚠️ but the supervisor has none yet (§6.5) |
| 🔴 `.mjs` | `prioritizer/skills/work/ecowork.db.mjs` | ❌ **no** |
| `.log` | `supervisor/skills/work/.test/.assets/` (**55** post-split) + `prioritizer/` (1 — the `eco.priority.get.truncated-body.log`) | ❌ no — **and correctly so**: fixtures are src-side test evidence, never a consumer runtime need |
| `.snap` | `prioritizer/skills/work/__snapshots__/`, `supervisor/skills/work/__snapshots__/` | ❌ no — same reason as `.log` |
| `.ts` | 9 files across both roles | ⚠️ **not rsync's problem — `tsc`'s.** see the second table |

🟡 the `.log` and `.snap` rows are **not** defects. they matter in `src/` for our own suite and a
consumer never reads them. stated here so the audit records a verdict per extension rather than a
single yes/no — the `.mjs` row is the one that bites.

### 🔴 the `.ts` half — a SECOND allowlist, with a different shape

the rsync list copies **assets**. `.ts` never goes through it: `tsc` compiles it, and `tsc` has its
own exclude list in `tsconfig.build.json`:

```
"exclude": ["**/*.test.ts", "**/*.test.js", "**/.test/**/*",
            "**/.scratch/**/*", "**/__test*__/**/*", "rhachet.use.ts"]
```

measured — the 9 `.ts` files the two roles carry:

| file | matches an exclude? | lands in `dist/`? |
|---|---|---|
| `work/crewwork.integration.test.ts` | ✅ `**/*.test.ts` | no |
| `work/ductwork.integration.test.ts` | ✅ | no |
| `work/syncwork.integration.test.ts` | ✅ | no |
| `work/termwork.integration.test.ts` | ✅ | no |
| `work/work.surface.integration.test.ts` | ✅ | no |
| `skills/git.grove.saturation.integration.test.ts` | ✅ | no |
| `prioritizer/skills/eco.seed.integration.test.ts` | ✅ | no |
| `prioritizer/skills/work/ecowork.integration.test.ts` | ✅ | no |
| 🔴 **`work/work.harness.ts`** | ❌ **none** — it is not a `.test.ts` | **YES** |

⇒ **`work.harness.ts` is the one `.ts` file that is test infrastructure without a test filename**,
so every exclude misses it and it compiles into the published package.

⚠️ the shape differs from the `.mjs` defect, and that matters for the fix:

| | `.mjs` | `work.harness.ts` |
|---|---|---|
| the error | a runtime asset **absent** from dist | dev-only code **present** in dist |
| when it bites | a consumer's first `eco.priority` | at **build time**, if it imports a devDependency type |
| how loud | 🔴 silent — green everywhere | ⚠️ probably loud — `npm run build` fails on an unresolvable type |

⇒ so this one is **less dangerous than the `.mjs` row and easier to overlook before the build runs**.
a loud break reads as *"the lift is broken"* rather than *"the manifest is wrong"*, and the repair is
one line — an exclude for the harness, or a rename to a `.test`-scoped path — but it must be
**decided up front**, or an hour goes to a compile error that was a manifest gap.

🟡 `[t8]`'s acceptance guard does **not** catch this one: a package with an extra file still runs.
that is the honest limit of the fail-safe, and the reason the audit is the other half.

⚠️ a second, smaller edge on the same axis: `.test/.assets/` and `__snapshots__/` are **dot- and
underscore-prefixed dirs**. confirm jest's roots and any `testPathIgnorePatterns` actually reach
them once they sit under `src/domain.roles/`, or `case=6`'s 56 fixtures become 56 files no test
asserts against.
