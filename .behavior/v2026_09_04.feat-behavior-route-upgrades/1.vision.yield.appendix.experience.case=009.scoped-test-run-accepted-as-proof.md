# case=009 — the scoped test run is accepted as proof

> **who** — a driver clone at `5.3.verification`, after a two-line change to an error-metadata key
> **came for** — to prove the change is safe and pass the verification gate
>
> cell — `actor=driver · lens=sweep · feel=happy · care=alterpath`
> — *(the scoped-run allowance is new, so the **fallback** is the status quo: run the full sweep.
> slow, and it proves the same claim. demoed anyway, because the saved time is the lens's payoff)*
> plus `actor=driver · lens=sweep · feel=sharp · care=alterpath` at `[t2]` — the under-scope that
> misses a regression
> — *(**fallback:** cicd runs the full unscoped sweep and fails **before** the release. it reaches
> the same goal — a verified change — so it is workable by the one test. demoed anyway: the backstop
> is what makes the scoped run safe to allow at all)*

## the narrative

i changed one key from `note` to `hint` in two files. i read the diff. i ran the two impacted
acceptance suites (113 passed) and four impacted unit suites (85 passed). all green.

then i read the stone, and it asks for a proof table with one row per **tier**, each of which demands
`exit 0, N tests passed`. that artifact can only be produced by an unscoped run of all six tiers.
so i run 393 unit suites, 149 integration suites, and the whole acceptance tier — four minutes for
integration alone — to re-verify two lines whose diff i already read.

and cicd produces that same result anyway, on every push, on a clean checkout. my local run is
strictly worse than the one it duplicates: it inherits my machine state, my daemons, my unlocked
credentials.

**after the fix**, the stone asks for the impacted tests. `rhx git.repo.test` already selects them
itself — that is its default, and its plan mode prints the match before it runs. i do not reason
about blast radius or hand-assemble a scope. the proof table's row is the suite that covers the
change, not the tier. `--thorough` is named as the flag NOT to reach for.

the gate's teeth do not move. zero skips, zero fake tests, zero deferrals, and *cite the exact
command and output* all stay exactly as they were. what narrowed is **which** tests i run locally —
never **whether** a claim needs proof.

## the demo

```gherkin
given a 5.3.verification stone and a two-line change to two files
  and cicd runs the full unscoped sweep on every push, on a clean checkout

[t0] the driver runs the impacted tests
  when it runs `rhx git.repo.test --what unit` in plan mode
  then the tool prints the matched files, selected from the change
   and `--mode apply` runs exactly those
   and the driver reasons about no blast radius by hand

[t1] the driver fills the proof table
  when it cites the exact command and the exact output for each scoped run
  then the proof table accepts the scoped suite as the row
   and the row names the suite that covers the change, never the tier
   and zero skips, zero fake tests, and zero deferrals are still enforced

[t2] the driver under-scopes, and the backstop holds
  when the scoped selection misses a suite that the change in fact broke
  then the local run is green and the driver arrives
   and cicd runs the full unscoped sweep and fails
   and the failure surfaces before the release, never after
```

## what this proves

- the stone was the cause, never the driver. a driver that reached for `--thorough` did so
  because the proof table demanded a whole-tier count. fix the artifact the gate asks for and the
  behavior follows.
- 🟡 **`[t2]` is the sharp edge, and the fail-safe is that cicd already exists.** the local sweep was
  never the only proof — it was a duplicate of a better one. the scoped run plus a green cicd run is
  the complete proof.
- the gate narrows *which* tests run locally, never *whether* a claim needs proof. that distinction
  is the whole safety of the change.
