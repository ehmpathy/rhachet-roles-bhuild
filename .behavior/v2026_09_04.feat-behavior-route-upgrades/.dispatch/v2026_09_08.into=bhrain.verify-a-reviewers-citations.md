# dispatch → `ehmpathy/rhachet-roles-bhrain`

**title:** `rhx review` — a result may cite a rule that does not exist, or evidence that is not in the diff. neither is reachable by an extant gate.

**home:** `bhrain/role=reviewer` — the contract is `contract.reviewer-output`, and the mechanism is
`rhx review`. bhuild is the reporter, never the owner.

🟡 **widened 2026-09-08 after a third round.** this opened as a **path** check. r003 shows a path
check is one notch too coarse: the citation was real, the verdict was right, and the **evidence was
invented**. the two defects are one class — *a result that reads sound, whose support is fiction* —
and a mechanism that reads only the path passes half of it.

---

## .the measured case — 2026-09-08, bhuild's first live `prose-of-briefs` run

a fresh peer lane ran the telepath's 25 rules over 59 `.md` files. it returned **1 blocker,
2 nitpicks** — and **all three cited a rule that does not exist**:

```
rule: .agent/repo=bhrain/role=telepath/briefs/rule.require.dimensional-decomposition.md

rhx globsafe --pattern '.agent/repo=bhrain/role=telepath/briefs/rule.require.dimensional-decomposition.md'
  → files: 0
```

the telepath's 25 rules carry no such name. the real `rule.require.dimensional-decomposition` is a
**bhuild behaver** brief, and it grades an experience space rather than a decision record — a
different subject entirely, in a repo the lane never loaded.

⇒ 2 of 3 attributions were fabricated. the third (`rule.forbid.absolutes`) was real.

## 🔴 .why this is worse than a wrong rule name

**the results were sound.** the blocker named a genuine self-contradiction: one fulcrum file whose
header recorded a reversed verdict while its body still stated the pre-reversal guess in the present
tense. that is a real defect, and the lane found it on its first run.

so the failure is not *"the reviewer was wrong."* it is:

> **a true result arrived under a false citation.**

| the driver's move | what it costs |
|---|---|
| checks the result, ignores the citation | ✅ fixes a real defect — but has no way to tell a fabricated cite from a real one, so this is luck |
| checks the citation first, per `rule.always.diagnose-reviewer-malfunctions` | 🔴 **dismisses a true blocker.** the rule points nowhere, so the lane reads as broken |

🟡 **the second move is the one the briefs teach.** a driver who diagnoses before they converge does
exactly what the driver rules ask, and it leads them to discard a real result.

## 🔴 .the second measured case — 2026-09-08, r003, and it defeats the ask as first written

two rounds later the same lane returned 1 blocker + 1 nitpick. **both cited real rules. one invented
its evidence.**

the nitpick claimed a dream was authored twice, verbatim, in two places — and stated the difference:

> *"Only the glyph differs (the `.behavior` copy was swept to 🟡, the `.dream` copy still carries ⚠️)"*

**there is one file.** the second path is a symlink, which is what `rule.always.catch-dreams-for-followups`
mandates:

```
$ git ls-files -s .behavior/v2026_09_04.feat-behavior-route-upgrades/dreams/
120000 6dfb503e…   ← mode 120000 = symlink. a blob is 100644.
```

one inode cannot hold two glyphs. the reviewer's true observation was that the route path returned
no `⚠️` hit while `.dream/` did — because a grep does not traverse a symlink. it then **invented a
swept twin** to account for the asymmetry.

🟡 **and the fabrication carried into the blocker's prose**, which repeats *"the two files are
byte-identical except for this glyph."* the blocker's conclusion was correct; its stated reason was
fiction.

⇒ **a path check passes r003 whole.** `rule.forbid.diffusion` and `rule.forbid.width-ambiguous-glyphs`
are both in the matched set. so the ask below covers the path **and** the claim.

| round | what it cited | what it invented |
|---|---|---|
| r001 | `rule.require.dimensional-decomposition.md` ×3 — absent from the matched set | the **source** |
| r002 | two real rules, both correct | — ✅ |
| r003 | two real rules, both correct verdicts | the **evidence** |

🔴 **intermittent, which is worse than consistent.** a driver cannot learn to distrust the output,
because two rounds in three were clean.

## .what the extant guarantees do NOT cover

| guarantee | what it catches | this case |
|---|---|---|
| strict mode — no `--optional rules` | a rules glob that matches **zero** files → `BadRequestError` → 💥 malfunction | ❌ the glob matched **all 25** |
| `contract.reviewer-output` | stdout with no numeric count for both severities → 💥 malfunction | ❌ counts were well-formed: `1 blocker`, `2 nitpicks` |
| the guard's tally | blockers > threshold → rejected | ❌ it rejected correctly, on a fabricated attribution |

⇒ **every gate passed, and the output carried two invented paths.** the lane was neither empty nor
malformed; it was *mis-attributed*, which no extant check reads.

## .the ask — two checks, and only the first is cheap

### 1. the cited RULE — a set-membership test on data the process already holds

`rhx review` knows the matched rubric set; it prints `rules: 25` in `metrics.expected`.

1. for each result, take its cited **rule** path
2. compare against the set of rule files the `--rules` glob matched
3. a cited path outside that set is a **malfunction** for that result

⇒ deterministic, no brain, and it closes r001.

### 2. the cited EVIDENCE — the harder half, and r003 is why it is owed

a result quotes a `snippet` and names `locations`. both are checkable against the target set the
lane already loaded:

1. is each cited **location** a member of the target set?
2. does its `snippet` appear in that file?

⇒ r003 fails check 2 outright: its snippet is real, and its **claim about a second file** cites a
path whose bytes say the opposite. a `snippet`-present test is deterministic and would have marked
the attribution untrusted.

🟡 **check 2 cannot reach every fabrication** — a claim about a file's *history*, or about two files'
*relation*, is not a substring test. the honest bound: check 2 catches an invented quote, never an
invented inference. that is still the majority of what a driver has to hand-verify today.

🔴 **and a symlink is the specific blind spot r003 exposes.** the target set is built from a diff; a
symlink appears as a path whose bytes live elsewhere. whether the lane sees the link, the target, or
both changes what a `locations` check even means — so that rule wants a statement rather than
inheritance from whatever the fs does by default.

**the severity is the design question, and there is a real fork:**

| option | for | against |
|---|---|---|
| **hard-fail the lane** | a reviewer that invents citations is untrustworthy wholesale | 🔴 discards true results — which is precisely the harm above |
| **flag the result, keep it** | preserves the result, marks the attribution untrusted | the driver must still judge it on its merits |
| **rewrite to the nearest match** | the reviewer clearly meant *some* rule | 🔴 a guess about intent, which is how the fabrication arose |

⇒ **bhuild's read is the middle option**, and the reason is the measured case: the result was right
and the cite was wrong, so a mechanism that throws away the result costs more than it saves. but the
call is bhrain's — this dispatch reports the gap and the evidence, never the verdict.

## 🟡 .a third instance of the same class, found in the same round — the search tools cannot see `.reviews/`

not part of the ask; recorded because it is the **same failure shape**, and it bears on how a checker
would be built.

| tool | over `$route/.reviews/peer/` |
|---|---|
| `rhx globsafe --pattern '…/.reviews/peer/*'` | **80 files** ✅ |
| `rhx grepsafe` · `rhx sedreplace` · `Grep` | **0 matches, 0 files** 🔴 |

a dotdir nested inside a dotdir. the string searched for is plainly present — `tail` prints it — and
all three report that absence exactly as they report a true one.

⇒ **three mechanisms in one round returned a well-formed clean result over a corpus they could not
see**: a sampled `--goal` default, a grep that skips a nested dotdir, and a grep that stops at a
symlink. **a clean result carries no mark of what it could not reach**, which is the property the two
checks above exist to repair — so a checker built on the same search primitives inherits it.

🔴 **and it bears directly on check 2.** if the target set is assembled by a walk that skips nested
dotdirs, a **true** citation into `$route/.reviews/` would be marked unresolvable — a false
malfunction, worse than the defect it hunts. **state the target-set walk before a check is built
on it.**
