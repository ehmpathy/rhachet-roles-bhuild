# wish: the floor walk steps past an empty reply, as it does past prose

**into:** `ehmpathy/rhachet-brains-openrouter` · **seen on:** `0.1.3` · **from:**
`ehmpathy/rhachet-roles-bhuild` @ `beav/feat-behavior-route-upgrades`

## .what

under `floor`, a host that replies `finish_reason: 'stop'` with **0 chars** where json was owed is
accepted as `served`. the walk ends there, and the defect check after it throws. the next cheapest
endpoint is never tried.

## .the evidence — one host, one model, three times on one route

| round | lane | generation | provider | output tokens | content |
|---|---|---|---|---|---|
| i049 | section-of-yields | `gen-1792380866-uBCb5CPD1V7Z3XSTq3HV` | Morph | — | 0 chars |
| i051 | hermetic-of-yields | `gen-1792381856-JPjhGeim9Y69y7csLh4Y` | Morph | 24,090 | 0 chars |
| i052 | hermetic-of-yields | `gen-1792382260-kgkoIzIiQJf4BiGO45Zn` | Morph | 28,075 | 0 chars |

model `openrouter/deepseek/flash`, slug segment `floor&speed=min50tps&privacy=full` (the default).
each run cost a full review round and returned no verdict:

```
💥 MalfunctionError: openrouter returned no usable reply (finish_reason=stop, 0 chars).
the host replied empty where a json schema was owed.
fix: retry the ask. if it recurs, admit other providers via filters, or choose another model
```

## .the cause — the empty reply falls between the two classifiers

`dist/domain.operations/supply/getOneFloorCompletion.js` steps past exactly two reply shapes:

| classifier | fires on | an empty `stop` reply |
|---|---|---|
| `isReplyJsonIgnored` | `finish_reason === 'stop'` and non-empty content that is not json | ✗ — `if (content.trim() === '') return false` |
| `isReplyFailed` | `finish_reason === 'error'` or `null` | ✗ — the reason is `stop` |

⇒ the walk returns `{ outcome: 'served' }`. then `getOneSuppliedCompletion` runs
`getOneReplyDefectError`, which does see the empty reply, and throws. the defect is caught one
step too late — after the walk that could have stepped past it has returned.

## .two promises the code breaks

1. the walk's own `.why`: *"a throttle, a refusal, or a reply the host failed mid-way steps to the
   next"*. an empty reply is a failed reply in all but its `finish_reason`
2. the error's own fix: *"admit other providers via filters"*. the filter set (`floor`, `speed`,
   `precision`, `privacy`, `region`, `price.max`) holds no way to exclude one provider, so the
   caller cannot follow it

## .the shape of the fix

- in the floor walk, treat an empty reply where json is owed (no tool calls) as a step-past
  outcome, `empty`, beside `prose` and `failed`
- 🟡 record it machine-wide for a bounded window, as `prose` is. Morph failed three of three, so
  a host that empties a json ask once is likely to again, and each retry costs a full reply of
  output tokens before it is refused
- either add a provider-exclude filter, or reword the error's fix line to one the caller can act on
- clamp: a fake endpoint list `[empty-stop host, healthy host]` under `floor` must serve from the
  healthy host and report `attempts: [{ outcome: 'empty' }, { outcome: 'served' }]`. it is red on
  `0.1.3`

## .why it is not fixed here

the walk lives in `rhachet-brains-openrouter`'s dist. a `pnpm patch` of a peer package in this tree
would cure one tree and leave every other consumer on the defect.
