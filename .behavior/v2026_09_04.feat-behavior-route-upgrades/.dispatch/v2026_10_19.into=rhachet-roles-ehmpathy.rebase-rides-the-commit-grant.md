# wish: a rebase that only moves commits rides on the commit grant alone

**into:** `ehmpathy/rhachet-roles-ehmpathy` · **seen on:** `1.39.5` · **from:**
`ehmpathy/rhachet-roles-bhuild` @ `beav/feat-behavior-route-upgrades` · **converge with:** the
`beav/feat-split-release-uses` tree, which redesigns these meters and ruled the same rule as its F12

## .what

`git.stage.add` refuses to mark a rebase-resolved file unless a separate **stage** grant is set. a
rebase that only moves commits must ride on the **commit** grant alone. a rebase with **no** commit
grant must still refuse.

## .the gap

in a mid-rebase repo with a commit grant (`uses > 0`) and no stage grant,
`rhx git.stage.add <resolved file>` exits 2 for want of `--stage allow`, so a crew granted commits
cannot finish a rebase. a conflict resolved by deletion fails a second gate: the skill requires the
path to exist on disk.

## .the clamp — red on 1.39.5

`v2026_10_19.into=rhachet-roles-ehmpathy.rebase-rides-the-commit-grant.clamp.md`, beside this
dispatch, holds the suite. it runs the INSTALLED skill in a temp repo halted mid-rebase on a content conflict plus a modify/delete conflict:

| case | expect | on 1.39.5 |
|---|---|---|
| case1 — commit grant, no stage grant; stage the resolved file, then the deleted path | proceeds; the path is no longer unmerged | 🔴 4 of 4 fail |
| case2 — NO commit grant, no stage grant | refused as a constraint; the file stays unmerged | ✅ holds |
| case3 — commit grant, a path outside the conflict set | refused: the commit grant covers only the conflict set | ✅ holds |

`rhx git.repo.test --what integration --scope path://rhachetRolesEhmpathy.gitStageAdd --mode apply`

🟡 the green proof runs upstream. a tool that gates the tree it runs in is repaired upstream only,
never by a local patch that frees that tree's own way — so the bhuild tree holds the diff as
evidence and installs naught. case2 and case3 are the refusals the cure must keep.

## .the shape of the fix — the patch diff

the diff, as a file: `v2026_10_19.into=rhachet-roles-ehmpathy.rebase-rides-the-commit-grant.patch`,
beside this dispatch. it is never registered with pnpm in the bhuild tree.

- while a rebase is in progress and the commit grant holds (`uses > 0`), every path asked for must
  sit in git's unmerged set; then the stage grant is not required
- a path outside the unmerged set, or no commit grant, falls through to the extant stage-grant
  refusal
- a tracked path whose deletion is staged passes the exists check; a `..` segment in a path whose
  dir is gone is refused, so the repo check cannot be walked past
