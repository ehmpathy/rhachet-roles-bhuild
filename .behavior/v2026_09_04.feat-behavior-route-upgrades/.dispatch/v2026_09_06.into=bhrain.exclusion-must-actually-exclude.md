## title

fix(review): exclusion must actually exclude — three defects, and a structural default

## body

## the ask

three defects, in the order a caller meets them. **each one alone makes the exclusion a no-op**, so
all three are owed together.

### 1. 🔴 `--paths-without` is parsed and discarded — a silent failhide

`rhx review` reads `--paths-wout`. the longer name is accepted and dropped, so a lane that passes
`--paths-without '**/*.test.ts'` has carried its test files the whole time.

**measured in bhuild:** 2 shipped guard templates carry it —
`5.1.execution.{from_vision,phase0_to_phaseN}.guard`, on the `mech-decode-friction` lane, since ~2026-04.

⇒ **the fix is not an alias — it is to fail loud on an unrecognized flag.** an alias repairs this one
name and leaves the next typo silent. per `rule.forbid.failhide`, a discarded input is a defect
whether or not we can guess what it meant.

### 2. 🔴 `--paths-wout` is inert against a `--diffs`-sourced target set

the correct flag, measured on a real run, **grew** both trees:

| tree | without the flag | with `--paths-wout` |
|---|---|---|
| `.agent/` | 140.0k | **145.4k** |
| `.behavior/` | 162.7k | **181.4k** |

targets are the **union** of `--diffs` and `--paths`. the exclusion appears to apply to the `--paths`
half only, so a file that entered via the diff cannot be removed. **measured in bhuild: 65 of the
65 review lanes in its guard templates bind `--diffs since-main`**, so a repo that stamps those
templates inherits the defect on every lane it runs.

### 3. ✅ default-exclude the non-deliverable trees

🟡 this is the part with the widest reach. **repos across the org run out of context for a cause
unrelated to their code** — the review target set sweeps trees that no rubric grades:

| tree | why it is never a review target |
|---|---|
| `.agent/**` | briefs and skills — the reviewer's own **rubric material**, not its subject |
| `.dream/**` | caught followups, deliberately deferred |
| `.behavior/**` | route scaffold, logs, guards, stamps, review artifacts |

⇒ **default these off.** a caller who wants one back says so explicitly.

### 🔴 blocklist, never allowlist — and this is a verdict, not a preference

the alternative that reads cleaner is a positive narrow: `--paths-with '{src,blackbox}/**/*.ts'`.
**reject it.**

| | what it must enumerate | what happens when it is wrong |
|---|---|---|
| **allowlist** — name the deliverable dirs | every deliverable dir in **every repo**: `src`, `blackbox`, `terraform`, `bin`, `infra`, `scripts`, `.github`, … | 🔴 a repo whose code sits elsewhere gets **zero targets** and a confident verdict |
| ✅ **blocklist** — name the non-deliverable trees | three, and they are a **convention** this org already fixes: `.agent/` · `.dream/` · `.behavior/` | a new non-deliverable tree is merely un-excluded — the lane still grades the real code |

⇒ **the sets are asymmetric.** the deliverable set is open, per-repo, and unknowable from a shared
template. the non-deliverable set is closed, org-wide, and already named by convention.

🔴 **and an allowlist fails in exactly the mode this issue exists to close** — silently, with a
well-formed verdict over an empty target set. a shared template that guesses a repo's directory
layout is the same class of defect as a parser that guesses a caller's intent.

🟡 **measured, and reverted:** bhuild#366 proposed `'{src,blackbox}/**/*.{test.ts,snap}'` for three
`5.3.verification` lanes. it was applied, then **reverted to `'**/*.{test.ts,snap}'`** on this
verdict. the doubled-flag fold it also proposed was kept — that was the real defect.

### 🔴 the precedence rule this needs, stated

> **an explicit `--paths-with` overrides the structural default.**

without it the default is unusable for the one legitimate case: a **stage** rubric whose subject
genuinely is a route artifact. bhuild#349 needs exactly this —

```
default:                exclude .behavior/**
the stage lane adds:    --paths-with '$route/*.yield.md'
result:                 the yield is in scope; the other 40 route files are not
```

so the contract is **subtract structurally, add back explicitly**, and the add-back wins.

## the acceptance

- an unrecognized flag on `rhx review` **exits nonzero and names the flag** — it is never dropped
- `--paths-wout` removes a matching file that entered the target set via `--diffs`
- with no flags, `.agent/**` · `.dream/**` · `.behavior/**` are absent from the target set
- an explicit `--paths-with '$route/*.yield.md'` puts that file back, and no other `.behavior/` file
- a metrics run reports the trees at **0k**, not merely smaller

## why it is worth its own ship

a review lane that overflows its context window **returns terminal**, so it unlocks the next level
and reads much like a lane that ran. it does not announce itself as broken.

⇒ **the failure is silent in both directions**: the exclusion silently removes no file, and the
overflow it was meant to prevent silently removes a lens from the drive. that is why this is not a
tuning knob.
