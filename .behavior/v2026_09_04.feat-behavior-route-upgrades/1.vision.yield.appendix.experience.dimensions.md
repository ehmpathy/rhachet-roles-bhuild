# 1.vision.yield.appendix.experience.dimensions

the experience space for the twelve queued route upgrades, factored into three orthogonal axes and
walked as a product. the inventory (`1.vision.yield.appendix.experience.case=_.md`) verdicts every cell.

## the axes

### axis I — actor (who encounters it)

| value | who |
|-------|-----|
| `driver` | the clone that drives a behavior route, stone to stone |
| `wisher` | the human who approves stones and rules the fulcrum council |
| `maintainer` | the human or clone that edits bhuild templates, or re-inits an extant route |
| `lane` | the reviewer process itself — a system actor, legitimate per `howto.experience.decompose:36` |

#### the system-actor bound — why `lane` is on the axis and `cicd` is not

both are processes, so the axis needs a stated rule rather than a taste call. the rule is: **a
system actor earns an axis value when this wish changes what it encounters.**

| system actor | does this wish change its encounter? | on the axis |
|--------------|--------------------------------------|-------------|
| `lane` | **yes** — #349 changes the subject a lane loads; #347 #351 #354 #356 add rubrics it runs | yes |
| `cicd` | **no** — it runs the same unscoped sweep before and after | no |

🟡 `cicd` is load-central to the `sweep` lens: it is the backstop `case=009` `[t2]` leans on when a
driver under-scopes. but it is a **precondition of the design, not a subject of it**.
`.github/workflows/.test.yml:133,242,330` runs `THOROUGH=true npm run test:{unit,integration,acceptance}`
unscoped and sharded on every push, and #355 edits `5.3.verification.stone` only — no workflow file
is in scope for any of the twelve.

⇒ so all 14 `cicd` cells would verdict "unchanged by this wish", which is the yagni smell this very
wish exists to cut. cicd's encounter is recorded where it acts — inside the `driver × sweep` demos
— and the axis stays closed by this rule rather than by convention.

### axis II — lens (which delivered change the actor meets)

one value per concern the wish delivers. the twelve issues collapse to seven lenses because four of
them (#347, #350, #351, #356) request the same reviewer pair at four different scopes.

🟡 **the five pulled in after the wish add no eighth lens.** each amends or blocks one of the twelve,
so each joins the lens its target already sits on — listed below in **bold**, so the axis's
*"seven values are the seven issue clusters"* claim reconciles against the wish's full set rather
than against a stale census.

| value | concern | issues |
|-------|---------|--------|
| `prose` | terseness, density, no chronological accretion | #347 #350 #351 #356 #357 · **#358 #360 #362** |
| `yagni` | what is not needed; how this could be simpler | #354 |
| `fulcrum` | is this fork real, and is it still owed | #352 #353 |
| `scope` | what a reviewer lane loads as its subject | #349 · **#365** |
| `audience` | a `case=N` demo declares its actor + goal | #346 |
| `sweep` | which tests the driver runs locally | #355 · **#366** |
| `dispatch` | where an authored dispatch file lands | #342 |
| `scouts-honor` | was an adjacent fix done now, or deferred to a dream | **wisher steer 2026-09-14** |

🔴 **the eighth lens, `scouts-honor`, is a driver-owned close discipline.** a peer lane at vision +
execution grades `$route/dreams/*`, so a dream that reads as a small safe + clean + adjacent fix is a
blocker — the fix belonged in-scope, not deferred. its provenance is a wisher steer rather than a
wish-issue, recorded in `define.invariant.scouts-honor.fix-forward`; per
`rule.require.experience-catalog-evolution` a lens added at any stage grows the contract in place.

### axis III — feel (what the actor feels)

| value | what |
|-------|------|
| `happy` | glides to the outcome |
| `sharp` | hits an edge that can cut |

## the product

`4 actors × 8 lenses × 2 feels = 64 cells`

every cell is verdicted in the inventory as **demoed** / **itemized** / **forbidden** / **impossible**.

## why these axes are orthogonal

- **actor ⟂ lens** — each lens is a change to shared machinery; any of the four actors can meet any
  of them, with **one whole-row exception**:

  | pair | why no experience exists | contingent on |
  |------|--------------------------|---------------|
  | `lane × sweep` | **zero of the 12 peer lanes at 5.3 grades test selection.** the proof table is an artifact the driver fills and the *judge* reads; 5 of the 12 glob `**/*.test.ts` or `**/*.snap` and grade test **content** (`grepsafe` over `5.3.verification.guard`: 12 `run:` binds, 5 match, 0 match a selection pattern) | nobody proposed a sweep lane; #355 edits the stone only |

  🟡 **this is impossible by the shipped design, NOT by nature — and the difference matters.**
  no law prevents a peer lane that grades test selection; we did not ship one. so the honest verdict
  is *impossible under the branch taken*, and both cells go live if a later route ships such a lane.

  🔴 **`lane × fulcrum` is a live itemized pair, on a contingency this section names.** the
  driver-owned close lane `fulcrums-self-sufficient` runs at vision + execution — a peer lane that
  grades the `.fulcrums/` inventory — so a lane meets a fulcrum and both cells are live. the
  contingency is the general one below: *both cells go live exactly when some lane has that
  subject*, and this route ships the lane.

  ✅ **`lane × dispatch` was the third such contingency, and F7 settled it live.** the council ruled
  #342 convention-only — but that branch still carries the lint (#342 point 4 asks for it outright,
  and it was owed under either branch), so a lane does meet dispatches and both cells stay real.
  🟡 **had the verdict dropped the lint, this pair would have joined the impossible set** — which
  is the check worth a keep: a `lane` row is live exactly when some lane has that subject.

  ⇒ **they are not `forbidden` either.** a `forbidden` cell needs an *attempt the behavior rejects*,
  which is what owes a fail-loud invariant. here there is no lane, so there is no attempt, so there
  is no rejection to demo and no guard owed. `forbidden = 0` holds on that test, and the inventory
  states the cell-vs-act boundary it rests on.

### the latent dimension the whole row implies — and where it already lives

a row that cannot occur is the rule's hidden-dimension smell, so the latent variable must be named.
here it is **self-review vs peer-review**, and it is **not** an absent axis: it is already the actor
axis, because the two forms have different actors by construction.

| review form | who lives the experience |
|-------------|--------------------------|
| **self** — the driver reads its own artifact against a slug | `actor = driver` |
| **peer** — a rubric runs as a review lane | `actor = lane` |

⇒ so a lens that ships **self-only** has no `lane` row by construction, and that is covariance
between a lens's *shipped form* and the actor — the one place these axes are not fully independent.
we name it here rather than add a fifth axis, which would duplicate the actor axis under a second
label and double the space to hold it.

🔴 **the two lenses on either side of the covariance:** `fulcrum` ships self + peer (two self slugs
and the `fulcrums-self-sufficient` peer close lane), so its `lane` row is live. `sweep` ships
self/judge-only, so its `lane` row is empty — the one whole-row exception.

- **feel ⟂ (actor × lens)** — every actor-lens pair has both a glide and an edge, except where the
  pair is itself impossible. a gate that can only pass is not a gate.

  🟡 **impossibility is a property of the pair, never of one feel.** a row whose happy cell is a
  real experience and whose sharp twin is impossible is a **partial row** — the tell of a cell
  nobody walked. `lane × sweep × happy` sat that way (itemized, with an empty note) until the
  `dimensional-decomposition` lane flagged the asymmetry; the honest verdict was that **both** cells
  are impossible.

## the axes considered — every candidate, with its disposition

`howto.experience.decompose` lists the usual candidates. **each gets a verdict here**, so the
completeness claim is falsifiable by a reader rather than asserted by me.

| candidate | disposition | in one line |
|-----------|-------------|-------------|
| **actor** | ✅ **promoted** — axis 1 | driver · wisher · maintainer · lane |
| **feel-trigger** | ✅ **promoted** — axis 3, as `feel` | happy vs sharp; the trigger is the cell's own edge |
| **goal** | ⛔ covaries with `actor × lens` | see below — `case=008` `[t2]` is the evidence, and it splits a *case file*, never an axis |
| **path-variant** | ⛔ folds into `feel` | a lens's two path variants **are** its happy and sharp cells |
| **resource-state** | ⛔ folds into `feel` | see below — the worked instance of the rejection rule |
| **concurrency / time** | ⛔ zero cells | see below — one actor per stone, one turn |
| **stage** | ⛔ covaries with lens | `audience` only at vision, `sweep` only at verification, `prose` at every yield — a ×4 multiplier over cells already walked. our own candidate, not on the method's list |

🟡 **the rejection rule, stated once: a candidate whose values relabel an extant axis is recorded
as an ATTRIBUTE, never added as a dimension.** it would multiply the space and fill the new cells
with `impossible`. `path-variant`, `stage`, and `resource-state` are each rejected by it; the row
above carries each, and `resource-state` below is the one worked out, because it is the one whose
values relabel the feel axis cell for cell.

only `lens` is ours to justify. the method offers no lens candidate; it is the axis this wish
introduced, and the seven values are the seven issue clusters. every other axis is either a
promoted candidate or a rejected one, above.

### goal — covaries with `actor × lens`, and the case=008 split is the proof

each **lens** names a concern, and an actor's goal *within* that concern is fixed: the driver's goal
under `prose` is to pass the stone with a terse yield; under `sweep`, to prove a change is safe. so
`actor × lens` already pins the goal, and only `feel` varies inside the pair.

🟡 **`case=008` `[t2]` looks like counter-evidence and is the strongest evidence for it.** it walks a
case file that *"serves two distinct goals"* and is therefore split — and the repair is to split
**the case file into two**, because it had covered **two cells**. the goal did not vary within a
cell; the file had spanned more than one.

⇒ that is why the `came for` field (#346) earns its place: it makes a covariance **visible**. a
header that must state the goal exposes a file that straddles two cells, which a coordinate never
did. the field is a *check on* the axes, not a fourth axis.

### concurrency / time — the unit of work is one stone, one turn

a route is driven by **one actor per stone, one turn at a time**. a stone is claimed, worked, and
arrived at; two drivers do not hold one stone. so there is no concurrent cell to walk — no
interleave, no race, no sequence variant.

🟡 **two paths look concurrent and are not:**

| looks concurrent | actually |
|---|---|
| `case=012` — the dispatch lint's repo-wide glob reaches files another route authored | a **blast-radius** property of one glob, walked in one turn. the cross-route reach is why the attribution split exists, and it is a question of scope, not of when |
| `case=009` — cicd runs the full sweep while the driver runs a scoped one | cicd is a **precondition** of the actor's world, not a subject of this behavior — the same reason it is not an actor (see the actor bound above) |

⇒ if a later route ships a lane that two stones can trigger at once, concurrency becomes an axis.
under this design it has zero cells.

### resource-state — absent-resource cells live in the sharp feel, not a third axis

the candidate here is *"the resource is absent / empty / malformed"*. every such state in this wish
is **already a sharp cell**, so an axis would duplicate the feel axis rather than add to it:

| absent resource | already walked at |
|---|---|
| no `.fulcrums/` dir to grade | `maintainer × fulcrum × sharp` — answers "none" |
| no bound route for a dispatch | `case=011` `[t2]` |
| an orphan dispatch with no route to attribute | `case=012` |
| an extant guard, so the new one never lands | `case=010` |

🟡 **the tell that it is not a real axis: it has only two values, and the second one is a feel.**
`resource=present` maps to the happy cell and `resource=absent` maps to the sharp one, cell for
cell.
