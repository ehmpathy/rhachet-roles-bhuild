# case=006 — the self review kills a false fulcrum

> **who** — a driver clone about to close a route and convene the fulcrum council
> **came for** — to hand the wisher only the forks the wisher alone can settle
>
> cell — `actor=driver · lens=fulcrum · feel=sharp · care=alterpath`
> — *(**fallback:** the false fulcrum reaches council and the wisher says "go read it". `cost` = one
> round of wisher attention, which is the status quo. demoed anyway: saved attention is the payoff)*

## the narrative

my inventory holds four rows. i registered each one at the moment of doubt, and i have never
revisited any of them. the council is about to cost the wisher four decisions.

the self review asks two questions per row, and they are different questions.

**first — is it a fork at all?** `F1: the shape of the guard` sits at 60% confidence. the review
asks what fact would settle it, and whether i *read* that fact or inferred it. i wrote F1 from grep
output — two lines, never the files end to end. i cite no path. that is the tell: a fulcrum entry
with no file path is usually a research question in disguise.

so i read the two functions end to end. they are already single-site and single-purpose. **the seam
the fulcrum debates already exists.** the fork was manufactured by an unread premise. it is not a
taste question; it is a read i owed and skipped. i close it myself.

**second — is it still owed?** `F3` traces to no acceptance criterion in `0.wish.md`, so it is a
fork about work nobody asked for; i delete the row and the work with it. `F4`'s two branches ship
the identical artifact, so it is a preference with no consequence.

`F2` survives both checks: two defensible options, no fact settles it, and the branches ship
different artifacts. that one is real.

four rows become one.

## the demo

```gherkin
given $route/.fulcrums/inventory.of=fulcrums._.md holds four rows F1..F4
  and F1 was registered from grep output, cites no file path, at 60% confidence
  and F3 traces to no acceptance criterion in 0.wish.md
  and F4's two branches ship the identical artifact
  and F2 is two defensible options that no fact settles

[t0] the driver signals the stone as arrived
  when the self review "is each fulcrum answerable by research rather than taste" runs
  then it demands, per row, the fact that would settle it and a path+line citation
   and F1 is flagged: a premise never read at the source

[t1] the driver reads F1's premise at the source
  when it reads the two functions end to end rather than by grep
  then the seam F1 debates is found to already exist
   and F1 is closed by the driver, with the read recorded in its entry
   and F1 never reaches the wisher

[t2] the self review "argue the case for each fulcrum's deletion" runs
  when it asks per row: still a fork? traced to acceptance? branches differ? simplest branch defensible?
  then F3 is deleted — no acceptance trace, so the work goes with the row
   and F4 is deleted — both branches ship the same artifact
   and F2 survives all four checks and carries to the council
   and the inventory retains every closed row with its verdict, so each decision stays auditable
```

## what this proves

- 🟡 **two checks, two questions.** *is it a fork at all* (research vs taste) and *is it still owed*
  (deletion) catch different defects — F1 fails only the first, F3 and F4 only the second. one
  merged slug would blur them, and `rule.require.slug-promise-format` wants each slug to read as
  exactly one promise.
- the tell is mechanical: a fulcrum entry that cites no file path is the flag.
- the sharp edge is a wrongly closed fork. the fail-safe is that a closed row is never erased
  — it stays in `.fulcrums/` with its verdict and reason, so the wisher can reopen it.
