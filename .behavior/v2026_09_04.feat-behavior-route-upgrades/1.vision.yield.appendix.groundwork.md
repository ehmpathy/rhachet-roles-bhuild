## the three load-central finds

### 1. 🔴 a `*.yield.md`-only subject would have hidden 6 of this route's 7 peer findings

**the question asked plainly: should peer review inputs be `$route/*.yield.md` and no other file?**

**answer: for the code lanes yes, for the stage lanes no — and the difference is not a preference,
it is what the prompt contract permits.**

bhrain's reviewer instructions, verbatim (`compileReviewPrompt.ts:136,139,140`):

> 1. ONLY review content in the `<target>` section
> 4. the "locations" array must ONLY contain paths from `<target>`
> 5. if you cannot find the violation in `<target>`, do not report it
> 6. `<refs>` section contains reference documents for context — **do not flag content from refs**

⇒ **a file moved from `--paths-with` to `--refs` becomes ungradeable, and still costs its full
context.** both sections are prompt content, so the move buys no headroom and forfeits every result
the rubric could have raised there. `--refs` is not a cheaper `--paths-with`.

**this route is its own counterexample. 6 of the 7 peer results across i001–i008 landed in
`1.vision.yield.appendix.experience.*` files, not in the yield:**

| iteration | the result | which file |
|---|---|---|
| i001 | four `←` pointers claimed false coverage | `case=_` |
| i002 | the repair crossed the lens; 8 rows defective | `case=_` |
| i003 | `[t4]` demoed an **unhandled** edge that ships handled | `case=004` |
| i004 | the narrative kept pre-repair arithmetic | `case=008` |
| i005 | the header lagged the index | `case=011` |
| i006 r001 | the verdict legend still said "by nature" | `case=_` |
| i006 r002 | the `and [tn]` overclaim | **the yield** |

⇒ **a yield-only subject scores 1 of 7.** the yield is a summary; the defects live in the artifacts
it summarizes. #349's intent is sound — a *code* rubric has no business with 366k of experience
narratives — but applied to the stage lanes it would blind the two reviewers whose entire rubric is
those files.

**so the cut is per-lane-family:**

| lane family | glob | from the behavior dir, the subject is |
|---|---|---|
| code lanes (`5.1`, `5.3`) | `**/*.{ts,sh,md,snap}` | **the yield only** — #349, as asked |
| stage lanes (`1.vision` peers) | `$route/1.vision.*.md` | **all of them** — they are the rubric's subject |
| test-only lanes | `**/*.test.ts`, `**/*.snap` | already exclude markdown — no change |

### 2. the glob families need opposite treatment

`$route/1.vision.yield.appendix.experience.*` is **noise** to a code rubric and **the subject** to the
experience-coverage rubric. a blanket `.behavior/**` exclusion would strip the coverage lanes
silently, so only the `{ts,sh,md,snap}` lanes narrow (`case=004` `[t2]`).

⇒ the cut is per-lane-family, never global. see F4.

### 3. `--paths-without` does not work, and we ship it

bhrain declares `--paths-wout` (`review.ts:48`) and reads only `options['paths-wout']` (`:158`); an
unrecognized flag is stored under its literal key and never read (`:126,147`). so the
`--paths-without '**/*.test.ts'` in `5.1.execution.from_vision.guard:173` and
`phase0_to_phaseN.guard:177` is **parsed and discarded** — those lanes have carried the test files
they meant to exclude since ~2026-04.

⇒ this is the same failhide shape #349 exists to repair: an exclusion that reads as protection and
excludes no file, exactly as an overflowed lane reads as a clean verdict. repaired in the same edit,
because those are the lanes #349 already opens — in scope, not a widen.

🟡 **had i copied the in-repo precedent, `case=004` would have shipped as a lie.** its falsified draft
claimed *"one flag on two bhuild lanes removes ~200k"*; the flag i would have written removes no file
at all.

🔴 **`~200k` here is a QUOTE of the falsified draft, never a live figure — do not "correct" it to
366,363.** the two numbers name different mechanisms: `~200k` was the draft's *one flag* claim, and
`366,363` is what the **structural default** removes. a grep that swaps the string breaks the
sentence, and has twice.

## the `--rules` misparse — the fourth scope flag, and a repair already paved

a since-retired prose lane was first written with the comma form the `review.sh` header advertises
(*"glob pattern(s) for rule files (comma-separated)"*). it threw on its first run:

```
BadRequestError: --rules glob was ineffective
```

read at source: `stepReview.ts:298` is `Array.isArray(input.rules) ? input.rules : [input.rules]`
— no comma split — and `review.ts:154` casts to `string`. so `'globA,globB'` becomes one glob whose
literal text holds a comma, and that glob matches zero files.

🔴 **F14's class, found a fourth time, and only luck made it loud:**

| the flag | how it misparsed | how it read |
|---|---|---|
| `--paths-without` | parsed and discarded — bhrain reads `paths-wout` | as though the exclusion applied |
| `--paths-with` ×2 | last wins — the first bind is dropped | as though both scopes applied |
| `--goal` (absent) | defaults to `representative` — a sample, not a sweep | identical to a swept verdict |
| `--rules 'a,b'` | one literal glob with a comma in it | ✅ threw — the one of the four that failed loud |

⇒ had either home been reachable by the malformed pattern, the lane would have run on a **partial
rubric** and reported a verdict — the other three's exact shape.

### the residual risk the brace keeps

if one member is renamed the brace still matches the survivors, `length > 0`, no throw — a silently
partial rubric.

⇒ 🔴 **that risk grew when the rubrics were narrowed on 2026-09-08.** while one lane globbed the
whole telepath dir, a renamed rule fell out of the braced lane and stayed enrolled in the globbed
one, so no rule could leave the gate entirely. no lane globs the dir any more, so that containment
is gone and the exposure is now every member of both braces.

⇒ it is a priced cost rather than an oversight: the glob's auto-enrollment is what put 60% surface
detail into the gate, and the brace is what removes it. the ask that gets both — an open glob minus
a named subtraction — is `--rules-wout`, dispatched at
`$route/.dispatch/v2026_09_08.into=bhrain.unenroll-the-entooled-rules.md`.

### the brace form is the paved repair

`--rules` takes one brace glob, never a comma list. bhrain records the same fix for the same defect
at `.behavior/v2026_06_25.fix-guard-stamp/5.3.verification.yield.md:80`, and
`blackbox/review.by.acceptance.test.ts:659` clamps it: *"review's glob (globby) does not split"*.

⇒ the cue `rule.always.reuse-pavement-before-improvise` names applies here: one `git.repo.get` on
the error string finds the paved repair.

### the root cause is a stale doc, still live

`review.sh:12,14` documents the form the parser rejects:

```sh
#   --rules   glob pattern(s) for rule files (comma-separated)
#   --paths   glob pattern(s) for target files (comma-separated)
```

⇒ **the documented form is the broken one.** bhrain repaired the call site twice — once in a guard,
once with a clamp — and never repaired the help text that produces the error. two independent
drivers, in two repos, have now written the comma form because the skill told them to.

that is `rule.forbid.surprises` and `rule.require.errors-name-the-fix` at the same site: the help
