# case=012 — an orphan dispatch flags, it never blocks

> **who** — a maintainer of a downstream repo that boots bhuild (`rhachet-roles-mhedic`)
> **came for** — to drive an unrelated route to completion
>
> cell — `actor=maintainer · lens=dispatch · feel=sharp · care=critipath`

## the narrative

**as the maintainer.** three files sit in my briefs dir — `dispatch.bhrowser.*`,
`dispatch.ghlitch.*`, `dispatch.bhrain.*`. i did not author them. the route that produced them
closed months ago. they are the exact leak #342 exists to prevent, and they were already moved by
hand once before the rule existed.

today i drive a route about referral-of-dermo. it touches no dispatch, no radio, no briefs.

the new lint globs `.agent/**/briefs/dispatch.*.[task].md`, finds three, and blocks my stone.

🟡 **the block is correct about the files and wrong about me.** i cannot satisfy it without a
decision i have no basis to make: *which route owns `dispatch.bhrain.*`?* the route is closed. its
dir may be gone. #342's own words admit this case — *"a dispatch with no known route = **flag**
(which route produced it?)"* — a flag, deliberately not a blocker.

**the two populations must part.** a dispatch **this route** authored is attributable, so the block
is fair and the fix is one `mvsafe` — the repo-safe file move, `rhx mvsafe --from … --into …`
(spelled in full at `[t1]` below). a dispatch that predates the rule is an orphan, and a blocker
on an orphan holds every future route in the repo hostage to a cleanup nobody scheduled.

## the demo

```gherkin
given a repo whose .agent/**/briefs/ holds 3 dispatch.*.[task].md files from closed routes
  and a bound route about an unrelated concern
  and the #342 lint that globs '.agent/**/briefs/dispatch.*.[task].md'

[t0] the lint treats every hit as a blocker
  when the maintainer drives their unrelated stone
  then the stone blocks on 3 files the maintainer did not author
   and the named fix asks which route owns each file
   and no route owns them — the routes are closed
   and the repo cannot drive any stone until an unscheduled cleanup lands

[t1] the lint parts the two populations by attribution
  when it finds a dispatch.*.[task].md under a briefs dir
  then it asks whether the bound route's .dispatch/ or radio trail claims it
   and an attributable dispatch blocks, and names the exact mvsafe command
   and an orphan dispatch flags, names the file, and lets the stone pass

[t2] the maintainer authors a NEW dispatch into briefs
  when they hand-place dispatch.foo.[task].md under .agent/repo=.this/role=any/briefs/
  then it is attributable to the bound route
   and the lint blocks and names the fix:
       rhx mvsafe --from '<path>' --into '$route/.dispatch/<name>'
```

## the fail-safe is the attribution split, not a softer severity

🟡 **a blanket downgrade to flag would forfeit the rule.** #342 asks for a blocker precisely because
the mhedic failure was *a bad precedent copied twice* — and a flag is what an agent that copies
scrolls past. so the severity must stay a blocker where it can be acted upon.

| the population | severity | why |
|----------------|----------|-----|
| attributable to the bound route | **blocker** | the fix is one `mvsafe` the driver can run right now (`rule.always.spend-own-levers-before-escalation`) |
| an orphan from a closed route | **flag** | there is no lever the driver holds; a blocker here is a wall with no door |

⇒ the split satisfies `rule.require.errors-name-the-fix`: **a blocker is only ever raised where a fix
can be named.** where the fix is unknowable, the rule reports and steps aside.

## the blast radius is why this cell is critipath and its audience twin is not

`maintainer × audience × sharp` (#346) is a near-identical shape — a new rule that fails artifacts
that predate it — and it is verdicted **alterpath**. the two part on glob reach:

| lens | the lint's subject | can it block unrelated work? |
|------|--------------------|------------------------------|
| `audience` | `$route/1.vision.yield.appendix.experience.case=*.md` | no — only the route under drive |
| `dispatch` | `.agent/**/briefs/**` | **yes** — a repo-wide dir no route owns |

a rule whose subject is route-local can only ever block the work that produced it. a rule whose
subject is a shared repo dir can block work that has no relation to it at all. that reach is the
whole of the difference, and it is what earns this cell a demo.

## what this proves

- #342 already named the fail-safe, in point 4, and it is easy to drop on the way to code —
  *"a dispatch with no known route = flag"* reads as a footnote beside the blocker clause and is the
  load-central half.
- attribution is the mechanism, and it costs no new machinery — the bound route already exposes
  `$route/.dispatch/`, and the radio trail already records what was pushed.
- 🟡 **a repo-wide glob is a different risk class than a route-local one.** the same rule text,
  pointed at a shared dir, gains the power to halt work it never examined. that is the check to run
  on any new lint before its severity is set.
