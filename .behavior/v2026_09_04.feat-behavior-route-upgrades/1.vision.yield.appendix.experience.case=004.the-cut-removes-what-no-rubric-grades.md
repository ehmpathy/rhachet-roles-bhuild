# case=004 — the cut removes what no rubric grades

> **who** — a reviewer lane (a system actor): `mech-failhides`, a 791-token rubric on a code rule
> **came for** — to grade the code the diff touched, and return a number
>
> cell — `actor=lane · lens=scope · feel=happy · care=critipath`
> — *the **only** happy critipath in the walk: every other lens's happy fallback is the world before
> its gate, but this one's status quo is a stalled stone — no prior state to fall back on*
> plus `actor=driver · lens=scope · feel=sharp · care=critipath` at `[t3]`, `[t4]` and `[t5]` —
> **three distinct ways to write a scope flag that never scopes**: the wrong name, the inert flag,
> and the repeated flag whose first bind is dropped
> plus `actor=lane · lens=scope · feel=sharp · care=alterpath` at `[t6]` — the cut applies, is still
> not enough, and the malfunction blocks the stone
> — *(**fallback:** the scoped re-run `rule.always.diagnose-reviewer-malfunctions` prints. `freq`
> rare — it needs a code diff alone above the gate — × `cost` moderate)*

## 🔴 the fix is a structural default, not a flag on two lanes

🟡 **`--paths-wout` — the correct flag, correctly spelled — is inert against a `--diffs`-sourced
target set.** bhuild#365 measured it:

| tree | without the flag | with `--paths-wout` |
|------|------------------|---------------------|
| `.agent/` | 140.0k | **145.4k** |
| `.behavior/` | 162.7k | **181.4k** |

the trees **grew**. targets are the union of `--diffs` and `--paths`, and the exclusion reaches the
`--paths` half only — so a file that entered via the diff cannot be removed.

⇒ **measured: 65 of the 65 review lanes in bhuild's guard templates bind `--diffs since-main`**
(`grepsafe` over `templates/` — 65 matches against 65 `rhx review` binds). so a repo that stamps
these templates inherits the defect on every lane it runs. the fix is therefore not a flag on two
bhuild lanes; it is a structural default in `rhx review` (bhrain#446), with the route's yield
added back explicitly.

## where these numbers come from

🟡 **the overflow was measured on another repo, and this case narrates it as that lane.** the token
figures in `[t0]` are quoted from #349's issue body, which measured `ehmpathy/test-fns` @
`.behavior/v2026_08_31.feat-tempdir-autoprune`, stone `5.3.verification`. the inertness figures
above are #365's, measured separately. none of it was measured here — this route's own diff spans
one behavior dir, so its code lanes are nowhere near the gate. **the hazard scales with how many
route dirs a diff touches**, not with one route's size.

## the narrative

**as the lane.** my rubric is 791 tokens and it grades acceptance journeys in code. my subject glob
is `**/*.{ts,sh,md,snap}` intersected with the diff.

**more than half of what that glob hands me is the `.behavior/` dir** — ≈318k of its 366k sits in
four items: two stage yields worth 119k, a 38k experience inventory, a 30k dimension matrix, and
twelve `case=N` demos worth ~131k. the ~48k balance is the route's support dirs — `0.wish.md`,
`.seeds/`, `.fulcrums/`, `.dispatch/`, `.reviews/`. not one of them holds an acceptance journey.

⇒ so the majority of my subject is a corpus my own rubric cannot grade, and it is what carries me
over the 75% context gate: i render **no verdict at all**. `[t0]` states the counts.

i have done this for nine iterations. **the stone does not pass** — a review that emits no numeric
count, a **countless** review, is a malfunction, and a malfunction blocks. what it does instead is **stall**: nine rounds, no verdict,
and a tree output that reads much like a lane that ran, so the driver can misdiagnose the cause.

**after the structural default.** `rhx review` excludes `.agent/**` · `.dream/**` · `.behavior/**`
from every target set unless a lane names one back. what leaves my subject is exactly the half no
rubric grades, and `[t1]` states the drop. the stage lanes re-add `$route/*.yield.md`, so the
deliverable stays gradeable.

## blocklist, never allowlist — and this is the shape, not a preference

the repair that reads cleaner is a positive narrow: `--paths-with '{src,blackbox}/**/*.ts'`.
reject it.

| | must enumerate | when the enumeration is wrong |
|---|---|---|
| **allowlist** | every deliverable dir in **every** repo — `src`, `blackbox`, `terraform`, `bin`, `infra`, `scripts`, `.github`, … | 🔴 **zero targets**, and a confident verdict over them |
| ✅ **blocklist** | the non-deliverable trees — three, fixed by org convention | a new tree is merely un-excluded; the lane still grades real code |

⇒ the sets are asymmetric, and that asymmetry decides it. the deliverable set is open, per-repo,
and unknowable from a shared template. the non-deliverable set is closed and org-wide.

🔴 **their failure modes are opposite: an allowlist fails to EMPTY, a blocklist fails to WIDE.** an
empty target set still returns a well-formed verdict, so it is silent. a wide one merely costs
context. ⇒ the term record is `term=review.scope.blocklist`.

measured and reverted 2026-09-06. bhuild#366 proposed `'{src,blackbox}/**/*.{test.ts,snap}'`
for three `5.3.verification` lanes. it bundled two changes: fold the doubled flag (correct — the
measured defect) and narrow to an allowlist (wrong). the first was kept; the second was reverted
across 4 sites. ⇒ an issue that proposes a fix proposes a SHAPE too, and its evidence covers only
the defect.

## the window is measured, and it closes the margin question

the gate is `75%` of `brainSpec.gain.size.context.tokens` (`compileReviewPrompt.ts:234`, fed from
`stepReview.ts:647`) — a **per-brain** value, not a constant:

> this route's own peer lane logged `estimate: 58017` at `contextWindowPercent: 5.8`
> (`.log/bhrain/review/2026-09-04T04-42-33-761Z/metrics.expected.json`), on
> `brain: fireworks/deepseek/v4-flash`. the guard names no `--brain`, so that is the **default**.
> ⇒ the window is **≈ 1.00M tokens**, and the gate sits at **≈ 750k**.

| subject | vs a ~750k gate |
|---------|-----------------|
| 707,400 targets **alone** | 94% of the gate — under it by a hair |
| plus rules (791), 7 refs, and the prompt scaffold | **over** — which is what test-fns observed |
| 341,037 after the cut | **~45%** of the gate — clear, with over half the gate to spare |

⇒ **the margin, not the magnitude, was the defect.** the lane sat at 94% on targets alone, so any
refs at all tipped it. the cut moves it from *one ref away from silent* to *more than half the gate
in reserve*.

🟡 **one link stays unverified: test-fns' guard may name a different brain.** the direction holds at
every window; the "comfortably clear" claim is bounded to a ~1M one.

⇒ and even a perfect exclusion cannot save a lane whose *code* diff alone is 327k. the behavior dir
is the half worth cut because **no rubric grades it**; the code half is what the rubric exists for.

## the failhide family — three ways a scope flag misfires, all silent

this is the heart of the case, and it grew from one instance to three. each produces a lane that
runs, reasons correctly from what it was shown, and returns a confident verdict over a corpus
nobody asked for.

| # | the misuse | what happens | measured |
|---|---|---|---|
| `[t3]` | an **unrecognized** flag — `--paths-without` | parsed and discarded | 2 bhuild templates, ~5 months |
| `[t4]` | the **correct** flag, `--paths-wout`, against a `--diffs`-sourced set | applies to the `--paths` half only; the tree **grows** | #365 |
| `[t5]` | a **doubled** single-value flag — `--paths-with X --paths-with Y` | last-wins; the first value vanishes | 3 lanes, 4 rounds (#366) |

```gherkin
[t3] the driver copies the in-repo precedent instead of the CLI contract
  when a lane is written with --paths-without '$route/*.experience.*'
  then the flag parses into an unread key
   and the subject is unchanged at ~707k
   and the lane still overflows
   and the guard config reads as though the fix were applied

[t4] the driver writes the CORRECT flag, and it still excludes no file
  when a lane is written with --paths-wout '.behavior/**' alongside --diffs since-main
  then the exclusion applies to the --paths half of the union only
   and every .behavior/ file that entered via the diff remains
   and the measured tree sizes GREW: .agent/ 140.0k -> 145.4k, .behavior/ 162.7k -> 181.4k
   and the driver holds a correct flag, correctly spelled, that removes not one file
   # this is why the repair is a structural default in rhx review, not a per-lane flag

[t5] the driver repeats a single-value flag, correctly generalizing from --refs
  when a lane is written with --paths-with '**/*.test.ts' --paths-with '**/*.snap'
  then the parser accumulates --rules, --refs and --optional only
   and every other key is overwritten by its last occurrence
   and the lane receives '**/*.snap' and sees not one .test.ts file
   and it denies that a test exists while the test sits on disk
```

🟡 **`[t5]` is the sharpest of the three, because the caller's form is REASONABLE.** repetition is
how `--refs` behaves in that same parser, so a caller who repeats `--paths-with` **generalized
correctly from the tool's own behavior** — and is silently wrong. `[t3]` punishes a typo and `[t4]`
punishes an omission; **`[t5]` punishes a correct inference.**

### the cost, by polarity — and one direction is dearer

from #366's four-round measurement on the three doubled lanes:

| polarity | count | what it cost |
|----------|-------|--------------|
| a false **blocker** — coverage denied a test that exists on disk | 2 | a round, reviewer budget, and a driver directed to author a test already written |
| a false clean **`0/0`** | 1 | a gap indistinguishable from a real pass |
| a **true** catch, by coincidence of the narrowed set | 1 | — |

the false blocker is the dearer, because it actively directs work. a driver who complies rather than
checks lands a duplicate test and calls it a repair.

⇒ **the class under all three: the parser guesses where it should refuse.** the repair is one arity
declaration — accumulate `--rules`/`--refs`/`--optional`, single-value for the rest, exit nonzero on
any violation. dispatched as bhrain#448.

an alias or a union repairs the instance and leaves the class open. an alias for `--paths-without`
fixes one typo and the next is still silent; a union for a doubled `--paths-with` fixes this shape
and the next doubled single-value flag is still handled quietly.

## `[t6]`'s fail-safe — the stone blocks, and it is not my design

```gherkin
[t6] the cut applies, is still not enough, and the fail-safe holds anyway
  given a repo whose code diff alone exceeds the ~750k gate
  when the mech-failhides lane runs WITH the structural default applied
  then the subject is smaller and still over the gate
   and compileReviewPrompt throws, so the lane emits NO numeric blocker/nitpick count
   and the guard cannot read a verdict, and does NOT assume zero
   and it grades the lane a 💥 malfunction
   and the malfunction is terminal-for-unlock, so level 3 still runs
   and THE STONE CANNOT PASS while that lane is broken
   and the driver is pointed at rule.always.diagnose-reviewer-malfunctions
   and that rule names the exact remedy: re-run the same rubric scoped
```

| layer | the guarantee | source |
|-------|---------------|--------|
| the output contract | *"if it finds no numeric count it can **NOT** assume zero... so an unreadable review is a `💥 malfunction` for that reviewer, and the stone blocks"* | `contract.reviewer-output` |
| the malfunction rule | *"terminal-for-unlock, **and it still blocks passage**... the stone cannot pass while it is broken"* | `rule.always.diagnose-reviewer-malfunctions` |

⇒ so a post-cut overflow is **loud in outcome** — the stone halts — and it **teaches the fix**.

**the evidence agrees.** #349's own report is of a stone **stuck for 9+ iterations**, never of one
that shipped ungraded. a silent pass never happened; a stuck stone did.

### the residual hazard is ergonomic

what the overflow **does** hide is its own **cause**:

> *"an overflowed lane returns terminal and unlocks the next level, so it reads much like a lane
> that ran"* — `rule.always.diagnose-reviewer-malfunctions`

a diagnosis hazard, not a passage hazard, and its fail-safe is the named remedy rather than a new guard.

## `[t7]` — the sharp critipath's fail-safe, walked rather than argued

`[t3]`–`[t5]` each show a scope flag misfire and **none of them ends in a catch**, because none can:
the edge is silent, so there is nobody to tell. a fail-safe by detection is unavailable here by
construction.

⇒ so the fail-safe must be a **bound on what the edge can reach**, and `[t7]` walks that bound under
the worst case the three misfires jointly produce:

```gherkin
[t7] the driver writes ALL THREE misfires, and no code file is lost
  given rhx review carries the structural default of [t1]
  when a code lane is written with every flag of [t3], [t4] and [t5] at once
  then each flag still misfires exactly as walked above
   and the default has already excluded .agent/**, .dream/** and .behavior/**
   and no .ts, .sh or .snap file outside those three trees is reachable by any of them
   and the stage lanes' own --paths-with '$route/*.yield.md' re-adds their subject regardless
   and the blast radius of all three misfires together is bounded to trees a named lane re-adds
```

🔴 **this is why the sharp cell is a design and not a hope.** the guarantee table beneath states why
each clause holds; the step is the walk, and the table is its proof.

## the coverage path fails safe by construction, not by detection

a silent coverage loss cannot be caught after the fact. a lane that quietly drops a file still
returns a verdict, and that verdict reads as clean. so a fail-safe that waits for someone to notice
the loss is no fail-safe at all.

the safety is structural, at rung 1 of `rule.prefer.prevent-over-correct`:

| the guarantee | why it holds |
|---------------|--------------|
| the default excludes **three named trees**, never a code path | no `.ts`, `.sh`, or `.snap` file outside those trees can be removed |
| an explicit `--paths-with` **overrides** the default | a lane whose subject is a route artifact re-adds exactly what it grades |
| the stage lanes bind `$route/1.vision.*.md` independently | their subject is unaffected by any change to a code lane |

⇒ the blast radius of a wrong exclusion is bounded to trees that a named lane re-adds. the cut
cannot reach what it must not touch.

🔴 **the precedence rule is what makes this work, and it is a design proposal in a repo we do not
own.** if bhrain implements the default as unconditional, a stage rubric cannot read its own
subject and #349 becomes undeliverable. that residual is priced in fulcrum F13 at 6%.

## what this proves

- 🔴 **an exclusion that does not exclude is worse than no exclusion**, because the guard config
  reads as protection. three distinct ways to write one — `[t3]`, `[t4]`, `[t5]` — and all three are
  silent.
- the layer matters more than the flag. this case opened as *"add a flag to two lanes"* and closed
  as *"fix the parser, add a default, and re-add one file"*. the same 48% cut, at the layer that can
  actually deliver it.
- blocklist, never allowlist — the deliverable set is open and per-repo; the non-deliverable set
  is closed and org-wide. an allowlist in a shared template fails to an empty target set, silently.
- the code/stage split is the whole design. `$route/1.vision.*.md` is *noise* to a code rubric
  and *the subject* to the experience-coverage rubric. the same files, two opposite verdicts, because
  the rubric differs.
- the overflow stalls the stone; it does not slip past it. what hides is the cause, never the
  outcome.
