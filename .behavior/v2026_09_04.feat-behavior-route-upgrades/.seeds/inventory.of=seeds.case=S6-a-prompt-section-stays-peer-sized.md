# S6 — a prompt's sections stay peer-sized; detail refs out

## .said

> and this should be condensed into a more equal-in-size section to the rest of the sections

> any details need to be reffed in. not appended here

> also, why is this at the top? … it should be furtehr below

## .settled

**a prompt's sections are peers, so their sizes are a signal.** one section that outgrows its
siblings tells a reader it matters more — and usually it merely accreted more edits.

three moves, and each names a different defect:

| the ask | the defect | the repair |
|---|---|---|
| *"equal-in-size"* | one section grew past its peers | condense to the peer size |
| *"reffed in, not appended"* | detail was appended where a pointer belonged | move it to the brief that owns it, cite by path |
| *"why is this at the top"* | a passage sits where the author wrote it | place it where its subject sits |

🔴 **a prompt accretes where a brief does not, and the mechanism is the ask.** every round that
sharpens one section appends to that section, so the growth is invisible per-edit and obvious when
the sections are read side by side. size relative to peers is the check the per-edit view cannot
make.

⇒ **the third move settles an ORDER question, not a size one.** an emit contract — a table of which
file holds what — is meaningless before the sections that produce those files are named. so it
belongs at the end, however early the author needed it.
