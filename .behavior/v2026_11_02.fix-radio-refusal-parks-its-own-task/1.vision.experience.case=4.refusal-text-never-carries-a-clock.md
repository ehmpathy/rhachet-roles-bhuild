# case=4 — the kept refusal never carries a clock, a token, or the command

feel: sharp · care: critipath · status: **the guard the new field owes** (the reason F10 of #605
kept no text at all)

## narrative

a clone drains its backlog. github refuses A, and this time its answer is noisy: a request id
and a clock value ride on the refusal line. the clone sets A aside and goes on with its round.
at the end it commits its work, and the commit goes through: the timestamp gate finds no clock in
A's record. the next day it drains again; github refuses A with the same words, and `git status`
shows A's record unchanged — no churn from the retry.

a later reader runs `get`. A's row has no `refusal:` line this time — the words held a clock, so
they were never kept — but it still reads `set aside (upstream:access)` with the amend and drop
fixes beneath. the reader takes the amend. the full noisy words were printed once, in the drain
that met them.

```
    then  A's record bytes are unchanged
  when  [t2] a later reader runs get
    then  A shows its class and its amend + drop fixes, and no `refusal:` line
given a backlog [B: a refusal whose stderr holds a token shape]
  when  [t0] the dispatcher drains
    then  B's record holds no token shape
```

## the mechanism, as an aside

the kept headline is the first line github said, with the echoed command cut
(`asRadioUpstreamFaultText`), bounded in length, and dropped whole — never half-masked — if it
holds a clock value or a token shape. it fails safe twice over: unsafe text never reaches disk,
and the fix lines never depend on the headline.
