# case=2 — a transient fault (rate limit or outage) still halts the drain

feel: sharp · care: critipath · status: **already true on main** (#605) — held by
`setRadioTaskRecordsDrainedByPush.case9.integration.test.ts` [case2] and
`setRadioTaskRecordsDrained.integration.test.ts` [case2]

## narrative

a clone holds four records. the head, A, is a create into a repo the bot has no grant on; B, C,
D sit behind it. the clone runs `rhx radio.task.queue drain`. github refuses A; the radio sets it
aside and delivers B. then github answers C with a rate limit. a rate limit binds the token, so
every record after C would meet it too: the radio halts at C, leaves D unsent and in line, and
says the next drain retries them.

on another day the same backlog meets an outage at C instead — github answers `HTTP 502`. an
outage binds github itself, so the radio halts there the same way.

## [tn]

```
given a backlog [A: create, access refused, at the head] [B] [C: rate limit] [D]
  when  [t0] the dispatcher runs `rhx radio.task.queue drain`      # the drain door (D3)
    then  A is set aside as upstream:access
    then  B delivers
    then  C halts the drain (upstream:rate-limit); D waits behind it, never sent
    then  the drain names the wall, and says the next drain retries C and D
    then  the drain exits 2
given the same backlog, but C meets an outage (HTTP 502)
  when  [t0] the dispatcher runs `rhx radio.task.queue drain`
    then  A is set aside; B delivers
    then  C halts the drain (upstream:transient); D waits behind it, never sent
    then  the drain names the wall, and says the next drain retries C and D
    then  the drain exits 2
```

## density

the densest single-actor drain: one drain crosses three boundaries — a refusal set aside, a
delivery past it, a wall that halts. it proves the line between "this record's own fault" and "a
fault every record would meet" in one pass. the centered walk across both actors is case=5.

## the guard

a 403 that says *secondary rate limit*, *abuse detection*, or *retry later* reads as
`upstream:rate-limit`, never as `upstream:access` — so a limit is never set aside as if it were a
refusal (`asRadioUpstreamReason.test.ts`). rate limit and outage share one halt rule
(`isRadioUpstreamReasonHalt`: `upstream:rate-limit` or `upstream:transient`).
