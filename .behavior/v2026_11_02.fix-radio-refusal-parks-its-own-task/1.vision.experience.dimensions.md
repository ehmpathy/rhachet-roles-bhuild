# experience dimensions — a permanent refusal parks its own radio task

## .actors

- the **dispatcher** — a clone or human that pushes a task, or drains the held queue
- the **later reader** — a clone or human that runs `radio.task.queue get` in another process,
  absent from the drain that met the refusal

the upstream (github) is a resource, not an actor. a second dispatcher in the same worktree is
the concurrency axis (D7), not a third actor.

## .dimensions

| # | dimension | values (closed) | why it is orthogonal |
|---|---|---|---|
| D1 | **fault** the upstream returns for one held record | `none` · `access` (the refusal) · `not-found` · `401` · `auth` (no token derived) · `fault` (unclassified) · `rate-limit` · `transient` · `refused` (a replay refusal: REFUSED for good) | what the upstream says is independent of where the record sits or who drains. the set is closed: it is every value `asRadioUpstreamReason` and `setRadioTaskRecordUpstream` can write |
| D2 | **position** of the faulted record in the backlog | `head` · `mid` · `tail` | the wedge exists only where records sit behind the faulted one |
| D3 | **entry** — what drives the delivery | `drain` (`radio.task.queue drain`) · `carrier` (a `radio.task.push` that flushes the backlog first) | two doors into one loop: the carrier calls the drain (`setRadioTaskRecordsDrainedByPush.ts:63`) |
| D4 | **op** of the held record | `create` · `edit` (`--exid`, `updateIssue`) | the measured refusals hit both: `repository.issues` (#511), `updateIssue` (#551, #591) |
| D5 | **history** of the record | `fresh` · `set aside` (a prior drain set it aside) · `legacy` (written before the headline field; every record held today) | a set-aside record meets every later drain; a legacy record is read by a newer install |
| D6 | **read** — how the later reader learns the state | `get` · `get --when hook.onStop` | the full list vs the one-line stop reminder |
| D7 | **concurrency** on one worktree's queue | `sole` · `concurrent drain` · `set / del mid-drain` · `get mid-drain` | two sessions can share one worktree; the records are files every session reads |
| D8 | **channel** of the record | `gh.issues` · `os.fileops` | only `gh.issues` calls github; `os.fileops` writes local files |
| D9 | **reader's act** after `get` | `amend` (`set --auth`) · `drop` (`del --why`) · `wait` | what the reader reads (D6) is apart from what the reader does next; each act is printed as a fix line |

## .the walked product

D1 × D2 is the core plane. the other axes are walked as families: each varies one axis against
the plane, and the code shows the plane holds unchanged across that axis (cited per row).

| D1 \ D2 | head | mid | tail |
|---|---|---|---|
| none | deliver, oldest first | same | same |
| **access** | set aside; the rest deliver (main since #605; halted before) | set aside; before + after deliver | set aside; before already delivered |
| not-found · 401 · auth · fault | set aside; the rest deliver | same | same |
| rate-limit · transient | halt; all behind wait | halt; before delivered | halt |
| refused | REFUSED for good; the rest deliver | same | same |

- **D3**: one loop, two doors — the carrier calls the drain. each door gets a demo: carrier in
  case=1, drain in case=2.
- **D4**: `create` and `edit` take one fault branch (`setRadioTaskRecordUpstream.ts:176-201`);
  an edit has one more call before it (`gh issue view`), whose fault takes the same branch.
- **D5**: a set-aside record is retried each drain: same fault → set aside again (same bytes);
  a different fault → the new reason and headline; `none` → it delivers, reason and headline
  cleared in the one write.
- **D6**: `get` shows the `refusal:` line; the stop line counts by class and shows no headline.
- **D7**: `withRadioDrainLock` serializes every drain, `set`, and `del` in a worktree, across
  processes; the second reads the backlog only after the first has written. the headline is
  written in the settled write, under that lock. `get` takes no lock — a read need not — and
  cannot see a torn record: every record write is a temp file plus a rename
  (`daoRadioTaskRecord/index.ts:375-387`), so a reader sees the old record or the new one, and the
  headline flips with its reason, in one file.
- **D8**: an `os.fileops` record makes no github call, so `access` cannot occur on it.
- **D5 `legacy`**: a record written before the field reads back `null`; `get` renders it as
  case=4 [t2] does (class + fixes, no `refusal:` line); its next drain writes the headline.
- **D9**: `amend` → the next drain delivers it (e8); `drop` → the record is gone, its why kept,
  and `get` no longer lists it (e22); `wait` → each drain retries it (e7, e16).

the inventory (`1.vision.experience.case=_.md`) verdicts each family and each cell a demo needs;
it does not list all 9 × 3 × 2 × 2 × 3 × 2 × 4 × 2 × 3 combinations (D1 … D9), since the
families above show which axes leave the outcome unchanged.
