# case=5 — read the queue, with keys

feel: happy · care: critipath

## .narrative

a fleet clone ends a long session. its stop line said "3 tasks held · 1 set aside · 1 at a
gate", and it wants to know which, and what to do. it runs `radio.task.queue get`.

three rows come back, oldest first. the first, an update to #599, reads "set aside" with its
fault code, `upstream:access` — the robot may not edit it — and two commands beneath it, each
with the key already filled in. gh's own words stay off disk (F10); the drain that hit the fault
printed them. the second waits at sandpine's gate; the line under it says a human must lift
it, and how. the third has not been reached yet. the clone copies the `del` command for the #599
row, since the supersede note already landed, and leaves the gate to the human. before, with
`radio.task.held`, it saw the same three titles with no key, and no verb could touch one.

later its human, at a terminal, reads the stop line at the end of the session: one line, counts
by state, and it never held the session open.

## .timeline

```
given the queue holds, oldest first
  - [A] update #599 → bhuild, set aside, upstream:access
  - [B] create "lesson reminders" → sandpine/svc-lessons, held at gate:org(sandpine)
  - [C] create "board rentals" → bhuild, not reached

when [t0] the fleet clone runs radio.task.queue get
  then one row per record, oldest first, each with key · label · target · state · reason
  then A carries its last fault and its two fixes (set --auth, del)
  then B carries its lift (human): radio.uses --org sandpine allow
  then the tail names the next move: radio.task.queue drain
  then exit 0; no network call

when [t1] the session stops, and the stop hook (system) runs radio.task.queue get --when hook.onStop
  then one line: "🦫 3 tasks held · 1 set aside · 1 at a gate · …", or naught when none
  then exit is never 2
```

a fourth state, `halted (upstream:rate-limit)`, marks a record that waits behind a wall
(case=6); it carries no fix line, since a retry later is the fix.
