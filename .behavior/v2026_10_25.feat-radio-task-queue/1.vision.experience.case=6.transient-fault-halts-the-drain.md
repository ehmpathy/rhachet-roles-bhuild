# case=6 — a transient fault halts the drain, as today

feel: sharp · care: critipath · #511 ("a transient failure keeps today's oldest-first order and stops the drain, as now")

⚠️ **an exception to the wish's literal words, flagged to the wisher (F1).** the wish says "a
record that faults is set aside, named, and the rest still deliver (no head-of-line block)". this
case keeps one halt: a rate limit or a github outage stops the drain. #511, which the wish folds
in, asks for exactly that. the vision reads the wish's "no head-of-line block" as *no one record
blocks the rest* — a wall every record behind would also hit is not one record. if the wisher
meant the words with no exception, the rework is clean: set the transient record aside like any
other, and let the rest each meet the wall (F1 (a)).

## .narrative

a fleet clone pushes its fourth task of the hour and gets exit 2. the output's first row reads
"⏸ halted — create → X (rate limit)", with github's own words beneath it, and two more rows
"behind it". the fix line says to wait; the next push or drain retries them in order. the clone
checks: one of the two behind is an update to an issue the first one creates — had the line
skipped ahead, that update would have hit an issue not yet there. it leaves the queue be, and an
hour later its next push carries all three out, in order.

(why the whole drain, not just repo X: a rate limit is a fact about the token, so every repo the
token reaches meets the same wall; an outage is wider still.)

## .timeline

```
given the queue holds, oldest first
  - [A] create → X   (stub gh: API rate limit exceeded)
  - [B] update → X
  - [C] create → Y
  and radio.uses allows both

when [t0] the fleet clone runs radio.task.queue drain
  then A held, reason upstream:rate-limit, and the drain halts
  then B and C held behind A, unsent, with A's reason
  then exit 2

when [t1] the rate limit lifts, and the clone runs radio.task.queue drain
  then A, B, C deliver in that order

given instead [A] faults on access (not accessible by integration)
when [t2] the clone runs radio.task.queue drain
  then A is set aside; B and C deliver (case=1)
```

## .the output sketch (fails safe: it names the wall and the next move)

```
🦫 drained the radio
   ├─ ⏸  halted     create → X (rate limit)
   │  ├─ why: API rate limit exceeded
   │  └─ fix: wait; the next push or drain retries in order
   ├─ ⏸  behind it  update → X
   ├─ ⏸  behind it  create → Y
   └─ 0 delivered · 3 wait on the rate limit
```

## .the line between halt and set aside

| fault | scope of the wall | so |
|---|---|---|
| rate limit | the token — every repo it reaches | halt the drain |
| network, 5xx | github itself | halt the drain |
| access refused, not found, 401, any other | this record (this issue, this repo under this auth) | set aside this one record |
