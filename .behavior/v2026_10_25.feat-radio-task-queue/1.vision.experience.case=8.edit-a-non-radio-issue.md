# case=8 — an update the radio cannot apply: a non-radio issue, or a repo out of reach

feel: sharp · care: critipath · #603, #511

## .narrative

two updates fail today for reasons the clone cannot see.

one targets `sandpine/svc-lessons#41`, which a human opened by hand ("lesson reminders send
twice"); its title has no `🎙️ task -` prefix. the dao throws `issue is not a radio task`, the
replay reads it as a refusal, and the record closes as REFUSED. that verdict is right — the radio
edits only issues in its own frame, so it never rewrites a human's words — but the output must
say so plainly, and name the move: edit #41 by hand, or `del` the record.

the other targets a repo that gh cannot find under the record's auth (the robot app has no
install there). the dao reads gh's repo-lookup error as "issue absent", so the update is REFUSED
as `task not found`. that verdict is wrong: under `--auth as-human` the repo may well be in
reach. after: it is set aside as `upstream:not-found`, with the as-human fix.

## .timeline

```
given sandpine/svc-lessons#41 was opened by hand, title "lesson reminders send twice"
  and radio.uses allows sandpine

when [t0] radio.task.push --via gh.issues --into sandpine/svc-lessons --exid 41 --status DELIVERED
  then the record is REFUSED, reason "not a radio task: #41"
  then the output says the radio edits only radio issues, and names the fix: edit #41 by hand
  then #41 is untouched
  then the record leaves the queue (a refusal is settled; no del is owed)

when [t1] radio.task.push --via gh.issues --into sandpine/svc-lessons --exid 9999 --status DELIVERED
  and #9999 does not exist, the repo is in reach
  then the record is REFUSED, task not found (a true absence)

when [t2] the record's auth cannot see sandpine/infrastructure at all (gh repo-lookup error)
  then the record is set aside as upstream:not-found, not REFUSED
  then the fix names `radio.task.queue set --key <K> --auth as-human` (needs a gh login on this host)
```

## .out of scope (F9)

an `--exid` update that edits a non-radio issue — its body or title, verbatim, with no radio
frame. the measured case (#599) is a radio issue, so it does not need this. it is flagged for the
wisher in F9; the rework is clean.
