# case=8 — an update the radio cannot apply: a non-radio issue, or a repo out of reach

feel: sharp · care: critipath · #603, #511

## .narrative

a fleet clone fixed "lesson reminders send twice" in sandpine/svc-lessons. a human opened that
issue, #41, by hand. the clone pushes `--exid 41 --status DELIVERED` to close it. today the push
comes back REFUSED with three bare words — "not a radio task" — and the clone cannot tell if it
typed the wrong number or the radio is broken. after: the refusal says the radio edits only
issues in its own `🎙️ task -` frame, so it never rewrites a human's words, and the fix is to
close #41 by hand. the clone leaves a note for its human and moves on; the record is settled, so
naught waits in the queue.

the same clone then pushes an update into sandpine/infrastructure, a repo the robot app was never
installed on. today that comes back REFUSED as "task not found", and the clone, sure the issue is
gone, drops the work. after: the record is set aside as "repo not found under this auth", with
the fix the clone can act on — `set --auth as-human`, if this host has a gh login — and the
update lands on the next drain.

## .timeline

```
given sandpine/svc-lessons#41 was opened by hand, title "lesson reminders send twice"
  and radio.uses allows sandpine

when [t0] the clone runs radio.task.push --via gh.issues --into sandpine/svc-lessons --exid 41 --status DELIVERED
  then the record is REFUSED, reason "not a radio task: #41"
  then the output says the radio edits only radio issues, and names the fix: close #41 by hand
  then #41 is untouched
  then the record leaves the queue (a refusal is settled; no del is owed)

when [t1] the clone runs radio.task.push --via gh.issues --into sandpine/svc-lessons --exid 9999 --status DELIVERED
  and #9999 does not exist, the repo is in reach
  then the record is REFUSED, task not found (a true absence)

given a held update → sandpine/infrastructure #7, auth = default robot
  and the robot app is not installed on sandpine/infrastructure (gh repo-lookup error under that auth)
when [t2] the clone runs radio.task.queue drain
  then the record is set aside as upstream:not-found, not REFUSED
  then the fix names `radio.task.queue set --uuid <K> --auth as-human` (needs a gh login on this host)
```

## .out of scope (F9)

an `--exid` update that edits a non-radio issue — its body or title, verbatim, with no radio
frame. the measured case (#599) is a radio issue, so it does not need this. it is flagged for the
wisher in F9; the rework is clean.
