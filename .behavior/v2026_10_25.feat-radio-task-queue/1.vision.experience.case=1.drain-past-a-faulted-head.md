# case=1 — drain past a faulted head

feel: sharp · care: critipath · the measured #599 case

## .narrative

a surdirector clone holds two records for `ehmpathy/rhachet-roles-bhuild`: an update to #599
(the robot app may not edit it), then a new create — the supersede note. today the update
faults, halts the line, and the create never goes out. a seat moves the file by hand.

with the queue in place, the clone runs `radio.task.queue drain`. the update faults again; it is
**set aside** — named, with the gh error verbatim and the fix. the line moves on, and the create
lands as a new issue. the clone reads one tree and knows: one delivered, one waits for a fix,
and which two moves fix it.

## .timeline

```
given a worktree whose queue holds, oldest first
  - [A] update #599 → ehmpathy/rhachet-roles-bhuild, auth = default robot
  - [B] create "supersede #599" → ehmpathy/rhachet-roles-bhuild
  and radio.uses allows ehmpathy
  and the stub gh refuses edit of #599 with `Resource not accessible by integration (updateIssue)`

when [t0] radio.task.queue drain
  then B delivers as a new issue
  then A stays QUEUED, reason upstream:access, set aside
  then the output names A's key, the gh error, and the fix:
       `radio.task.queue set --uuid <A> --auth as-human` · or `del --uuid <A> --why "..."`
  then exit 2 (a record still waits)

when [t1] radio.task.queue drain again, with no change since t0
  then A is retried once and set aside again, named again
  then B is not re-sent (DELIVERED answers first)
```
