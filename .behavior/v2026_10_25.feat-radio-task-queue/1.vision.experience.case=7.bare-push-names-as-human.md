# case=7 — a bare push whose robot auth fails names as-human

feel: sharp · care: critipath · #513

## .narrative

a fleet subagent pushes with no `--auth`. the default stays as-ehmpath (the commander's rule).
the keyrack token is absent, so the push is held. the output says why in one line and names the
unblock: `--auth as-human`, or `radio.task.queue set --key K --auth as-human` for a push already
held. no behavior changes once the robot token works.

## .timeline

```
given the keyrack holds no EHMPATH_BEAVER_GITHUB_TOKEN

when [t0] radio.task.push --via gh.issues --into ehmpathy/rhachet-roles-bhuild --title "..." --description "..."
  then the push is held QUEUED, reason upstream:auth, exit 2
  then the output names the cause (keyrack status: absent) and the unblock (--auth as-human)
  then the output names `radio.task.queue set --key <K> --auth as-human` for this held push

when [t1] radio.task.push ... --auth as-robot:env(TOKEN)
  then the push uses that mode, not the default
```

## .the extant state

the keyrack nudge already names `--auth as-human` (`getKeyrackAuthFailureMessage.ts`). this
case adds only the `queue set` line and the three clamps #513's own body lists:

| #513 label | the clamp |
|---|---|
| caseA | a bare push still goes as-ehmpath — this case's precondition |
| caseB | a bare push whose as-ehmpath auth fails is held, and names the auth cause and `--auth as-human` — this case's [t0] |
| caseC | an explicit `--auth` keeps its mode — this case's [t1] |

where a clamp already exists in `src/contract/cli/radioTaskPush.integration.test.ts` for one of
these, the pr cites its test name rather than add a duplicate.
