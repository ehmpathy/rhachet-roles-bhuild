# 1.vision.experience.dimensions — radio.task.queue

the experience space of every actor that reads, edits, or drains the radio queue.

## .the dimensions

each axis is a closed set. each value names one concept.

| # | dimension | values |
|---|---|---|
| A | actor | fleet clone (no tty) · human at a terminal · system: the stop hook (no tty, no prompt, must never exit 2) |
| V | verb | `get` · `set` · `del` · `drain` · `push` (its implicit drain) |
| M | mode of `get` | list · `--when hook.onStop` |
| N | entry name | `radio.task.queue` · `radio.task.held` (the alias, one release) |
| Q | queue shape | empty · all deliverable · one fault, the rest deliverable · a transient fault ahead of others · mixed backlog (one or more faults, of any classes, + gate-held + deliverable, across targets) · two updates to one issue, the earlier still held |
| F | fault class of one record's send | none · access refused (403, `not accessible by integration`) · repo not found under this auth · issue absent in a reachable repo · outside the radio frame · auth not derivable (keyrack) · token rejected (401) · rate limit (token-wide wall) · network or 5xx (github-wide wall) · refusal (a constraint upstream keeps) |
| G | gate (radio.uses) for the record's target | open · shut |
| U | on-disk auth of the record | null (the default, `as-robot:via-keyrack(ehmpath)`) · `as-robot:via-keyrack(<owner>)` · `as-robot:env(<VAR>)` · `as-robot:shx(<cmd>)` · `as-human` |
| O | drain auth override | none · any one of the five U modes |
| K | key a verb names | held (QUEUED) · settled (DELIVERED · REFUSED · DROPPED) · absent |
| C | concurrency | alone · a drain runs in this worktree (another clone's, or this clone's own in another shell) · a push re-types this record mid-send |
| T | time wall of one drain | within bounds · send budget spent (records left `not attempted`, "run … drain again", exit 2) · drain deadline near the lock lease (no new record starts) · a gh call past its timeout (the record set aside as `upstream:transient`) · lock acquire past 2 min (`ConstraintError`, names the fix) |

U is closed by the auth grammar itself: `asGithubAuthMode.ts` parses exactly these five. `set` and
`drain` refuse any other string before they act. a push still records an unknown string, and holds
it as `upstream:auth` with the valid modes named, so the push is never lost; `set --auth` repairs it.

K's settled values leave the queue: `get` lists only held records. a REFUSED record shows once, in
the drain that closed it; a DROPPED one in the `del` that dropped it (grid 4). the settled values
split under `del`: a DROPPED key converges (a retried `del` is a no-op), while a DELIVERED or
REFUSED key is refused. a DROPPED key also splits under `push`: a push of the same task re-queues it.

a second clone is not an actor value: it is a fleet clone at C ≠ alone. a clone on old briefs is
not one either: it is any actor at N = `radio.task.held`.

`F` covers every update-target state the earlier draft held as its own axis (radio issue,
non-radio issue, absent issue, unreachable repo): each is a fault class of the send, or none.

## .the collapse rules — why the product is walkable

the raw product is large. six rules fold it to a handful of grids, and each rule is a fact of
the code or a stated decision, so no tuple is lost — each lands in the cell its rule names.

| # | rule | from | folds |
|---|---|---|---|
| R1 | a shut gate holds the record before any send; its fault class and auth never matter | `setRadioTaskRecordUpstream.ts` (the gate is read first) | G=shut × F × U × O → one cell |
| R2 | an empty queue sends naught | logic | Q=empty × F × G × U × O → one cell per verb |
| R3 | a record's outcome depends only on its own G, F, and the auth it sends with; the line has two effects: a halt, and the same-issue wait — an update whose `(repo, exid)` matches an earlier record still held (not at a gate) waits behind it, unsent | `setRadioTaskRecordsInLine` fold; `setRadioTaskRecordNextInLine`; F1 | Q folds to: the per-record matrix + the halt rule + the same-issue wait |
| R4 | the auth a send uses = O when O is set, else U; the four robot modes differ only in how the token is derived, and a failed derivation is F = auth not derivable | F3; `getGithubTokenByAuthArg.ts` | U × O → one send-auth of two kinds, robot or as-human; it moves F only for the auth-sensitive classes (access, not found, 401) |
| R5 | `set`, `del`, `get` never send; `set` and `del` read only the key, the record, and the lock — no tty, no auth, no gh — so they are actor-invariant | the contract | `set` / `del` cross only K, G, C; `get` crosses A, M, N, Q, C |
| R6 | `M` and `N` bind only `get` | the contract | M × N × Q → the reminder grid |

## .the grids that remain

| grid | axes | where verdicted |
|---|---|---|
| per-record outcome | F × G × send-auth | `case=_` — the per-record matrix, every row |
| line rule | Q (where the halt sits; which issue an update names) | `case=_` — the line matrix, every Q value |
| key verbs | V∈{set,del} × K × C (actor-invariant, R5) | `case=_` — every row |
| read + reminder | M × N × Q (as empty / non-empty) × A × C | `case=_` — every row |
| actors | A × feel | `case=_` — every cell answered |

## .the axis that does the work

F decides halt scope. today every fault halts the whole line. the vision splits F in two:

| fault class | halt | why |
|---|---|---|
| rate limit | halts the drain | the wall is the token: every repo it reaches |
| network or 5xx | halts the drain | the wall is github itself |
| every other class | halts naught; the record is **set aside**, named with its fix | the wall is this record: this issue, or this repo under this auth |

rate limit and network/5xx share a halt and differ in their fix text ("wait for the reset" vs
"wait for github"), so they stay two values.
