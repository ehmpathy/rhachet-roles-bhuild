# 1.vision.experience.case=_ — the inventory

every cell of the walked product, verdicted. the axes and the collapse rules (R1–R6) that fold
the raw product to these grids live in `1.vision.experience.dimensions.md`. each grid below is
walked whole: every value of its axes has a row.

care = freq × cost. verdicts: **demoed** (a case file) · itemized (on record, no demo) ·
**forbidden** (the actor may try; the behavior refuses) · **impossible** (no attempt can occur).

## .grid 2 — the line: Q, for `drain` and for `push`

R3: each record takes its grid-1 fate; the line adds the halt, and the order of updates to one
issue: an update whose `(repo, exid)` matches an earlier record still held (not at a gate) waits
behind it, unsent. a gate-held record ahead adds no wait: the same repo meets the same gate, so
the update behind is held at that gate, its gate reason kept. `push` differs only in that this
push's own fate leads the output and sets the exit.

| Q | `drain` | `push` (its own target's gate open) | feel · care | verdict |
|---|---|---|---|---|
| empty | "naught held", exit 0 | as today: this push alone | happy · alterpath — a no-op; its break would show at once and costs naught | itemized |
| all deliverable | all deliver oldest first, exit 0 | all deliver, this push in its turn | happy · critipath — the core deliverable | **demoed** case=9 [t0] (C, D, and the push deliver) · extant clamp: the #409 suite |
| one fault, the rest deliverable | the fault set aside, the rest deliver, exit 2 | the rest and this push deliver, exit 0 | sharp · critipath | **demoed** case=1 (the measured #599) |
| a transient fault ahead of others | halts at it; every record behind waits in order, exit 2 | this push waits too, exit 2 | sharp · critipath | **demoed** case=6, case=9 [t2] |
| mixed backlog across targets (one or more faults, any classes, + gate-held + deliverable) | each per grid 1 | each per grid 1; this push lands | sharp · critipath — the densest | **demoed** case=9 [t0] |
| two updates to one issue (`CLAIMED`, then `DELIVERED`), the first set aside | the first set aside; the second waits behind it, QUEUED and unsent (`behind:<key> (same issue #N)`), never refused, shown as a wait with no fault and no fix of its own; updates to other issues and other repos still go | the same; this push lands; a pushed record that is itself behind points to the record ahead | sharp · critipath — a `DELIVERED` sent past its set-aside `CLAIMED` is refused upstream and closed for good, so the issue ends in the wrong state | **demoed** case=10 · clamp `setRadioTaskRecordsDrainedByPush.case9.integration.test.ts` [case3] |

| a long line: the send budget spent, or the deadline near the lock lease (T) | no new record starts; each left reads `not attempted`, the output says "run `rhx radio.task.queue drain` again", exit 2; naught lost, order kept | the same; this push waits in its turn, exit 2 | sharp · alterpath — the next drain carries the rest; the bound keeps the lock lease from a lapse mid-send | itemized — clamped `setRadioTaskRecordsDrained.sendLimit.integration`, `setRadioTaskRecordsDrained.deadline.integration`, `asRadioDrainSections.test` [case8] (the text) |

| (any) — the `push` row: its own target's gate shut | — | this push held at gate; no drain runs | sharp · critipath — the radio's core bound | **demoed** case=4 (the same gate rule, R1) · extant clamp |

a backlog of many faults with no gate-held record is not its own value: by R3 each record's fate
is its own, so it is case=9 [t0] less record E, and grid 1 verdicts every class it could hold.

## .rank by boundary-density

case=9 crosses the most boundaries (two set-aside classes, a gate, deliveries past each, the
carrier push, the exit code, and in [t2] the drain-wide halt) — it is the center, and the shape
of the acceptance journey. case=1 is the measured incident, narrowed to one boundary. case=6
