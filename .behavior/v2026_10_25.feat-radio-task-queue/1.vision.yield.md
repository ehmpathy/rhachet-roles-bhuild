# 1.vision — a clone can read, edit, and drain the radio queue

## .the outcome world

### before

a push that radio.uses blocks, or that upstream faults on, is held under `.behavior/.radio/`.
the next open push delivers the backlog oldest first — and **any** upstream fault halts the whole
line, in every route, for every target. `radio.task.held` lists what waits, with no key, so no
verb can name one record. the one cure is a hand move of a json file.

measured 2026-10-25: one update to bhuild#599 faulted (`Resource not accessible by integration
(updateIssue)`) and held every later push to rhachet-roles-bhuild.

### after

```
radio.task.queue get                                   # what waits: key · target · state · last fault · fix
radio.task.queue set   --key K --auth as-human         # amend one held record
radio.task.queue del   --key K --why "superseded"      # drop one, body and why kept
radio.task.queue drain [--auth as-human]               # deliver now; a fault sets one record aside
radio.task.queue get   --when hook.onStop              # the stop line, moved here
```

a day in the life: a surdirector clone pushes the supersede note for #599. the push delivers it;
the #599 update, which the robot may not edit, is **set aside** and named with two fixes. the
clone runs `set --key 3f9a… --auth as-human`, then `drain`. the edit lands under the human's gh
login. no file was moved by hand.

### the aha

a fault is a fact about **one record** — unless the wall is the token or github itself (a rate
limit, an outage), which no record can pass. never about the queue. once the drain treats it that way, a queue can always be read, amended, and emptied
with verbs.

## .the contract

| verb | does | sends? | exit |
|---|---|---|---|
| `get` | list held records, oldest first, each with its key | no | 0 |
| `get --when hook.onStop` | one line, or naught | no | never 2 |
| `set --key K [--auth A] [--description D]` | amend one QUEUED record; place in line kept | no | 0 · 2 if K absent or settled |
| `del --key K --why W` | mark one QUEUED record DROPPED; body and `dropped: W` kept on disk | no | 0 · 2 if `--why` absent, K absent or settled |
| `drain [--auth A]` | deliver every held record oldest first, under its own gate | yes | 0 when none wait after · 2 when any wait |
| `radio.task.push` | as today; its drain gains the new halt scope | yes | as today |
| `radio.task.held` | alias of `queue get`, one release, with a rename notice | no | as `get` |

`set`, `del`, and `drain` each hold the worktree drain lock (`withRadioDrainLock`), so a drop or
an amend never interleaves with a send. `get` reads without it.

halt scope (the head-of-line fix):

| fault | effect |
|---|---|
| rate limit, network, 5xx | **halts the drain**, as today (#511) — the wall is the token or github itself, so every record behind it would meet it too |
| access refused, not found, 401, unknown | **sets aside** that one record; the line moves on |
| refusal (a constraint upstream keeps) | REFUSED, as today |
| auth not derivable (keyrack) | set aside, as today (`halt: false`) |

new reasons: `upstream:access`, `upstream:not-found`, `upstream:transient` (F8). the transient
class (network, 5xx) has no detector today; `asRadioUpstreamReason` knows only 401 and rate limit.

`--auth as-human` already exists on push (since #80, `asGithubAuthMode.ts`); the gap is a drain
that can use it and a verb that amends a held record to it.

edit of an extant issue (#603). the measured case, #599, is a radio issue a human opened; the
robot app may not edit it, the human's gh login may. so the cure is auth: `set --auth as-human`,
or `drain --auth as-human`, over the extant `--exid` path. two edges sit beside it:

| edge | today | after |
|---|---|---|
| an issue outside the radio frame (no `🎙️ task -` title) | `get.one.byPrimary` throws `issue is not a radio task` → REFUSED, with that bare text | still REFUSED — the radio does not rewrite a human's issue — but the output names the rule and the fix (edit by hand). a verbatim edit is out of v1 (F9) |
| a repo that gh cannot find under the record's auth | `byPrimary` returns null on gh's repo-lookup error → `task not found` → REFUSED for good | set aside as `upstream:not-found`, since another auth may reach it (F8) |

## .mental model

- to a friend: *"the radio has an outbox now. you can look in it, fix a letter, tear one up
  with a note why, or mail them all — and one bad address no longer jams the box."*
- the metaphor is a mail outbox; a set-aside record is a letter returned to sender, left on top
  with the reason clipped to it
- their words: "stuck", "jammed", "the queue". our words: held, set aside, halt, gate. `get`
  says "set aside" in plain text beside each such record, so the human term and ours meet

## .evaluation

| goal (wish) | met by |
|---|---|
| get: every record, state, last fault | `get`, case=5 |
| set: amend a held record | `set`, case=3 |
| del: drop with a kept reason | `del`, case=2 |
| drain: oldest first, fault set aside, rest deliver (#511) | halt scope, case=1, case=6 |
| push and drain take `--auth as-human` (#513) | push: extant; drain: `--auth`, case=3; nudge: case=7 |
| push edits an extant issue with as-human (#603) | extant `--exid` path + `set --auth` / `drain --auth`, case=3; its edges, case=8 |
| radio.uses gate stays | case=4; `set`/`del` never send |
| no github write outside the radio | every send goes through `setRadioTaskRecordUpstream` |
| each fault path a clamp, red before, green after | one clamp per demo; case=1 and case=6 are red on main today |

pros: verbs replace hand edits; one bad record costs one record; order holds where it matters
(a transient wall stops the line, as today); every verb is local-first and gate-bound.

cons: a set-aside record costs one failed gh call per drain (F2). a new command name to learn;
the alias softens one release. `--auth as-human` cannot run in tests (extant guard), so its case
is proven when the override auth reaches the send, not by a real gh login.

pit of success: `del` refuses without `--why`; `set`/`del` on a settled or absent key name
`queue get`; a set-aside record's fix is printed as a copy-paste command; `drain` at a shut gate
names the lift and sends naught.

## .what is awkward?

- **two fault rules in one drain.** a reader must learn that a rate limit or outage stops the
  line and every other fault does not. the drain output names which ("halted" vs "set aside"),
  so the rule shows where it acts
- **a halt still blocks a record under another auth.** a rate limit on the robot token stops a
  record queued as-human behind it, though its auth is clear. a per-auth halt would cure that;
  it is a clean rework, left out for want of a case (F1)
- **a re-push already amends a held record.** `asRadioTaskRecordFromPush` lets the push's own
  fields win, so a re-push with `--auth as-human` re-types the auth today. `set` earns its place
  by not needing the title and body again — and a re-push after a `set` resets what `set` changed
- **"set aside" is a state with no field.** a set-aside record is QUEUED with an `upstream:*`
  reason that is not rate-limit. that keeps the record shape unchanged, but the term lives only in
  the render
- **F3 departs from a stated ask.** #511 wanted the carrier push to lend its auth. the vision
  refuses that for safety, and offers `drain --auth` instead — one more flag to know
- **"edit an issue it did not open" has two senses.** the vision meets the sense the evidence
  supports (the robot did not author it) and refuses the other (the radio did not frame it). if
  the wisher meant the second, case=8 [t0] flips from a named refusal to a verbatim edit (F9)
- **`--auth as-human` is untestable as-is.** the extant test-env guard forbids it. the clamp
  proves the override reaches the send under a robot env token; the as-human branch keeps its
  own unit
