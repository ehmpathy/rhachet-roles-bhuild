# case=11 — `drain --auth <x>` refused, no fallback (sharp · critipath)

## narrative

bert drains his queue with `--auth as-robot:env(SANDPINE_BOT_TOKEN)` because he wants this batch
filed as the surf school's bot and as no one else. the token was rotated an hour ago, so github
refuses it. his gh login is right there, but he chose. every record stays held with the fix,
none quietly lands under his own name, and the drain tells him what to do.

## [tn] sketch

```
given two held records, auth null
  and SANDPINE_BOT_TOKEN is set, but github refuses it (401)
  and gh is logged in, and GITHUB_TOKEN is set (ambient is available)
  when [t0] `rhx radio.task.queue drain --auth 'as-robot:env(SANDPINE_BOT_TOKEN)'`
    then both records stay held with reason upstream:401
    then each detail names the fix: re-run with another --auth, or fix the token at its source
    then ambient is never read (no GITHUB_TOKEN sent, no `gh auth token` call)
    then no fallback line prints; the extant `drain --auth` notice still names the override
    then the drain exits 2
```

records with auth null take the fallback on a bare drain (case=4); the override makes the
whole drain a chosen-auth drain, so none do here.
