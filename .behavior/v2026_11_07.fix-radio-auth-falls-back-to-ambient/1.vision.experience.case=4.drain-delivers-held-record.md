# case=4 — drain delivers a record held on an absent bot token (happy · critipath)

## narrative

yesterday, before this change, a push held a record with `upstream:auth`: the bot token was
absent. today the next `drain` (or the next push, which drains first) reads that record, finds
its auth is the default, falls back to the ambient credential, and delivers it. the human did
not amend the record.

## [tn] sketch

```
given a held record with auth null and reason upstream:auth
  and keyrack still reports the bot token absent, and gh is logged in
  when [t0] `rhx radio.task.queue drain`
    then the record is delivered via the gh login
    then the record settles DELIVERED
    then one line names the fallback for the drain:
      🦫 delivered via the gh login; the ehmpath bot token was absent
  when [t1] `rhx radio.task.queue get`
    then the record no longer waits
```
