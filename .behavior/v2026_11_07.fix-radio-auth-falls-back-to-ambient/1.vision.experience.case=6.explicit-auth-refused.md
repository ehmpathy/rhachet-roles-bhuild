# case=6 — explicit `--auth` refused, no fallback (sharp · critipath)

## narrative

a seat passes `--auth as-robot:env(SANDPINE_BOT_TOKEN)` on purpose — it wants the task filed as
that bot, or not at all. github refuses the token. the push must not quietly deliver it as the
human's gh login; it fails, holds the record, and names the fix, exactly as today.

## [tn] sketch

```
given SANDPINE_BOT_TOKEN is set but github refuses it (401)
  and gh is logged in (an ambient credential is available)
  when [t0] `rhx radio.task.push --via gh.issues --into sandpine/svc-lessons --title "..." --description "..." --auth as-robot:env(SANDPINE_BOT_TOKEN)`
    then the record is held with reason upstream:401
    then the ambient credential is never read
    then the fault names the fix: re-run with `--auth as-human`, or fix the token at its source
    then no fallback line prints
```

the same holds for `drain --auth <x>` and for a record whose stored auth is not null.
