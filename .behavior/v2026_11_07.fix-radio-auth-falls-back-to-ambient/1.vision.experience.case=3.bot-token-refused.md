# case=3 — bot token refused, ambient accepted (happy · critipath)

## narrative

on a grove the bot token has expired: keyrack grants it, github answers 401 bad credentials. the
grove's git config names the robot user, and `GITHUB_TOKEN` in the env holds its token. the push
sends once under the bot, is refused, resends under `GITHUB_TOKEN`, and lands one issue — the
upstream findsert keeps a resend from a double.

## [tn] sketch

```
given keyrack grants the bot token but github refuses it (HTTP 401: Bad credentials)
  and GITHUB_TOKEN is set in the env and github accepts it
  when [t0] `rhx radio.task.push --via gh.issues --into sandpine/svc-lessons --title "..." --description "..."`
    then the first send under the bot token is refused
    then the same record is resent under GITHUB_TOKEN and created
    then exactly one issue exists upstream for the title
    then one line prints:
      🦫 delivered via the GITHUB_TOKEN env; github refused the ehmpath bot token (401)
```

a 403 that refuses the write (`resource not accessible`, `must have admin rights`) takes the same
path, and its line says `(403)`. a 403 rate limit does not: it halts, as today.
