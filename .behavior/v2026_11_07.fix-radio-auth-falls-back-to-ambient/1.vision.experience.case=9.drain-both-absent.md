# case=9 — drain, bot token absent, ambient absent (sharp · critipath)

## narrative

bert sets up a new laptop and, before his first login, a clone drains two follow-ups it queued.
there is no bot token in keyrack, no token in the env, no gh login. the clone sees both records
still held, and under each, the two credentials it tried and one command per credential that
would unblock it. it does not guess, retry in a loop, or lose a record. it hands bert the two
commands. bert runs `gh auth login`; the clone drains again and both land, with the line that
says they went out under bert's login.

## [tn] sketch

```
given two held records, auth null
  and keyrack reports the bot token absent
  and no GH_TOKEN, no GITHUB_TOKEN, and gh has no login
  when [t0] `rhx radio.task.queue drain`
    then both records stay QUEUED with reason upstream:auth
    then each record's detail names both credentials, each with its fix:
      ├─ the ehmpath bot token: absent from keyrack
      │  └─ fix: rhx keyrack set --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env prep
      └─ the ambient credential: no GH_TOKEN, no GITHUB_TOKEN, no gh login
         └─ fix: gh auth login
    then no gh send is attempted (no credential to send with)
    then the drain exits 2
  when [t1] gh is logged in, and `rhx radio.task.queue drain` runs again
    then both records deliver via the gh login, with the fallback line
```
