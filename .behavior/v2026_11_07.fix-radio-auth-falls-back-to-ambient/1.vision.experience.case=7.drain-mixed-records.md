# case=7 — one drain, mixed records (sharp + happy · critipath · densest)

## narrative

a grove's queue holds three records. A was pushed with no `--auth` while the bot token was
absent. B was pushed with `--auth as-robot:env(SANDPINE_BOT_TOKEN)`, and that token has since
been revoked. C was pushed with no `--auth` and the bot token is now granted but github refuses
it. the clone runs one drain. A and C deliver under the grove's `GITHUB_TOKEN`; B stays held with
its own fix, because its auth was chosen. the line prints once, and B's fault never mentions an
ambient credential.

this one walk crosses every boundary of the contract: chosen vs default auth, absent vs refused
bot token, a pre-send and a post-send fallback, a per-record verdict, and a once-per-drain line.

## [tn] sketch

```
given records, oldest first:
  A — auth null, bot token absent at its push
  B — auth as-robot:env(SANDPINE_BOT_TOKEN), and github now refuses that token
  C — auth null
  and keyrack grants the bot token, but github refuses it (401)
  and GITHUB_TOKEN is set and accepted
  when [t0] `rhx radio.task.queue drain`
    then A is delivered via the GITHUB_TOKEN env (bot refused, so it resends)
    then B is held with reason upstream:401 and its own fix; ambient is never tried for it
    then C is delivered via the GITHUB_TOKEN env
    then one line prints for the drain:
      🦫 delivered via the GITHUB_TOKEN env; github refused the ehmpath bot token (401)
    then the drain exits 2, since B still waits
    then the order of sends is A, B, C — unchanged (#511 bounds)
```
