# experience dimensions — radio auth falls back to ambient

## the dimensions

| # | dimension | values | orthogonal because |
|---|---|---|---|
| D1 | command | `push` · `drain` | each command reaches any auth state; both send through one seam |
| D2 | auth chosen | **none** (no `--auth`, stored auth null, no `drain --auth`) · **explicit** (a replayable auth the caller chose) · **unreplayable** (a stored auth the replay guard refuses: `shx`, odd keyrack owner, non-token env) | a choice of the caller, set before any credential is read |
| D3 | bot token | **accepted** · **absent** (keyrack absent / locked and unlock fails / blocked) · **refused** (github 401, or 403 access) | a fact of the keyrack + github, independent of the caller's choice |
| D4 | ambient state | **accepted** · **refused** · **absent** | a fact of the box's env + gh login, independent of keyrack |
| D5 | ambient kind | `GH_TOKEN env` · `GITHUB_TOKEN env` · `gh login` | which source is present; shapes only the line text |
| D6 | targets in one send set | **one** · **several, with bot access that differs per target** | a property of the queue's records, not of any credential |

non-dimensions, held constant by the bounds:
- queue order and set-aside rules (#511) — unchanged
- a 403 rate limit / abuse detection is a limit on the token, never a refusal: it halts the
  drain as today and never triggers a fallback
- a 403 `resource not accessible by integration` on the best-effort assignee add is handled
  inside the dao as today, never surfaced as a send fault
- the reader of the issue upstream is not an actor of push or drain; see the inventory's
  `## out of the space`

## the walked product, and where it collapses

the full box is D1 × D2 × D3 × D4 × D5 × D6 = 2 × 3 × 3 × 3 × 3 × 2 = 324 combinations.
three collapses reduce it, each recorded as **impossible** in the inventory:

1. **D2 ≠ none moots D3, D4, D5.** only the chosen credential is tried, so the bot token,
   ambient state, and ambient kind cannot shape the outcome
2. **D3 = accepted moots D4, D5.** ambient is never consulted
3. **D4 = absent moots D5.** no ambient source is present to have a kind

D5 shapes only text: the delivery line where ambient is accepted, and the fault line where it is
refused. so it is walked as the (kind × bot reason) cross of the line (rows 21–23, 27–29) and the
refused-kind fault (row 30), not crossed with every other cell. D6 matters only where
D3 varies per target, so it is walked as one row (20).

after the collapses: D2 = none → D1 × (1 + 2 × 3) = 14 cells (rows 1–14); D2 = explicit →
D1 × {accepted, refused-or-absent} = 4 cells — push accepted (15), push refused (16), drain
refused (17 stored, 24 `drain --auth`), drain accepted (25); the drain cells split by where the
auth came from, since a stored auth and a `drain --auth` override reach the seam by two fields.
D2 = unreplayable → 1 cell (row 18, drain only — a live push never reads its own record as
stored). plus row 19 (the densest walk, crosses D2 values in one drain), row 20 (D6), rows 21–23
(D5 × reason, with 27–29), row 30 (refused kind), and row 26 — the non-dimension a 403 rate
limit, walked once so its halt is clamped.

**30 rows in all**, verdicted in `1.vision.experience.case=_.md`.
