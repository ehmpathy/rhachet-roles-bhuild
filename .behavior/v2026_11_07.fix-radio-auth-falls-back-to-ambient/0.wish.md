# wish: radio push and drain fall back to the ambient credential (ehmpathy/rhachet-roles-bhuild#513)

## outcome
`rhx radio.task.push` and `rhx radio.task.queue drain`, with no `--auth` passed, use the ehmpath bot token when it is present and accepted. when that token is absent, or github refuses it (401/403), they fall back to the ambient credential of the box (the gh login, or `GITHUB_TOKEN` in the env, which on a grove is the robot user git config names), deliver the task, and print one line that says which credential delivered it and why the bot token did not. no seat needs to pass `--auth as-human` by hand.

an explicit `--auth <x>` is honored as given: no fallback past an auth the caller chose.

## done means
- a test clamps each case: bot token present and accepted (no fallback); bot token absent (falls back, says so); bot token refused (falls back, says so); explicit `--auth` refused (no fallback, fails with the fix named); ambient also absent (fails, names both)
- the held-record drain takes the same fallback, so a record held on an absent bot token delivers on the next drain
- pr open to the commander's review; never released or merged

## bounds
- nano. no change to the queue's order or its set-aside rules (that is #511, a separate tree)
- the fallback line names the credential kind, never a token value
