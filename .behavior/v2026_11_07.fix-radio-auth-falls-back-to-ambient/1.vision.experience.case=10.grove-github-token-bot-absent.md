# case=10 — grove, bot token absent, `GITHUB_TOKEN` accepted (happy · critipath)

## narrative

a clone wakes on a fresh grove in the night. its keyrack was never filled with the bot token,
and no human is at the terminal to re-run a command. the grove's env holds `GITHUB_TOKEN` for
the robot user that git config names. the clone dispatches a follow-up with no `--auth`. it
lands, and the clone reads one line that tells it which identity filed the task and why. before
this change, the task sat held until a human woke and typed `--auth as-human` — which on this
grove would have failed too, since that mode strips `GITHUB_TOKEN`.

## [tn] sketch

```
given keyrack reports the bot token absent
  and GITHUB_TOKEN is set in the env and github accepts it, and no GH_TOKEN
  and gh has no login (an unattended grove)
  when [t0] `rhx radio.task.push --via gh.issues --into sandpine/svc-lessons --title "..." --description "..."`
    then the task is created under GITHUB_TOKEN
    then one line prints:
      🦫 delivered via the GITHUB_TOKEN env; the ehmpath bot token was absent
    then no `gh auth token` call is made (an env source came first)
    then the push exits 0
```
