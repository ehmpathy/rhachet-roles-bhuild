# 5.3 handoff v1 — two absent test credentials

## .the wall

two keyrack keys are absent at `--env test`. only a human can fill a keyrack value.

| key | keyrack state | red cells it drives |
|---|---|---|
| `EHMPATH_BEAVER_GITHUB_TOKEN` | absent at every env | `genAuthFromKeyrack`, `getGithubTokenByAuthArg` (domain.operations, integration); `radio.task.push via gh.issues` case1–case4 (acceptance, 14 cells) |
| `OPENROUTER_API_KEY` | `ehmpathy.prep` and `ahbode.prep` only; absent at `test` | `imagineReviewSelfVerdict` ×3 (domain.operations, integration) |

none of these suites is touched by this route. each failure is the suite's own
`ConstraintError` with its fix line, never a silent skip.

## .what was tried

1. `rhx keyrack status --owner ehmpath` — read the state above; no test-env value exists to unlock
2. `rhx git.repo.test` unlocks `ehmpath/test` on every run — the unlock succeeds; the keys are simply absent
3. a prep value cannot stand in: the suites read `--env test` by contract, and a copy of a prep secret into test is a human's call, not a driver's

## .why it needs the foreman

a keyrack fill is a human act. no driver lever writes a secret value.

## .the ask

```sh
rhx keyrack set --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env test
rhx keyrack set --owner ehmpath --key OPENROUTER_API_KEY --env test
```

then rewind and re-verify:

```sh
rhx route.stone.set --stone 5.3.verification --as rewound
```
