## .6.preship.stone — sketch

```md
ship the route's work: green locally, then a green pull. never merge.

## .the steps
1. run the full suite: `rhx git.repo.test --what all --mode apply`. paste each command, summary,
   and exit code into $BEHAVIOR_DIR_REL/6.preship.yield.md. red → fix the cause; no commit on red.
2. commit at the done gate: `rhx git.commit.set -m @stdin --mode apply --push`.
   the push opens the pull, or updates the one a checkpoint opened (findsert).
3. watch: `rhx git.release --watch`. then prove it watched your push:
   `gh pr view --json headRefOid,statusCheckRollup` — `headRefOid` must equal `git rev-parse HEAD`,
   and the rollup must be non-empty and all green; else re-watch. a green on an older head (a
   checkpoint's) does not count. red → `rhx show.gh.test.errors`, fix, commit, re-watch.
   a flake → `rhx cicd.deflake init`, never a blind re-run.
4. stop. never `--apply`, never merge. the commander merges at the release gate.

## .when a commit is refused
a refused commit is **held, never a halt**:
- paste the refusal verbatim into the yield, under `## .held`
- name the grant it asks for, as printed
- name what is held (the done work, uncommitted)
- go on to the next stone. the director lands a held commit when the switch opens.
- never route around it: no raw `git commit`, no new branch, no wait loop.

## .when a push is refused   ← F10, ⚑ flagged best guess
the same hold as a refused commit, with one exception: a hook failure you can fix
(a lint the local suite skipped) is fixed, then pushed — never `--no-verify`, never a force push.
```

no clock appears in this text (F3). when to land a held commit is the director's switch.

## .`rhx git.release --watch` does not prove the head sha — a defect (settled from source)

read in `.agent/repo=ehmpathy/role=mechanic/skills/git.release/`:

- `get_pr_status` (`git.release.operations.sh`) reads `gh pr view --json statusCheckRollup,…` — the
  rollup of whatever head github holds now. it never compares `headRefOid` to the sha just pushed
- `parse_check_counts` returns `0/0/0` on an empty rollup
- `_watch_pr_transport` (`git.release._.emit_transport_watch.sh`), with no automerge and
  `progress == 0`, prints `🫧 no runs inflight`, then `done`, and returns 0

⇒ a watch run right after a push, before github updates the pull's head or registers its checks,
reports done on an empty rollup — or green on the prior head. that is c23 live.

the cure owner is `rhachet-roles-ehmpathy` (the watch should wait for `headRefOid == git rev-parse
HEAD` and at least one check before it reports done). a dream is caught for it. in this repo, the
preship text carries the driver's check, step 3:

```md
3. watch: `rhx git.release --watch`. then prove it watched your push:
   `gh pr view --json headRefOid,statusCheckRollup` — `headRefOid` must equal `git rev-parse HEAD`,
   and the rollup must be non-empty and all green. either fails → re-watch. a green on an older
   head does not count.
```

and `has-watched-the-head-green` asks for that paste: the pushed sha, the `headRefOid`, the rollup.
