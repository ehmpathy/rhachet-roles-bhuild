## what I tried

1. **read each error** — all 16 name the same key and status `absent`, and print the `keyrack set` fix
2. **checked the vault** — `rhx keyrack status --owner ehmpath` lists `ehmpathy.test.OPENROUTER_API_KEY`,
   `ehmpathy.test.ANTHROPIC_API_KEY`, `@all.camp.GITHUB_TOKEN`, `ehmpathy.prep.OPENROUTER_API_KEY`. no
   beaver token under any env, so an unlock cannot reach it — it was never set
3. **looked for a substitute** — the tests assert a `ghs_*` installation token minted from the beaver
   github app; `@all.camp.GITHUB_TOKEN` is a different credential, and to swap it in would change what
   the tests verify. not a fix
4. **looked for a mock** — `rule.forbid.integration.mocks` and `rule.forbid.acceptance.mocks` forbid it;
   these suites exist to prove the real auth path
5. **checked scope** — no file this pr changes reaches the radio auth path; the reds are the box's
   vault, not the code. on a host with the key they would run as on main
6. **fixed what I could** — a third red, `daoRadioTaskViaGhIssues.shell` [case1], was a load flake
   (300 ms timeout beat the stub's bash start). fixed at the cause (2 s), green 12/12 on three runs

## why it is foreman-only

the token is a github app secret. only a human who holds the app's key can mint and set it; the
keyrack refuses a driver `set` of a secret it cannot see, and no grant a driver holds reaches it. ⇒
yes — the foreman holds the key.
