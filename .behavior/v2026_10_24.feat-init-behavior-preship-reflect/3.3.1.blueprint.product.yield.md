### 6.preship.stone — the steps it asks for

each step names its skill calls. steps 0, 2 and 3 also hold decision arms (re-entry, the refusal
sort, the head proof) that a driver executes from text. whether those arms lift into one tested
leaf skill is the commander's call: q9 (F16).

the **route record** is the route's own ledger: `$route/.route/` (bhrain appends to
`passage.jsonl` on every arrive and pass), `$route/.radio/` (the dispatcher's local record of every
push, a hold's included), and the two tail yields. the record dirties the tree on every stone, so no
step keys on "the tree is clean". whether the record reaches the pr is q7 (F15).

a **work change** is an uncommitted path the commit owes. q2 decides how it is known: under q2 (b)
or (c) it is the allowlist the driver stages; under q2 (a) it is every uncommitted path outside the
route record. q2 and q7 are coupled: q2 (a) commits the record too, so it answers q7 as (b).

the yield keeps a `### rounds` ledger: one line per try of each bounded loop (fix round, watch),
so a re-entry or a lost context counts from the ledger, never from memory. the count of a loop
resets when a human unblocks a halt on it, or when its cause changes; the ledger line names which
(to build).

the route dir holds three kinds of file: the **record** (above), the **deliverable** (each stone's
yield, the behavior's own files), and **scratch** (`drafts/`, `appendix/`, `archive/`, a stale
`blocker/`). under q2 (b) or (c) the allowlist is the deliverable plus the execution yield's
filediff tree — that tree is its source, never memory and never `git status` minus a deny list.
scratch never rides (to build).

0. **re-entry**, keyed on the commit, never on the tree. read the pr with
   `gh pr view --json state,headRefOid,statusCheckRollup`:
   - a pr that is `MERGED` or `CLOSED` → halt with that state verbatim: a cure or a push onto a
     merged branch cannot prove a head
   - no pr yet (`gh` reports none for the branch): no work change → a prior run committed but its
     push did not land, so push only, via `rhx git.commit.push --mode apply` (that push opens the
     pr), then step 3; a work change → step 1
   - a pr, no work change, local head (`git log -1 --format=%H`) = `headRefOid` → done; step 3
   - a pr, no work change, local head ≠ `headRefOid` → push only, as above, then step 3
   - a pr and a work change → step 1
   - a second run, after a full or a partial first run, then adds no commit (to build)
1. **the full suite** — every test kind the repo's cicd runs, in two calls, since `--what all`
   expands to lint, unit, integration and acceptance only (`git.repo.test.sh:766-767`: "not
   types/format"), and a comma list refuses `--against` (`:847`):
   - `rhx git.repo.test --what types,format --mode apply`
   - `rhx git.repo.test --what all --against local --env test --mode apply` — `--what all` refuses
     without `--against` and `--env` (verified on `rhachet-roles-ehmpathy` 1.39.9:
     `--against local|cloud required for --what all`)
   - a kind the repo's `test:*` scripts declare beyond these (e.g. `test:commits`) is named and run
     too; the yield lists each kind run, so a skipped kind shows
   - pass the tool's max timeout to each call; a call cut off by the tool is re-run, per q10

   paste each command, summary, exit code. sort the outcome by what the skill printed, never by the exit code alone (a red suite and
   a refused input both exit 2):
   - a test failed → fix the cause, run again. no commit on red. **at most 3 fix rounds**; still
     red → halt (`--as blocked`) with the last failure verbatim
   - the skill refused its input or a credential (a flag it names as absent, a locked keyrack) →
     halt now, the refusal and its printed hint verbatim. a fix round cannot unlock a key
   - the same test fails on `main` too → not this change's red: halt with both runs verbatim
   - (to build)
2. **commit at the done gate**: first write the yield's `### before` entry — the head sha before
   the commit (`git log -1 --format=%H`) and the allowlist to be staged. step 0 and this step's
   landed-or-not check read it after a lost context, so "a new commit at the head" has a baseline,
   and a stray file never reads as owed work (to build). then
   `rhx git.commit.set -m @stdin --mode apply --push`, preceded by the same call in `--mode plan`:
   the grammar, quota, push, and sponsor refusals all fire before the plan branch, so the preflight
   sorts a refusal without a quota spend. the message follows the pinned skill's grammar
   (`git.commit.set.sh`, ~500–686), which keys on **branch state**, never on the stone's own
   count (to build):
   - the branch holds no behavioral commit yet → `feat(scope):` or `fix(scope):`, per the branch
     bind; `--promise is-netnew-behavior` only when the branch has no level and the wish adds a
     new behavior — never to dodge a refusal
   - the branch already holds one (an earlier route in the worktree, a human's commit, preship's
     own) → `cont(scope):`. a reflect cure after a held preship is the branch's first, so it takes
     `feat|fix`
   - the body follows a skeleton in the stone, so `templates.tail` snaps it: what shipped, the
     route path, the issue line (q6 decides `closes #N` or `refs #N`), and each `### held` item.
     `git.commit.push` takes the pr title and body from the first behavioral commit, so this is
     the human's view of the pr on github
   - the unstaged mode is the commander's call (q2, F11). under q2 (b) or (c), `rhx git.stage.add`
     adds the allowlist to the index, and it needs its own grant: `--stage allow`

   sort a refusal by who can clear it (to build):
   - **an input refusal** — a file left unstaged, a message of the wrong shape → the driver
     fixes it and runs step 2 again, inside the shared bound
   - **a grant refusal** — no commit quota, quota spent, push not allowed, stage not allowed
     (q2 b/c), no sponsor bound → held (see `a hold` below)
   - **the commit landed, the push failed** — `git.commit.set` exits 2 here too, after the commit
     exists. before any re-run of step 2, read `git log -1 --format=%H` against `### before`: a
     head that moved means the commit landed, so never commit again — push only, as step 0 does. a re-run would
     spend quota on a commit of the route record alone, or meet "no changes to commit"
3. `rhx git.release --watch`, in the foreground (the skill requires a tty; never background it),
   with the tool's max timeout (the watch caps at 15 minutes), then prove the head:
   `gh pr view --json state,headRefOid,statusCheckRollup` — `headRefOid` equals
   `git log -1 --format=%H`, and the rollup is non-empty and all green.
   - `MERGED` or `CLOSED` → halt with that state verbatim, as step 0
   - no workflow runs on the pr at all (the repo has no cicd, or none that fires on a pr) → record
     "no cicd" and the empty rollup in `### pr`, and pass; an empty rollup is a wait only where the
     repo declares workflows
   - not yet proven → watch again, **at most 3 watches**; still unproven → halt (`--as blocked`)
     with the rollup verbatim, since a check that never reports is a wall, not a wait (to build)
   - red → `rhx show.gh.test.errors`, fix the cause, commit, push, back to step 3. **at most 3 fix
     rounds**; still red → halt (`--as blocked`) with the failed checks verbatim (to build)
   - every loop in the tail shares this one bound: 3 tries per loop, counted in `### rounds`, then
     a halt with the cause verbatim. the bound itself — its size, and whether a watch cut off by a
     tool timeout counts as a try — is the commander's: q10 (F17)
   - a flake → `rhx cicd.deflake init`, never a blind re-run
   - the watch alone can report done on an empty or stale rollup — the root fix belongs to
     `rhachet-roles-ehmpathy` (dream caught); this check covers the gap until it lands
4. stop: never `--apply`, never merge
- **a refused commit** (a grant refusal): held (F4; q8 puts the wish's "halt" back to the commander)
- **a refused push**: held, except a hook failure the driver can fix, which it fixes and pushes
  again (F10, q1)
- **a hold** — durable and discoverable, not a lone yield line (to build):
  - the yield's `### held` names the refusal verbatim, the human who can grant it, the grant
    command as the skill printed it (e.g. `rhx git.commit.uses set --quant N --push allow`, plus
    `--stage allow` under q2 b/c), and
    N: the commits this route still needs — 1 for preship, plus 1 per fix round and per in-repo
    reflect cure
  - the same record goes off the box, to the repo's own issue tracker:
    `rhx radio.task.push --via gh.issues --into @this --title "<route slug>: held <stone> commit, round <n>" --description @stdin`,
    from a description skeleton in the stone that `templates.tail` snaps. the dispatcher dedupes
    on repo + title and, on a match, returns `found` without an update (`setFullRadioTask.ts:60-77`),
    so the title carries the stone and the round: a second hold is a second task, never a silent
    drop. the stone reads the outcome: `found` for a hold not yet sent means it was not
    delivered, and the yield says so.
    a held commit means no push and no pr, so an on-box record alone repeats #590 (eight routes
    found by a chase of worktrees). if the radio gate is shut, the dispatcher holds the task
    QUEUED in `$route/.radio/` and delivers it on the next push that gets through — so the worst
    case is the on-box record, never less. the task's description carries the commit message and
    the route path; the land steps are cited by
    name (`6.preship.stone`'s commit and watch steps), never copied, so the record cannot drift
    from a later template edit.
    the dispatcher records every push locally before any gate, so a hold is never lost, and
    `radio.task.held` shows it at stop
  - a hold at a step-3 fix round leaves the pr red: the yield says so verbatim, and the head-proof
    review takes its held arm (below). the route never claims a green it did not see
  - shipped text names "the human", never "director" or "commander" — those are this factory's
    roles, not a consumer's (to build)
- **the roles the tail needs** — the first stones to call skills outside `behaver` and the bhrain
  driver. the stone lists them once, and a consumer enrolls them (to build):

  | role | skills the tail calls |
  |---|---|
  | ehmpathy `mechanic` | `git.repo.test`, `git.commit.set`, `git.commit.push`, `git.stage.add` (q2 b/c), `git.release`, `show.gh.test.errors`, `cicd.deflake`, `symlink` |
  | bhuild `dispatcher` | `radio.task.push` |
  | bhuild `dreamer` | `catch.dream` |

- **an absent skill** — `rhx` cannot find **any** skill the tail calls: paste the error, name the
  role from the table above, and halt. a halt, not a hold: a hold waits for a grant, but an absent
  tool has none to wait for (vision q7, case=16; to build). one exception keeps a hold durable: if
  only `radio.task.push` is absent at a hold, the hold is still recorded in the yield's `### held`
  and printed to stdout, and the route goes on; `7.reflect`'s `has-held-not-bypassed` review asks
  the driver to carry each hold into the reflect yield, so no hold ends the route unsurfaced
- **forbidden around any refusal**: raw `git commit`, a new branch, `--no-verify`, a force push, a
  sleep-and-retry loop. (the bounded re-watch in step 3 is a fresh call per watch, not a loop
  around a refusal)
- **forbidden in a fix round**: a skip, an `.only`, a loosened assertion, or a deleted test to turn
  red green. a fix round lands after `5.3`'s peer gate, under `peer: []`, so the stone says it
  outright: a red the driver cannot fix is a halt (to build)

### 7.reflect.stone — the steps it asks for

1. read the record, not memory: peer rounds, re-raised blockers, halts, holds, fulcrums (the route's
   `.fulcrums/` rows), dreams
2. three whys per item
3. per layer, enbrief + entool in the owner repo:
   - first, the lesson: grep the owner repo's briefs for it. an extant brief is extended or
     sharpened, never duplicated — every route's lesson boots into every later route (to build)
   - this repo → the cure lands on the same pr, re-watched to green (F6), through preship's
     re-entry, suite, commit, and watch steps — cited by those names, never by number, so a
     renumber of preship cannot break reflect. a hold there is held, as in preship. the cure's
     state lives in the reflect yield's own `### ship` section — `### before`, `### rounds`,
     `### pr`, `### held`, the same shapes as preship's — never in the passed preship yield;
     `has-rewatched-after-a-cure` reads it there (to build; `templates.tail` case2 asserts it)
   - another repo → the owner repo comes from a source, never a guess: the installed role
     package's `package.json` `repository` field. no source → "no owner found", which is a
     dream. the whole call, with a title that carries the item **and the layer**, so a second
     layer owned by the same repo is a second task, and a second reflect round finds each one
     (the dispatcher dedupes on repo + title; findsert is its default) (to build):
     `rhx radio.task.push --via gh.issues --into <owner/repo> --title "<route slug>: <item slug>, layer <n>" --description @stdin`.
     exit 2 with the task QUEUED is a recorded hold (the gate was shut), not a failure; `found`
     for a task this round did not send means the cure was not delivered, and the yield says so
   - **what leaves the repo**: a cross-repo item names the lesson and the cure's shape only —
     never quoted record content (peer findings, fixtures, yields, names from the route). the
     stone has no pii read (F1 is deferred), so the rule binds in every repo: a pii repo's route
     must not post its data to another repo's tracker (c34, case=19; to build). the pii-aware path
     (a pii route's item held locally until a human sends it) moves to the F1 follow-up dream
   - **the yield shape is per layer**, not per item: under each why sits its own `lesson`, its own
     `cure`, and the repo that owns that layer — the deepest cause often belongs to another repo
     (the mechanic, bhrain), and a per-item `cure` invites a layer-1 cure only (to build;
     `templates.tail` case2 asserts the shape)
   - the dream: `rhx catch.dream --name <item slug>`, then
     `rhx symlink --at "$route/dreams/<dream file>" --to ".dream/<dream file>" --mode relative --idem findsert`

   - the stone glosses "enbrief", "entool", and "fulcrum" inline, in the words of `## terms` (to build)
