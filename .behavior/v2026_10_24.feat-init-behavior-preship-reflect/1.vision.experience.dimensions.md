# 1.vision.experience.dimensions

the experience space of "a behavior route ships and learns at its end", factored into axes. each
axis is a small closed value set; why each is independent sits below the table. two properties a
reader might expect as axes — the actor and the pull state — are **derived attributes**, not axes;
why sits in `.derived, not axes`.

> **scope:** the walk covers the whole space the wish named, checkpoints included, so the follow-up
> starts from a walked product. in this behavior the D2 values `vision checkpoint` and
> `blueprint checkpoint`, and D5 (privacy, which only a checkpoint reads), are **deferred** to the
> follow-up (`dreams/2026_10_24.feat-init-behavior-checkpoint-commits-with-pii-hold.dream.md`). the
> cells they span (c10–c13, c20, c22, c26) are itemized as deferred in `case=_`. with no checkpoint,
> D12 `overlapped` now arises from github lag on preship's own push (c23), not from a checkpoint run.

## .why each axis is independent

- **D2 moment vs D3 size** — size picks which moments exist: every size has init, vision, preship,
  reflect; only mini+ has the blueprint checkpoint. that one bar (c17, impossible) is the only place
  D3 constrains D2, and it is recorded as a cell, not hidden.
- **D4 grant** — set by a human (quota) and the remote (push rules), never by the moment. any commit
  the route asks for can meet either refusal. commit-refused and push-refused are split because they
  fail at two different operations, with two different verbatim texts and two different fixes.
- **D5 privacy** — a property of the repo. it decides whether a checkpoint pushes, and so whether
  preship pushes one commit or a local backlog (c22).
- **D6 clock** — when the driver reaches a commit. independent of all else.
- **D7 vs D8** — the local suite and remote cicd can disagree (env, secrets, a flake). D8's
  `ignored` value holds the run a *pushed* checkpoint triggers, so a pushed checkpoint reads
  `ignored`, never `n/a`. a checkpoint that does not push (pii, a refused commit) has no run, and
  reads `n/a`.
- **D9 origin** — findsert: an extant route keeps its stones. independent of the others.
- **D10 owner** — set by where the lesson's cause lives; `none found` is the feigned-reflect edge.
- **D12 run order** — when the route's own pushes land relative to its own runs. it surfaces the
  races a happy-path list skips. another party's push to the branch is a different cause with a
  different fix (a non-fast-forward halt), so it lives in D4 as a push-refused cause (c25), not here.
- **D13 ship tools** — a property of the consumer's enrollment, set before the route starts.
  independent of the moment: any commit the route asks for needs them.
- **D7 refused vs red** — a refused suite never ran a test (an absent flag, a locked keyrack), so
  no fix round can turn it green; a red suite did run. both exit 2, so the split is by what the
  skill printed. surfaced at the blueprint review (i004), added per
  `rule.require.experience-catalog-evolution`.
- **D14 run** — a stone can be re-entered after a crash or a halt. independent of the grant: a
  re-run meets whatever the first run left (a commit landed, its push not). surfaced at i004.
- **D5 × D10** — the scope note said D5 is read only by a checkpoint. that holds for git pushes,
  not for reflect's cross-repo item, which sends text to another repo's tracker. c34 is that cell,
  surfaced at i006; this behavior holds it by a text rule (lesson and shape only), and the
  pii-aware hold moves to the F1 follow-up.
- **D4 × the moment of the commit** — a grant refusal can meet preship's first commit, a step-3
  fix round's commit, or a reflect cure's commit. the walk first visited only the first (c5); the
  other two are c28 and c29, surfaced at i004.

## .derived, not axes

- **actor** — each moment fixes who meets it: the initiator meets init; the maintainer meets the
  size config edit; the driver meets every checkpoint, preship, and reflect; the wisher meets each
  pushed yield and the pull. no value of "actor" varies on its own once the moment is fixed, so it
  is an attribute of the cell, written in the cell text. **no system actor exists**: no stone runs
  on a schedule. the 20:00 hold (D6) is the driver's wait, not a cron.
- **pull state at preship** — `open` iff D5 = public and a vision checkpoint pushed (D4 = granted
  there); else `none`. it changes what preship does ("update" vs "open"), so cells c3 and c20 name
  it in their text, but it is computed from D5 × D4.

- **D9 extant** — one cell (c16); every other cell is `fresh`.

- **D12 overlapped** — one cell per form: c23 (a checkpoint run still in flight at preship), c24
  (reflect pushes after preship's green).
- **D13 absent** — dominates: the first commit the route asks for halts. one cell (c27); every
  other cell is `present`.
