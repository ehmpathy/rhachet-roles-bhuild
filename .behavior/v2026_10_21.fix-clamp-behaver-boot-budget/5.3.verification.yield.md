### a flake found and fixed — `ductwork.verbs` [case1]

the first full integration run failed 4 tests, all in
`supervisor/skills/work/ductwork.verbs.integration.test.ts` `[case1]` (`duct.open` → exit 1). run
alone, the file passed 70/70; under the 102-file load it took 208s.

- **the cause:** `runDriver` in `work.harness.ts` spawns each bash driver with a 30s timeout and
  read `spawned.status ?? 1`. a driver the timeout killed has `status: null`, so a saturated box
  came back as `exit 1` — the shape of a real ductwork fault, with no word the harness ended it
- **the fix:** a kill now throws a `MalfunctionError` with the signal, the bound, and both streams
  so far; the bound is 60s (`MS_DRIVER_TIMEOUT`), under the 90s hook timeout
- **the clamp:** new `work.harness.integration.test.ts` — a driver that outlives a 500ms bound
  throws, and a driver that exits 3 on its own still returns `{ exit: 3 }`
- **proven:** with `?? 1` restored → 1 red (the kill read as an exit code). fix restored → 2/2 green
- `suitesPorted` census: supervisor `work/` suites 23 → 24, with its reason in the table
