# 1.vision.experience.dimensions

the experience space of a budgeted, dense behaver boot. the axes below are walked per actor in
`1.vision.experience.case=_.md` — one row per tuple, every row verdicted.

## .the axes

| # | axis | closed value set | why it varies the experience | why it is orthogonal |
|---|---|---|---|---|
| D1 | actor | `seat` · `author` · `disputer` · `commander` | each meets the boot at a different moment, for a different need | an actor is a person in a seat; no value of D2–D7 picks who that is |
| D2 | role | `behaver` · `other` (decomposer, dispatcher, dreamer, prioritizer, supervisor) | behaver gets a refout + a cut budget; `other` gets a freeze only | which role a spec belongs to is fixed by its dir; it implies no state, render, act, or merge order |
| D3 | budget state, **read per render** | `undeclared` (no `budget:` line, or no `boot.yml` at all) · `invalid` (`0`, a non-number) · `fits` (payload ≤ budget) · `over` (payload > budget) | `fits` is silent; the other three are where the system must speak | the state is a fact of one spec's yaml + one render's payload. it is NOT independent of D4 — see `.the one correlation` |
| D4 | render | `src` (`src/domain.roles/<role>/`) · `linked` (`.agent/repo=bhuild/role=<role>/`) | the linked base path is longer, so one spec costs more linked (behaver: 2,571 → 2,601) | the render is where the spec is read from; the same yaml is in both |
| D5 | author act | the 22 acts below; a23–a31 surfaced in execution and verification, each with an inventory row | what the author does decides which state the clamp then meets | an act is a choice; it applies to either role and is graded in both renders |
| D6 | ref integrity | `intact` · `broken` (a boot `ref` entry or a `.see also` pointer names a file that is gone) | `broken` dead-ends the disputer's fetch, and shorts the seat's boot in silence | integrity is a fact of the tree, independent of budget, render, or who reads |
| D7 | merge order | `solo` (one branch lands on a main it was tested against) · `concurrent` (two branches, each green alone, merge in sequence) | each branch's ci saw a tree that main never holds | the merge order is a fact of the queue; it implies no role, act, or render |
| D8 | box load (found at verification) | `idle` · `saturated` (the full suite holds every core, so a child process can outlive its harness bound) | a kill at the bound must read as a kill, never as the fault the test hunts | load is a fact of the run, independent of role, act, or render |

### .D5, enumerated — and why the set is closed

the set is closed by the **object** each act touches. the boot payload and its gate depend on eight
objects, and each act is one kind of change to one of them:

| object | acts |
|---|---|
| a said brief's content | a1 grow · a8 condense via `.md.min` · a12 cut a cue line · a19 edit the role readme (it boots) |
| a said brief's file | a22 delete it while its `say` entry stays (the said twin of a13) |
| a ref brief's content | a2 edit |
| the say / ref / `not` lists | a3 add a brief, unlisted · a16 add a brief, listed in say · a17 add a brief, listed in ref · a18 drop a say entry, unlisted · a7 move content say → ref · a9 catalogize a set · a10 list under `not:` |
| the `budget:` line | a4 delete · a5 set invalid · a6 set = src payload · a11 raise · a14 set from a stale measure |
| a ref target file | a13 rename or delete |
| the role dir | a15 add a role with a `boot.yml` and no budget · a21 add a role with no `boot.yml` |
| the clamp itself | a20 delete or neuter the clamp case |
| a glob entry's targets (found at verification) | a30 re-home the dir a glob reads, or rename a brief its `!(…)` names |
| a condensed cue's text (found at verification) | a31 reword a cue no claim pin holds |

the `boot.yml` yaml text does not boot; a title or structure edit changes the payload only through
the lists, which the list row already walks. so no "chrome" act stands apart.

### .equality, stated

`fits` includes payload = budget. rhachet halts only when the payload **exceeds** the budget — its
refusal reads `boot payload exceeds its declared budget` (probe, 2026-10-21; and
`assertBootWithinBudget.js`: `if (counted.tokens <= input.budget.tokens) return`).

### .the one correlation — D3 × D4

one budget number meets two payloads, so D3 is read **once per render**. a row whose renders
disagree records both: `fits @src · over @linked` (a6). this is the correlation the pr discovered;
it is declared here, not hidden in a compound value.

### .where an axis is degenerate — and why

| actor | degenerate axes | why |
|---|---|---|
| seat | D4 = `linked` only · D5 n/a · D7 n/a | a seat boots from `.agent/`; it never boots `src` (by nature), authors naught, merges naught |
| author | D3 = the act's yield · D4 = both, always · D6 is act a13 · D7 free only for payload-raise pairs | each act yields one state per render (a3 and a16 yield `fits` or `over` by size — they fork to a1's row when over). the clamp boots `src` **and** the linked layout on every run (F3) |
| disputer | D3 n/a · D4 = `linked` · D5 n/a · D7 n/a | a dispute is about a rule's argument, never about its budget |
| commander | D3 = `fits` (the pr is green) · D4 n/a · D5 n/a · D6 n/a · D7 n/a | the commander reads one table in a pr whose ci passed |

### .D7, reduced

under `concurrent`, two acts compose. a composition yields a new experience only when **both acts
raise the payload and each fits alone** — the sum can exceed what either branch's ci saw. every
other pair composes to a state some `solo` row already holds (a raise + a grow = a11's diff; a
refout + a grow = the larger of the two). so `concurrent` adds one tuple per role: c1.

## .the boundaries a walk can cross

a boundary counts for a row only when the row's own walk visits **both** sides of it:

- **edit → ci** — every author row: the clamp grades each act. `roles cost --all` exits 0 over
  budget, so only the clamp turns red
- **src → linked** — counts only where the two renders yield different D3 values (a6)
- **owned → consumer** — counts only where a consumer seat's boot is at stake. rhachet warns when
  the spec is a symlink under `.agent/repo=*/role=*/` and halts otherwise
  (`isBootSpecForeign.js` + `getOneBootBudgetRung.js`)
- **say → ref** — counts where content crosses from say to ref, or a reader fetches across it
- **branch → main** — counts where main holds a tree no branch's ci saw (D7 = `concurrent`)
