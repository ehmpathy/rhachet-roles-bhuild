# 1.vision — clamp the behaver boot to a declared budget

## .the outcome world

every seat that boots `role=behaver` pays 2,105 tokens (measured) where it paid 2,601, and knows
the same rules. each role a seat boots carries a `budget: tokens:` line, and a test turns red the
moment a boot outgrows it. growth stops at the diff, where a human sees it.

### before / after

| | before | after |
|---|---|---|
| behaver boot (linked) | 2,601 tokens, uncapped | 2,105 measured, under a declared 2,200 budget (F1) |
| `rule.require.experience-catalog-evolution` at say | 1,233 tokens — cue + argument | ~600 — cue only; argument at ref in an adjacent `.reason.md` (F2) |
| other roles | uncapped | the three a seat boots (decomposer, prioritizer, supervisor) budgeted at their shipped cost; supervisor 32,482 → 9,865 and prioritizer 7,728 → 5,397 (shipped) under the wisher's 10k cap (F8); dispatcher and dreamer are inert — no seat boots them (F4) |
| a boot that grows | invisible — `roles cost --all` exits 0 over budget | red in ci via a clamp test (F5) |

### the aha

the expensive half of a rule is the half a seat already accepted. move the *why* out, keep the
*when → then*, and the boot shrinks with no sense lost — and a number in the diff keeps it shrunk.

## .the contract we propose

```yaml
# src/domain.roles/behaver/boot.yml
budget:
  tokens: <measured linked cost after refout, rounded up to the next 100>   # settled at 2_200 (2,105 measured), F1
always:
  briefs:
    say:
      - briefs/practices/behavior.verification/philosophy.verification-strictness.md
      - briefs/practices/behavior.vision/rule.require.experience-catalog-evolution.md   # now cue-only
    ref:
      - briefs/practices/behavior.vision/rule.require.experience-catalog-evolution.reason.md   # new
      # …the 20 extant refs, unchanged
```

- `rule.require.experience-catalog-evolution.md` keeps: the claim, the three evolve steps, the
  when-fires table, the terminus (forward / backward), the bounds, every enforcement line, see-also
- `rule.require.experience-catalog-evolution.reason.md` receives: the `.why` section verbatim, plus
  each explanatory sentence the cue sheds, and a `.see also` back up to its rule. the cue → reason
  pointer is clamped already: `briefCitations.integration.test.ts` resolves every backticked
  `*.md` in a `.see also` against the shipped basenames (case=5)
- a **sense map** proves "no sense changed": a table in the execution yield, one row per sentence
  of the original rule → where it now lives (a cue line, condensed; or the `.reason.md`,
  verbatim). no original sentence maps to naught; no cue line maps to no original. the cue is
  denser words for the same claims, never new claims
- `{decomposer,prioritizer,supervisor}/boot.yml` gain `budget: tokens:` at today's cost, rounded
  up to the next 100. dispatcher and dreamer carry a `boot.yml` on disk, but the role registry
  declares neither, so no seat boots it — the wish's "(dispatcher has no boot)" holds in effect.
  both stay on the clamp's named inert list, so a later declaration must add a budget
- `roleArtifacts.integration.test.ts` gains a case with three assertions per role **dir** under
  `src/domain.roles/` (dirs, not `boot.yml` files, so a role with no `boot.yml` cannot slip past):
  it holds a `boot.yml` that declares a budget (case=7); `rhachet roles boot --what <it>` exits 0
  (case=2, 3); and the same role, copied as real files into a temp repo at
  `.agent/repo=bhuild/role=<role>/`, boots with exit 0 too — so a consumer seat's render fits,
  measured, not estimated (case=4, F3). a real-file copy gets rhachet's `halt` rung, not its
  `warn` rung: `isBootSpecForeign` returns true only for a symlink (`lstat`)
- the pr body leads with the before/after table from `npx rhachet roles cost --all`

## .mental model

- to a friend: *"the role's boot re-argued a rule every session. we kept the rule, filed the
  argument, and put a price tag on the boot so it can't creep."*
- analogy: a cockpit checklist vs the flight manual. the pilot reads the checklist every flight;
  the manual sits on the shelf for when someone asks why.
- their words → ours: "the short version" → cue (say) · "the long version" → argument (ref) ·
  "price tag" → `budget.tokens` · "the alarm" → the clamp

## .evaluation

| goal | met? |
|---|---|
| 1. behaver declares a budget, `roles cost` reads under it | ✅ — at 2,200 (2,105 measured), not 1.5k (F1) |
| 2. cues stay at say, argument refs out | ✅ — cue lines preserved, `.why` moved |
| 3. other roles frozen at today's cost | ✅ — the three a seat boots; two inert (F4) |
| 4. before/after table in the pr | ✅ |

**pros** — same knowledge, 19% fewer tokens per seat (2,601 → 2,105, measured); every booted role
now has a cap; growth turns red.

**cons** — 1.5k is out of reach under the bound; the clamp test adds nine `rhachet roles boot`
calls to the integration suite — each of the four declared roles booted twice (src and linked),
plus one copy forced over its budget — measured at 45s quiet, 129s on a loaded box (see the
execution yield, `.the clamp's cost`).

**edgecases → pit of success**

- linked render costs more than src → the clamp boots the linked layout too, so a too-tight
  budget fails in ci, not as a warn in every consumer seat (case=4, F3)
- a new role ships with no budget, or no `boot.yml` at all → the clamp walks role dirs, requires
  both, and names the measure command (case=7)
- two prs each grow one role within the margin, and merge → main holds an over boot no pr saw; the
  release pr goes red and naught publishes. the fix is a1's tree; `git log` names both prs (c1)
- `roles cost --all` exits 0 over budget → the clamp uses `roles boot`, which exits 2 (F5)
- a brief added later → the say list is an allowlist, so it lands as a path in `<also>` (a3)
- a cue cut to fit, or a brief listed under `not:` → forbidden by the wish; left to review, and
  the sense map exposes a cut (a10, a12)
- a ref target renamed or deleted → rhachet drops a dead boot entry in silence, but two extant
  clamps catch it: `roleArtifacts` `[case4]` (every non-glob boot entry exists on disk) and
  `briefCitations` (every `.see also` pointer resolves) (a13, d2)
- the `budget` line itself adds ~8 tokens to the stats block (dreamer 244 → 252, measured) →
  measure after the line exists, never before

## .open questions & assumptions

- [wisher] is 1.5k firm, or proposed? the evidence says the floor is ~1.9k without cue cuts or
  `not:` drops (F1)
- [answered] which roles are "director seat" roles? the three a seat boots — decomposer,
  prioritizer, supervisor. dispatcher and dreamer are inert: the registry declares no boot for
  either, so no seat boots them (F4)
- [answered] is a clamp test owed? by logic, yes: R3's "cannot grow unseen" fails without one,
  since `roles cost --all` exits 0 over budget. kept as F5 so the wisher may still defer it
- [answered] how big is the src→linked delta? it scales with path occurrences (each said brief
  carries its full path; each `base=` block one more) — ~5 tokens each on behaver. so no constant
  margin fits all roles; the clamp measures the linked layout directly (F3)
- [answered] does rhachet support `budget: tokens:`? yes — `.agent/repo=.this/role=any/boot.yml`
  declares `budget: tokens: 30_000`; `parseRoleBootYaml.assertDeclaredBudgetValid` validates it
- [answered] does `roles cost` gate? no — it exits 0 and marks 🟡; `roles boot` halts with exit 2
  on an owned spec (measured 2026-10-21) and warns on a foreign one. "foreign" means a symlink
  under `.agent/repo=*/role=*/` (`isBootSpecForeign.js`, `getOneBootBudgetRung.js`, read
  2026-10-21) — so a real-file copy halts
- [answered] can two green prs merge into an over boot? yes (c1). pushes to `main` run no tests
  (`test.yml` ignores `main`), but the release-please branch runs `test.yml` and `publish.yml`
  needs `test`, so the over tree goes red on the release pr and never publishes
- [answered] does a `.md.min` replace its `.md` at boot? yes — strictness boots as `.md.min`
- [research] does `roles boot --what` accept a role copied into a temp dir at the linked layout?
  the rung is settled by code (a real-file copy halts); what stays unprobed is whether `--what`
  resolves in a temp repo used as cwd, and whether the temp render costs what the in-repo linked
  render costs. execution probes both first, with a per-role margin as the fallback (F3)
- assumption: a cue restated in denser words keeps its sense. not self-evident — so it is made
  checkable by the sense map in the contract above, not trusted
- assumption: an integration test may spawn `npx rhachet roles boot` — rhachet is a pinned
  devDependency (1.50.0), and the clamp runs from the repo root, so `--what src/...` resolves as
  it did in this session's probes
- assumption: the strictness `.md.min` stays as is — it is already cue-shaped (lists and one-line
  claims); its two "cost / benefit" lines are one-line grounds, which the refout rule exempts

## .what is awkward?

- the wished number and the bound conflict. "dense, not cut" and "≤ 1.5k" cannot both hold; we
  honor the bound and surface the number (F1)
- most of the remainder is path pointers, which cost as much as the rule we condensed and teach
  less — yet they are the discoverability of every ref'd brief
- one budget governs two renders that cost different amounts; the clamp must boot each role twice
  (src + a temp linked layout) to hold both (F3)
- the wisher capped supervisor and prioritizer at 10k (F8); supervisor's linked render fits at ~99.9% of it, so its
  next said brief forces a choice between cues
