# playtest: a push to a public repo needs an anonymized promise

one command walks every path below, in a scratch consumer repo, against a stub `gh`. it prints each
command as a human types it, its full output (stdout and stderr, in order), and `> exit <code>`.

walked by the driver on 2026-11-18: all nineteen paths (A–S) passed as written below.

## prerequisites

- node >= 18, and deps installed. on a clean checkout of the pr branch: `rhx pnpm.patch sync --frozen`
  (the repo's paved install against the lock, as ci runs it). in the driver's worktree, deps are
  already installed; skip this line there: that tree also holds unrelated, unstaged edits to
  `package.json`, `pnpm-lock.yaml` and `patches/`, so a frozen install there fails with
  `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`, and the pr carries none of them
- the build: `npm run build` (the walk runs `dist/`, so a stale build walks stale code)
- no github access needed: the stub `gh` answers every call and logs it; no real request leaves

## sandbox

- the walk makes its scratch repo under `@gitroot/.temp/radio-walk-promise.XXXX/` and removes it at
  exit. records, the radio.uses meter, and the isolated `$HOME` all live inside it
- naught is written to this repo outside `.temp/`
- after the walk: `rhx globsafe --pattern '.temp/radio-walk-promise.*'` lists no dir

## the run

```sh
npm run build
rhx radio.walk.promise
```

the stub reads these repos as: `sandpine/spot-forecast-widget` PUBLIC · `sandpine/svc-lessons`
PRIVATE · `sandpine/tide-feed` unreadable (its visibility reply is not json).

how to read the steps below:

- you type only the two commands above. each step below is a line the walk prints, after `$ `; a
  `…` in a step stands for flags the walk prints in full (`--auth as-robot:env(RADIO_WALK_TOKEN)`, the
  body text). to try one step by hand, copy its full line from the walk output, not from here
- `→` is what that step must print. match on the quoted text
- `#7NN` is an issue number the stub mints (700 + its call count); any value in that form passes
- `J [caseN]` cites `blackbox/role=dispatcher/skill.radio.task.push.promise.acceptance.test.ts`; the
  table at the end names each path's tests in full

## happy paths

### A. a text push into a public repo, then the printed command — J [case1] [t1][t3]

1. `rhx radio.task.push --via gh.issues --into sandpine/spot-forecast-widget --title 'add a swell height legend' --description '…' --auth …`
   → `🦫 hold up — this task goes to a public repo`, the repo shown `(public)`, the three things the
   text must hold none of, and `└─ this push: naught sent, naught queued; once checked, re-run the
   command below`. below the tree: the full command with `--promise task-to-public-repo-is-anonymized`
   appended. `> exit 2`.
   → gh calls: only `repo view` (the clamp: no promise → no request that sends)
2. the printed command, as typed
   → `🦫 onto the pile!`, `🎙️ created: add a swell height legend`, `status: QUEUED`. `> exit 0`.
   → gh calls add exactly one `issue create`

### B. a text push into a private repo, unchanged — J [case2][t1]

`rhx radio.task.push … --into sandpine/svc-lessons …` with no `--promise`
→ `🎙️ created: remind surfers of their lesson`, no nudge. `> exit 0`.

### C. a public push held at a shut gate, then a drain, then a vouch — J [case6] [t0][t1][t5][t4]

the walk shuts the sandpine gate, pushes, then reopens it.

1. the push → `🦫 held for the radio`, `status = QUEUED (radio.uses:blocked — org)`, and
   `└─ a public repo will owe --promise; pass it now if so`. `> exit 2`.
2. `rhx radio.task.queue drain` → `naught delivered`, the record under `still held` with reason
   `(public-repo:unpromised)` and four moves: check its record file, scrub via `queue set`, vouch via
   `drain --promise`, or drop via `queue del`. `> exit 2`.
3. `rhx radio.task.queue get` → the same record, `state: awaits promise`, the same moves, and a
   footer that names `drain --promise`. `> exit 0`.
4. `rhx radio.task.queue drain --promise task-to-public-repo-is-anonymized`
   → `back in the river!`, `#7NN list wetsuit sizes` drained, `backlog = 0`. `> exit 0`.

### D. a status-only update into a public repo — J [case5]

`rhx radio.task.push … --exid 5 --status CLAIMED` (no title, no body)
→ `🎙️ updated: list wetsuit sizes`, `status: CLAIMED`. `> exit 0`.
→ gh calls hold no `repo view`: a status-only push needs no promise and reads no visibility

### I. an internal repo, and a private push with a stray `--promise` — J [case2] [t3][t2]

1. `rhx radio.task.push … --into sandpine/infrastructure …` (stub: INTERNAL), no `--promise`
   → `🎙️ created: rotate the board-rental keys`, no nudge. `> exit 0`.
2. `rhx radio.task.push … --into sandpine/svc-lessons … --promise task-to-public-repo-is-anonymized`
   → `🎙️ created: lesson waitlist`, no nudge; the promise is ignored. `> exit 0`.

### L. a promise rides on a held record — J [case6] [t0][t1] (record A)

1. the push, with `--promise`, at a shut gate → `🦫 held for the radio`. `> exit 2`.
   no `a public repo will owe --promise` line: this record already carries it
2. `rhx radio.task.queue drain` (no `--promise`) → `#7NN rash guard sizes` drained, `backlog = 0`.
   `> exit 0`.

### M. a private push flushes a backlog that holds an unvouched public record — J [case7]

1. a public push at a shut gate, no promise → held. `> exit 2`.
2. the gate opens; `rhx radio.task.push … --into sandpine/svc-lessons --title 'tide chart refresh' …`
   → `🦫 onto the pile!`, `pushed` `#7NN tide chart refresh (created)`, and `still held` `retry
   lesson reminders … (public-repo:unpromised)` with the same four moves as C2. `> exit 0`.
   → gh calls: one `issue create`, for svc-lessons only
3. the walk drops the held record (`queue del`, `> exit 0`), so later paths start clean

### H. both `--help` outputs name `--promise` — J [case9][t4], via-gh-issues [case9] help snap

1. `rhx radio.task.push --help` → a usage line that ends `--promise task-to-public-repo-is-anonymized`,
   a branch `a public repo needs a promise`, and the option row `--promise
   task-to-public-repo-is-anonymized (needed for text into a public repo)`. `> exit 0`.
2. `rhx radio.task.queue --help` → the usage line `drain --promise task-to-public-repo-is-anonymized`
   (`deliver now, and vouch for every held public record`) and its option row, `never stored on a
   record`. `> exit 0`.

## edgey paths

### E. a wrong `--promise` value — J [case1][t2], [case9][t1.1] (drain)

`rhx radio.task.push … --promise yes`
→ `✋ ConstraintError: --promise 'yes' is not a promise this radio knows; the one valid value:
--promise task-to-public-repo-is-anonymized`. `> exit 2`. gh calls: none.

### F. a repo whose visibility cannot be read — J [case3][t4]

`rhx radio.task.push … --into sandpine/tide-feed …`
→ `🦫 hold up — this task may go to a public repo`, `repo: sandpine/tide-feed (visibility unreadable
— treated as public)` with child `cause: visibility json unparsable`, then the same check list and
the printed command with `--promise`. `> exit 2`. naught sent, naught queued.

### G. two held public records: one scrubbed then vouched, one dropped — J [case17], [case19]

both bodies hold the marker `SECRET-DETAIL`; both are held at a shut gate (`> exit 2` each).

1. `printf 'a scrubbed coach note\n' | rhx radio.task.queue set --uuid <coach-notes key> --description @stdin`
   → `amended the held record`, `description: amended`, and the footer `naught sent; … a public repo
   needs \`drain --promise task-to-public-repo-is-anonymized\`, once checked`. `> exit 0`.
2. `rhx radio.task.queue del --uuid <wetsuit-count key> --why 'text not safe to publish'`
   → `dropped from the radio, never sent`. `> exit 0`.
3. `rhx radio.task.queue drain --promise task-to-public-repo-is-anonymized`
   → only `#7NN coach notes` drained, `backlog = 0`. `> exit 0`.
   → the walk prints the one body sent: it holds `a scrubbed coach note`, and the check
     `any sent body holds SECRET-DETAIL? (expect: no)` prints `no`

### J. an `--exid` text edit into a public repo — J [case4] [t1][t2]

1. `rhx radio.task.push … --exid 41 --title 'lesson reminder retry' --description '…'`, no promise
   → the public nudge; its printed command holds `--exid 41` and the title. `> exit 2`.
   → gh calls: only `repo view`, no `issue edit`
2. the printed command → `🎙️ updated: lesson reminder retry`, `exid: 41`. `> exit 0`.
   → gh calls add exactly one `issue edit`

### K. os.fileops into the public repo, no promise — J [case4][t3]

`rhx radio.task.push --via os.fileops --into sandpine/spot-forecast-widget --title 'board wax order' …`
→ `🎙️ created: board wax order`, `via: os.fileops`, no nudge. `> exit 0`.
→ gh calls: no `repo view`, no `issue create` (only `api user`, to name the pusher)

### N. a rate limit on the visibility read — J [case8][t1]

1. a push into `sandpine/swell-feed` (stub: rate limit on `repo view`) at a shut gate → held.
   `> exit 2`.
2. the gate opens; `rhx radio.task.queue drain` → `naught delivered`, the record `(upstream:rate-limit)`,
   `fault: visibility read: upstream:rate-limit (HTTP 403: …)`, `halted: the line stops here`, `wait,
   then: rhx radio.task.queue drain`. `> exit 2`.
   → gh calls: only `repo view`. never sent unchecked, never nudged
3. the walk drops it (`queue del`, `> exit 0`)

### O. a nudged push re-run with a scrubbed title — J [case18]

1. `--title 'surf-ops coach notes'`, no promise → the public nudge. `> exit 2`.
2. `--title 'coach notes' --promise task-to-public-repo-is-anonymized` → `🎙️ created: coach notes`.
   `> exit 0`.
3. `rhx radio.task.queue get` → `🦫 naught held for the radio`. `> exit 0`. the nudged record of step 1
   was dropped, so no stale record waits behind the scrubbed one

### P. a body piped via `--description @stdin` into a public repo — J [case20]

1. `printf 'add a\nswell legend\n' | rhx radio.task.push … --title 'swell legend' --description @stdin …`
   → the public nudge, plus `├─ re-pipe the checked body into the command below` with child `the body
   this push piped: .behavior/.radio/record.<key>.json`, and `└─ this push: naught sent, naught queued;
   once checked, run the command below with the body piped in`. the printed command keeps
   `--description @stdin`. `> exit 2`. gh calls: only `repo view`.
2. the same pipe into the printed command → `🎙️ created: swell legend`. `> exit 0`. the walk prints
   the one body sent: it ends `add a` / `swell legend`

### Q. a body with a quote, a dollar, a backtick, and a newline — J [case13]

1. the push, no promise → the public nudge; the printed command quotes the body for a shell
   (`'it'\''s $HOME and \`tick\` and "quotes"` across two lines). `> exit 2`.
2. the printed line, run through bash as typed → `🎙️ created: quote probe`. `> exit 0`.
   → the check `the body on the wire ends with the original, byte for byte? (expect: yes)` prints `yes`

### R. a rejected token on the visibility read — J [case8][t3]

`rhx radio.task.push … --into sandpine/wave-feed …` (stub: 401 on `repo view`)
→ `🦫 hold up — this task may go to a public repo`, `(visibility unreadable on this auth — try
as-human)`, `cause: github auth failed: the robot token was rejected by github (401)`, then two peer
moves: `first: re-run with --auth as-human; a private repo then sends with no promise` and `or, with no
human login or a public repo: check the text, then add --promise … instead`. the printed command ends
`--auth as-human` with no `--promise`. `> exit 2`. naught sent.

### S. a bare `--promise`, and an empty body — J [case9] [t1][t1.1][t2]

1. push with `--promise` and no value → `✋ ConstraintError: --promise (no value) is not a promise this
   radio knows; the one valid value: --promise task-to-public-repo-is-anonymized`. `> exit 2`.
2. `rhx radio.task.queue drain --promise` → the same line. `> exit 2`.
3. push with `--description ''` → `✋ ConstraintError: --description is empty; a new task needs a body:
   …`. `> exit 2`.
→ gh calls across all three: none

## pass/fail criteria

- ✓ pass if: every `> exit` code matches the step above (A 2·0 · B 0 · C 2·2·0·0 · D 0 · E 2 · F 2 ·
  G 2·2·0·0·0 · H 0·0 · I 0·0 · J 2·0 · K 0 · L 2·0 · M 2·0·0 · N 2·2·0 · O 2·0·0 · P 2·0 · Q 2·0 ·
  R 2 · S 2·2·2)
- ✓ pass if: no gh call log shows `issue create` or `issue edit` after a step that printed a nudge or
  a refusal (A1, E, F, J1, O1, P1, R, S)
- ✓ pass if: path Q prints `yes` under the byte-for-byte check
- ✓ pass if: path D's and path K's gh calls hold no `repo view`
- ✓ pass if: path M creates for svc-lessons only, and path N creates naught
- ✓ pass if: path G prints `no` under the SECRET-DETAIL check, and the dropped record never appears
  in `drained`
- ✗ fail if: any public-repo push with text and no `--promise` reaches `issue create`
- ✗ fail if: a nudge or refusal lacks the copy-pasteable `--promise task-to-public-repo-is-anonymized`
- ✗ fail if: a `--help` output omits `--promise`
- ✗ fail if: a `.temp/radio-walk-promise.*` dir remains after the walk
