# case=5: an --exid update of title or description, public, no promise → nudged

sharp × critipath · cell #8 · happy × alterpath · cell #9

## .narrative

a clone finished the work behind issue 599 on `ehmpathy/rhachet` (public) and wants to add a note
to its description: "fixed in sandpine/svc-lessons route v2026_11_02, see pr 88". it runs
`rhx radio.task.push --via gh.issues --into ehmpathy/rhachet --exid 599 --description '…'`. the push
stops before the edit: the same beaver nudge as a new push, the repo marked `(public)`, the three
lines of what to look for, and as its last line the exact command it just ran plus
`--promise task-to-public-repo-is-anonymized`. issue 599 on github is untouched — the edit, and so
its history, never happened. `queue get` shows naught held. the clone sees "sandpine/svc-lessons"
and "pr 88" in its own note, rewrites it as "fixed upstream", and re-runs the printed command with
the new text. the edit lands.

## .bdd sketch

```
given a gh repo whose visibility is PUBLIC, and an extant issue 599
  when radio.task.push --exid 599 --description '..' (no --promise)
    [t0] then exit code is 2
    [t1] then stdout holds the 🦫 nudge, the repo marked `(public)`
    [t2] then the nudge's last branch is the exact command + `--promise task-to-public-repo-is-anonymized`
    [t3] then no edit request reached the transport
    [t4] then the push's record is DROPPED, so `queue get` shows naught held
  when the same push, its text rewritten, carries --promise task-to-public-repo-is-anonymized
    [t5] then one edit request reached the transport; exit code is 0     (#9)
```
