# evaluation: a push to a public repo needs an anonymized promise

compares the execution to `3.3.1.blueprint.product.yield.md`.

## summary (as implemented)

one **promise gate** in `setRadioTaskRecordUpstream`, the per-record send. it sits after the auth derive and before the request, at one line: `setRadioTaskRecordHeldOnPromiseGate`. every send path runs through it: a push's own record, the backlog that push carries out, and `radio.task.queue drain`. a test pins the single egress: `radioTaskPush` has one importer, and that importer is called only by the per-record send.

the gate:
- reads `gh repo view <o/n> --json visibility` under the record's own auth, but only for a gh.issues record that carries text and holds no promise
- PRIVATE or INTERNAL → the request goes out
- PUBLIC, an unknown value, or a rejected read → the record is held, QUEUED, with reason `public-repo:unpromised`, `public-repo:unreadable`, or `public-repo:unreadable-auth`, and `halt: false`
- a rate limit or outage on the read is a wall: held, `halt: true`, with a detail line that names the promise the record will owe once the read clears (F14, F20)
- the push's own record is DROPPED in the same settle, under the same lock, behind the same re-push guard

promise flows:
- `--promise` on a push is stored only when that push passed every text the record will carry. it is never inherited, a description amend clears it, and a body the gate dropped is never inherited by a later push
- `drain --promise` vouches every held record that drain sends, and is never stored
- any other value, a bare flag, or a blank value exits 2 before any record

the push cli drops its own record and prints the 🦫 nudge: the backlog fates, then the tree, then the exact command flush-left with `--promise`, exit 2. `--help` of push and queue name the flag.

one extra review-driven fix: a blank `--exid`, `--title`, or `--description` is refused on every push.
