# blueprint: a push to a public repo needs an anonymized promise

## summary

one **promise gate** in `setRadioTaskRecordUpstream` (the **per-record send**). every path that sends a
record routes through it: a `radio.task.push` of its own task, the backlog that push carries out, and
`radio.task.queue drain`. for a gh.issues record that carries text (a create, or an `--exid` title /
body edit) and no promise, the promise gate reads the repo's visibility via `gh repo view <owner/name>
--json visibility` under the record's own auth. PRIVATE or INTERNAL → the **request** goes out as
today. PUBLIC, any other value, or a failed read → the record is **held**: its fate is `held`, its
status stays `QUEUED`, its reason is `public-repo:unpromised` or `public-repo:unreadable`, and
`halt: false`, so the line goes on.

terms, each used in one sense below:
- **promise** — the literal `task-to-public-repo-is-anonymized`. it comes from `--promise` on a push
  (stored as `record.promise`) or on a drain (`promiseOverride`, never stored). a record is
  **promised** when either equals the literal
- **promise gate** — the visibility check above, new. never a bare "gate" below. the extant check
  is always **radio.uses gate**, and its extant state word `held at gate` keeps that sense alone
- **the clamp** — the integration test that pins the promise gate: no promise → no create/edit
  request on calls.log (the read still lands there); promise → exactly one create/edit request.
  the pr description says so: the wish's "no request" is read as no create/edit; the read still
  shows in calls.log, so the commander is not surprised by it
- record dispositions, three layers: **status** is the stored field (`QUEUED`, `DELIVERED`,
  `DROPPED`, …); **fate** is what one per-record send returned (`held`, `delivered`, …); **state** is
  the word `queue get` shows, derived from status + reason by `asRadioTaskRecordState`
  (`held at gate`, `set aside`, `awaits promise`, …)
- **per-record send** — `setRadioTaskRecordUpstream`, whole. it makes up to two gh calls:
  **the read** — `gh repo view … --json visibility`, the promise gate's call; and **the request** —
  the create/edit call that delivers the task (`setRadioTaskUpstreamFromRecord`). the read is not a
  request

the promise flows:
- `radio.task.push --promise <promise>` stores it on the push's own record, taken only from the push
  at hand (never inherited), and only when that push passes text (a title or a description) itself.
  a push with no text stores no promise, so a body it inherits from an earlier push is always owed and
  the nudge names it (catalog #28, #35, #39). one rule: a promise vouches for the text it came with
- `radio.task.queue drain --promise <promise>` promises every held record this drain sends (F3,
  ruled: a deliberate widen — the drain's caller attests for records it did not author; the drain
  output names each record it sent, so the attestation is on the page)
- any other value, or a bare flag, exits 2 before any record or request, the valid value named

residual windows, accepted and named:
- the read and the request are two gh calls; the promise gate attests "private one round-trip ago", not
  "private at the request" — github offers no atomic check-then-write on visibility
- a body piped via `--description @stdin` re-prints as `@stdin` in the nudge's command; the caller
  re-pipes the checked body (that re-pipe is the scrub moment the nudge exists for)
- a status-only CLAIMED / DELIVERED publishes the source branch name and assignee, derived by the
  extant send, ungated (see omitted: issue row 7)

the push cli, when its own record was held by the promise gate, drops that record (F2) and prints the 🦫
nudge with the exact command plus `--promise`; exit 2. a drained record stays held, named with its fix
lines. status-only updates and os.fileops never read visibility. `--help` of push and queue name the
flag; the queue's help says `drain --promise` promises every held public record.

## nudge layout

one order, every shape: the backlog fates first (if any), then the 🦫 tree, then a blank line, then
the command flush-left as the LAST line, so the line a clone copies is always the bottom one and a
multi-line body is never railed. the tree's last leaf is "once checked, re-run the command below".
this departs from the issue's literal tree (command inside the last leaf) for copy-safety; named in
the omitted table. "verbatim" in this blueprint means: the issue's lines, in its order, with the
command moved below the tree.

plain (catalog #1):
```
🦫 hold up — this task goes to a public repo
   ├─ repo: ehmpathy/rhachet (public)
   ├─ check the title and body hold none of:
   │  ├─ the source org, repo, route path, or pr / issue numbers
   │  ├─ internal endpoint, service, table or product names
   │  └─ customer, revenue or other business detail
   └─ once checked, re-run the command below

rhx radio.task.push --via gh.issues --into ehmpathy/rhachet --title '…' --description '…' --promise task-to-public-repo-is-anonymized
```

inherited body (catalog #28, #39) — a status-only push whose record carried an earlier body:
```

   ├─ repo: ehmpathy/rhachet (public)
   ├─ this record carries a body from an earlier push, at .behavior/.radio/record.<key>.json
   │  └─ a --promise here cannot vouch it; that body is dropped now
   ├─ to send status alone: re-run the same command, as you ran it
   ├─ to send the body too: check it (none of the three below), then re-run the command below
   ├─ check the title and body hold none of:
   │  ├─ …the three lines…
   └─ once checked, re-run the command below

rhx radio.task.push --via gh.issues --into ehmpathy/rhachet --exid 5 --status CLAIMED --description @stdin --promise task-to-public-repo-is-anonymized
```
