## P1 — the per-record send is the one site push, backlog flush, and drain share · [EXTEND]

[1] `src/domain.operations/radio/record/setRadioTaskRecordUpstream.ts`:
> ".what = send one record upstream on its own terms, then settle its fate"
> ".why = each record meets its own target's gate (X1) and its own channel + auth (C22)"

its order: the radio.uses gate (`if (!gate.allowed) return setRadioTaskRecordHeldAtGate(...)`), the auth
derive, the near-deadline check, the auth fault hold, then the send:
> "const send = await setRadioTaskUpstreamFromRecord(\n    { record },\n    asRadioContextWithSendLimit({ radioContext: auth.radioContext, limit }),\n  );"

- relation: one gate placed after the auth fault hold and before `setRadioTaskUpstreamFromRecord`
  covers every path (criteria 2.3: "composes the promise gate after the radio.uses gate and the auth
  derive, before the send"). the read needs the record's own auth — available only after the derive
- extend: compute `limit` before the gate, so the read and the send share one send bound
