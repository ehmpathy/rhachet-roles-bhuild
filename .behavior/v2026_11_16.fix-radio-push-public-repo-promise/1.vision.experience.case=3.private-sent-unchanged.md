# case=3: a push to a private repo → sent as today

happy × critipath · cells #3, #5, #10 · happy × alterpath · cells #4 (and #10b, #14, #17b by the promise-ignored rule)

## .narrative

a clone on `sandpine/svc-lessons` (private) finishes a lesson-reminder fix and hands the follow-up
to its own repo:
`rhx radio.task.push --via gh.issues --into sandpine/svc-lessons --title 'retry failed lesson reminders' --description '…'`.
the visibility read says PRIVATE, so the gate lets it through. the clone sees the usual
`🦫 delivered` output, issue #212 created, with no nudge and no new flag. the next day, out of habit
from a public push, it adds `--promise task-to-public-repo-is-anonymized` to a push into the same
repo: the push lands the same way, the flag accepted and ignored. a week on it amends issue #212's
description with `--exid 212`, no promise: the edit lands, no nudge.

## .bdd sketch

```
given a gh repo whose visibility is PRIVATE (or INTERNAL)
  when radio.task.push ... with no --promise                                  (#3, #5)
    [t0] then exit code is 0
    [t1] then exactly one create request reached the transport
    [t2] then stdout matches the extant push output (no nudge)
  when radio.task.push ... --promise task-to-public-repo-is-anonymized         (#4)
    [t3] then exit code is 0, one request sent, the promise ignored
  when radio.task.push --exid 212 --description '..' with no --promise             (#10)
    [t4] then exit code is 0, one edit request reached the transport, no nudge
```
