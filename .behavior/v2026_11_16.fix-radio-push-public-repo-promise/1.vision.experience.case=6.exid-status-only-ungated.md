# case=6: a status-only update → never gated

happy × critipath · cells #13 (and #14 by the same rule)

## .narrative

a worker claims issue 599 on a public repo: `--exid 599 --status CLAIMED`. no text leaves the
machine, only a label move. the claim must not stall on a promise, or every claim and delivery on a
public repo would grow a ceremony with no payoff.

## .bdd sketch

```
given a gh repo whose visibility is PUBLIC, and an extant issue N
  when radio.task.push --exid N --status CLAIMED (no title, no description, no --promise)
    [t0] then exit code is 0
    [t1] then the status update reached the transport
    [t2] then no visibility read was needed (the gate is skipped, not passed)
```
