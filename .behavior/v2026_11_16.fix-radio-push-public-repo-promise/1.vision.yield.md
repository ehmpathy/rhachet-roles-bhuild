# vision: a push to a public repo needs an anonymized promise

## .the outcome world

### before

a clone pushes a follow-up into `ehmpathy/rhachet` (public). its description, pasted from its own
notes, names the private repo it came from, a route path, and a pr number. `radio.task.push` sends
it. the issue is world-readable at once. a later edit hides the text from the page, not from the
edit history. the leak is permanent and no one was asked.

### after

the same push stops before the send:

```
🦫 hold up — this task goes to a public repo
   ├─ repo: ehmpathy/rhachet (public)
   ├─ check the title and body hold none of:
   │  ├─ the source org, repo, route path, or pr / issue numbers
   │  ├─ internal endpoint, service, table or product names
   │  └─ customer, revenue or other business detail
   └─ once checked, re-run the command below

rhx radio.task.push --via gh.issues --into ehmpathy/rhachet --title '…' --description '…' --promise task-to-public-repo-is-anonymized
```

exit 2. no request reached github. the clone reads its own text against the three lines, strips
what it finds, and re-runs the printed command. the issue lands clean.

### the aha

the gate costs a private-repo push naught — no nudge, no new flag. it costs a public-repo push one
deliberate re-read, at the only moment a re-read can still help: before the send.

## .the experiences

the experience space is decomposed in `1.vision.experience.dimensions.md` (content × visibility ×
promise × pusher presence × channel), every cell verdicted in `1.vision.experience.case=_.md`, and each critipath
demonstrated:

| case | experience | feel × care |
|---|---|---|
| `case=1` | public, no promise → nudge, exit 2, naught sent | sharp × critipath |
| `case=2` | public, with promise → sent | happy × critipath |
| `case=3` | private / internal → sent as today, a promise ignored | happy × critipath |
| `case=4` | visibility unreadable → treated as public | sharp × critipath |
| `case=5` | `--exid` text update, public → gated like a create | sharp × critipath |
| `case=6` | `--exid` status-only → never gated | happy × critipath |
| `case=7` | drain of a held public record → promise on record or on drain sends it; else set aside, rest deliver | happy + sharp × critipath |
| `case=8` | a private push flushes a backlog with an unvouched public record → it lands, the public one waits, named with its fix | sharp × critipath (densest) |

## .the contract

- new flag on `radio.task.push`: `--promise task-to-public-repo-is-anonymized`
- new flag on `radio.task.queue drain`: the same `--promise`, which vouches for every held public
  record in that drain
- a held record carries the promise when its push did, so a later drain needs no re-promise. the
  promise is never inherited from a prior push: a re-push without it drops it, so a promise only
  ever vouches for the text it came with
- a nudged push is recorded, like every push, then its record is dropped (DROPPED, the nudge as
  why). the caller is present and told to re-run, so naught waits on its behalf:
  - a re-run with the same title lands on the same key, and a push re-queues a dropped record
  - a re-run with a scrubbed title lands on a new key, and no stale record lingers behind it
- a held record bound for a public repo, met by a drain with no promise, is set aside QUEUED with
  the nudge as its reason — its caller is absent, so it waits for `drain --promise`
- the gate reads visibility via `gh repo view <owner/name> --json visibility`, only when text would
  leave the machine on the `gh.issues` channel, and only after the radio.uses gate is open
- `--help` on both skills names the flag and when it is owed
- any `--promise` value other than the one literal is refused, exit 2, the valid value named

## .mental model

> *"public repos make you promise you scrubbed the text first."*

a customs declaration: most travel is domestic and nobody asks. cross the border and you sign a line
that says you carry naught forbidden. the officer does not search the bag — the signature is the
point, and the line names what to check.

the caller's words: "public repo", "scrub", "anonymize". ours match: the promise slug is the
caller's own sentence, `task-to-public-repo-is-anonymized`, so it reads as *"i promise the task to a
public repo is anonymized."*

## .evaluation

### pros

- the leak is caught at the one moment it is still reversible
- zero friction on the common case (private repos), one re-run on the rare one
- the nudge names what to check, so the re-read is concrete, not a ritual
- fail-safe: an unreadable visibility never yields an unchecked send

### cons

- the promise is self-attested; a caller can re-run without a real re-read. the gate makes the
  check deliberate, it cannot make it honest. a content scanner is out of scope (the wish asks for
  a promise, not a filter)
- one extra `gh repo view` per gated send — a few hundred ms on a path that already calls gh

### edgecases held in the pit of success

- **status-only update** — no text, no gate, no visibility read (`case=6`)
- **auth fault, or an unreadable answer** — treated as public, never sent unchecked (`case=4`)
- **rate limit or outage on the read** — a wall, as for a send: the record stays queued and reads again next drain; never sent unchecked, never nudged (fulcrum F14)
- **one bad record in a drain** — set aside, the rest deliver (`case=7`)
- **a mistyped promise** — refused loud, never a silent non-vouch (`case=_` #23)
- **os.fileops** — no remote send, so no gate (`case=_` #20–22)

## .open questions & assumptions

### assumptions

- [answered] `internal` sends as private — the issue's row 4 says so (F4)
- [answered] the gate covers only `gh.issues` — os.fileops sends no request, and the issue's clamp
  is phrased on the transport. a logic answer; F1 holds it for the council
- [answered] a nudged push's record is dropped; a re-run re-queues it when the title is the same
  (`isRadioTaskRecordRequeuedByPush.ts` L29–31: a DROPPED record re-queues on any push of the
  same task), and leaves no stale record when the title changes (the key hashes
  `create\nrepo\ntitle`, `asRadioTaskRecordKey.ts` L21–24)
- [answered] when radio.uses blocks a push, the record is held before any send; the visibility
  read happens at delivery, per record, so the promise rides on the record until then
- [answered] "no send" (row 2) binds the public record, not the whole push. a nudged push still
  carries out a private backlog that owes no promise (`case=8` in reverse); to abort the whole push
  would regress "the next push that gets through delivers the backlog"
- [answered] the backlog flush a push performs is a send path the gate covers, though row 6 does
  not name it — it is the same drain as `queue drain`, and to skip it would be a bypass

### open questions

- [research] how does `runGhCommand` surface a failed `gh repo view` — a thrown error, or an exit
  code and stderr? the gate must classify every failure as "unreadable", never let one escape as a
  malfunction that halts the drain
- [research] how does the drain output render a held record's reason and fix
  (`asRadioQueueFixLines.ts`, `asRadioDrainOutput.ts`)? the public-repo hold needs its own fix line
  (`drain --promise …`), and `queue get` and the stop-hook reminder must show it too
- [research] which stub `gh` scripts exist across the test suites, and how each answers an
  unknown subcommand — each must learn `repo view --json visibility`, default PRIVATE, or extant
  journeys turn red
- [research] which real-github acceptance tests push text into the public demo repo — each owes
  `--promise`
- [wisher] none. the issue states every row; the calls above are fulcrums with clean reworks,
  itemized at `.fulcrums/`

## .groundwork

### external research

- `gh repo view <owner/name> --json visibility` — checked live, 2026-11-16:
  - a real public repo → `{"visibility":"PUBLIC"}`, exit 0
  - an absent repo → `GraphQL: Could not resolve to a Repository…`, exit 1 → the gate's
    "unreadable" path
- the values are `public | private | internal` (`gh repo list --help`: "Filter by repository
  visibility: {public|private|internal}"); `--json visibility` renders them upper-case, as seen above

### internal research

- **one send site serves every path.** `radioTaskPush.ts` (cli) records the push first
  (`setRadioTaskRecordFromPush`, L200), then drains the backlog with this push in its place
  (`getOneRadioPushDrainWithBacklog`, L220). `radio.task.queue drain` calls the same
  `setRadioTaskRecordsDrained`. both reach `setRadioTaskRecordUpstream.ts`, which re-reads the
  radio.uses gate per record (L68), derives auth (L83), then sends (L152). ⇒ the promise gate sits
  there, after auth and before the send: rows 1–6 of the issue hold for every path at once
- **the record key** — `asRadioTaskRecordKey` hashes `create\nrepo\ntitle` or
  `update\nrepo\nexid\nstatus`; description is not in the key, so a re-push with the same title
  upserts the same record
- **the record** — `src/domain.objects/RadioTaskRecord.ts` (DomainEntity, unique on `key`), fields
  `kind, repo, via, auth, idem, title, description, exid, status, recordStatus, reason, heldSeq,
  deliveredExid`; file schema mirrored at `src/access/daos/daoRadioTaskRecord/index.ts`. a
  `promise` field is new
- **set aside, rest deliver** — a fault that does not halt settles the record QUEUED with a
  `reason` and returns `fate: 'held', halt: false` (`setRadioTaskRecordUpstream.ts` L177–201); the
  line continues (`setRadioTaskRecordNextInLine.ts`). the public-repo hold reuses this shape
- **status-only** — an update record whose `title` and `description` are null; the gate skips it
- **gh transport** — the `gh` binary via `execFile` (`runGhCommand.ts`), with `GH_TOKEN` set from
  the record's auth. the visibility read rides the same communicator and the same token
- **stdout shape** — held pushes render via `asRadioPushOutput.ts` (`🦫 held for the radio`, treestruct
  via `asRadioTreeLines`); drain via `asRadioDrainOutput.ts`. the nudge follows the issue's text
- **tests** — gh is faked by a stub `gh` first on `PATH` that logs each call to `calls.log` and reads
  per-repo `mode.<owner>_<name>` files (e.g. `skill.radio.task.recorder.acceptance.test.ts`
  L1266–1283 asserts `calls` is empty). every stub must learn `repo view --json visibility`, or the
  gate reads extant journeys as unreadable → public
- ⚠️ **the real-github acceptance tests push into `ehmpathy/rhachet-roles-bhuild-demo`, which is
  PUBLIC** (checked live). they will owe `--promise` once the gate lands
- **no extant visibility or promise code** — the only `gh repo view` reads `nameWithOwner`
  (`src/infra/git/getRepoFromGitContext.ts`)

## .what is awkward?

- the promise is a long literal. it is long on purpose: it reads as the sentence the caller signs,
  and the nudge prints the full command, so no one types it from memory
- drain's `--promise` vouches for every public record in that drain at once. a caller who wants to
  vouch for one record alone re-pushes it with the promise instead (same key, same record)
- a push's own nudged record is dropped, while a drained one is held. two fates for one gate — the
  split follows who is present: the pusher is told to re-run now; a drained record's pusher is gone
