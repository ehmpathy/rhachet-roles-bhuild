# reflection.premortem: we shipped the promise gate, and it failed

## premortem: imagine we shipped and it failed

1. **a leak shipped through a path the gate never saw.** the gate sat in the push cli, not in the
   per-record send, so a backlog flush or a `queue drain` sent an unvouched record to a public repo.
   or the gate covered creates but not an `--exid` text edit
2. **the gate failed open.** the visibility read threw (timeout, 401, an absent repo) and the throw
   was read as "no gate", or bubbled as `upstream:transient` and was retried until a later read said
   PRIVATE by a stub — or an unknown value (`""`, a future enum) fell through as private
3. **every clone learned to append `--promise` with no re-read.** the nudge printed the full command;
   after a week the re-run was a reflex, and a leak shipped with the promise on it
4. **the vouch outlived its text.** a re-push of new text with no `--promise` inherited the old vouch
   from the record (auth and body inherit; a copy of that pattern carried promise too), and sent
5. **the suites went red the night before the window.** six stub `gh` executables did not answer
   `repo view`; every stubbed send held; the demo-repo journeys nudged; case7's 401 turned into a
   hold. the pr missed its 2026-11-17 window
6. **the drain halted the whole line on one public record.** the hold carried `halt: true`, so a
   private record behind it never sent
7. **a held record from before the change failed to parse.** the record file shape gained `promise`
   as required, and every record on disk failed loud on the next drain

## what obvious signs did we ignore?

- the per-record send is already shared by push, backlog flush, and drain (code.prod P1); a gate
  anywhere else was a sign of a split path
- `runGhCommand` throws three classes (flagged yield, topic 1); a catch of one class was a sign of a
  fail-open path
- `asRadioTaskRecordFromPush` inherits auth, body, idem with `??` (code.prod P3); a copy of that line
  for promise was the obvious mistake to avoid
- the stubs extract the repo from `--repo` only, and `repo view` takes it positionally (code.test T1)
- the demo repo is public (flagged yield, topic 4)
- the habituation research (claims yield, L5)

## what assumptions could turn out wrong?

| assumption | what if wrong? | likelihood |
|---|---|---|
| `gh repo view --json visibility` answers PUBLIC / PRIVATE / INTERNAL | an absent or new value reads as private → fail open | low; mitigated by "only PRIVATE / INTERNAL allow" |
| the record's own auth can read the repo's metadata | a token scoped to issues only fails the read → every send to that repo holds as unreadable | low ([13] of access yield: a metadata read comes with repo access); fail-closed, with a clear marker and a promise path |
| most pushes target private repos | a crew that mostly files into public repos sees the nudge often → habituation | medium; the ehmpathy role packages are public |
| a clone re-reads its text before the re-run | it re-runs blind | medium; no gate can force a read |
| one extra gh call per gated send is cheap | the drain send budget runs out sooner | low; one call, bound by the same limit |
| the vouch slug is the only accepted value | a typo is accepted as a vouch, or silently ignored | low; the value check refuses any other value |

## what is the nightmare scenario?

the gate ships, reads green, and a clone pushes a follow-up into `ehmpathy/rhachet` (public) with the
private org's repo name, route path, and customer detail — with `--promise` on it, appended by habit.
the issue is archived within the hour (claims L1). the commander learns of it from outside. the gate
gave false comfort: everyone believed leaks were now impossible.

the second nightmare is quieter: the gate fails open on unreadable visibility for a month, because the
tests stubbed only PUBLIC and PRIVATE.

hardest to recover from: either — a public leak cannot be recalled.

## what mitigations to consider?

| risk | mitigation | cost of mitigation |
|---|---|---|
| a path the gate never saw (1) | gate in `setRadioTaskRecordUpstream`, the one shared send; acceptance for push, `--exid` edit, backlog flush, drain | none beyond the plan |
| fail open (2) | catch every throw → `unreadable`; allow only exact PRIVATE / INTERNAL; unit cases for empty, unknown, malformed json; stub case for a failed read | a few unit cases |
| reflex promise (3) | nudge only where owed (no nudge on private / status-only); a checklist of concrete detail; the vouch per push; `--help` says the promise is per push; the pr names this residual risk | copy only |
| vouch outlives text (4) | `promise: input.push.promise`, never `?? before.promise`; a unit test for the re-push with no promise | one unit case |
| red suites before the window (5) | update all six send-path stubs first, default PRIVATE; promise on the demo-repo text pushes and on case7's record; run the full suite before the pr | an hour of test edits, planned early |
| one record halts the line (6) | `halt: false` on the promise hold; a drain case with a private record behind a held public one | one acceptance case |
| old records fail to parse (7) | `promise` defaults to null in the file shape; key order appends a defaulted key | one dao case |
