# case=8: a private push flushes a backlog that holds an unvouched public record

sharp × critipath · cells #16 and #17 via the push path (the densest walk: radio.uses gate → hold →
backlog flush → visibility read → promise gate, in one experience)

## .narrative

yesterday radio was blocked, and a clone's push to `ehmpathy/rhachet` (public, no promise) was held
at the radio.uses gate — no visibility was read, since naught was sent. today a human lifts the
gate, and a different clone pushes a task to `sandpine/svc-lessons` (private). that push gets
through, so it carries the backlog out first: the public record meets the promise gate with no
promise, and is set aside, QUEUED, with the nudge as its reason. the private push lands. the push's
output says its own task was delivered, and names the one backlog record that still waits and why,
with the drain command that sends it once its text is checked. no text reached the public repo.

## .bdd sketch

```
given a held record A bound for a PUBLIC repo, no promise on record (held at a shut gate)
  and the gate now open
  when radio.task.push --into <a PRIVATE repo> --title .. --description ..
    [t0] then this push's create request reached the transport; exit code is 0
    [t1] then no create request for A reached the transport
    [t2] then A stays QUEUED, its reason the public-repo hold — not DROPPED (its pusher is absent)
    [t3] then the output names A as still held, with `rhx radio.task.queue drain --promise task-to-public-repo-is-anonymized`
```
