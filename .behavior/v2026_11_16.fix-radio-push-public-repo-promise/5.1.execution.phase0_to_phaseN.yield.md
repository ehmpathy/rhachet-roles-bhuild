## deviations from the blueprint
- the fault sort sits in `getOneRadioPromiseHold` (domain), not the communicator: `getOneGhRepoVisibility` (access) throws on a gh fault, and the domain sorts fault vs defect via `asRadioUpstreamFault` — the access layer must not import a domain transformer (directional deps)
- `asHeldFixBranch`'s `next` line names the exception when the backlog holds a record that awaits a promise (`getAllRadioFatesAwaitPromise`); journey [case8][t5] snaps it
- the "will owe --promise" note shows at the shut gate and in the read wall's detail; under other faults a held fate cannot tell a fault before the gate from one on the send (F20)
- an update with a blank `--title` is refused like a blank body (`asPushTaskFromArgs`); journey [case9][t2] snaps it
- the plain `@stdin` nudge names the record file that holds the piped body
- a blank `--exid` is refused, so an update record never sends as a create (`asPushTaskFromArgs`)
- the auth-cure nudge names the `--promise` way through for a host with no human login; journey [case8][t3] snaps it
- the one egress is pinned: `setRadioTaskUpstreamFromRecord.egress.integration` asserts `radioTaskPush` and its caller each have one importer
- a hold detail cuts the class header off its cause (`asRadioPromiseHoldDetail`), so no nested `✋ ConstraintError:` sits inside a row
- `eco.seed gen` shows the push's stdout on a failed push, so a public repo's nudge reaches its caller; clamp `eco.seed.integration` [case6][t4], proved red with the fix reverted
- the shared cli parser keeps `--flag ''` as an empty string (F19); the `init.behavior --wish ""` snap moved with it
- `asRadioPushOutput` keeps its own backlog fates render; `asRadioPushBacklogBranches` serves the nudge only. the one line both wrote (`backlog = N awaits the radio`) is lifted to `asRadioBacklogBranch`, shared
- a promise vouches only when the push passed every text the record will carry: a title-only push over an inherited body stores no promise (`asRadioTaskRecordFromPush`), so the gate still reads the repo and the nudge names the inherited body. clamp: `asRadioTaskRecordFromPush.test.ts`, proved red with the guard reverted
- a held row of a record that awaits a promise reads `awaits:`, not `fault:` (`asRadioFaultDetailLine`); read faults keep `fault:`
- the drain lock's wait notice fires on a probe acquire that finds the key held (`withRadioDrainLock`), not on a 750ms timer: under load the timer fired on an uncontended acquire, and a journey snap caught a false `another drain holds it`
- criteria usecase.3 and the vision `.edgecases` now agree with usecase.12: a rate limit or outage on the read is a wall, for a push as for a drain (F14). journey [case8][t5] proves the push path: exit 2, no create, record QUEUED, no nudge
- a whitespace-only body on a create meets the create-required message, not the update-only blank-body advice (`asPushTaskFromArgs`)
- the journey test is `skill.radio.task.push.promise.acceptance.test.ts`, not the blueprint's `….promise.play.acceptance.test.ts`: no other blackbox file uses a `.play` suffix; a variant is a plain dot segment (`.wish.`, `.flags.`, `.bind.`)
