# case=1 — a vision writer meets a poc and a parity target, and restates both

feel = happy · care = critipath · rows v.how.restate, w.how · 3 boundaries (wish → yield, evidence → spec, yield → review)

## .narrative

a clone drives `1.vision` on a wish for `rhx brains auth get|set|use|del`. the wish says *"`get`
should show what `brains.auth.usage` shows"* and *"see the swap command for how `use` works"*.

the session booted the behaver cue, so the clone reads those two lines as evidence, not spec. it
opens the swap command and `brains.auth.usage` to learn from them, then writes a table into the
yield before any design:

| how in the wish | restated in domain terms | verdict |
|---|---|---|
| parity with `brains.auth.usage` | per account: each usage window, its used share, its reset | keep the facts; drop the tool as the yardstick |
| the swap command's three scopes | which seats must change account, and who asks | challenge → `[wisher]` is scope an explicit input? |

the verbs `get|set|use|del` stand untouched. the guard's self-review `has-restated-the-wisher-how`
strikes both tools and re-reads each requirement: each still reads right.

the wisher opens the vision and sees their own hows, each with a verdict, and one question their
swap command raised that they had not thought to ask.

## .bdd sketch

```
given('[case1] a wish that names a poc and a parity target', () => {
  when('[t0] the writer drives 1.vision with the behaver cue booted', () => {
    then('the yield holds a table of each how in the wish')
    then('each how is restated in domain terms, with a keep or drop verdict')
    then('the verbs the wisher asked for are all present')
  })
  when('[t1] the self-review strikes the prior tools from the repo', () => {
    then('each requirement still reads right')
  })
  when('[t2] the wisher reads the vision', () => {
    then('each of their hows shows its verdict')
    then('a how that raised a real question is marked [wisher]')
  })
})
```
