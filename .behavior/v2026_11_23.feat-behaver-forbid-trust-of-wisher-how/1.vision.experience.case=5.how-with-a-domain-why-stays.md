# case=5 — a how backed by a domain why stays, as a constraint

feel = happy (t0) / sharp (t1) · care = critipath · rows v.hww.restate, v.hww.overcorrect · 3 boundaries (wish → yield, evidence → spec, yield → review)

## .narrative

a sandpine wish asks for `rhx instructor.cert set` and says: *"store the cert scan in the keyrack,
because a cert scan holds an instructor's id number and must never sit in the repo."*

this is a how — a named storage mechanism — but the wisher tied it to a domain why: id numbers
never land in git. the rule's constraint row covers it. the writer keeps it, and states it with its why:

> a cert scan holds personal id; it is never written to a tracked file. it is held where secrets
> are held (today, the keyrack).

the strike test passes: delete the keyrack from the sentence and the constraint still reads right —
*"never written to a tracked file"*.

`[t1]`, the inverse: another writer reads *"never trust the how"* and drops the keyrack line as an
implementation detail. the yield now lets a cert scan land in a tracked json. the self-review asks
*"does a how the wisher tied to a domain why survive, stated with that why?"* — no. the writer
restores it.

## .bdd sketch

```
given('[case5] a wish whose how carries a domain why', () => {
  when('[t0] the writer restates it as a constraint', () => {
    then('the yield states the why, not only the mechanism')
    then('the strike test passes: the constraint reads right with the tool struck')
  })
  when('[t1] a writer drops it as just a how', () => {
    then('the self-review flags the absent constraint')
    then('the writer restores it, stated with its why')
  })
})
```
