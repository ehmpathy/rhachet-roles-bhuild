# case=5 · a dropped prescription goes red

feel = sharp · care = critipath

## .narrative

six weeks later, rio reworks the blueprint guard's self-reviews. in the edit she deletes the
`brain:` line by accident. no runtime error would ever surface: the blueprint stone would inherit
opus from the vision, so the drive would look fine. but a route that resumed at the blueprint on a
sonnet session would now shape its blueprint on sonnet, and nobody would notice.

the test suite catches it. the test is this change's deliverable; what follows is what it asserts.
for each of the 10 size × variant pairs — nano, mini, medi, mega, giga, each under light and
heavy — the test walks the stones in route order and
computes the brain each stone lands on — its own `brain:` if its guard has one, else the prior
stone's. it asserts design stones land on opus and build stones on sonnet. it also asserts every
guard template declares a brain. rio's run goes red, and the failure names the stone and the
template.

she restores the line. green.

the same suite guards a new stone, reached from the other side — see `case=9`.

## .timeline

```
given('[case5] the bhuild template set')
  when('[t0] every guard template carries its brain')
    then('for each of nano·light, nano·heavy, mini·light, mini·heavy, medi·light, medi·heavy, mega·light, mega·heavy, giga·light, giga·heavy: the walk lands design stones on claude-opus-5-5[1m]')
    then('for each of the same 10 pairs: the walk lands build stones on claude-sonnet-5-5[1m]')
  when('[t1] a maintainer deletes brain: from 3.3.1.blueprint.product.guard.light')
    then('the test fails, and the message names 3.3.1.blueprint.product.guard.light')
  when('[t2] she restores the line')
    then('the test passes')
```

## .why it fails safe

the failure is fast (an integration test that reads the templates; no route drive), loud (red in
ci), and it teaches the fix (it names the template and the brain it expected).
