# case=6 · an unenrolled driver halts at the vision

feel = sharp · care = critipath

## .narrative

theo opens a terminal, types `claude`, and runs `rhx init.behavior --name fix-hint-typo --size nano`.
his session was never spawned by `rhx enroll`, so it has no clone address. until today that did
not matter: no bhuild stone declared a brain.

he asks his clone to drive. the drive reaches `1.vision`, whose guard now declares
`brain: claude-opus-5-5[1m]`. bhrain must say `/model` into the driver, and it has no address to
say into. it does not shrug and drive on — that would let a route claim opus on a stone opus never
saw. it halts (bhrain seed S8: always halt):

```
🗿 route.drive
   ├─ where do we go?
   │  ├─ route = .behavior/v2026_10_05.fix-hint-typo
   │  ├─ stone = 1.vision
   │  └─ brain = claude-opus-5-5[1m]
   ...
   └─ ✋ halted, brain switch could not land
      ├─ this driver runs = unknown — no clone address was confirmed
      │
      ├─ why
      │  ├─ this driver is not an enrolled clone, so `clone say` has naught to address
      │  └─ the usual cause is a driver launched directly rather than by `rhx enroll`
      │
      ├─ fix: re-enroll the driver with a slug, then re-enter the stone
      │  └─ rhx enroll claude --as @:driver --roles driver
      │
      └─ or: remove `brain:` from the stone's guard, and inherit the brain deliberately
         └─ .behavior/v2026_10_05.fix-hint-typo/1.vision.guard
```

the halt rows are bhrain 0.39.2's `unenrolled` cause, quoted from
`formatStoneBrainUndispatched` (`HALTS.unenrolled`). bhrain picks the cause from what
`clone whoami` reports (exit 2 outside an enrolled clone = `unenrolled`). the acceptance journey
proves this halt: `skill.init.behavior.guards` `[t13]`–`[t15]` drive as an unenrolled session and
snap it at three `brain:` stones. the `[t1]`–`[t2]` steps below (the switch lands once enrolled) are
bhrain's dispatch to an enrolled clone; they stay a sketch, since no bhuild test holds one. a session whose probe gives no readable answer meets a peer halt
with a different fix: cell c16b.

theo runs the fix. the new, enrolled clone re-enters `1.vision`, the switch lands, and the route
drives as in `case=1`. every later `brain:` stone dispatches cleanly in that session — one
re-enroll clears the route for that session. enrollment belongs to the session, not the route: if
theo later opens a fresh terminal and types `claude` again, that session halts at the next
`brain:` stone it enters, with the same fix.

the halt is bhrain's; the reach is ours. this change is what puts a `brain:` on the first stone of
every route, so it is what puts theo in front of this halt.

## .why it fails safe

fast (the halt fires at the first stone, before any design work), loud (the stone stops), and it
teaches the fix (a copy-paste `rhx enroll` line). no stone runs on an unswitched brain while it
claims the prescription. bhrain owns the message; bhuild owns no code on this path.

whether this reach is wanted is a separate question — the wisher's, recorded as fulcrum F8.
