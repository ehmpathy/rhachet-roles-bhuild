# 5.3.verification · handoff v1 → foreman

one red group in the full suites needs a grant only a human can make. it does not sit in this diff
(`git diff --stat origin/main` over `src/access`: empty). each ask is a command you can run.

## 1 · the beaver github token is absent from keyrack

**reds:** integration `genAuthFromKeyrack`, `getGithubTokenByAuthArg` (2); acceptance `radio.task.push`
via gh.issues (14, measured at 5.1).

**the error, verbatim:**

```
✋ ConstraintError: github auth via keyrack failed: EHMPATH_BEAVER_GITHUB_TOKEN (status: absent)
  • or set the robot token: rhx keyrack set --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env test
```

**the ask:**

```sh
rhx keyrack set --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env test
rhx keyrack set --owner ehmpath --key EHMPATH_BEAVER_GITHUB_TOKEN --env prep
```

**levers spent:** `rhx keyrack unlock --owner ehmpath --env test` runs on every test invocation
(`keyrack: unlocked ehmpath/test`); the key is `absent`, not locked, so unlock cannot reach it. a
token value is a credential no clone may mint.

**rides along (F12):** integration `daoRadioTaskViaGhIssues` and acceptance
`skill.radio.task.pull.via-gh-issues` are each `describe.skip` until keyrack provides
`BHUILD_DEMO_REPO_ACCESS_GITHUB_TOKEN`. if you grant that key too, both skips can be lifted:

```sh
rhx keyrack set --owner ehmpath --key BHUILD_DEMO_REPO_ACCESS_GITHUB_TOKEN --env test
```

## why no other way

the wall is a secret value that only its owner holds. a mock would fake the
very boundary these suites exist to prove (`rule.forbid.integration.mocks`), so it is no option.
