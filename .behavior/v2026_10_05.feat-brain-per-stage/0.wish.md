## .the outcome

- every behavior stone **up through the blueprint** (wish, vision, criteria, research, distill,
  blueprint) is driven on `claude-opus-5-5[1m]`
- every stone **after the blueprint** (roadmap, execution, verification, and on) is driven on
  `claude-sonnet-5-5[1m]`
- every **enrolled reviewer that already specifies a sonnet brain** moves to
  `claude-sonnet-5-5[1m]`. a reviewer that names any other brain keeps it — this changes which
  sonnet a sonnet reviewer runs on, never which family a reviewer runs on
- this holds for every behavior size (nano through giga), and a freshly `init.behavior`'d route
  carries it with no step after init
- tests prove the brain each stone and each reviewer resolves to, so a later template edit that
  drops a prescription goes red

## .why now

bhrain can now prescribe a brain per stone, and bhuild's routes do not use it yet. the design
stones earn the stronger brain; the build stones do not need it, and run cheaper and faster on
sonnet. the sonnet reviewers should run on the current sonnet, not an older one.
