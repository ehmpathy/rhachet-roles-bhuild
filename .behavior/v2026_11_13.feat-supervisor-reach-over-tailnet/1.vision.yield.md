# 1.vision — the supervisor reaches every grove over the camp tailnet, as camper

## .the outcome world

### before

- a grove is reachable only if it is an aws instance. `git.grove.wake` always runs keyrack → sts → ec2 → ssm agent wait → ssm port-forward → `HostName localhost / Port <tunnel>`. a hetzner grove dies at the keyrack (`git.grove.wake.sh:248-264`)
- the ssm tunnel brings its own failure modes, each with its own patch: a 20-minute idle expiry (patched by an ssh keepalive), a bound-but-mute orphan port (patched by a banner probe + `pkill`), a plugin that quits on stdin EOF (patched by `setsid … </dev/null`), a tunnel log, an orphan prune
- every unreachable hint, in ~20 sites, says "asleep" and prescribes the wake

### after

- **two axes, never one.** power: an ec2 grove (row holds `account`) is powered up through aws, unchanged; a grove outside aws has no power lever, because it does not sleep. reach: every grove is reached the same way, `ssh camper@<host>` over the tailnet
- `git.grove.wake` on any grove: power up if aws, then await one ssh answer over the tailnet, then upsert the alias `HostName <host> / Port 22 / User camper`. no `aws ssm` call in any supervisor skill
- every crew and term verb already rides `ssh <alias>` + remote tmux (`work/ductwork.uri.sh:267` et al.), so they need no change beyond the alias the wake writes
- a grove that does not answer keeps its extant verdict words (`😴 asleep` at the crew boundary, `💤 asleep` / `🔴 DOWN` / `🔴 MUTE` at the grove boundary); what changes is the **cure** beside them. a grove outside aws gets a tailnet fix; an ec2 grove keeps the wake fix (F06)

### the aha

the supervisor stops to know which cloud a grove lives in. the hetzner box and the ec2 box answer the same `ssh <alias>`, and the only place aws still appears is the one place it has a real job: to switch a sleep box on.

## .the contract

### the reach of a row — one transformer (F05)

| field | rule |
|---|---|
| `power` | `aws` when the row holds `account`, else `none` (F01) |
| `host` | `.host`, unless it is loopback (`localhost`, `127.0.0.1`, `::1`) or absent — a tunnel relic — then `.exid // .name` (F02). `.exid` first: a `.ground` row's name (`grove-x.ground`) is a seat, not a host, while its exid names the box |
| `port` | `.port` when `.host` is not loopback, else 22; absent → 22 |
| `user` | `.user // "camper"` |

wake, list, saturation, saturation.spend, and the unreachable hint all ask this one reader, so they cannot disagree about where a grove answers.

### `git.grove.wake <grove>`

1. read the row's reach
2. if `power = aws`: keyrack, account guard, nat, box — unchanged
3. if `--mode plan`: stop here; no ssh, no alias
4. await `ssh -o BatchMode=yes -o ConnectTimeout=8 -o StrictHostKeyChecking=accept-new -p <port> <user>@<host> true` — up to `--timeout` (default 300) after an aws resume; ~10s for `power = none`. `accept-new` is required: a relic row's new `HostName` has no `known_hosts` entry, so a plain `BatchMode` probe — and every `ssh -n` crew verb after it — would fail `Host key verification failed`. first contact records the key; a CHANGED key still refuses, loud. precedent: `git.grove.saturation.sh:926`, `git.grove.saturation.spend.sh:330`. the tailnet authenticates each peer by its WireGuard key, so trust on first use here is first use over an authenticated link (F07)
5. upsert the alias block, compared whole, as today, with `HostName <host>`
6. on an await failure: exit 1, name `tailscale status` (run here first: is this caller a peer?) then `tailscale ping <host>`, and (aws only) the needs-longer vs starved split. never name ssm (case=7's sharp arm)

leaves the skill: the ssm agent wait, the port-forward, the tunnel log, the `git.grove.stop --prune orphans` hint, the `localhost` keepalive rationale (F04). the keepalive lines may stay in the alias block; they are cheap and harmless on a direct link.

### the no-answer cure — one transformer (#653's `__grove_unreachable_hint`, renamed at blueprint)

per ssh host: find the row whose alias it is; `power = none` → cause "no tailnet answer from <host>", fix `tailscale status` / `tailscale ping <host>`; else → the extant wake hint. each site calls it in its refused/timed-out branch: the 21 #653 lists (each verified at its cited line) plus `duct.poll.sh:1088`, which #653 missed.

the verdict word beside the cure does not change (F06). `unreachable` is a **forbidden synonym** of `asleep` (`term=asleep._.choice._.md`), so #653's proposed `🔴 unreachable` render would put a forbidden word in a contract. the dispute over whether `asleep` over-claims a cause is OPEN in `term=asleep._.choice.reason.md`; this wish adds evidence to it (its counter 2, "hibernation is the dominant cause by construction", fails for a grove that never sleeps). the evidence is appended there; the word stays until the dispute settles.

### docs

- glossary `grove.tunnel` ("the ssm port-forward that carries every reach") restates as: the tailnet carries every reach
- `define.camp-mythology` "a hibernation-ready ec2 work-box" restates as: a grove is a work-box on the tailnet; an ec2 grove also sleeps
- `git.grove.list`'s `MUTE` verdict ("bound, but no banner") is a tunnel symptom; over the tailnet a starved box reads as a banner timeout, and the text says so

## .mental model

- to a friend: "the supervisor ssh-es into every box over tailscale now. aws is just the on-switch for the ec2 ones."
- analogy: an office's intercom vs its power breaker. the intercom (tailnet) reaches every room the same way; only some rooms have a breaker (aws) you may need to flip first
- their words vs ours: they say "tailscale", "box", "ssh in"; we say "tailnet", "grove", "reach". `box` is a forbidden synonym of grove in contracts (`term=grove`); it stays out of skill output

## .evaluation

### how well it meets the goals

| wish outcome | met by |
|---|---|
| every crew + term skill reaches a grove over the tailnet, as camper | the alias names the tailnet host; every verb already rides the alias (case=1, case=2) |
| aws used only to power an ec2 grove up; no ssm | wake's reach half has no aws call; ssm leaves whole (F04, cell c21) |
| wake + every hint name the tailnet path, never ssm | wake failure text (case=2.fail, case=4); hint transformer (case=4) |

### pros

- one reach path; four ssm-only failure modes and their patches leave with it
- a non-aws grove needs no special case anywhere past the power leg
- the migration is silent: a relic row converges on its next wake (case=3)

### cons

- the supervisor's own machine must be on the tailnet. under ssm it only needed aws credentials
- relic rows now depend on magicdns (F02)
- a box whose tailscaled fails to rejoin after a resume now has no supervisor-side fallback; the cure is an admin breakglass skill outside this role

### edge cases and their pit of success

- relic row → read loopback as absent (case=3)
- ground seat → refused over the tailnet; saturation probes as camper (case=6); a wake of a `.ground` row fails loud on ssh's own refusal, with no special branch (c13)
- locked rack on an ec2 grove → power fails before reach, with the rack's words (case=5)
- plan mode → no ssh, no alias (c08, c09)

`ahbode/infrastructure` holds no tailscale code on `origin/main` (searched: `tailscale`, `tailscale up`), so these cannot be read from code. four were probed live before execution (`rhx grove.reach.probe`, output in `appendix/5.1.execution.probe.tailnet-reach.md`); the rest are measured in 5.3.

- **[answered, partly false]** magicdns answers the exid only while a box keeps its first tailnet name. a rebuilt hetzner box rejoined as `…-1`; the row's `.host` pins it (F09). and an ssm-era `~/.ssh/config` alias shadows the exid, so every probe pins `-o HostName` (F08)
- **[answered]** the grove's sshd is OpenSSH with key auth: `BatchMode` + `accept-new` probes pass and write `known_hosts`
- **[research]** a hibernated ec2 grove's tailscaled rejoins within `--timeout` after resume. if false: the needs-longer cause names a re-wake
- **[answered]** camper trusts the supervisor's key on every live node, ec2 and hetzner

### the scope calls — [answered]

- **[answered]** do `git.grove.set` / `git.grove.stop` change? no: neither ships in this package (glob of `supervisor/skills/git.grove.*`). the hints that name them are rewritten to the tailnet shape (`--at <user>@<host>` in place of `<user>@localhost:<port>`; the `--prune orphans` hint leaves with the tunnel). the skills belong to whoever ships them
- **[answered]** do `.ground` rows get removed? no: the forest is human-declared config outside this package. they stay registered and unreached by the supervisor (c13, c20); saturation skips them as a prober (F03). a forest cleanup is the operator's call, not this wish's
- **[answered]** does `--port` keep its name? yes: it is still "the port the grove answers ssh on"; only its default moves (36901 → 22). a stale `--port 36901` fails loud as a refused ssh

## .what is awkward

- `.host` once meant "where the tunnel listens" and now means "where the grove answers". F02 bridges it by a rule, not a rename; a reader who meets `host: localhost` in a row must know it is a relic
- `--port` changes sense: from the local tunnel port to the remote ssh port. a caller who passed `--port 36901` gets a refused ssh, loud, not silent; still a sharp edge for muscle memory
- the `.ground` rows become dead weight the supervisor carries but cannot use
- `git.grove.list`'s three verdicts (live · mute · down) were shaped for a tunnel. over a direct link, `down` (refused) and `mute` (no banner) still discriminate, but their cure text shifts per power
