# 1.vision.experience.dimensions — comment on an extant task

the experience space of one act: **a comment pushed onto an extant task, through the radio**.
each axis is a small closed set.

| # | dimension | values | why it varies the experience |
|---|---|---|---|
| D1 | **gate** at push time | `open` · `shut` | shut → the comment is held QUEUED, sends naught (the wish's core clamp) |
| D2 | **channel** | `gh.issues` · `os.fileops` | gh.issues posts an issue comment; os.fileops appends an entry beside the task file |
| D3 | **target** | `radio task` · `foreign thread` (an issue or pr the radio did not frame) · `absent` (repo reachable, number absent) · `unreachable` (the repo cannot be seen under this auth) | a comment amends a thread, so it need not be a radio task (#489, the incident, is such a thread); an absent number must not post and is refused; an unreachable repo is set aside, since another auth may reach it |
| D3′ | **thread state** (gh.issues, target extant) | `open` · `closed` · `locked` | a closed thread takes a comment; a locked one answers the post with a fault |
| D4 | **repeat** | `first` · `same body again` (record held or settled) · `same body after a delete upstream` | idempotency: the same body on the same task posts once (#533, #406); a settled record re-runs, and the thread read decides (F13) |
| D5 | **input** | `well formed` · `no --exid` · `with --title/--description/--status` · `empty body` · `--idem upsert` · `push --comment` · `gh body over 65536 chars` | each malformed form is a nurture-forbidden cell: exit 2, a fix named, naught recorded |
| D6 | **backlog** | `empty` · `held records ahead` | a comment waits its turn: oldest first, and a comment push that gets through carries the backlog ahead of it |
| D7a | **actor kind** | `clone` · `human at a terminal` · `system / cron (no human)` | who runs the push — see law 3: it never changes the outcome |
| D7b | **auth mode** | `as-robot:*` (via-keyrack(owner) · env(VAR) · shx(cmd) — the default is via-keyrack) · `as-human` | decides whose name the comment carries; as-human must never post as a robot token |
| D8 | **concurrency** | `sequential` · `concurrent, one worktree` · `concurrent, two worktrees` | the idempotency guard is a read, then a post: two sends that race can both read "absent" |

## .orthogonality — and the two domain laws

most axes are independent. two correlations are real, and recorded as **domain laws**, not
dismissed:

- **law 1 — os.fileops holds only radio tasks.** D2 = `os.fileops` implies D3 ≠ `foreign
  thread`: every file the channel names under `.radio/` is a task the radio wrote. so the cells
  `os.fileops × foreign thread` are **impossible** by nature. the axis is kept whole (not split
  into "github artifact" vs "local task") because the gh.issues half needs all three values and the
  correlation touches one value only
- **law 2 — os.fileops carries no identity.** D2 = `os.fileops` makes D7's `as-human` a no-op:
  the channel writes a file, with no login to choose. the flag is accepted and ignored, as push
  does today. D7 is walked for gh.issues; for os.fileops every actor collapses to one cell
- **law 3 — the token, not the actor, names the comment.** every `as-robot:*` mode derives one
  token (`getGithubTokenByAuthArg`), and github signs the comment with whatever identity owns that
  token; `as-human` derives none and gh signs with its session login. the actor kind (D7a) feeds
  no branch: a human, a clone, and a cron that pass the same `--auth` get the same signature. so
  D7a × D7b collapses to D7b for every outcome, and the robot sub-modes collapse to one cell
  ("the token's owner") — the harm case=8 names (a wrong signature) lives on D7b alone
- **D3′ exists only where D3 is an extant gh.issues thread**: it is a sub-axis of D3, walked for
  the cells where it changes the outcome (`locked`)
- **D3 `unreachable` exists only on gh.issues**: os.fileops has no auth to fail (law 2)

the other pairs hold:

- D4 × D1: a repeat can occur open or shut. a shut repeat **lands on its extant held record** —
  the key is (`comment`, repo, exid, sha of body) — so it is never a second record; on delivery it
  posts once
- D5 is checked before D1: a malformed call never reaches the gate, so each bad D5 value collapses
  every other axis (one cell each)
- D7a `system / cron` collapses by law 3: no prompt exists in the comment path, and the robot auth
  is the default. recorded as its own row so the collapse is a verdict, not an omission
- D8 × D1: a race needs two sends, so it matters only when the gate is open at send time

## .the product

well-formed calls: D1(2) × D2(2) × D3(4) × D4(2) × D6(2) × D7a(3) × D7b(2) × D8(3) = 1152 tuples,
plus D3′ on the extant gh.issues cells. most collapse: D6 changes one line of the outcome, D7a
collapses by law 3, D7b changes only the signature. the inventory walks the cells that change the
kind — 2 gate × 2 channel × 3 target × 2 repeat = 24 core cells, plus the `unreachable` cells — then
D3′, D5, D6, D7, D8 and the queue as their own rows. see
[`1.vision.experience.case=_.md`](./1.vision.experience.case=_.md).
