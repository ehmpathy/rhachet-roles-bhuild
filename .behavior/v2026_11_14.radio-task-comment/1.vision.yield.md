# 1.vision — a comment on an extant task, through the radio

## .the outcome world

### before

a clone that must amend an extant issue or pr has no radio path. `radio.task.push --exid N`
rewrites the body (often a human's text), and a robot app often may not edit at all
(`Resource not accessible by integration (updateIssue)`, #394). so directors built side paths:
a raw `gh.issue.comment` wrapper posted on #489 on 2026-10-22 while global radio was blocked.
`radio.uses` is the commander's gate on every github write; a write path beside it is no gate.

### after

```sh
cat note.md | rhx radio.task.comment --via gh.issues --into owner/repo --exid 489 --comment @stdin
```

the comment is recorded first, meets `radio.uses` like any push, and:

- **gate open** → one comment posted on #489. body, title, status untouched
- **gate shut** → held QUEUED, exit 2, naught sent. `radio.task.queue get` lists it beside held
  tasks. the next push that gets through delivers it, oldest first
- **same body again** → posted once (`kept`)

a day in the life: in open hours the commander blocks the radio. a director learns the cure on
#489 is wrong. it pushes the correction as a comment; it is held. after hours the block lifts;
the director's next ordinary push carries the correction out, in line. no side path exists to
tempt it, and the commander's gate held the whole time.

### the aha

a comment is one more **act** on the same rails — record, gate, queue, drain — not a new rail.
once it rides them, the radio is again the only github write path, and a block means a block.

## .the contract

| call | does | exit |
|---|---|---|
| `radio.task.comment --via V --into R --exid N --comment <text\|@stdin> [--auth A]` | a new skill in role=dispatcher: record a comment act; deliver it if the gate is open | 0 delivered · 2 held or refused |
| `radio.task.comment` without `--exid` | refused before record: names `--exid <n>` | 2 |
| `radio.task.comment` with `--title`, `--description`, or `--status` | refused: a flag this skill does not read; the fix names `radio.task.push` | 2 |
| `radio.task.push` | **unchanged contract** — same flags, help, and output. it shares one helper with the comment skill (the record → gate → drain path); its drain already carries every held record oldest first, so a push that gets through also carries a held comment out | as today |
| `--comment` with an empty body | refused: a comment needs a body | 2 |
| `--comment` with `--idem upsert` | refused: a comment is append-only. `--idem findsert` is accepted; it is the comment's only mode, always on (#533) | 2 |
| `radio.task.queue get` | lists held comments beside held tasks, label `comment on #N` | 0 |
| `radio.task.queue set --uuid U --auth A` | amends a held comment's auth | 0 |
| `radio.task.queue set --uuid U --description D` on a comment | refused: a comment's body is its identity; del + push again | 2 |
| `radio.task.queue del --uuid U --why W` | drops a held comment, body kept | 0 |

per channel:

| channel | a comment is | the same body twice |
|---|---|---|
| gh.issues | one issue comment, via github's issue-comment endpoint — serves issues and prs alike | the thread is read first; a comment with that exact body → `kept`, naught posted |
| os.fileops | one entry appended to a comment log beside the task file (never inside it) | the log is read first; an entry with that exact body → `kept` |

record:

- a third `kind`, `comment`, beside `create` and `update`; the body rides the extant `description` field, no new field (F8)
- key = (`comment`, repo, exid, sha of the body): a repeat lands on its extant record; a
  different body on the same task is its own record
- the gate, drain, halt scope, same-issue order, auth, and settle paths are kind-blind today
  (`setRadioTaskRecordUpstream.ts`); only the final send branches on the kind

## .mental model

- to a friend: *"the radio could only mail new letters or rewrite old ones. now it can staple a
  note onto a letter already sent — and the note waits in the same outbox, behind the same lock."*
- their words: "comment", "reply", "amend", "follow up". our words: a comment act, held, the
  gate. `radio.task.comment` is the verb #406 named, and `--comment` the flag word #567, #533,

## .evaluation

| goal (wish) | met by |
|---|---|
| the radio can comment on an extant task, gh.issues and os.fileops (#567) | `radio.task.comment --exid N --comment`, case=1, case=7 |
| a separate `radio.task.comment` skill; no change to `radio.task.push` beyond a shared helper (the wish, per the director's F4 verdict) | the comment skill owns its cli; push keeps its flags, help, and output; both call one record → gate → drain helper |
| obeys `radio.uses` like a new task: held QUEUED, oldest first (#567) | the extant record + gate + drain, case=2 |
| held comments listed beside held tasks (#567, `radio.task.held` → `radio.task.queue get`) | case=2 [t1] |
| a clamp: gate shut → held, sends naught (#567) | case=2 [t0], red without the gate check |
| never touches body or title (#533, #406) | the send posts a comment only, case=1, case=4 |
| `--comment` + `--title`/`--description` → exit 2; without `--exid` → exit 2 with the fix (#533) | case=5 |
| idempotent: same body not posted twice (#533, #406) | key + thread read, case=3; one worktree serialized by the drain lock; the cross-worktree race is accepted (F7) |
| `--auth` modes as push; as-human never posts as the robot (#406) | the extant auth path; `runGhCommand` clears `GH_TOKEN` for as-human |
| post on an issue or pr the radio did not frame (#567's #489, #255) | case=4 |
| semantic exit codes (#255) | 2 on bad input, held, or refused; a gh malfunction holds the record (extant fault scope) |

pros: zero new rails — the gate, queue, drain, and halt scope are reused as they stand; one
send branch; push's contract untouched; the side-path temptation is gone.

cons: a thread read before each post costs one gh call; a very long thread is paged. a comment's
body cannot be amended once held (by design: it is the key).

pit of success: every malformed form fails before it is recorded, with its fix; a repeat is
`kept`, never a duplicate; a shut gate names the lift and sends naught.

## .groundwork

### external research

- github rest: `GET /repos/{owner}/{repo}/issues/{n}/comments` and `POST` to the same path create
  and list comments on issues **and** prs (a pr is an issue for this endpoint). verified by a read
  against pr #625 (above). an absent issue returns 404 — the extant `isGithubIssueAbsent` reads
  gh's text for it. **not verified**: how a locked thread answers a post; whatever gh returns,
  the extant fault scope settles it (refusal → REFUSED, else held), so the vision does not lean
  on the code. the execution stone checks it against the stub, not a live lock
- the gh cli is already the transport (`runGhCommand.ts`, `execFile('gh', args)`), so the send is
  gh calls with a body file — no new dependency
- **one read covers existence and idempotency**: `gh issue view <n> --repo <r> --json
  number,comments` accepts a pr number too (checked: #625 → `{"number":625,"state":"MERGED"}`)
  and returns each comment's `body` and `url` (checked: #625's `…/pull/625#issuecomment-6543936244`)
- **the read must be `gh issue view`, not a bare REST call**: an absent number answers with gh's
  graphql text `… to an issue or pull request with the number of 99999` (checked) — the exact
  phrase `isGithubIssueAbsent.ts` reads, and `isGithubRepoUnreachable.ts` reads its repo twin. a
  REST `gh api …/issues/N/comments` answers both with one `Not Found (HTTP 404)`, which would blur
  an absent issue (refuse) with a repo the auth cannot see (set aside, F8 of #605)
- a gh timeout is a transient fault that halts the drain: `RadioGhSendTimeoutError` text holds
  `etimedout` → `asRadioUpstreamReason` → `upstream:transient` → `isRadioUpstreamReasonHalt` (read)

## .what is awkward

- `--exid` names a radio task's id, yet for a comment it may name any issue or pr number. the
  flag reads a touch narrow; the help line says so ("a task, issue, or pr number")
- a comment rides the `radio.task.*` noun though it targets threads beyond tasks. a separate noun
  would split the gate path the wish exists to unify, so the slight stretch is the cheaper cost
- the thread read for idempotency costs a call per post, and on a busy pr it pages. the clone
  retry case (#406) makes it worth it
- same-issue order (F6): a comment held behind an update the robot may not apply (#394's
  `updateIssue` refusal) waits with it, though the robot could post the comment. the cure for the
  update (`queue set --auth as-human`, or `del`) frees both; but the comment's wait is a surprise
