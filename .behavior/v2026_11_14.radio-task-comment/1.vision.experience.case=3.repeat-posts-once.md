# case=3 — a repeat posts once

feel · care: sharp · critipath (inventory row 2). the shut-gate repeat, row 13, is case=2 [t4].

## .narrative

a clone pushes a comment onto #640. the gh call times out at the client, though github did
post it. the clone, unsure, runs the exact same push again.

```
🎙️ radio.task.comment
   ├─ act: comment on #640
   └─ outcome: kept — this comment is already on #640
      └─ https://github.com/sandpine/svc-lessons/issues/640#issuecomment-…
```

one comment on #640, not two. the same body on the same task is one act: its record key is
derived from (repo, exid, body), so a repeat lands on its extant record, and the send checks the
thread for that body before it posts.

a **different** body on the same task is a new comment, posted — a thread may hold many.

## .bdd sketch

```
given('[case3] an open gate; github posts body B but the gh call times out at the client')
  when('[t0] body B is pushed onto #640')
    then('the record is held (the timeout is a transient fault), exit 2')
    then('github holds one comment with body B')
  when('[t1] body B is pushed onto #640 again')
    then('the push lands on the same record (same key)')
    then('the thread read finds body B; no new comment is posted')
    then('stdout says kept, with the extant comment url')
    then('the record settles DELIVERED; exit 0')
  when('[t2] body B2 (one char differs) is pushed onto #640')
    then('a new record, a second comment is posted')
```
