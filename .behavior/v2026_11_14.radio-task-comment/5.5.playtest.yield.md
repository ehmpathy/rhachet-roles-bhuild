## happy paths

### H1. help names both channels and the two rules

```sh
rt "$S/radio.task.comment.sh" --help
rt "$S/radio.task.comment.sh" -h
```

→ exit 0, both print the same tree: three usage lines (gh.issues, gh.issues via @stdin,
os.fileops), `held, never lost`, `posted once` (`the task or thread is read first…`), and seven
options, among them `--idem  findsert, the only mode; upsert is refused`.
proof: acceptance `skill.radio.task.comment` [case4] [t0], [t1].

### H2. a task to comment on (gate open)

```sh
rt "$S/radio.uses.sh" --org sandpine allow
rt "$S/radio.task.push.sh" --via os.fileops --into sandpine/svc-lessons \
  --title 'restock the wax rack' --description 'two boxes of cold-water wax'
```

→ exit 0, `🎙️ created: restock the wax rack` with an `exid:` line (8 hex chars, e.g. `1972ac9f`).
capture it:

```sh
export EXID="$(ls "$PT_HOME/git/.radio/sandpine/svc-lessons/" | sed -n 's/^task\.\([0-9a-f]*\)\._\.md$/\1/p')"
echo "$EXID"
```

→ prints the same exid the push printed.

### H3. the clamp: a shut gate holds the comment, and sends naught

```sh
rt "$S/radio.uses.sh" --org sandpine block
printf 'the cold-water wax is back in stock:\n\n- two boxes, rack b\n- receipt in the office drawer\n' \
  | rt "$S/radio.task.comment.sh" --via os.fileops --into sandpine/svc-lessons --exid "$EXID" --comment @stdin
echo "exit=$?"
ls "$PT_HOME/git/.radio/sandpine/svc-lessons/"
```

→ `exit=2`, and the output reads:

```
🦫 held for the radio
   ├─ comment = #<EXID>
   ├─ into    = sandpine/svc-lessons
   ├─ status  = QUEUED (radio.uses:blocked — org)
   ├─ held at = .behavior/.radio/ (no route bound to this branch)
   ├─ backlog = 1 awaits the radio
   └─ lift it (human): rhx radio.uses --org sandpine allow
      └─ then the next push or comment delivers the backlog first
```

the `ls` shows no `task.<EXID>.comments.jsonl`: naught was sent.
proof: acceptance [case2] [t3] (os.fileops: held, the log holds no entry), [case1] [t0] (gh: no gh call made).

### H4. a held task waits beside it; the queue lists both, and the stop line names both

```sh
rt "$S/radio.task.push.sh" --via os.fileops --into sandpine/svc-lessons \
  --title 'rinse the wetsuits' --description 'after the dawn lesson'
rt "$S/radio.task.queue.sh" get
rt "$S/radio.task.queue.sh" get --when hook.onStop
```

→ the push exits 2, held, `backlog = 2 await the radio`.
→ `get` shows two rows, oldest first: `<uuid> comment on #<EXID> → sandpine/svc-lessons`, then
`<uuid> rinse the wetsuits → sandpine/svc-lessons`, each with `state: held at gate
(radio.uses:blocked — org)` and its lift; the last line reads `then the next push or comment, or
\`rhx radio.task.queue drain\`, delivers the backlog`.
→ the stop line reads `🦫 2 tasks or comments held for the radio · 2 at a gate · lift: rhx
radio.uses --org sandpine allow · next push or comment delivers them`.
proof: acceptance [case1b] [t0] (both rows), [case1b] [t0b] (the stop line); unit `asRadioHeldOutput` [case9].

### H5. the gate opens; the next push delivers the backlog, oldest first, body intact

→ exit 0, and the output reads, in this order:

🦫 back in the river! the backlog is delivered

   │  ├─ comment on #<EXID>
   │  └─ #<exid> rinse the wetsuits
   ├─ pushed
   │  └─ #<exid> wax the rental boards (created)

the log holds exactly one line: the body with its blank line and both list items.
proof: acceptance [case1b] [t1] (a held task, then a held comment, then the new push), [case1]
[t12] (multi-line via @stdin).

## edgey paths

### E1. push refuses `--comment` and names the comment skill

```sh
rt "$S/radio.task.push.sh" --via os.fileops --into sandpine/svc-lessons --exid "$EXID" --comment hi
```

→ exit 2, `✋ ConstraintError: --comment is not read by radio.task.push, … use rhx
radio.task.comment --via os.fileops --into sandpine/svc-lessons --exid <EXID> --comment @stdin`.
proof: acceptance [case3] [t6].

### E2. a gh exid that is not a number

```sh
rt "$S/radio.task.comment.sh" --via gh.issues --into sandpine/svc-lessons --exid '#489' --comment hi
```

→ exit 2, `exid "#489" is not a github issue number; a gh.issues exid is the issue's number, e.g. 599`.
no record is written. proof: acceptance [case3] [t11].

### E3. `--idem upsert`

```sh
rt "$S/radio.task.comment.sh" --via os.fileops --into sandpine/svc-lessons --exid "$EXID" --comment hi --idem upsert
```

→ exit 2, `--idem upsert does not apply to a comment, which is append-only; a comment is always
findsert (the exact body already recorded is kept). omit --idem`. proof: acceptance [case3] [t4].

### E4. a task that does not exist

```sh
rt "$S/radio.task.comment.sh" --via os.fileops --into sandpine/svc-lessons --exid nope404 --comment 'for a task long gone'
```

→ exit 2, `🦫 refused upstream`, `status = REFUSED (#nope404 not found in sandpine/svc-lessons;
check --exid and --into, then comment again) — closed, never retried`, `backlog = 0`.
proof: acceptance [case2] [t2] (os.fileops absent task), [case1] [t5], [t9] (gh absent thread).

### E5. a held comment, amended and dropped

```sh
rt "$S/radio.uses.sh" --org sandpine block
rt "$S/radio.task.comment.sh" --via os.fileops --into sandpine/svc-lessons --exid "$EXID" --comment 'the rack key is lost'
rt "$S/radio.task.queue.sh" get                                    # one row: the held comment
export UUID="$(rt "$S/radio.task.queue.sh" get | grep -oE '[0-9a-f]{16}' | head -1)"
rt "$S/radio.task.queue.sh" set --uuid "$UUID" --description 'x'   # refused: a body is the key
rt "$S/radio.task.queue.sh" del --uuid "$UUID" --why 'found the key'
rt "$S/radio.task.queue.sh" get
```

→ `set --description` exits 2 and names the drop; `del` reports `🦫 dropped from the radio, never
sent`, `comment = #<EXID> …`, the why, and where the body is kept; the last `get` lists naught.
proof: acceptance [case2] [t6]; integration `radioTaskQueue` [case12b] [t1c], [t3]; unit `asRadioDropOutput` [case5].

### E6. a blank body

```sh
rt "$S/radio.task.comment.sh" --via os.fileops --into sandpine/svc-lessons --exid "$EXID" --comment ' '
```

→ exit 2, `--comment is empty; a comment needs a body. pass it, or pipe it via --comment @stdin`.
proof: acceptance [case3] [t3].

### E7. a body full of shell and markup characters posts literally

```sh
printf 'the `tide` table says $HOME is "dry" — 🌊 & <done>\n' \
  | rt "$S/radio.task.comment.sh" --via os.fileops --into sandpine/svc-lessons --exid "$EXID" --comment @stdin
tail -1 "$PT_HOME/git/.radio/sandpine/svc-lessons/task.$EXID.comments.jsonl"
```

→ exit 0, `posted`; the last log line holds `` the `tide` table says $HOME is \"dry\" — 🌊 & <done> ``,
naught expanded (the json escape on the quotes is the log's own).
proof: acceptance [case1] [t14].

  title, body, or status changes; any refusal lacks its fix; any output reads `task` for a comment
