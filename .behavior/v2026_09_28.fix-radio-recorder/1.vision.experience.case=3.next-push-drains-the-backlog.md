# case=3 — the next push that gets through drains the backlog

cells: **C4**, **C5**, **C20**, **C22** · feel: happy `[t0–t1]`, sharp `[t2–t3]` · care: critipath · **the aha**

the drain is the happy path; its two sharp edges — a shut org (C20) and a locked keyrack (C22) —
ride inside it, and each shows its fail-safe: the task stays held, the output names which one and
the command that frees it.

## .narrative

two tasks sit held in the route from case=2. at noon the human runs `radio.uses --global allow`
for an unrelated reason — they want to file an issue of their own. they do not recall the two
held tasks.

later the clone finds a third defect and pushes it. the gate is open now. before it sends the new
task, the push delivers the two held ones, oldest first. then it sends the new one. three issues
land. the clone did not remember, the human did not remember, and no flag was typed. the fact the
push got through is the proof the radio is open.

one week later, a quirk: the human allows `ehmpathy` but keeps `ahbode` blocked. the backlog holds
one task for each. the clone pushes into `ehmpathy`. the drain delivers the `ehmpathy` task and
leaves the `ahbode` one held — and says so, with the command that would open `ahbode`. the open
gate of one org never carries a task past the shut gate of another.

the same care holds for credentials. a task held under the robot's keyrack auth is delivered
with the robot's auth, even when the push that drains it runs as the human. if the robot's
keyrack is locked, that one task stays held and the output names the unlock.

## .timeline (sketch)

```
given('[case3] two records QUEUED in $route/.radio/; radio.uses now allowed')

  when('[t0] the clone pushes a third task')
    rhx radio.task.push --via gh.issues --into ehmpathy/rhachet --title "..." --description @stdin

    then('the third task is transcribed first, as QUEUED')
    then('the gate is checked for each record\'s target, and reads open for all three')
    then('the backlog is delivered oldest first, then the new task')
    then('each delivered record is marked DELIVERED with its upstream exid')
    then('stdout lists each delivery')
        🦫 back in the river! the backlog is delivered
           ├─ drained
           │  ├─ #412 fix flaky keyrack test          (held since 09:14)
           │  └─ #413 guard absent sponsor on commit  (held since 10:02)

           └─ backlog = 0
    then('exit code is 0')

given('[case3] two records QUEUED, one of them "fix flaky keyrack test"; radio.uses now allowed')

  when('[t1] the clone, which forgot it pushed that task, pushes it again verbatim (C5)')
    then('the transcribe findserts onto the extant record — no second record')
    then('the drain delivers both held records, the re-typed one once')
    then('stdout lists two deliveries, not three')

given('[case3] backlog holds one task for ehmpathy/rhachet and one for ahbode/svc-gateway; org ahbode is blocked')

  when('[t2] the clone pushes a new task into ehmpathy/rhachet-roles-bhrain (allowed)')
    then('the gate is checked per record, by each record\'s own target')
    then('the ehmpathy task is delivered')
    then('the ahbode task stays QUEUED — its gate is still shut')
    then('stdout lists 1 drained, 1 still held for ahbode, and who lifts that gate')

given('[case3] one record held with --auth as-robot:via-keyrack(ehmpath); the ehmpath keyrack is locked; radio allowed')

  when('[t3] the clone pushes a new task with --auth as-human (C22)')
    then('the new task is delivered with the as-human credentials')
    then('the held record is delivered with its own auth, not the push\'s — which fails to unlock')
    then('the held record stays QUEUED with reason upstream:auth')
    then('stdout names the fix: rhx keyrack unlock --owner ehmpath --env prep')
```

## .why this is the aha

the wisher's phrase: *"if you can dispatch at all, the radio is open."* the drain needs no verb of
its own, because every push is already a probe of the gate. the backlog rides out on the first
push that finds the gate open.
