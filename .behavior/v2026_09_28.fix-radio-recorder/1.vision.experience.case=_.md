# 1.vision.experience.case=_ — the inventory

the walk of `gate × other-held × this-task` (see `1.vision.experience.dimensions.md`), plus the
actor, route, and push-kind rows. every cell carries a verdict; each real experience carries
feel × care.

care = freq × cost. cost here is dominated by **a lost task** (the wisher re-types it from memory,
or never does) and **a duplicate upstream issue** (a triager closes it by hand; trust in the radio
drops). both are high-cost, so most cells that can lose or double a task are critipaths.

## .the push-kind row (D6)

`radio.task.push` carries two kinds: a **create** (`--title --description`) and an **update**
(`--exid --status`, e.g. a claim). F5 (wisher): **both** are recorded and held. an update record is
keyed `(target repo, exid, status)`; it drains in the same oldest-first line as creates, so a held
claim then a held deliver replay in order.

an update differs from a create in one place: its replay can meet a task another actor moved
meanwhile. `setPartRadioTask` already refuses those moves (`applyStatusTransition`: a claim onto a
task claimed by another branch, any move out of DELIVERED). the recorder's job is to surface that
refusal and close the record — never swallow it, never retry it.

| # | cell | verdict | feel | care | note |
|---|------|---------|------|------|------|
| U1 | update × open gate | **itemized** | happy | alterpath | recorded, drains the backlog first (as C4), then applies via today's `setPartRadioTask`; record marked DELIVERED. a human who only files claims still drains held tasks |
| U2 | update × any block | **demoed** → case=7 `[t0]` | sharp | critipath | held QUEUED with the block as reason, exit 2, names who lifts the gate — exactly as a create (C7). today a blocked claim is refused and gone until the actor recalls and re-runs it |
| U3 | a held update replays after another actor moved the task | **demoed** → case=7 `[t2]` | sharp | critipath | `setPartRadioTask` refuses (`task already claimed by different branch` · `cannot transition from DELIVERED`). the record closes as **refused**, with that reason, printed loud; never retried, the rest of the drain continues. a swallowed refusal would let two actors each believe they hold the task |
| U4 | a held update is re-pushed verbatim | **itemized** — subsumed by C11 | sharp | alterpath | local findsert on `(repo, exid, status)`: no second record, count unchanged |
| U5 | an update whose target status upstream already reflects | **itemized** | happy | alterpath | `setPartRadioTask` returns `unchanged` (a same-branch re-claim is a no-op); record marked DELIVERED, "already CLAIMED" |

## .the list row — a human asks what is held

surfaced at verification. `rhx radio.task.held` is the third moment the recorder speaks: a human
asks on demand. like the stop, it only reads local records and `radio.uses` and never sends. unlike
the stop, it prints the whole backlog, one row per task, and it prints even when naught is held (the
human asked). its cells vary on the same D3 × D2 as the stop row.

care: every list cell is an **alterpath**. the fallback is the stop reminder (S2), which already
names the held count and the lift at the moment the human is present; a list that misprinted would
cost one re-read, never a lost task.

## .the invariants — what the behavior must hold

X1 and X2 are **forbidden by nurture**: an actor's push may attempt them, and the behavior must
refuse. X3 is not an attempt at all — it is a **sequence** the behavior holds whatever the cause
of a failed write.

| # | kind | the rule | why | where proven |
|---|------|----------|-----|--------------|
| X1 | forbidden (nurture) | a drain never sends a record whose target's gate is shut | the block is a human's explicit "not now" | case=3 `[t2]` (C20) |
| X2 | forbidden (nurture) | a delivery never files a second upstream issue for one record | a duplicate costs a triager and erodes trust | case=4 |
| X3 | sequence invariant | transcribe precedes the gate check and the send; a failed transcribe halts with a loud malfunction (`💥`, exit 1), never a silent send | the local write is the transaction | not demoed — the trigger is the environment (read-only fs, full disk), not an actor's choice; its fail-safe is the extant malfunction path |
| X4 | read invariant (F13) | a malformed record file on disk fails loud and names its path — at a push and at the stop hook alike; never skipped, never read as "naught held" | a skipped record is a lost task the human is never told of | `skill.radio.task.recorder.acceptance.test.ts` `[case2]` (the stop hook) — surfaced at verification |
| X5 | render invariant | a record marked DELIVERED always carries its exid; a delivered record with none fails loud (`delivered radio task record lacks its exid`) rather than print a blank `#` | a blank exid reads as delivered-nowhere | `asRadioPushOutput.test.ts` `[case3.1]`. not an actor experience: no push can produce it — the write sets both together — so the check guards a defect, not a path |
| X6 | order invariant | the backlog drains in push order, by `heldSeq`; a tie in `heldAt` (one-second precision) never falls back to the record key | the wish says oldest first; a key order would replay two same-second pushes backwards | `setRadioTaskRecordFromPush.integration.test.ts` `[case1]` — surfaced at verification; implied by C4 / C16, named here |

## .the hidden dimension the walk surfaced — the gate is per target

`radio.uses` decides per **target repo** (`computeRadioUsagePermissionDecision.ts`: global, then
org, then `@all`, then local). so one backlog can hold tasks whose gates differ — `ehmpathy`
allowed, `ahbode` blocked. D2 is a property of each record, not of the push.

| # | cell | verdict | feel | care | note |
|---|------|---------|------|------|------|
| C20 | open push to `ehmpathy/*`; backlog holds a task for a blocked `ahbode/*` | **demoed** → case=3 `[t2]` | sharp | critipath | the drain delivers only records whose own gate is open. the `ahbode` task stays QUEUED. without a per-record gate check, X1 breaks |

⇒ the wisher's line *"if you can dispatch at all, the radio is open"* holds **per target**, not
per worktree. see the yield's awkward section.

## .the ranks — boundary-density

the densest cells cross the most boundaries (gate change, backlog, idempotency) in one encounter:

1. **C16** (drain fails midway) — gate flips mid-run, backlog partially drains, order + status must hold
2. **C4 / C20 / C22** (drain on an open gate) — the aha, plus per-target gate and per-record auth
3. **C3 / C19 / X2** (re-push or race never doubles) — idempotency under a lagged local record
4. **C7 / C10** (blocked, recorded) — the core fix
5. **C1** (happy path) — today's push, plus a record
