# case=5 — upstream fails, alone or mid-drain

cells: **C13**, **C16**, **C17** · feel: sharp · care: critipath · densest cell

## .narrative

the radio is allowed, but the robot token has expired. a clone pushes a task. the transcript is
written, the gate is open, and the upstream call returns 401. the task stays QUEUED with reason
`upstream:401`, and the output names the fix — unlock the keyrack. this is the case #319 reports
from `rhachet-roles-mhedic`, where only a manual retry saved the task.

later, three tasks wait. the token is fixed. the next push drains: the first delivers, the second
hits a rate limit. the drain stops there. the first stays DELIVERED; the second, third, and the
new task stay QUEUED, in order. the clone, unsure the third went out, pushes it again — the record
is found, not doubled, and the drain stops at the second once more. the next push after the limit
clears resumes from the second.

## .timeline (sketch)

```
given('[case5] radio.uses allowed; the gh token returns 401; backlog empty')

  when('[t0] the clone pushes a task')
    then('the task is transcribed as QUEUED first')
    then('the upstream call returns 401')
    then('the record stays QUEUED with reason upstream:401')
    then('stdout reads held, names the reason, and names the fix')
        🦫 held for the radio
           ├─ status = QUEUED (upstream:401 — the token was refused)
           ├─ backlog = 1 await the radio
           └─ fix: rhx keyrack unlock --owner ehmpath --env prep
              then the next push delivers the backlog first
    then('exit code is 2')

given('[case5] three records QUEUED; the token works; the 2nd delivery hits a rate limit')

  when('[t1] the clone pushes a fourth task')
    then('record 1 is delivered and marked DELIVERED')
    then('record 2 fails with upstream:rate-limit; the drain stops')
    then('records 2, 3, and the new task stay QUEUED, order kept')
    then('stdout lists 1 delivered, 3 held, and the reason')
    then('exit code is 2')

  when('[t2] the clone re-pushes record 3 verbatim while the rate limit holds (C17)')
    then('the transcribe findserts onto record 3 — no second record')
    then('the drain stops at record 2 again; order and count unchanged')

  when('[t3] a later push finds upstream healthy')
    then('the drain resumes at record 2 — record 1 is not re-sent')
```

## .why the drain stops at the first failure

to skip past a failed record and deliver the later ones would reorder the tasks and hide a fault
that likely hits them all (a token, a network). stop at the first failure, keep order, report it.
