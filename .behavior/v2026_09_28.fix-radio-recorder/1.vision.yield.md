# 1.vision — the radio.recorder

## .the outcome world

### before

a clone finds a defect in another repo mid-route. it runs `radio.task.push`. the human blocked the
radio at dawn. the push prints `✋ BadRequestError: radio.task.push blocked: global blocked`, exits
2, and the task is gone — the gate runs before `--description @stdin` is even read
(`src/contract/cli/radioTaskPush.ts`, gate at L188-203, stdin at L206). the clone notes it in prose
or a dream. nobody re-types it. #379 measured six such tasks stalled up to five days, shipped only
because a human asked *"what have we dispatched?"*.

### after

the same push writes the task into `$route/.radio/` first. then it meets the block, sends naught,
and says **held** — with the reason, the backlog count, and who can lift the gate. the clone drives
on. hours later the human opens the radio for their own reasons and forgets the backlog. the clone
pushes its next task. that push finds the gate open, delivers the held tasks oldest first, then the
new one. three issues land. nobody remembered; no task was lost.

### the aha

**every push is already a probe of the gate.** so the drain needs no verb, no flag, no memory: the
first push that gets through carries the backlog out with it.

### a day in the life

| time | event | route's `.radio/` |
|------|-------|-------------------|
| 09:14 | clone pushes task A; radio blocked | A = QUEUED (`radio.uses:blocked`) |
| 10:02 | clone pushes task B; still blocked | A, B = QUEUED · "2 await the radio" |
| 12:00 | human runs `radio.uses --global allow` | unchanged |
| 14:30 | clone pushes task C | A → #412, B → #413, C → #414, all DELIVERED |
| 14:31 | clone re-pushes A by accident | "already delivered as #412" — no second issue |

the six invariants the behavior must hold:

- **X1** — the gate is checked before every upstream send, drain included, per record's target
- **X2** — delivery findserts upstream by `(repo, title)`; never a second issue
- **X3** — transcribe precedes gate and send; a failed transcribe is a loud malfunction (exit 1)
- **X4** — a malformed record file fails loud and names its path; never skipped as "naught held"
- **X5** — a record marked DELIVERED always carries its exid; one without fails loud
- **X6** — the backlog drains in push order, by `heldSeq`, never by record key

## .the contract, testdriven

no new verb. `radio.task.push` keeps its args. the dispatcher gains three behaviors:

1. **transcribe first** — before the gate, write one record to `$route/.radio/` for **every**
   push — open or blocked, create or update (F5). an open push is recorded too, then marked
   DELIVERED (case=1), so the route holds a full ledger of what it dispatched. a create is keyed `(target repo, title)` — the identity
   `RadioTask.unique` already declares; an update is keyed `(target repo, exid, status)`. the
   record holds all a later drain needs to deliver it **on its own terms**: kind, target repo,
   channel (`--via`), auth mode (`--auth`), title + description or exid + status, record status,
   reason, held-at
2. **drain on pass** — when the gate is open for a record's target, deliver QUEUED records oldest
   first, then this one; mark each DELIVERED with its exid. an update whose replay upstream
   refuses (the task moved meanwhile) closes as **refused**, printed loud, never retried (case=7)
3. **remind at stop** — the dispatcher's onStop hook (the empty `onStop: []` slot in
   `getDispatcherRole.ts:30`) reads the route's records and `radio.uses`, local files only. with
   tasks held it prints one line for the human — the held count, the lift command if the gate is
   shut, "next push delivers them". with none held it prints naught. it exits 0: never blocks the
   stop, never sends upstream (case=8). the clones remind the humans

⚠️ transcribe-first reorders the cli: today `--description @stdin` is read **after** the gate
(`radioTaskPush.ts` gate L188, stdin L206), so a blocked push never even reads the body. the
record needs the body, so arg parse and the stdin read move **ahead** of the gate. auth
(`getOneRadioContextFromCliArgs`) stays after it — a held push needs no token.

⚠️ the drain builds a context **per record**, from that record's own channel + auth + target —
never from the push that triggered it. `getOneRadioContextFromCliArgs({ via, repo, auth })` is
bound to one target; a held task for another repo, or pushed `--auth as-human` while the drain
push runs `as-robot`, must not borrow the wrong credentials. a record whose auth cannot be derived
now (keyrack locked) stays held with reason `upstream:auth`, like case=5.

output on a block (sketch):

```
🦫 held for the radio
   ├─ task    = fix flaky keyrack test
   ├─ into    = ehmpathy/rhachet
   ├─ status  = QUEUED (radio.uses:blocked — global)
   ├─ backlog = 2 await the radio
   └─ lift it (human): rhx radio.uses --global allow
      then the next push delivers the backlog first
```

output on a drain (sketch):

```
🦫 back in the river! the backlog is delivered
   ├─ drained
   │  ├─ #412 fix flaky keyrack test          (held since 09:14)
   │  └─ #413 guard absent sponsor on commit  (held since 10:02)
   ├─ pushed
   │  └─ #414 retry race in route.bounce
   └─ backlog = 0
```

## .mental model

- **to a friend:** *"radio push is an outbox now. if the radio's shut, it waits in the outbox. the
  next time you send anything, the outbox goes too."*
- **the metaphor (#319):** a tape recorder on the transmitter. it records every transmission
  before it airs; if the airwave is closed, the tape keeps it and plays it out the moment the
  airwave reopens.
- **the beaver's own:** a winter cache. the beaver stores what it cannot use now under the ice,
  and lives off it when the pond seals. no store is lost to the season.
- **their words vs ours:** a human says *outbox*, *pending*, *didn't send*. we say *record*,
  *QUEUED*, *held*, *drain*. the output leads with **held** — the one word that rules out *lost*.

## .evaluation

### against the wish

| wish outcome | met by |
|--------------|--------|
| every attempt transcribed first; the local write is the transaction | transcribe-first + X3 — for every attempt, create and update alike (F5) |
| a blocked push leaves the record QUEUED with the block as reason | case=2, case=5 |
| the queue drains itself on the next push that gets through | case=3; per target (C20) |
| delivery is idempotent; no duplicate upstream | case=4, X2 — reuses extant findsert |
| supersedes #308 (catch.dream fallback) | a held record is replayed by construction; a dream is not |

### pros

- zero new verbs, zero new flags — the fix lives inside the command the clone already runs
- reuses the extant identity (`RadioTask.unique = ['repo','title']`) and the extant findsert — the
  idempotency is not new code, only a new caller
- the route becomes a ledger of what it dispatched — the answer #379 asks for, for free
- honors the human's block exactly: no send, ever, while blocked

### cons

each con is a tradeoff felt in use — see `.what is awkward`.

### edge cases held in the pit of success

each sharp demo above is an edge and its guard. the guards, one line each: a repeat push findserts
locally (C11) · a lost mark is repaired by upstream findsert (case=4) · each record meets its own
gate (C20, X1) · a mid-drain fault stops the drain in order (case=5) · an unbound push holds in
`.behavior/.radio/` (R2) · a race costs one redundant findsert (C19) · a stale update replay closes
as refused (case=7).

## .what is awkward

- **"if you can dispatch at all, the radio is open" is only true per target.** a clone with
  ehmpathy open and ahbode shut will drain half a backlog. the output must say which half waits,
  and why, or the held tail looks lost.
- **the drain rides someone else's push.** a clone that pushes one small task may see four
  deliveries it did not ask for. it is the design's whole point, and it still surprises. the stop
  reminder softens it: the human hears of the backlog first, so its drain is expected
- **held is a success that exits 2.** the recorder did its job; the delivery did not happen. one
  code cannot say both. F3 picks the conservative read.
- **the backlog waits on a push.** a held task stays until someone pushes. the stop reminder makes
  sure the human knows; it cannot push for them
- **"no task lost" holds only while the worktree lives.** worktrees here are disposable
  (`_worktrees/…`). a held task survives a block, a crash, a session end — but not an `rm` of its
  worktree. the wisher accepted that loss (F8); the stop reminder is the guard before removal.
- **two stores named `.radio`.** inbound cache (per target, global) and outbound record (per
  route). the name rhymes on purpose; the places differ on purpose. a reader will confuse them once.
