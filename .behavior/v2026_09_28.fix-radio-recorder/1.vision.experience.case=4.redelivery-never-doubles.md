# case=4 — a re-delivery never files a second issue

cells: **C3** (critipath), invariant **X2** (critipath), **C19** (alterpath) · feel: happy `[t0–t1]`, sharp `[t2]`

## .narrative

a drain delivers a held task. the issue lands upstream as #412. then the process dies — a killed
session, a laptop lid — before the local record is marked DELIVERED. the record still reads
QUEUED.

the next push drains again and reaches that record. it does not blindly create. delivery is a
**findsert** against upstream by the task's identity — `(repo, title)`, the same identity
`setFullRadioTask` already uses (`src/domain.operations/radio/task/push/setFullRadioTask.ts`,
`idem ?? IdempotencyMode.FINDSERT`). upstream answers "#412 exists". the record is marked
DELIVERED as #412. one issue, not two.

## .timeline (sketch)

```
given('[case4] a record reads QUEUED; upstream already holds its issue #412 (the mark was lost)')

  when('[t0] the next push drains')
    then('delivery findserts by (repo, title)')
    then('upstream reports the task found, not created')
    then('the record is marked DELIVERED with exid 412')
    then('stdout reads: #412 already upstream — marked delivered')
    then('no second issue is filed')

given('[case4] a record reads DELIVERED as #412')

  when('[t1] the clone re-pushes the same task verbatim (C3)')
    then('the local record answers first; no upstream call is made')
    then('stdout reads: already delivered as #412')
    then('exit code is 0')

given('[case4] one record QUEUED; radio allowed; a human and a clone each push at the same moment')

  when('[t2] both pushes drain the same record (C19)')
    then('each delivery findserts by (repo, title)')
    then('one creates #415; the other finds #415')
    then('the record ends DELIVERED as #415; one issue upstream')
```

a third scene, rarer: the human and the clone push in the same second, and both drains reach the
same held record. each asks upstream first. one creates the issue; the other finds it. the worst
case is one redundant lookup — never a second issue.

## .the limit this rests on

the gh findsert scans the 100 most recent issues (`daoRadioTaskViaGhIssues.ts`, `--limit 100`).
a lost mark is repaired on the very next drain, so the issue is seconds old — well inside the
window. the window only bites a record that sat QUEUED *after* it was delivered, across 100 newer
issues. named in the yield as an assumption, not a gap to fix here.
