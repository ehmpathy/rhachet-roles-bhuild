# case=2 · the supervisor gates a sprout on capacity

covers: G1 (happy), G2 (sharp), G6 (sharp), G10 (sharp) · care: critipath

## .narrative

the supervisor holds a wish ready to dispatch. before it sprouts a behavior crew onto the 0901
grove, it asks: is there a slot?

on a calm tick the answer is `✅ 2 behavior slots left (binds: ram)`, and it sprouts.

an hour later, with four crews on the grove, it asks again. the answer is no — ram binds, the
grove holds 0 free behavior slots. the render does not stop at no: it names the two crews whose
routes are complete and can be felled, and it says that the wish can be **seeded** now (a seed
costs the grove naught) and sprouted once a fell returns a slot. the supervisor seeds the wish
and fells one done crew; the next tick sprouts.

that same afternoon, two supervisors — the surdirector's and a director's — each hold a wish
for 0901, and the grove has one slot left. both ask in the same tick. a gate that only reads
would grant the slot twice, and the second sprout would push ram past its cliff. so a grant is
not a bare read: the first ask's grant **holds** the slot as a ledger row for a sprout in
flight. the second ask, a moment later, sees `0 slots — 1 held by a sprout in flight` and
seeds its wish instead.

### case3, as the second supervisor lives it

two supervisors each want a crew on local, and local has one slot left. the first asks and
gets it; its sprout starts to boot. a moment later the second asks, and expects the same `1
slot left` it read a minute ago.

it sees `0 slots — 1 held by a sprout in flight`, with the holder named. so it does not sprout
onto a grove that is about to be full. it seeds its wish instead, and re-asks once the held
crew is live or the hold lapses. had the first sprout died at boot, the second's next ask would
read the slot free again, so a dead sprout never starves it of the slot.

```
🐚 git.grove.capacity --grove local --for behavior
   ├─ ✋ 0 behavior slots
   │  └─ 1 held by a sprout in flight   (granted to the other supervisor's ask)
   └─ next  seed the wish; re-ask once the held crew is live or its hold lapses
```

the hold's bound and where the claim is written are execution choices (yield A7).

### case4, the count says yes and the box says no (G10)

the grove holds a free behavior slot by count: ram and cpu both leave room. but the box is
stalled: work waits on the cpu past the 10% line, or memory stopped outright. a count read off
free ram and idle cores cannot see a queue, and a sprout onto a stalled box slows every crew
already on it. so the stall overrides the count. the gate refuses before it counts, names the
stall and its line, and names the seed as the move. the supervisor seeds, and re-asks once the
stall clears.

```
given('[case4] a grove with a free slot by count, whose cpu stall reads 🔴')
  when('[t0] the supervisor asks for a behavior slot')
    then('it is refused with exit 2, and names the stall and its line')
    then('it names seed as the move')
  when('[t1] the ram full stall reads above 0 instead')
    then('it is refused the same way, and names the ram stall')
```
