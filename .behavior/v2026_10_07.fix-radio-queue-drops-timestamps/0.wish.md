wish =

## .what

in `ehmpathy/rhachet-roles-bhuild`, rip clock timestamps out of the radio queue files the repo
commits, and enrule that no driftable timestamp is ever written into a tracked file again.

## .the outcome

- the radio queue records the dispatcher writes into a repo carry no wall-clock field — e.g.
  `"heldAt": "2026-10-07THH:MM:SSZ"` is gone. where an order is needed, it comes from the record's
  position or a stable sequence, never from a clock
- a rerun of the same dispatch on another day writes byte-identical queue files, so a diff shows
  only real changes
- 🔴 the dispatched tasks carry no timestamp either — a radio push never writes a clock value into
  the task body, title, or envelope it sends (a gh issue, an os.fileops task file), so a task reads
  the same whenever it was sent
- 🔴 a rule, in this repo's briefs: **never write a driftable timestamp into a tracked file** — a
  clock value changes on every run with no change in sense, so it churns diffs, breaks snapshots,
  and trips the repo's own hook that forbids it. the rule names where a timestamp may live instead
  (an untracked log, `.log/`, a git commit's own date) and grades a tracked one a blocker
- the hook that already forbids such timestamps passes on every file the dispatcher writes
- tests prove the queue files and the dispatched task bodies hold no clock field, and that two runs
  a day apart write the same bytes

## .why now

measured 2026-10-07: the radio queue wrote `"heldAt": "2026-10-07THH:MM:SSZ"` into a tracked file,
which violates the repo hook that forbids driftable timestamps, so every dispatch leaves a file the
hook rejects.
