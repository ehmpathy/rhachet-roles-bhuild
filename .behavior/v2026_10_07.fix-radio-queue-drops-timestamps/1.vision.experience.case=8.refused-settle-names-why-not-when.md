# case=8 — a refused settle names why, never when

feel: sharp · care: alterpath

## .narrative

a clone held an update: mark task 212 DELIVERED. before the gate opened, a human delivered 212 by
hand. the drain sends the held update; upstream refuses it — `cannot transition from DELIVERED`.

the record closes for good:

```diff
-  "recordStatus": "QUEUED",
-  "reason": "gate:org",
+  "recordStatus": "REFUSED",
+  "reason": "cannot transition from DELIVERED",
```

before this fix the same diff also added `"settledAt": "2026-10-08THH:MM:SSZ"`. now it does not.

care is alterpath: a refusal is rare (it needs a race between a held update and a hand change) and
cheap (the task already sits in the state the update wanted).

## .the fail-safe

the refusal already fails safe, and this fix keeps it so:

- **loud, once.** the push output names the refusal and the reason, as today.
- **closed, never retried.** `recordStatus: REFUSED` takes the record out of the drain; the next push
  will not resend it.
- **why, in a fixed line.** `reason` is the first line of a `BadRequestError` the task op threw — a
  literal (`setPartRadioTask.ts:206`), never upstream prose with a clock in it.

## .bdd sketch

```
given('[case1] one held update record whose task upstream is already DELIVERED')
  when('[t0] the drain sends it')
    then('the record reads recordStatus=REFUSED and reason="cannot transition from DELIVERED"')
    then('the record holds no field whose value is a clock')
  when('[t1] a later push drains on a later day (clock pinned +1 day)')
    then('the refused record is not resent')
    then('the record file is byte-identical to [t0]')
```
