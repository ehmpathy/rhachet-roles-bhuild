# 1.vision — the radio writes no clock

## the outcome world

### before

a clone holds a push. `$route/.radio/record.3f9a….json` gains `"heldAt": "2026-10-07THH:MM:SSZ"`.
the push drains next week; the record gains `"settledAt": "2026-10-14THH:MM:SSZ"`. a rerun of the
same dispatch the next day writes a new `heldAt` — the same task, a new diff. the consumer repo's
husky hook that forbids timestamps rejects the file. every dispatch leaves a file a guard refuses.

the os.fileops twin writes only datestamps — `pushed_at: 2026-10-07`, a backup named
`task.<exid>.bak.2026-10-08.md`. a datestamp holds no time of day, and the wisher ruled it fine, so
os.fileops needs no change; a clamp keeps it from a slide into a timestamp.

### after

the record holds what the push **means** — identity, target, channel, body, fate, place in line:

```json
{ "key": "3f9a0c1e7d2b4a58", "kind": "create", "repo": { "owner": "sandpine", "name": "svc-lessons" },
  "via": "gh.issues", "title": "fix lesson reminder copy", "recordStatus": "QUEUED",
  "reason": "gate:org", "heldSeq": 1, "deliveredExid": null }
```

the order is `heldSeq`. "when?" is a question git answers (the commit's own date) and github answers
(the issue's own `createdAt`). the same dispatch on any day writes the same bytes.

### a day in the life

- **the clone** pushes; the gate holds it; the route gains one clean record. it reruns tomorrow —
  `git status` shows naught new.
- **the reviewer** reads the settle diff: `QUEUED → DELIVERED`, `deliveredExid: 212`. every changed
  line is a change in sense.
- **the maintainer** adds `lastTriedAt` six weeks on; the clamp test goes red and names the brief.

### the aha

> the record stops to narrate **when** and starts to state **what**. once "when" belongs to git,
> every diff is a real change — and the guard has no reason to refuse.

## the contract we propose

| surface | change |
|---------|--------|
| `RadioTaskRecord` | drop `heldAt`, `settledAt`. `heldSeq` = 1 + max across **every** record dir in the worktree (F2) |
| record read (`daoRadioTaskRecord`) | shed `heldAt` / `settledAt` from a legacy file, so the next write drops them; a record with no numeric `heldSeq` fails as the extant `MalfunctionError` that names its path and fix (case=3) |
| drain order (`asRadioTaskRecordOrder`) | `heldSeq`, then `key` — no clock |
| drain lock (`withRadioDrainLock`) | the `.behavior/.radio/.locks/` dir writes its own `.gitignore` (`*`), so a crashed drain's lock file — which holds an epoch-ms `expiresAtMse` — never reaches git (F10, case=9) |
| stdout held label | `held since <stamp>` → `held #N in line`; the age is dropped, not moved — the wisher ruled it irrelevant (F3) |
| os.fileops task file + backup | unchanged — datestamps only (`pushed_at`, `claimed_at`, `delivered_at`, `.bak.<date>`); a clamp keeps them datestamps (F4, F5) |
| `RadioTask` | unchanged |
| gh.issues title + body | unchanged — already clock-free; a clamp keeps it so |
| brief | `rule.forbid.timestamps-in-tracked-files` in `.agent/repo=.this/role=any/briefs/` (F6). **timestamp** = a value with a time of day — an iso datetime, an epoch number. a **datestamp** (`2026-10-07`, `v2026_10_07.*`) holds a day only and is allowed. names the sanctioned homes for a timestamp (`.log/`, an untracked file, a git commit's own date) and grades a tracked timestamp a blocker (F9) |
| this repo's husky | adopt `.husky/check.timestamps.sh` byte for byte from `declapract-typescript-ehmpathy` main (`src/practices/husky/best-practice/.husky/`), and source it from `.husky/pre-commit` the same way the best practice does. it blocks a staged file (not `.ts`/`.sh`) that holds `T?HH:MM:SS`; iso durations pass (F11) |
| tests | a byte scan for an iso datetime over every record + task the radio suites write — the same pattern the husky check uses; a two-run byte-identity test over the records, clock pinned a day apart, which also catches an epoch number the scan cannot read (F8) |

## mental model

- **to a friend:** "the radio queue used to stamp the time on every ticket. now each ticket just
  has its number in line. git already knows when you committed it."
- **analogy:** a deli counter ticket. it says `#47`, never `11:42am`. the order is the number; the
  clock on the wall is someone else's job.
- **their words vs ours:** they say "the queue file churns for no reason" and "the timestamp hook
  yells". we say "timestamp in a tracked file" and "place in line (`heldSeq`)".

## evaluation

**goals:**

| wish outcome | met by |
|--------------|--------|
| queue records carry no wall-clock field | drop `heldAt`, `settledAt` (case=1, 2) |
| order from position or a stable sequence | worktree-wide `heldSeq` (case=4) |
| rerun on another day → byte-identical | key is a sha256 of identity; seq is deterministic (case=1) |
| dispatched tasks carry no timestamp | already true: os.fileops writes datestamps only, gh.issues no date at all; a clamp keeps it so (case=5) |
| a rule in this repo's briefs | the brief (case=6, F6) |
| the hook passes on every file the dispatcher writes | the clamp uses the hook's own pattern; and the hook itself now runs in this repo's pre-commit too (F1, F8, F11) |
| tests prove no clock + same bytes a day apart | the clamp + the two-run test (case=6) |

**pros:** diffs read as change in sense; snapshots stop to drift; one fewer reason a guard refuses a
dispatch; the order becomes explicit instead of implied by a clock with one-second grain.

**cons:** "how long has this task waited?" loses its direct answer — stdout says the place in line,
not the age. the wisher ruled the age irrelevant (F3).

**edge cases + the pit of success:**

- **legacy record with `heldAt`** — the read sheds it; the write never carries it forward (case=3).
- **two pushes in two dirs at once** — could mint one seq twice; the key tiebreak keeps the order
  total (F2).
- **a human title that holds a date** (`ship by 2026-11-01`) — a datestamp, allowed. a human title
  with a time of day is human text, not a clock we wrote; the clamp runs on fixture titles that
  hold none (F8).
- **a maintainer adds a new `*At` field** — the clamp fails loud and cites the brief (case=6).
- **a record's `reason`** — never a clock. a held reason is a closed set (`upstream:401` /
  `:rate-limit` / `:fault`, `asRadioUpstreamReason.ts`) that drops github's text, reset time and
  all. a refused reason is the first line of a `BadRequestError` (`isRadioReplayRefusal.ts`) — and
  every such headline in the send path is a fixed literal (`setPartRadioTask.ts:59,163,189,197,206,213`,
  `daoRadioTaskViaGhIssues.ts:120`); the metadata json falls on later lines, which
  `asRadioErrorHeadline` cuts. the byte scan (F8) keeps it so.
- **records in a repo that does not want them tracked** — out of scope; trackability stays the
  consumer's call (F7).

## what is awkward

- **the hook bites this route.** once `check.timestamps.sh` sits in pre-commit, it scans every
  staged file. this route's own `0.wish.md` quotes `"heldAt": "2026-10-07T…Z"` with a real time,
  so the commit that lands this fix would block on its own wish. the vision artifacts mask their
  examples as `THH:MM:SSZ`; the wish is the wisher's text, so its mask is the wisher's call (F12).
- **the hook bites old files on touch.** fixture logs, a `.mjs` schema, a few briefs and old routes
  hold `HH:MM:SS`. none block today; each blocks the first commit that edits it. a fixture log that
  must hold a real time is a case for `.log` masks or an exempt path — not for this fix (F11).
- **a datestamp still drifts by day.** an os.fileops task pushed today and an identical one pushed
  tomorrow differ in `pushed_at`. the wisher ruled that fine — the line the rule draws is time of
  day, not byte-identity. the byte-identity promise binds the queue records only.
- **an epoch number escapes a text scan.** the drain lock's `expiresAtMse` is a bare integer. the
  scan cannot tell it from a count; the two-run byte test and the lock dir's self-ignore cover it
  (F8, F10).
