# case=9 — a crashed drain leaves no tracked clock

feel: sharp · care: critipath

## .narrative

a consumer repo tracks its routes' `.radio/` dirs, as the wish describes. a clone's push starts a
drain; the drain takes the worktree lock at `.behavior/.radio/.locks/`; the clone's process is killed
mid-drain. the clean release (`delMutexLock.js`, compare-and-delete) never runs.

the lock file stays on disk. its envelope holds `"expiresAtMse": 1791392531000` — a clock, five
minutes past the crash. the human runs `git status` and sees an untracked file in the radio dir; a
`git add .behavior/` stages it; the next commit carries a clock. a later drain overwrites it with a
new clock — the same churn the wish names, through a door the record fix does not close.

care is critipath: a crash is not frequent, but every one leaves a tracked clock, and an epoch-ms
number slips past an iso-date scan (F8) by its very shape.

## .the fail-safe

**hold the limit — lock state is never trackable.** the lock dir writes its own `.gitignore` (`*`)
when it is created, so `git status` never lists a lock file, whether the drain exited clean or not
(F10). the lock itself works as today; only its visibility to git changes.

records stay trackable (F7). the line between them: a record is the route's account of a push; a
lock is a moment's mutual exclusion, with no sense after the moment ends.

## .bdd sketch

```
given('[case1] a consumer-shaped temp repo that does not ignore .radio/')
  when('[t0] a drain takes the lock')
    then('.behavior/.radio/.locks/.gitignore exists and holds "*"')
    then('git check-ignore reports every file in .locks/ as ignored')
  when('[t1] the drain process dies before release')
    then('the lock file remains on disk')
    then('git status lists no file under .behavior/.radio/.locks/')
  when('[t2] a later push drains after the lease lapses')
    then('the drain proceeds, and git status still lists no lock file')
```
