# case=2 — a delivered settle diff shows only the fate

feel: happy · care: critipath

## .narrative

the human opens the sandpine gate. the clone's next push gets through and drains the held
`fix lesson reminder copy` first. the record moves from QUEUED to DELIVERED.

before this fix the diff read:

```diff
-  "recordStatus": "QUEUED",
-  "reason": "gate:org",
-  "settledAt": null,
+  "recordStatus": "DELIVERED",
+  "reason": null,
+  "settledAt": "2026-10-08THH:MM:SSZ",
-  "deliveredExid": null
+  "deliveredExid": "212"
```

after this fix it reads:

```diff
-  "recordStatus": "QUEUED",
-  "reason": "gate:org",
+  "recordStatus": "DELIVERED",
+  "reason": null,
-  "deliveredExid": null
+  "deliveredExid": "212"
```

every changed line is a change in sense. when it was delivered is a question git answers: the
commit that carried the change has its own date. github answers it too: issue #212 has its own
`createdAt`.

the refused settle is a separate, sharp experience: case=8.

## .bdd sketch

```
given('[case1] one held record for sandpine/svc-lessons; the gate now open')
  when('[t0] a second push gets through and drains the held record')
    then('the record reads recordStatus=DELIVERED and deliveredExid=<the issue number>')
    then('the record holds no field whose value is a clock')
  when('[t1] the same drain is replayed on a later day (clock pinned +1 day) against the same upstream')
    then('the record file is byte-identical to [t0]')
```
