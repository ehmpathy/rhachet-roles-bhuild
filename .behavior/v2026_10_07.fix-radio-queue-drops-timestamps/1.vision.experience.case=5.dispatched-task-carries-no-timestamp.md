# case=5 — a dispatched task carries no timestamp, from push through deliver

feel: happy · care: critipath

## .narrative

a clone pushes `cert-ingest: retry on 429` via `os.fileops` into `sandpine/infrastructure`. the
task file `~/git/.radio/sandpine/infrastructure/task.a1b2c3d4._.md` reads:

```
---
exid: "a1b2c3d4"
title: "cert-ingest: retry on 429"
status: QUEUED
repo: "sandpine/infrastructure"
pushed_by: bert
pushed_at: 2026-10-07
claimed_by: null
branch: null
---
```

`pushed_at` is a datestamp — a day, no time of day — which the wisher ruled fine. a mechanic claims
it the next day: `status: CLAIMED`, `claimed_at: 2026-10-08`; the prior version is kept as
`task.a1b2c3d4.bak.2026-10-08.md`. on deliver, `delivered_at` is a day too. no line holds an hour,
a minute, or an epoch number.

the gh.issues twin reads the same way: its body holds title + description + the tree line and no
clock at all.

os.fileops is unchanged by this fix — it already writes only datestamps (the iso string cut at `T`,
at `setFullRadioTask.ts:60`, `setPartRadioTask.ts:151`, `:180`; `toIsoDateStamp` for the backup
name, `daoRadioTaskViaOsFileops.ts:63`). this case is the clamp that keeps it so.

## .bdd sketch

```
given('[case1] an empty os.fileops radio dir for sandpine/infrastructure')
  when('[t0] radio.task.push --via os.fileops --title "cert-ingest: retry on 429"')
    then('the task file holds no iso datetime and no epoch number')
    then('pushed_at, where present, is a bare YYYY-MM-DD')
  when('[t1] radio.task.push --exid <id> --status CLAIMED, on a later day')
    then('the task file and its backup name hold no iso datetime')
  when('[t2] radio.task.push --exid <id> --status DELIVERED')
    then('the task file holds no iso datetime')
given('[case2] a gh.issues create and a status update')
  when('[t0] the title and body are composed')
    then('neither holds an iso datetime or an epoch number')
```
